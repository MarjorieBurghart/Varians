Varians — TEI-XML-Editor für Textkritik

Benutzerhandbuch — Version 0.8.5.25.2

Varians ist eine Arbeitsumgebung für textkritische TEI-Editionen. Sie verbindet XML-Bearbeitung, RELAX-NG-Validierung, XSLT/CSS-Vorschau, Verwaltung von Textzeugen und Bildern, optionales ALTO, Synchronisierung von Textzeugen und die Erzeugung eines Web-Viewers.

1. Projekte und Start

Beim ersten Start ist kein Projekt geöffnet. Später kann Varians das Projekt erneut öffnen, das beim Beenden aktiv war. Datei → Projekt schließen (Ctrl+W) kehrt zum Startbildschirm zurück und verhindert das automatische Wiederöffnen dieses Projekts.

Datei → Neues Projekt… kann eine vorhandene TEI-Datei verwenden oder eine neue Transkription beginnen. Im zweiten Fall wird xml/edition.xml minimal erzeugt und ein TEI-<listWit> aus den Projektzeugen aufgebaut. Ein Textzeuge kann zunächst ohne Bilder, ALTO oder Synchronisierung bestehen; diese Ressourcen lassen sich später ergänzen.

project.xml
xml/edition.xml
images/
alto/
alignments/
rendering/
i18n/
web_output/

Ältere Projekte mit edition.xml im Stammordner bleiben unterstützt.

2. XML-Bearbeitung und XSLT/CSS-Vorschau

XML-Quelltext enthält das TEI-Dokument. Der visuelle Zeilenumbruch verändert weder XML noch logische Zeilennummern. XSLT / CSS zeigt eine redaktionelle Vorschau. Auswahlbereiche in Quelltext und Vorschau werden nach Möglichkeit synchronisiert, auch wenn dasselbe Wort mehrfach in einer Passage vorkommt.

Der Fragment-Editor erlaubt die Bearbeitung eines begrenzten Ausschnitts und die anschließende Rückübernahme in das Hauptdokument.

Gemeinsame Auswahl mit dem Fragment-Editor. Der Stift ✎ am Anfang eines Absatzes der Vorschau öffnet diesen Absatz im Fragment-Editor, ohne die Bilder der Textzeugen zu verschieben; ein Klick auf den Text der Vorschau synchronisiert sie weiterhin. Ist der Editor geöffnet, wird eine in diesem Absatz der Vorschau ausgewählte Zeichenkette (durch Ziehen mit der Maus oder per Doppelklick) auch im Fragment-Editor ausgewählt, der den Fokus erhält: Die zu korrigierende Stelle ist sofort gefunden. Umgekehrt wird eine im Fragment-Editor getroffene Auswahl in der Vorschau ausgewählt, die dorthin blättert; der Fokus bleibt im Editor. Dasselbe Vorkommen eines wiederholten Wortes wird gefunden, auch bei einem durch <lb break="no"/> getrennten Wort. Eine Auswahl in einem anderen Absatz ändert den Fragment-Editor nicht: Öffnen Sie diesen Absatz mit seinem Stift. Im Fragment eingegebener Text erscheint in der Vorschau erst nach Auf XML anwenden.

3. Markup-Hilfen, RNG und custom-elements.xml

Ctrl+E umschließt eine Auswahl mit einem Element oder fügt am Cursor ein neues Element ein. Ctrl+Space ergänzt Elementnamen, Attribute und ausgewählte Attributwerte anhand des RELAX-NG-Schemas und von custom-elements.xml. Vorschläge sind nach ihrer Herkunft gekennzeichnet.

Zeigerlisten wie @wit werden tokenweise ergänzt. Die dynamische Quelle witnesses kann Projektkennungen wie #A1 und #B1 anbieten.

Wichtig: projektspezifische Eingabehilfen verändern niemals die RELAX-NG-Gültigkeit. Die vollständige Validierung mit F8 bleibt maßgeblich.

Validierungsergebnisse erscheinen in einem unteren Bereich. Beim Projektwechsel werden sie geleert, damit keine Diagnose aus einem älteren Dokument sichtbar bleibt.

4. XPath-Suche

XPath (Ctrl+Shift+F) führt XPath 1.0 gegen die TEI aus. Ein einfacher Ausdruck wie //note wird gegebenenfalls automatisch im TEI-Namensraum erneut versucht; komplexe Ausdrücke können den Präfix tei: ausdrücklich verwenden.

Die Ergebnisse zeigen Quellzeile, Element, Pfad und Vorschau. Beim Anklicken wird das vollständige XML-Element von der öffnenden bis zur schließenden Markierung ausgewählt, auch über mehrere Quellzeilen hinweg. Selbstschließende Elemente werden vollständig markiert.

Skalare Ausdrücke wie count(//tei:note) zeigen ihren Wert statt einer Elementliste.

Zur Prüfung des kritischen Apparats bietet Hilfe → Apparat debuggen… fertige Abfragen an: siehe Apparat debuggen.

5. Tag-Paare und sicheres Formatieren

Varians erkennt XML-Tag-Paare. Befindet sich der Cursor in einem öffnenden Tag, wird das zugehörige schließende Tag hervorgehoben. Eindeutige QName-Änderungen und das vollständige Löschen eines öffnenden Tags können auf das zugehörige schließende Tag gespiegelt werden.

Einrücken formatiert strukturelle Bereiche konservativ und schützt gemischten Text. Um <lb/> wird kein neuer Leerraum eingefügt; xml:space="preserve" wird beachtet; mehrdeutiger oder gemischter Inhalt bleibt unverändert. In custom-elements.xml sind formatting="inline", block und preserve möglich.

6. Textzeugen, Bilder, Faksimile und Seiten

Ein Textzeuge kann ohne Bilder, mit lokalen JPEG/PNG/TIFF/BMP/WebP-Dateien oder mit einem IIIF-Presentation-2/3-Manifest arbeiten. Lokale Dateien können in das Projekt kopiert oder an ihrem ursprünglichen Ort referenziert werden.

Bildseiten können in TEI mit stabilen <surface>-Kennungen beschrieben werden:

<facsimile>
  <surface xml:id="A1-p0002" n="1v">
    <graphic url="../images/A1/002.jpg"/>
  </surface>
</facsimile>
Sicherheit: Varians aktualisiert Faksimile-Daten schrittweise. Ein vorhandenes <facsimile> wird nicht blind neu aufgebaut; manuell ergänzte Zonen und Metadaten bleiben erhalten.

Seite markieren fügt einen Seitenwechsel für die aktuell angezeigte Seite ein:

<pb n="1v" edRef="#A1" facs="#A1-p0002"/>

Befindet sich der Cursor innerhalb irgendeines XML-Tags, wird der Vorgang verweigert. Setzen Sie den Cursor in Text oder zwischen Tags.

7. ALTO und Zeilensynchronisierung

ALTO ist optional und von der Bildquelle unabhängig. Es liefert OCR-Text und Seitengeometrie, aber ALTO allein ist keine Zeilensynchronisierung. Ohne echte Zuordnung TEI ↔ Zeile bleibt Varians im Seitenmodus und zeigt die gesamte aktuelle Seite.

Der Zeilenmodus wird nur aktiviert, wenn die Synchronisierung tatsächlich nutzbar ist: Referenzzeilen beim Pivot-Textzeugen und echte base_keys bei sekundären Textzeugen. Ein leeres oder vorläufiges Alignment-JSON schaltet die Oberfläche nicht in den Zeilenmodus.

8. Anzeige der Textzeugen

Das Menü Ansicht enthält Bilder neu laden, Angezeigte Textzeugen auswählen… und das Sprachmenü. Es können null bis beliebig viele Textzeugen angezeigt werden. Die Auswahl wird lokal pro Projekt gespeichert und verändert project.xml nicht.

Die Textzeugenbereiche liegen in einem vertikalen Splitter und können in der Höhe verändert werden. Ein Doppelklick auf die Kopfzeile maximiert einen Textzeugen vorübergehend; ein weiterer Doppelklick stellt die vorherigen Größen wieder her.

V0.8.5.16 — Sichtbarkeit und Reihenfolge. Öffnen Sie Ansicht → Angezeigte Textzeugen auswählen…, markieren Sie die gewünschten Textzeugen und wählen Sie eine Zeile. Mit Nach oben und Nach unten ordnen Sie die Bildbereiche von oben nach unten. Ausgeblendete Textzeugen behalten ihre Position. Die Auswahl wird lokal pro Projekt gespeichert und beim Neustart wiederhergestellt; neue Textzeugen werden angehängt. Weder Pivot-Textzeuge noch Alignmentdaten, project.xml oder die Reihenfolge im erzeugten Web-Viewer werden geändert.

9. Web-Viewer

Web-Viewer erzeugen erstellt eine eigenständige Ausgabe, normalerweise unter web_output/. Benötigte lokale Bilder werden in das Ausgabepaket kopiert.

Ohne Zeilensynchronisierung arbeitet der Viewer im Seitenmodus mit ← Seite und Seite →. Ein Klick in den Editionstext ermittelt für jeden Textzeugen unabhängig das letzte passende <pb>. Bei nutzbarer Zeilensynchronisierung wird stattdessen die Zeilennavigation aktiviert. Projekte ohne Bilder werden ohne leere Faksimilespalte exportiert.

10. Speichern und Sicherheit

Ctrl+S speichert die Edition. Die XML-Wohlgeformtheit wird automatisch geprüft, kompilierte RNG-Schemata werden zwischengespeichert, und wichtige Schreibvorgänge verwenden soweit sinnvoll atomaren Ersatz und/oder .bak-Sicherheitskopien. Mehrdeutige automatische Eingriffe sollen verweigert werden, statt redaktionelle TEI stillschweigend umzuschreiben.

ALTO, PAGE XML und lokale IIIF-Kopien (0.8.5)

Layout-Dateien der Textzeugen

Unter Projekteinstellungen → Textzeugen → Bearbeiten im Bereich Layout-Transkription (ALTO / PAGE) können Sie XML-Dateien in Seitenreihenfolge hinzufügen. Varians erkennt das Format jeder Datei einzeln. Verschiedene Textzeugen und auch ein einzelner Textzeuge dürfen ALTO und PAGE kombinieren. Für ein übertragbares Projekt sollten Sie die XML-Dateien ins Projekt kopieren.

ALTO-Zeilen besitzen meist rechteckige Koordinaten; PAGE-Polygone (Coords/@points) und optionale Grundlinien (Baseline/@points) bleiben erhalten. Mit Rahmen werden die Umrisse eingeblendet. Der PAGE-Zeilentext stammt aus TextEquiv/Unicode, ersatzweise aus den Wörtern. Der Layout-Import erzeugt keine automatische Verknüpfung mit TEI-<lb>-Elementen; die Synchronisierung ist eine eigene Ressource.

IIIF-Downloadverwaltung

Aktivieren Sie unter Projekteinstellungen → Textzeugen → Bearbeiten die lokale Arbeitskopie und wählen Sie Alle Seiten des Manifests oder Nur Seiten mit zugeordneten ALTO- oder PAGE-Dateien. Diese Einstellung gilt pro Textzeuge. Für die gezielte Auswahl müssen die ALTO-/PAGE-Dateien zuvor eingetragen sein. Varians gleicht Bilddateinamen, Seitenbezeichnungen und Folioangaben mit den IIIF-Canvases ab; die bloße Dateireihenfolge wird nicht als Zuordnung verwendet. Mehrdeutige oder nicht zuordenbare Seiten werden gemeldet und übersprungen.

Der Download startet nach dem Speichern der Projekteinstellungen in einem eigenen Fenster, ohne die Editionsarbeit zu blockieren. Die Verwaltung kann über Datei → IIIF-Downloadverwaltung… jederzeit erneut geöffnet werden. Sie zeigt die Gesamtzahl, die ausgewählten, lokal gespeicherten, ausstehenden und ausgeschlossenen Seiten. Fehlende herunterladen setzt fort, ohne vorhandene Dateien erneut anzufordern; Auswahl neu herunterladen erzwingt eine Aktualisierung. Pausieren, Fortsetzen und Abbrechen wirken zwischen den Bildern. Das Schließen des Fensters blendet es nur aus.

Die Dateien liegen unter iiif/local/<Textzeuge>/ und können nach Abschluss des Vorgangs ohne erneutes Öffnen des Projekts verwendet werden. Nicht heruntergeladene Seiten bleiben auf das Netzwerk angewiesen. Die Einstellung für den Web-Viewer ist unabhängig; nur vorhandene lokale Bilder können mitgeliefert werden.

Unabhängige Einstellung für den Web-Viewer

Mit Lokale Kopie beim Erstellen des Web-Viewers verwenden werden vorhandene Bilder in web_output/images/ eingebunden. Andernfalls verwendet der Web-Viewer weiterhin die IIIF-URLs, auch wenn die Desktop-Anwendung lokal arbeitet. Fehlende Bilder benötigen gegebenenfalls eine Internetverbindung. Beachten Sie vor der Weitergabe die Bildrechte und Lizenzbedingungen.

Gezielte IIIF-Bildauswahl und manuelle OCR-Zuordnung (0.8.5.4)

Unter Projekteinstellungen → Textzeugen → Bearbeiten wählen Sie „Nur für die Edition ausgewählte Bilder“ und anschließend „Bilder auswählen und OCR-Dateien zuordnen…“. Das Manifest bleibt der vollständige Katalog; nur markierte Canvases gehören zu den Editionsseiten. Die Liste lässt sich nach Folio filtern und die Auswahl auf sichtbare Zeilen anwenden. Die Vorschau öffnet das IIIF-Bild im Browser.

Varians schlägt eine Zuordnung zwischen IIIF-Canvas und ALTO/PAGE automatisch vor, wenn die Bilddateinamen ohne Endung exakt übereinstimmen. Auch der im OCR-XML angegebene ursprüngliche Bildname wird geprüft. Mehrdeutige Treffer werden nicht übernommen; vorhandene manuelle Zuordnungen haben Vorrang. Mit „Automatisch zuordnen (exakte Namen)“ können Sie leere Felder füllen und Vorschläge jederzeit ändern oder entfernen. Eine Zuordnung nach Dateireihenfolge oder ungefährer Folio-Bezeichnung erfolgt nicht.

Nach dem Einlesen lokaler ALTO-/PAGE-Dateien ordnen Sie jedem ausgewählten Canvas seine OCR-Datei in der letzten Spalte zu. Unterschiedliche Dateinamen sind zulässig. Eine manuelle Zuordnung setzt derzeit eine OCR-Datei pro Bild voraus.

Im Downloadmanager bedeutet „Gesamtes Manifest“ bei aktiver gezielter Auswahl nur noch die für die Edition ausgewählten Bilder. „Seiten mit ALTO/PAGE“ schränkt die Auswahl zusätzlich auf OCR-zugeordnete Seiten ein. Nicht ausgewählte Canvases erzeugen weder Downloads noch neue TEI-Oberflächen. Ihre Kennungen behalten die ursprüngliche Position im Manifest.

Bereits angelegte TEI-Oberflächen und heruntergeladene Bilder werden nicht automatisch gelöscht: Sie können editorische Verweise enthalten. Prüfen Sie ungenutzte Oberflächen vor einer manuellen Bereinigung. Lokale Bilder und ALTO-/PAGE-Dateien werden beim Einlesen in natürlicher Dateinamenfolge sortiert (1r, 1v, 2r usw.); mit „Natürlich sortieren“ lässt sich eine vorhandene Liste neu ordnen.

Synchronisierte Seiten und IIIF-Canvases (0.8.5.6)

Importieren Sie für einen IIIF-Textzeugen die von Varians-Synchro exportierte JSON-Datei und öffnen Sie Bilder auswählen und OCR zuordnen…. Die Seiten- und Zeilenkennungen der JSON-Datei bleiben unverändert; die IIIF-Auswahl legt nur die abzubildenden Seiten fest, auch wenn das Manifest Hunderte Canvases enthält.

Varians ermittelt die passende Bildseite anhand der exakten Canvas-Kennung, des IIIF-Image-Dienstes, einer vorsichtig normalisierten Bild-URL, einer verlässlichen ALTO/PAGE-Zuordnung oder einer eindeutigen Folio-Bezeichnung. Übereinstimmende Dateinamen werden automatisch zugeordnet. Ist keine sichere Zuordnung möglich, wählen Sie in der Spalte Synchronisierte Seite ausdrücklich die entsprechende JSON-Seite aus. Die Listenposition ist niemals ein Identitätsnachweis. Manuelle Entscheidungen haben Vorrang und werden in project.xml gespeichert.

Die Spalten Lokale Kopie und Zuordnungsstatus zeigen den Downloadstatus, die Grundlage der Zuordnung und die bevorzugte Bildquelle. Für die Offline-Anzeige ist eine vorhandene lokale Kopie nötig; andernfalls bleibt der IIIF-Dienst als Ersatz verfügbar. Mehrdeutige Treffer werden nicht willkürlich ausgewählt. Nur die ausgewählten Canvases erzeugen neue TEI-Surfaces; vorhandene werden nicht stillschweigend entfernt.

Leere TEI-Transkription aus dem Leitzeugen vorbereiten

Unter Neues Projekt oder Projekteinstellungen lässt sich die Erstellung von <pb/> für den Leitzeugen und wahlweise von <lb/> aktivieren. Nur ausgewählte Editionsseiten erhalten ein <pb/>; @facs verweist auf die <surface>, @edRef auf den Zeugen. Die erzeugten <lb/> tragen @edRef, jedoch weder @n noch einen automatischen Verweis auf Bildzonen. Vorrangig werden eindeutig zugeordnete ALTO/PAGE-Zeilen gezählt; andernfalls die im Synchronisations-JSON tatsächlich verzeichneten Zeilen, auch wenn die Zählung erst bei 41 beginnt. Fehlende Zeilen werden angezeigt, aber nicht erfunden. Eine ausgewählte Seite ohne verzeichnete Zeilen behält ihr <pb/>. Vorschau, Bestätigung und datierte Sicherung schützen bestehende Texte; OCR-Text wird nicht übernommen.

TEI aus dem Leitzeugen vorbereiten (0.8.5.7)

Unter Datei → Neues Projekt wählen Sie Neue Transkription beginnen. Der Bereich zur Vorbereitung der Transkription aus dem Leitzeugen befindet sich direkt unter dem Ausgangspunkt, vor der Zeugenliste. Aktivieren Sie die Erzeugung von <pb/>; die anfangs ausgewählte Option <lb/> wird dadurch freigeschaltet. In den Projekteinstellungen steht der Bereich vor der Zeugenliste. Die Dialoge sind auf kleineren Bildschirmen scrollbar. Der Fenstertitel zeigt „Varians 0.8.5.7“.

Varians 0.8.5.8 — Teilseiten und Zeilen

Korrektur 0.8.5.8: Ein Seitenausschnitt mit den Zeilen 41–68 erzeugt 28 <lb/>, nicht null oder 68; die Markierungen tragen kein @n. Eine JSON-Seite mit leerer Zeilenliste erhält dennoch ein <pb/>, wenn ihr Bild zur Editionsauswahl gehört. Andernfalls wird auf die fehlende Bild-/Surface-Zuordnung hingewiesen.

Bildzuschnitt an Spalten- und Seitengrenzen (0.8.5.9)

Wenn die Synchronisierung eine Zeile an einem Spalten- oder Seitenwechsel auswählt, bezieht Varians keine Nachbarzeilen aus einer anderen Spalte oder Seite mehr in den Bildausschnitt ein. Der Ausschnitt bleibt auf tatsächlich benachbarte Schriftzeilen begrenzt. Zeilennummern, JSON-Zuordnungen und Synchronisierungsschlüssel bleiben unverändert. Mit „Seite ↗“ lässt sich weiterhin das vollständige Bild öffnen.

Umrisse synchronisierter Zeilen (0.8.5.10)

Die Schaltfläche „Rahmen“ wird für jeden Textzeugen separat aktiviert; ihr aktiver Zustand ist jetzt deutlich erkennbar. Orangefarbene Umrisse kennzeichnen synchronisierte Zeilen, blaue eine manuell ausgewählte Zeile ohne zusätzliche editorische Zuordnung. Wenn eine Zeile des Leitzeugen mehreren Zeilen eines anderen Textzeugen entspricht, zentriert Varians die Ansicht stets auf eine tatsächlich zugeordnete Zeile, auch am Spaltenwechsel. PAGE-Polygone werden polygonal dargestellt, klassische ALTO-Zeilen meist rechteckig. Fehlen Geometriedaten, erscheint ein Hinweis. Der erzeugte Web-Viewer verwendet derzeit rechteckige Markierungen.

Gemischte Navigation: Seiten und Zeilen je Textzeuge (0.8.5.11)

In einer Edition können zeilensynchronisierte Textzeugen und ein Textzeuge mit ausschließlich lokalen Bildern gemeinsam verwendet werden. Jedes Handschriftenfenster folgt seiner eigenen Zuordnungsebene. Textzeugen mit verwendbaren Synchronisationsdaten folgen weiterhin den <lb/>-Markierungen des Leithandschrift und den base_keys; ein nicht synchronisierter Textzeuge folgt seinen eigenen <pb/>-Markierungen über @edRef und den Verweis @facs auf eine <surface>. Fehlt @facs, wird @n nur bei eindeutiger, exakter Übereinstimmung mit einer Seitenbezeichnung berücksichtigt. Die Reihenfolge der Bilder wird niemals zur Zuordnung verwendet. Seitenmarkierungen eines Textzeugen verändern die Ansicht der anderen nicht. Dasselbe gilt für die formatierte Ansicht, die Zeilennavigation und den exportierten Web-Viewer.

V0.8.5.12 — Mehrere Textzeugen. Die Bildleiste ist vertikal scrollbar; der vierte Textzeuge wird nicht mehr zusammengedrückt. Der „Pivot-Textzeuge“ dient nur als technischer Bezugspunkt der Synchronisierung, nicht als editorisch festgelegte Leithandschrift. Fehlt @facs in <pb/>, wird die Kombination @edRef + @n verwendet; identische Folionummern in verschiedenen Handschriften sind zulässig.

Automatische Ergänzung von End-Tags

Im XML-Quelltexteditor und im Fragmenteditor schlägt Varians nach Eingabe von </ das zuletzt geöffnete, noch nicht geschlossene Element vor. Nach <div><p>…</p></ erscheint beispielsweise div>. Mit Eingabe oder Tab wird daraus </div>. Auch ein bereits getippter Anfang wie </di wird berücksichtigt. Mit Esc lässt sich der Vorschlag ohne Änderung verwerfen; Strg+Leertaste ruft ihn erneut auf. Qualifizierte Namen wie tei:div bleiben erhalten. Leere Elemente (<lb/>), Kommentare, CDATA und unvollständige Attribute werden nicht als offene Elemente behandelt. Bei unklarer Verschachtelung wird kein End-Tag geraten.

IIIF-Bilder und nachträglich hinzugefügte ALTO/PAGE-Dateien (0.8.5.14)

Beim Hinzufügen von ALTO- oder PAGE-Dateien zu einem nicht synchronisierten IIIF-Zeugen bleiben dessen Bilder erhalten, auch bei lokalen Arbeitskopien. Die ausgewählten Canvases bleiben maßgeblich. OCR-Geometrie wird nur bei eindeutigem Canvas-Bezug, manueller Verknüpfung, eindeutigem Blattlabel oder nachweislich identischer lokaler Bildkopie zugeordnet. Nicht zugeordnete OCR-Seiten bleiben im abgeleiteten Cache erhalten; ihre Anzahl erscheint als Hinweis am Zeugen. Eine Zuordnung anhand der Reihenfolge findet nicht statt. Für die Zuordnung öffnen Sie die Zeugeneinstellungen und die Auswahl der Bilder mit OCR-Verknüpfung. Synchronisations-JSON und TEI bleiben unverändert.

Zeilensynchronisierung und IIIF-Bildqualität (0.8.5.15)

ALTO/PAGE-Rahmen allein belegen keine Zeilensynchronisierung. Enthält das JSON eines Zeugen keine base_keys-Verknüpfungen zum Pivot-Textzeugen, meldet Varians dies und bleibt bei der Seitennavigation. Auch Verknüpfungen ohne Entsprechung im Pivot-Textzeugen werden gemeldet. Wenn ein IIIF Image API-Dienst verfügbar ist, fordert der Editor das Bild in voller Auflösung statt eines Vorschaubildes aus dem Manifest an; bei einem Fehler dient die Vorschau als Ersatz. Die Rahmen werden auf die tatsächliche Größe des angezeigten Bildes skaliert, auch wenn eine lokale Kopie kleiner als der Canvas ist. Die Zoomangabe bezieht sich auf die automatische Einpassung und gibt nicht die Dateiauflösung an.

V0.8.5.18 — Diagnose und Aktualisierung

Unter Ansicht → Handschriften prüfen… werden Seiten, Bilder, Schriftzeilen und gültige Verweise auf den Pivot-Textzeugen angezeigt. Die Diagnose unterscheidet normale Seitennavigation von fehlenden JSON-Dateien, abweichendem Pivot-Textzeugen, unbekannten base_keys und nicht zugeordneten ALTO/PAGE-Seiten.

Mit Ansicht → Synchronisierung aktualisieren… (Strg+Umschalt+R) lesen Sie nach einem neuen Export aus Varians-Synchro die Ressourcen erneut ein. Zunächst werden sämtliche Daten geprüft, anschließend werden erkannte Änderungen zur Bestätigung angezeigt. Fehlerhaftes JSON ersetzt nicht den bisherigen Zustand. Lücken der Textzeugen

Die Passage, die einem Textzeugen fehlt (ein verlorenes Blatt, ein abbrechender Text), wird in TEI von <lacunaStart/> und <lacunaEnd/> eingeschlossen. Die TEI setzt diese Elemente in eine Lesart: Der Textzeuge ist der des <rdg> (oder <lem>), das sie enthält, oder, in einer Lesart mehrerer Textzeugen, der ihres eigenen @wit:

<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaStart/></rdg></app>
…
<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaEnd/></rdg></app>

<rdg wit="#T2 #P">… <lacunaStart wit="#P"/></rdg>

Varians erkennt diese Elemente auch außerhalb einer Lesart mit @wit, doch die TEI-Validierung meldet sie dort als Fehler.

In den Panels. Steht der Cursor in einer Lücke eines Textzeugen, behält sein Panel die Zeile (bei einem seitenweise verfolgten Textzeugen die Seite), an der sein Text abbricht, mit dem Banner „Lücke in diesem Textzeugen: Sein Text bricht hier ab.“. Seitenweise verfolgte Textzeugen folgen weiter ihren <pb>, die nicht vom Pivot abhängen.

Apparat debuggen. Die Prüfung „Unvollständige <app> (ein Textzeuge hat keine Lesart)“ erwartet von einem Textzeugen innerhalb seiner Lücke keine Lesart.

Eine Lücke ohne <lacunaEnd/> reicht bis zum Ende des Textes. In einer Edition in Teilen kann eine Lücke in einem Teil beginnen und in einem anderen enden; in einem separat synchronisierten Text zählen nur die Lücken dieses Textes. Der Web-Export zeigt die Lücken noch nicht.

Die anderen Textzeugen folgen dem Pivot, wie wenn sich der Cursor bewegt. Ist ein Hilfsdokument angezeigt, blättern die Pfeile nur im Textzeugen.

Zeilenweise synchronisierter Textzeuge. Das Panel geht zur nächsten Zeile des Textzeugen; die Edition springt zu der Zeile des Pivots, die diese Zeile bezeichnet. Eine nicht mit dem Pivot verknüpfte Zeile lässt die Edition auf der verknüpften Zeile davor, und die Statusleiste meldet es. Die Schaltfläche ⤺ bringt das Panel zurück auf die mit der Zeile des Pivots verknüpfte Zeile.

Seitenweise verfolgter Textzeuge. Die Pfeile und die Folioliste führen die Edition zur gewählten Seite: zur ersten Zeile des Textzeugen auf dieser Seite in einem seiner JSON, sonst ans Ende seines <pb edRef="#M" n="45v"/>, sonst an den Anfang des Textes, dessen <locus from> des Textzeugen diese Seite ist. Ohne einen dieser Anhaltspunkte bewegt sich die Edition nicht, und die Statusleiste meldet es.

Von einem Text zum nächsten. Am Ende eines Textes gehen die Pfeile zum nächsten Text in der Handschrift, ob er der durchlaufenden Zählung folgt oder separat synchronisiert ist. Das Panel des Pivots tut dasselbe: Ein mehreren Texten gemeinsamer Pivot wird in einem Zug durchlaufen. Eine Seite mit dem Ende eines Textes und dem Anfang eines anderen bleibt angezeigt. Das Panel eines Textzeugen, der im angezeigten Text fehlt („Kein Alignment dieses Textzeugen für diesen Text.“), führt mit seinen Pfeilen zum nächsten oder vorherigen Text mit diesem Textzeugen, in der Reihenfolge der Edition.

Reihenfolge der Texte in einer Handschrift. Varians leitet sie aus den Seiten des Textzeugen ab:

  • die Stelle der Seiten in der deklarierten Bilderliste des Textzeugen (IIIF-Manifest oder Dateien, in Datei → Projekteinstellungen…);
  • sonst die Seiten, die seine JSON gemeinsam haben: Jedes JSON steht bereits in der Reihenfolge der Handschrift, und eine Seite mit dem Ende eines Textes und dem Anfang eines anderen verbindet sie;
  • sonst das <locus from> des Textzeugen für den Text oder die Foliierung der ersten Seite des Textes (eine Zahl mit r oder v), verglichen mit der der anderen Seiten;
  • sonst behält der Text seine Stelle in der Reihenfolge der Edition, und Varians meldet es.

Ansicht → Handschriften prüfen… nennt die Reihenfolge der Texte in jeder Handschrift, die in mehreren Texten vorkommt, und meldet eine unsichere Stelle. Um sie sicher zu machen, deklarieren Sie die Bilder des Textzeugen oder fügen Sie in seinem <witness> ein <locus from="80r" target="#s04"> hinzu.

Zusammengesetzte Editionen (XInclude)

Wie man ein solches Projekt Schritt für Schritt einrichtet, beschreibt die Anleitung.

Eine Edition kann ihre Teile, zum Beispiel eine Datei pro Predigt, nach dem XInclude-Standard einbinden. Die in project.xml deklarierte Edition bleibt das Hauptdokument; ihre Teile ergeben sich aus ihren xi:include-Elementen, ohne weitere Deklaration:

<TEI xmlns="http://www.tei-c.org/ns/1.0"
     xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
    <xi:include href="sermons/s03.xml" xpointer="element(/1/2/1/1)"/>
  </body>

Ein Teil ist entweder ein Fragment (die ganze Datei, deren Wurzel zum Beispiel das <div> der Predigt ist) oder ein Element eines vollständigen TEI-Dokuments, das über xpointer bezeichnet wird: durch seinen Bezeichner (s02 oder element(s02)) oder seinen Pfad (element(/1/2/1/1): TEI, dann sein 2. Kind text, dann body, dann das erste div). Ein Teil kann selbst weitere Teile einbinden. Relative Pfade in einem Teil gehen vom Ordner des Teils aus.

Teile und Registerkarten

Jeder Teil hat eine eigene Registerkarte, benannt nach seiner Datei, nach der Karte der Edition und in der Reihenfolge der Einbindung. Er wird für sich bearbeitet und gespeichert (Ctrl+S), mit eigenem Rückgängig-Verlauf; vor dem Beenden bietet Varians an, geänderte Teile zu speichern. Die Liste der Teile wird bei jedem Speichern der Edition oder eines Teils neu gelesen. „Registerkarte umbenennen…“ und „Dokument aus dem Projekt entfernen“ betreffen nur Hilfsdokumente. Die XSLT-/CSS-Ansicht bleibt der Edition vorbehalten; die Textzeugen bleiben dagegen sichtbar, solange ein Teil angezeigt wird (siehe unten). Würde die Edition in einem anderen Ordner gespeichert, wären die Pfade ihrer xi:include-Elemente unterbrochen: Varians warnt vorher.

Validierung

Die Edition und jeder ihrer Teile lassen die zusammengesetzte Edition validieren, mit dem Schema der Edition und unter Berücksichtigung der nicht gespeicherten Änderungen der Teile. Das RELAX-NG-Feld zeigt dann eine Spalte Dokument; ein Doppelklick auf einen Fehler öffnet den richtigen Teil an der richtigen Zeile. Die Registerkarte jedes Teils nimmt die Farbe seiner eigenen Fehler an. Ein fehlender oder nicht wohlgeformter Teil, eine zirkuläre Einbindung oder eine nicht unterstützte Form (parse="text", xi:fallback, ein anderes xpointer-Schema) wird in der Zeile ihres xi:include gemeldet.

Verweise und Textzeugen

Die Edition und ihre Teile bilden ein einziges Dokument: Ein #id wird zuerst in der Datei gesucht, die ihn enthält (einschließlich Kopf), dann in den anderen Teilen. F12, der Befehl Verweise und die Vervollständigung berücksichtigen das. Nur die Bezeichner des eingebundenen Elements eines Teils gehören zur zusammengesetzten Edition: Ein Textzeuge, der nur im <teiHeader> einer per xpointer eingebundenen Predigt deklariert ist, wird von Varians in dieser Predigt gefunden, aber ein Werkzeug, das nur die zusammengesetzte Edition liest, sieht ihn nicht. In einem Teil verwendet Hilfe → Apparat debuggen… die eigenen Textzeugen des Teils: sein <listWit>, sonst die Textzeugen der Edition, deren <locus target="#s01"> auf den Teil verweist, sonst die in seinen @wit genannten.

Synchronisierung der Textzeugen

Ist die Edition nur der Bequemlichkeit halber in Dateien aufgeteilt (eine Sammlung, deren Texte wie im Pivot-Textzeugen aufeinander folgen), werden die Textzeugen wie bei einer Edition in einer einzigen Datei synchronisiert: Die Zeilen des Pivots (<lb edRef="#A"/>) werden in der Reihenfolge der zusammengesetzten Edition gezählt, von einem Teil zum nächsten, und die Alignment-Dateien bleiben die gewohnten, eine pro Textzeuge für die ganze Edition. Der Cursor der Edition oder eines Teils bewegt die Textzeugen; ein Klick oder Blättern im Pivot setzt den Cursor in den Teil, der die Zeile enthält, und öffnet seine Registerkarte, auch nach „Registerkarte ausblenden“. Der Strukturstatus (Statusleiste) zählt die Zeilen des Pivots in der ganzen zusammengesetzten Edition, und beim Speichern der Edition oder eines Teils warnt Varians, wenn diese Zahl vom Alignment des Pivots abweicht. Ein <lb/> in einem Kommentar oder außerhalb des eingebundenen Elements eines Teils zählt nicht, wie in anderen XML-Werkzeugen.

Bedingung: Der Pivot muss diese Texte in der Reihenfolge der Edition enthalten. Varians prüft die Zahl der Zeilen, nicht ihre Reihenfolge. Die anderen Textzeugen können eine andere Reihenfolge haben oder einen Text nicht enthalten: Ihr Alignment verweist bereits auf Zeilen des Pivots. Ein seitenweise synchronisierter Textzeuge folgt dem letzten <pb>, das ihn betrifft, in der Reihenfolge der Edition, auch in einem vorangehenden Teil: Hat dieser Textzeuge die Texte in einer anderen Reihenfolge, markieren Sie seine Seite am Anfang jedes Textes.

In einem Teil fügt „Seite markieren“ das <pb> am Cursor in den Teil ein und ergänzt das <facsimile> der Edition; „Doppelseite…“ schreibt seine Zonen in das <facsimile> der Edition. Die Edition wird dann geändert, ohne angezeigt zu werden: Ihre Registerkarte trägt „*“. Rückgängig im Teil entfernt das <pb>, nicht die Ergänzungen im <facsimile>.

Separat synchronisierte Texte

In einem Korpus, dessen Texte nicht von denselben Textzeugen und nicht in derselben Reihenfolge überliefert werden, kann ein Text eigene Alignments haben: ein JSON pro Textzeuge, im gewohnten Format, in einem Ordner, der den Namen der Datei des Textes ohne Endung trägt (alignments/s02/B.json für xml/sermons/s02.xml). Nichts muss deklariert werden: Ein Text mit eigenem Ordner wird separat synchronisiert; die anderen folgen der fortlaufenden Zählung. Der Pivot eines Textes ist der des Projekts, außer bei einer in project.xml deklarierten Ausnahme: <part name="s02" base="B"/>.

Wird ein solcher Text angezeigt, übernehmen die Felder der Textzeugen seine Alignments und seinen Pivot; Anordnung, Zoom und abgelöste Fenster ändern sich nicht. Ein Textzeuge ohne JSON für diesen Text behält sein Feld, das „Kein Alignment dieses Textzeugen für diesen Text.“ anzeigt. Die Zeilen werden im Text allein gezählt (zum Beispiel „B: 8 Zeilen ✓“); ein Klick im Pivot bleibt im Text. Die Prüfung der Textzeugen und das Aktualisieren der Synchronisierungen betreffen den angezeigten Text.

Seitenweise verfolgte Textzeugen. Ein Textzeuge, der für diesen Text kein JSON hat, den Text aber enthält – ein <pb edRef="#C"/> im Text oder ein <locus target="#s04"> in seinem <witness> der <listWit> –, folgt dort seinen Seiten. Vor seinem ersten <pb> im Text zeigt er seine Anfangsseite: das @from dieses locus (<locus from="13r" to="14r" target="#s04">), sonst die Seite vor der dieses ersten <pb>, in der Seitenfolge des Textzeugen. „Seite markieren“ funktioniert dort ebenfalls. Die Textzeugen-Diagnose nennt für jeden Text seine seitenweise verfolgten Textzeugen. Andere Textzeugen ohne JSON behalten die Abwesenheitsmeldung.

Grenzen dieser Version

Die Reihenfolge der Texte in einer Handschrift wird aus ihren Seiten abgeleitet; ein Text, der sich nicht zuordnen lässt, behält seine Stelle in der Reihenfolge der Edition (siehe Eine Handschrift in ihrer eigenen Reihenfolge verfolgen). Die XSLT-/CSS-Ansicht zeigt die zusammengesetzte Edition samt Teilen, aber schreibgeschützt: Die Bearbeitung von Fragmenten, die Synchronisierung per Klick und die Übernahme einer Auswahl zwischen Quelltext und Vorschau sind dort noch nicht möglich. Der Web-Export enthält die Teile noch nicht; vor dem Export bietet Varians „Trotzdem exportieren“ an. Ein Projekt ohne xi:include ist nicht betroffen.

Eine Edition in Teilen einrichten (XInclude): Anleitung

Diese Anleitung beschreibt Schritt für Schritt, wie man ein Projekt organisiert, dessen Edition auf mehrere Dateien verteilt ist, zum Beispiel eine Datei pro Predigt. Die einzelnen Funktionen sind in Zusammengesetzte Editionen (XInclude) beschrieben.

1. Die Dateien ordnen

Behalten Sie eine einzige Editionsdatei, die in project.xml deklarierte (zum Beispiel xml/edition.xml): Sie ist das Hauptdokument, mit dem Kopf, der Liste der Textzeugen und der Reihenfolge der Texte. Legen Sie die Texte in einen benachbarten Ordner, eine Datei pro Text. Geben Sie jeder Datei einen im ganzen Projekt eindeutigen Namen: Dieser Name ohne Endung dient auch als Name des Alignment-Ordners eines separat synchronisierten Textes (Schritt 4). Pfade sind relativ zur Datei, die sie enthält: sermons/s01.xml von der Edition aus, ../personnes.xml#augustinus von einer Predigt aus.

project.xml
alignments/T1.json, T2.json …
alignments/s02/B.json, D.json
xml/edition.xml
xml/sermons/s01.xml, s02.xml, s03.xml …

2. Die xi:include schreiben

Deklarieren Sie den XInclude-Namensraum im Wurzelelement der Edition und setzen Sie an die Stelle jedes Textes ein xi:include:

<TEI xmlns="http://www.tei-c.org/ns/1.0" xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
  </body>
</TEI>

Ein Text ist entweder ein Fragment: die ganze Datei, deren Wurzel das eingebundene Element ist und den TEI-Namensraum trägt (<div xmlns="http://www.tei-c.org/ns/1.0" xml:id="s01">); oder ein vollständiges TEI-Dokument, von dem nur ein Element eingebunden wird, über seinen Bezeichner (xpointer="s02") oder seinen Pfad (xpointer="element(/1/2/1/1)"). Ein vollständiges Dokument kann auch für sich validiert werden; sein Kopf gelangt nicht in die Edition. Ein Text kann selbst einen weiteren einbinden. Verwenden Sie weder parse="text" noch xi:fallback: Varians meldet sie, unterstützt sie aber nicht. Speichern Sie die Edition: Jeder Text erhält seine Registerkarte.

3. Die Textzeugen deklarieren

Deklarieren Sie jede Handschrift nur einmal, in Datei → Projekteinstellungen…, mit einer für die ganze Sammlung gemeinsamen Sigle. Im TEI deklarieren Sie die Textzeugen im <listWit> der Edition, in dem jedes Textes (vollständiges TEI-Dokument) oder in beiden. Ein Textzeuge, der nur im Kopf eines per xpointer eingebundenen Textes deklariert ist, wird von Varians gefunden, aber ein Werkzeug, das nur die zusammengesetzte Edition liest, sieht ihn nicht.

4. Die Synchronisierung jedes Textes wählen

  • Die Texte folgen aufeinander wie im Pivot, mit denselben Textzeugen (eine der Bequemlichkeit halber aufgeteilte Sammlung): fortlaufende Zählung. Ein JSON pro Textzeuge für die ganze Edition, wie bei einer Edition in einer einzigen Datei, deklariert in den Projekteinstellungen. Die Zeilen des Pivots werden von einem Text zum nächsten in der Reihenfolge der Edition gezählt; der Pivot muss die Texte in dieser Reihenfolge enthalten.
  • Die Textzeugen wechseln von Text zu Text (ein Korpus): separat synchronisierter Text. Legen Sie den Ordner alignments/<Name der Datei des Textes>/ an und darin ein JSON pro Textzeuge für diesen Text, im gewohnten Format: alignments/s02/B.json, alignments/s02/D.json. Erzeugen Sie diese JSON mit VariansSynchro auf der Datei des Textes. Nichts muss deklariert werden: Der Ordner genügt. Ein Textzeuge ohne JSON für diesen Text, aber mit seinen <pb edRef> darin oder einem <locus target> in seinem <witness>, folgt dort seinen Seiten: siehe Separat synchronisierte Texte.
  • Beides lässt sich mischen: Die Texte mit eigenem Ordner werden separat synchronisiert; die anderen folgen der fortlaufenden Zählung, und das globale JSON jedes Textzeugen enthält nur deren Zeilen.

5. Einen eigenen Pivot für einen Text deklarieren

Der Pivot eines separat synchronisierten Textes ist der des Projekts. Fehlt dieser Text im Pivot des Projekts oder soll ein anderer Textzeuge als Bezug dienen, schreiben Sie die Ausnahme von Hand in project.xml, vor </teiManuscriptProject>, und öffnen Sie das Projekt erneut:

<parts>
  <part name="s02" base="B"/>
</parts>

name ist der Name der Datei des Textes ohne Endung; base die Sigle des Pivots. Die Zeilen dieses Textes sind dann seine <lb edRef="#B"/>, und sein Ordner muss B.json enthalten. Varians behält dieses Element, wenn die Projekteinstellungen gespeichert werden.

6. Prüfen

  • Zeigen Sie jeden Text an: Der Strukturstatus in der Statusleiste muss stimmen, zum Beispiel „B: 8 Zeilen ✓“; sein Tooltip sagt, ob die Zählung die zusammengesetzte Edition oder einen separat synchronisierten Text betrifft.
  • Ansicht → Handschriften prüfen… nennt den Bereich (die Edition oder den angezeigten Text), die separat synchronisierten Texte mit ihrem Pivot und ihren Textzeugen sowie die Probleme: JSON eines nicht deklarierten Textzeugen, unbekannter Pivot, fehlendes JSON des Pivots…
  • Die RELAX-NG-Validierung betrifft die zusammengesetzte Edition; die Spalte Dokument nennt die Datei jedes Fehlers.
  • Der Befehl Verweise prüft die Verweise von einem Text zum anderen.
  • Ein anderes XML-Werkzeug setzt das Projekt ohne Varians zusammen: xmllint --xinclude --noout xml/edition.xml, oder oXygen mit in den Validator-Einstellungen aktiviertem XInclude.
  • Ansicht → Handschriften prüfen… nennt auch die Reihenfolge der Texte in jeder Handschrift und meldet eine unsichere Stelle: siehe Eine Handschrift in ihrer eigenen Reihenfolge verfolgen.

7. Im Alltag

  • Jeder Text wird in seiner Registerkarte bearbeitet und für sich gespeichert (Ctrl+S); vor dem Beenden bietet Varians an, geänderte Texte zu speichern.
  • Einen Text hinzufügen: seine Datei anlegen, sein xi:include in die Edition einfügen, die Edition speichern; seine Registerkarte erscheint. Für einen separat synchronisierten Text zusätzlich seinen Alignment-Ordner anlegen, dann Ansicht → Synchronisierung aktualisieren….
  • Bei vielen Registerkarten: Rechtsklick auf eine Registerkarte → Registerkarte ausblenden; ein Klick im Pivot lässt die Registerkarte des gesuchten Textes wieder erscheinen.
  • Würde die Edition in einem anderen Ordner gespeichert, wären ihre xi:include unterbrochen: Varians warnt vorher.
  • Der Web-Export enthält die eingebundenen Texte noch nicht; die XSLT-/CSS-Ansicht zeigt sie, schreibgeschützt.
  • Um eine Handschrift von einem Text zum nächsten zu lesen, benutzen Sie die Pfeile ihres Panels: Die Edition zeigt den richtigen Text an.

Ein Projekt ohne xi:include, seine Daten und das Format von project.xml bleiben unverändert.

Version 0.9.1.1 — separat synchronisierte Texte

In einer Edition in Teilen wird ein Text mit eigenem Alignment-Ordner (alignments/s02/, ein JSON pro Textzeuge) separat synchronisiert, mit eigenem Pivot, wenn project.xml ihn deklariert (<part name="s02" base="B"/>); ein Textzeuge ohne JSON für diesen Text zeigt dies in seinem Feld an. Eine Anleitung beschreibt das Einrichten einer Edition in Teilen: siehe Eine Edition in Teilen einrichten. Ein Projekt ohne Ordner pro Text bleibt unverändert.

In der XSLT-/CSS-Ansicht öffnet der Stift ✎ einen Absatz im Fragment-Editor, ohne die Bilder der Textzeugen zu verschieben. Version 0.9.1.3 — Lücken, seitenweise verfolgte Textzeugen in einem separat synchronisierten Text

Lücken der Textzeugen (<lacunaStart/> … <lacunaEnd/>) werden erkannt: Das Panel eines Textzeugen in einer Lücke behält die Zeile oder Seite, an der sein Text abbricht, mit einem Banner; während einer Lücke des Pivots werden die Zeilen nicht mehr synchronisiert; siehe Lücken der Textzeugen. In einem separat synchronisierten Text folgt ein Textzeuge, der den Text ohne JSON dafür enthält, dort seinen Seiten, ab seiner Anfangsseite (<locus from>). Das Durchlaufen einer Handschrift in ihrer eigenen Reihenfolge folgt in Version 0.9.1.4.

Version 0.9.1.4 — eine Handschrift in ihrer eigenen Reihenfolge verfolgen

Die Pfeile jedes Textzeugen-Panels führen nun die Edition, nicht mehr nur die des Pivots: Der Textzeuge wird in seiner eigenen Reihenfolge verfolgt, von einem Teil oder Text zum nächsten, auch ein seitenweise verfolgter Textzeuge (Pfeile und Folioliste); der Pivot geht von einem separat synchronisierten Text zum nächsten. Die Reihenfolge der Texte in jeder Handschrift wird aus ihren Seiten abgeleitet und erscheint in „Handschriften prüfen…“; siehe Eine Handschrift in ihrer eigenen Reihenfolge verfolgen. Einen Textzeugen durchblättern, ohne die Edition zu bewegen, ist nur noch möglich, während ein Hilfsdokument angezeigt ist.
