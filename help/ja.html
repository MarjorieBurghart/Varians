Varians — 本文校訂のためのTEI XMLエディタ

Variansは、写本や古い刊本によって伝えられ、TEIで符号化されたテキストの校訂版を作るためのXMLエディタです。翻刻、伝本の画像、閲覧用のビューを一つのインターフェースにまとめ、校訂版をWeb形式に変換することもできます。

1. 概要

Variansでできること

  • TEIを編集する。 スキーマにもとづいて要素と属性を補完し、マークアップを支援し、テキストを検索し（正規表現、XPath）、文書間の参照をたどり、テキストを損なわずに折りたたみやインデントを行うXMLエディタです。
  • XMLを検証する。 RELAX NG と Schematron ルールによる検証を、入力中に、ウィンドウを止めずに行います。
  • 編集しているものを読む。 XSLT / CSSビューは整形された校訂版を表示します。各ブロックはそこから断片エディタで開いて修正できます。既定で開いている XMLソース タブでは、いつでも生のXMLコードにアクセスできます。
  • 写本を見る。 各伝本の画像（ローカルファイルまたはIIIF）は、場合によってはその行（ALTO、PAGE XML）とともに、利用できるデータに応じてページ単位または行単位で翻刻と対応付けられます。
  • 校異を検査する。 すぐに使えるクエリで、校異によくある誤り（たとえば伝本の書き落としや重複）を見つけられます。伝本の欠落部も認識されます。
  • 公開する。 本文とファクシミリが同期したままの独立したWebビューア、校異付きのHTML校訂版、Variansに同梱の TEI Stylesheets による DOCX、ODT、EPUB、HTML、LaTeX など、そして任意の XSLT スタイルシートによる出力。

汎用XMLエディタとの違い

汎用XMLエディタは、どのXML文書も同じように扱います。Variansは、テキストの校訂者の作業から出発しています。

  • テキストの隣に写本。 各伝本には専用のパネルがあります。翻刻の中でカーソルが動くと、各パネルはその写本の対応するページ、または行を表示します。逆に、特定の写本の順序に従って校訂版を読むこともできます。その写本のパネルの矢印が、校訂版を対応する箇所へ導きます。
  • ピボット伝本。 同期は、ここでピボットと呼ぶ基準伝本の行にもとづきます。ほかの各伝本は、翻刻を始める前からでも、自分の行をピボットの行に視覚的に整列させることができます。ピボット伝本の選択は整列のための技術的なものであり、ステンマについても、どの写本を底本とするかについても、何ら前提とするものではありません。
  • 校異が中心。 伝本一覧にもとづく @wit の補完、校異の検査、欠落部、そして公開時には校訂本文か特定の伝本の翻刻かの選択。まだ <lem> に由来しない読みは強調表示できます。
  • 編集できる閲覧ビュー。 読んでいるその場所で、ブロックごとに、XML内の位置を失わずに校訂版を修正できます。
  • 複数のファイルに分けることもできる版（テキストごとに1ファイル、XIncludeで組み立て）は、検証、参照、伝本の同期、公開において一つの文書として扱われます。
  • 組み込みのWeb公開。 Webビューア、校訂版の慣習を取り入れたパラメータ設定可能なXSLT、TEI Stylesheets の各形式を、サーバーもネットワークもなしにVarians内で利用できます。
  • 標準のTEI。 Variansがファイルに書き込むのは、通常のTEI（<pb/>、<lb/>、<facsimile>…）だけです。プロジェクトだけに関わるもの（伝本、画像、整列、シナリオ）は別のファイル project.xml にあり、表示の設定はお使いのコンピュータに残ります。ほかのどのXMLツールでも校訂版を読めます。
  • 慎重さ。 Variansは推測しません。行と画像の疑わしい対応、曖昧なタグの閉じ方、見つからないページを作り出すことはなく、必ず知らせます。重要な書き込みでは .bak のコピーを残します。
  • 7つのインターフェース言語：フランス語、英語、ドイツ語、日本語、チェコ語、イタリア語、ロシア語（表示 → 言語）。

Variansがしないこと

  • 写本の行を自ら整列させることはしません。整列ファイル（JSON）は、別のツールである Varians-Synchro で作ります。
  • 画像上の行を認識（セグメンテーション）しません。ALTO や PAGE XML の行は、認識ソフトウェア（eScriptorium、Transkribus、PERO OCR…）から得ます。
  • 照合はしません。校異はご自身でTEIに符号化します。Variansはその入力と検査を支援します。
  • ワードプロセッサではありません。編集するのはXMLです。XSLT / CSSビューは、読むため、そして一度に一つのブロックを修正するためのものです。

2. クイックスタート

この手順で、空のフォルダーから最初の公開までを進めます。各手順には、それを詳しく説明する章へのリンクがあります。

  1. インストールと起動。 Variansには Python 3 と三つのライブラリ（PySide6、lxml、Saxon）が必要です。Windows では、installer_dependances.bat を一度実行し、その後 lancer_editeur.bat でVariansを起動します。それ以外の環境では、pip install -r requirements.txt の後に python editeur_tei.py を実行します。
  2. プロジェクトを作成する。 ファイル → 新規プロジェクト…：空のフォルダーを選び、次に 開始方法 として、既存のTEI校訂本文から開始（ファイルはプロジェクトにコピーされます）または 新しい翻刻を開始（Variansが最小限のTEIを作成します）を選びます。プロジェクトを参照してください。
  3. 伝本を宣言する。 伝本とリソース で、各写本を 追加… します。その シグラム、表示名、画像ソース（当面なし、ローカル画像、IIIF Manifest から選べます）を指定します。ピボットを指定します：ピボット伝本に設定。残りは後からでもかまいません。基本概念と伝本とファクシミリを参照してください。
  4. 翻刻とマークアップ。 XMLソース タブでは、Ctrl+E で選択範囲を要素で囲み、Ctrl+Space で要素名や属性名を補完し、F8 で文書を検証します。XSLT / CSSビュー タブでは、ブロックの鉛筆 ✎ をクリックするか、修正したい箇所を選択して F2 を押すと、その箇所が断片エディタで開きます。XMLに適用 でソースが更新されます。XMLの編集と検証を参照してください。
  5. テキストを画像に結び付ける。 テキストの中で、ある伝本（例：A1）のページ（例：f. 1v）の始まりにカーソルを置き、その伝本のパネルで ページをマーク をクリックします。Variansは <pb n="1v" edRef="#A1" facs="#A1-p0002"/> を挿入します。以後、パネルはページ単位でテキストに追従します。行単位で追従させるには、ファイル → プロジェクト設定… でその伝本の整列ファイル（JSON）を宣言します。伝本とファクシミリを参照してください。
  6. 校異を符号化し、検査する。 @wit の中で # を入力すると、一覧から伝本を選べます。ヘルプ → 校異をデバッグ… は、読みのない伝本や二度挙げられた伝本を見つけます。校異を参照してください。
  7. 読み直す。 XSLT / CSSビュー タブは整形された校訂版を表示します。鉛筆 ✎ でブロックを開いて修正できます。XSLT / CSSビューと断片エディタを参照してください。
  8. Web形式。 Webビューアを生成 は、テキストと画像が同期した独立したサイトを web_output/ に作成します。変換 ボタンはシナリオを実行します：校訂版（HTML）、TEI：DOCX（Word）…。WebビューアとXSLTによる公開を参照してください。
  9. 保存する。 Ctrl+S で表示中の文書を保存します。終了やプロジェクトの切り替えの前に、Variansは変更された各文書の保存を提案します。

3. 基本概念

プロジェクト

プロジェクトは、project.xml ファイルを含むフォルダーです。このファイルには、校訂版、その伝本とそれらのリソース（画像、行、整列）、プレビューのスタイルシート、公開用のシナリオが記されます。校訂版そのものは TEI ファイル xml/edition.xml で、部分に分けることもできます（部分に分かれた版を参照）。ほかの文書を加えることもできます：典拠、注、XSLT スタイルシート、Schematron ルール。

3種類のデータ、3つの場所。 テキストに関わるものはTEIにあります：ページ、行、校異、ファクシミリ。プロジェクトに関わるものは project.xml にあります：伝本、画像、整列、シナリオ、保存済みのクエリ。作業上の設定（表示する伝本とその配置、表示するタブ…）は、お使いのコンピュータにプロジェクトごとに保存され、プロジェクトのどのファイルも変更しません。

伝本、シグラム、ピボット伝本

伝本とは、テキストを伝える写本または刊本です。そのシグラム（A、T1、P…）が、あらゆる場所でその伝本を指します。TEIでは、<listWit> 内のその <witness> の識別子であり、@wit（校異の中）と @edRef（その伝本に固有のページと行）がそれを参照します。伝本のシグラムと識別子を参照してください。

ピボット伝本 は同期の基準です。その行（<lb edRef="#A"/>）がテキストの中の区切りを示し、ほかの各伝本は自分の行をピボットの行に結び付けます。この選択は 技術的 なものであり、ステンマにおけるその伝本の位置も、校訂版がどの写本を底本として採用するかも、前提とするものではありません。部分に分かれた版では、部分ごとに独自のピボットを持つことができます。

伝本をページ単位または行単位でたどる

伝本のパネルは、次の二つの方法のいずれかで翻刻に追従します。

  • ページ単位：<pb edRef="#B" .../> が、翻刻の中で伝本 B の各ページの始まりを示します。パネルは、カーソルより前にある B の最後の <pb> のページを表示します。画像と、正しい @edRef を持つ <pb> があれば十分です。
  • 行単位：Varians-Synchro で作成した整列ファイル（JSON）が、ALTO または PAGE XML によって画像上に位置が示された写本の各行を、ピボットの行に結び付けます。このときパネルは、対応する行を切り出して表示します。写本の画像に整列した校訂版を見るには、ピボット伝本の <lb/> を、そしてそれだけを 挿入しておく必要があります。ほかの伝本はそれによって整列されるので、それら自身の <lb/> を校訂版に挿入する必要はありません。

各伝本には独自の方式があります。同じ校訂版の中で、ある伝本は行単位で、別の伝本はページ単位でたどることができます。まだデジタル画像のない伝本があってもかまいません。

校異

Variansは parallel segmentation による校異を前提とします。各異読箇所は、テキストの中の <app> で、採用した読み（<lem>）と異読（<rdg>）をまとめ、それぞれにその読みを持つ伝本を示します。

<app><lem wit="#A">dixit</lem><rdg wit="#B #C">ait</rdg></app>

校訂作業では段階を追って進めるのが普通です。まず異読を中立的に記録しておき、伝承の全体像がよく見えてきた段階で、何をレンマとして採用するかを決めることがよくあります。

<app><rdg wit="#A">dixit</rdg><rdg wit="#B #C">ait</rdg></app>

Variansでは、すべてのレンマを選ぶ前から作業の結果を見ることができます。校訂版（HTML） と Webビューアの 校訂本文 は、まず <lem> から作られ、<lem> がない箇所では、選んだ伝本（既定ではピボット）の読みから作られます。どちらも、<lem> に由来しない読み、つまりまだ決定すべき読みを黄色で強調表示できます（本文の選択と校訂版を参照）。

4. プロジェクト

作成する・開く・閉じる

初回起動時、Variansはプロジェクトを開きません。以後は、終了時に開いていたプロジェクトを再び開きます。ファイル メニューには、新規プロジェクト…（Ctrl+N）、プロジェクトを開く…（Ctrl+O）、最近のプロジェクトを開く… があります。ファイル → プロジェクトを閉じる（Ctrl+W）は、Variansを終了せずに開始画面に戻ります。閉じたプロジェクトは、次回の起動時には開かれません。

新規プロジェクト… は空のフォルダーを尋ね、続いて 開始方法 を尋ねます。既存のTEI校訂本文から開始 では、そのファイルが xml/edition.xml にコピーされます。新しい翻刻を開始 では、Variansがプロジェクトの伝本の <listWit> を含む最小限のTEIを作成します。

<listWit>
  <witness xml:id="A1">Assisi, Sacro convento, 541</witness>
</listWit>

伝本は、画像も ALTO も同期もなしで宣言できます。これらのリソースは、必要に応じて後から、どの順序でも、ファイル → プロジェクト設定… で追加できます。同じダイアログで、RELAX NG スキーマ（文書の <?xml-model?> から検出、プロジェクトで選択、またはなし）、プレビューの XSLT スタイルシートと CSS、Ctrl+E の設定（custom-elements.xml）、Webビューアのフォルダーとファイル名を設定します。

プロジェクトの構成

project.xml        プロジェクト
xml/edition.xml    校訂版（その部分とほかのXML文書はこの隣に置く）
xslt/              プロジェクトのXSLTスタイルシート
images/  alto/     プロジェクトにコピーしたローカル画像、ALTO または PAGE XML の行
alignments/        整列ファイル（JSON）
iiif/local/        IIIF画像のローカルコピー
rendering/         プレビューのCSS、custom-elements.xml
i18n/              インターフェースの翻訳
publications/      変換シナリオの結果
web_output/        Webビューア

プロジェクトの i18n/ フォルダーには、インターフェースの翻訳のコピーがあり、Variansのものより優先されます。新しいバージョンのVariansの文言を取り入れるには、そのファイルをVariansの i18n/ フォルダーのファイルで置き換えてください。

伝本のシグラムと識別子。 ファイル → プロジェクト設定… で入力した伝本のシグラムは、その XML 識別子にもなります。<witness> の xml:id であり、@wit と @edRef の参照先です。XML 識別子は文字または「_」で始まり、空白や「/」「:」などの記号を含みません。入力したシグラムがこの規則に従わない場合（「1760」「T 2」）、Variansはそこから有効な識別子を作り、欄の下に表示します。使えない文字はそれぞれ「_」になり、文字で始まらないシグラムには先頭に「_」が付きます。「1760」は _1760、「T 2」は T_2 になります。その場合、TEI では wit="#_1760" と書きます。Variansが伝本を名指すところでは、どこでもシグラムが表示されます。シグラムは project.xml（<witness> の siglum 属性）に、またプロジェクトとともに作成された TEI では <idno type="siglum"> に保存されます。

<witness xml:id="_1760"><idno type="siglum">1760</idno>Troyes, BM, ms. 1760</witness>

Variansに付属するスタイルシート（プレビュー、校訂版、脚注の校異）とWebビューアは、識別子の代わりにこのシグラムを表示します。後から ファイル → プロジェクト設定… で追加した伝本は、校訂版に <listWit> があれば、その末尾に同じ形の <witness> を受け取ります。Variansが <listWit> を新たに作ることはありません。設定の保存を確認するダイアログに、追加した内容が示されます。同じ識別子になる二つのシグラム（「T 2」と「T/2」）は共存できません。

ピボット伝本にもとづいて空の翻刻を準備する

翻刻を始めるにあたり、Variansはピボット伝本のページ（<pb/>）と行（<lb/>）をあらかじめ入れておくことができます。ファイル → 新規プロジェクト…（新しい翻刻を開始 を選んだ場合）または ファイル → プロジェクト設定… の ピボット伝本から転写の枠組みを準備 の枠に、空のTEIにピボット伝本の<pb/>（改ページ）を生成する と、続いて ALTO・PAGE・同期データから<lb/>（改行）も生成する があります。

<pb/> を受け取るのは、校訂版のために選んだページだけです。その @facs は <surface> を、@edRef は伝本を指します。<lb/> には @edRef だけが付きます。Variansは、そのページに確実に対応付けられた ALTO または PAGE の行を使い、それがなければ整列ファイルに記述された行を使います。41行目から68行目までのフォリオの抜粋なら、<lb/> は28個になります。既知の行がないページでも <pb/> は残ります。欠けている箇所は知らされるだけで、補われることはありません。プレビュー、確認、日時付きのバックアップがテキストを保護します。自動翻刻が取り込まれることはありません。

プロジェクトの文書とタブ

プロジェクトには、校訂版のほかに、典拠ファイル（人名・地名）や注などのほかのXML文書を含めることができます。ファイル → プロジェクトのXML／XSLT文書… を使ってください。XML文書、XSLTまたはSchematronを追加… は既存のファイルを登録します。プロジェクトフォルダーの外にあるファイルは xml/ にコピーされ、既存のファイルが置き換えられることはありません。新しいXML文書… は、ルート要素を指定して空の文書を作成します。文書をプロジェクトから外す は、表示中の文書をプロジェクトから外しますが、そのファイルは削除しません。

補助文書が一つでもあると、XMLソースの上にタブの列が表示されます。校訂本文 に続いて、文書ごとに一つのタブが並びます。各文書は、それぞれの取り消し履歴、位置、状態を保持します。アスタリスクは未保存の変更を示し、名前の色は整形式でない、または妥当でないXMLを示します。RELAX NG 検証と補完は、表示中の文書の <?xml-model?> に従います。写本、XSLT / CSSビュー、伝本のコマンドは校訂版にのみ関わるため、別の文書を表示している間は隠され、戻るとそのまま復元されます。Ctrl+S は表示中の文書を保存します。終了やプロジェクトの切り替えの前に、Variansは変更されたすべての文書の保存を提案します。Web書き出しは校訂版だけを使います。

表示するタブ。 表示 → 表示する文書を選択… で、タブを表示する文書とタブの順序を選べます。タブを右クリックすると、そのタブの文書について（表示中でなくても）タブを隠す、タブの名前を変更…、表示する文書を選択…、文書をプロジェクトから外す が使えます。タブを隠した文書もプロジェクトに残ります。その変更は保持され、終了前にVariansが保存を提案します。参照からその文書に移動すると（F12、Ctrl+クリック、参照 パネルでのダブルクリック）、タブが再び表示されます。最後に残ったタブは隠せません。プロジェクトを開くと、校訂版がそのタブとともに表示されます。これらの選択はプロジェクトごとにローカルに保存され、project.xml は変更されません。ただし、タブの名前を変更… で付けた名前は、project.xml の <document> の label 属性に書き込まれます。空欄にするとファイル名に戻ります。タブが列に収まらなくなると、その右に矢印 ▾（「すべてのタブ」）が表示されます。クリックするとすべてのタブの一覧が開き、表示中の文書にチェックが付いています。一覧から選んだ文書が表示されます。一覧の最後は 表示する文書を選択… です。

文書は、project.xml の <documents> 要素で宣言されます。

保存

ファイル → 校訂本文を保存（Ctrl+S）は表示中の文書を保存します：校訂版、その部分の一つ、またはプロジェクトの別の文書です。校訂本文を別名で保存…（Ctrl+Shift+S）は別の場所に書き出します。終了やプロジェクトの切り替えの前に、Variansは変更された各文書の保存を提案します。整形式でない文書や妥当でない文書も、確認のうえで保存できます。

重要な書き込みはアトミックな置き換えで行われ、.bak のコピーを残します。自動操作が曖昧になる場合、VariansはTEIを黙って書き換えるのではなく、操作を控えます。

5. XMLの編集

エディタ

XMLソース タブ（Ctrl+1）は表示中の文書を、XSLT / CSSビュー タブ（Ctrl+2）は整形された校訂版を表示します（XSLT / CSSビューと断片エディタを参照）。長い行を画面上で折り返す は表示上だけのもので、XMLも行番号も変更しません。

タグのペア。 開始タグまたは終了タグの中にカーソルを置くと、<app> からでも </app> からでも、ペアの両方のタグが淡い青色で強調表示されます。入れ子、接頭辞（tei:div）、空要素も考慮されます。コメント、CDATA、処理命令はペアになりません。開始タグの名前を変えると、その終了タグの名前も変わります。開始タグ全体を削除すると、内容を残して終了タグも取り除かれます。交差したマークアップや不確かなマークアップでは、ペアは示されません。

終了タグ。 XMLエディタでも断片エディタでも、</ と入力すると、最も近い開いている要素の終了タグが提案されます。<div><p>…</p></ の後では div> が提案され、Enter または Tab で挿入されます。</di のように名前を途中まで入力してもかまいません。Esc で一覧を閉じ、Ctrl+Space で再び開きます。空要素（<lb/>）、コメント、CDATA、未完成の属性は無視されます。入れ子が曖昧な場合、終了タグを推測で作ることはありません。

折りたたみ。 表示 → XMLの折りたたみ：要素を折りたたむ／展開する（Ctrl+Alt+F）、構造要素を折りたたむ、すべて展開する（Ctrl+Alt+Shift+F）。余白の ▾ / ▸ で要素を折りたたんだり展開したりできます。折りたためるのは、複数行にわたり、タグがそれぞれ独立した行にある要素だけです。折りたたみはXMLも取り消し履歴も変えません。テキストを変更するとすべて展開され、隠れた行にカーソルを移すとその行が表示されます。

インデント。 編集 → XML をインデント は、文書の構造的な部分を慎重にインデントします。

  • <lb/> の前後に空白を加えません。
  • xml:space="preserve" を尊重します。
  • 混在内容や曖昧な内容には手を付けません。
  • スキーマ上テキストを受け付ける要素は、テキストとして扱います。

custom-elements.xml では、formatting="inline"、formatting="block"、formatting="preserve" を指定できます。上記の保護が優先されます。

マークアップ支援

Ctrl+E は、選択範囲を要素で囲むか、カーソル位置に新しい要素を挿入します。一覧の項目は、選んだときだけ強調表示されます（クリック、矢印キー、またはフィールドから Tab ／ ↓ で最初の項目を選択）。Enter は強調表示された項目を、選ばれていなければフィールドに入力したテキストを挿入します。フィールドに入力し直すと選択は解除されます。その位置で RELAX NG スキーマが許す要素が先に提案されます。

Ctrl+Space は、要素名と属性名、一部の属性値を補完します。別のタグの直前に入力した要素名（</p> の前の <h）も補完できます。候補は RELAX NG スキーマ、custom-elements.xml ファイル、またはその両方から得られ、その由来が表示されます。開始タグの中では、許される属性名の最初の文字を入力すると、絞り込まれた一覧が自動的に開きます。Enter または Tab で属性とその引用符が挿入されます。

@wit のようなポインター属性の中で # を入力すると、プロジェクトの伝本または識別子の一覧が開きます（文書間の参照を参照）。Variansは空白で区切られた値のリストを補完し、すでにある値は再び提案しません。

Ctrl+E の設定。 ファイル → Ctrl+E 設定… は、プロジェクトの custom-elements.xml ファイルを開きます。Ctrl+E が提案する要素、Ctrl+Space が提案する属性と値（ソース witnesses は、プロジェクトの伝本を #A1、#B1… の形で与えます）、インデントの規則です。このファイルは入力を助けるためのもので、文書の妥当性を変えることはありません。その形式は CUSTOM_ELEMENTS.md に記述されています。

辞書。 Ctrl+?（または ヘルプ → ラテン語辞書）は、選択したテキストをラテン語辞書 Vocabula でブラウザーを使って検索します。

文書間の参照

ポインター属性（@ref、@corresp、@target、@who、@wit、@edRef、@sameAs、@ana、@resp、@source、@hand、@facs、@prev、@next、@synch、@copyOf）は、要素をその @xml:id で指し示します。標準のTEIと同じく、したがってどのXMLツールにとっても、短い形式 #bernard は文書自身の中の要素を指します。プロジェクトの別の文書（補助XML文書を参照）を指すには、personnes.xml#bernard と書きます。パスは、参照を含む文書からの相対パスです。Webアドレス（https://…）や「#」を含まない値は処理されません。一つの値に、空白で区切った複数のポインターを書くことができます：wit="#T1 #T2"。

入力。 このような属性の値の中で # を入力すると、識別子の一覧が自動的に開き、各項目のテキストとファイルが表示されます（例：「personnes.xml#bernard — Bernardus」）。続けて文字を入力すると一覧が絞り込まれ、Enter または Tab で値が挿入され、Esc で一覧が閉じます。@wit と @edRef では、TEIに記述された伝本（<listWit> の <witness>）が一覧に表示されます。Ctrl+Space は、同じ値をダイアログ（「プロジェクト内の識別子」）で開きます。そこでは説明文も絞り込みの対象になり、「Bern」で personnes.xml#bernard が見つかります。提示される識別子は要素によって異なります。persName/@ref では person、personGrp、persona、placeName/@ref では place、orgName/@ref では org、@who では人物が提示されます。それ以外では、すべての識別子が提示されます。custom-elements.xml では、<values source="ids" elements="person personGrp" prefix="#"/> によって属性ごとにこの一覧を指定できます。別の文書の識別子は fichier.xml#id の形式で、文書自身の識別子は #id の形式で挿入されます。

移動。 参照の上で F12 を押すか、Ctrl+クリックするか、右クリックメニューの 参照先へ移動 を選ぶと、参照先を含む文書が表示され、その要素が選択されます。識別子が複数回定義されている場合は、どの参照先を表示するかをVariansが尋ねます。Alt+←（または右クリックメニューの 戻る）で、別の文書からでも元の位置に戻ります。見つからない参照先はステータスバーに示されます。参照先が別の文書にしかない短い形式の場合も、Variansはそこへ移動し、書くべき形式を示します。

検査。 編集 → 参照 コマンドは、プロジェクトのすべての文書の参照を検査します。ソースの下に開くパネルには参照の数が示され、問題のある参照（参照先が見つからない、参照先が別の文書にある短い形式〔書くべき形式を表示〕、参照先が複数ある〔参照先の文書で識別子が複数回定義されている〕、ファイルが見つからない）が、文書、行、属性、値、問題 の列とともに一覧表示されます。ダブルクリックするとその参照へ移動します。修正後は 再検査 で検査をやり直せます。この検査は補助的なものであり、保存を妨げることはなく、どのファイルも変更しません。

検索と置換

検索 メニューには、XML と断片の中の検索がまとめられています。XPath 検索については専用の節があります。

  • 単純検索（Ctrl+F）：XML ではツールバーのフィールド、フォーカスが断片にあるときは断片の検索バーです。F3 と Shift+F3 で次または前の一致へ移動します。
  • すべて一覧（検索 → すべての一致を一覧表示、Ctrl+Shift+L）：検索フィールドの横にあるボタンです。エディタの下のパネルに、XML の検索のすべての一致を、同じオプション（大文字・小文字、正規表現）で一覧表示します。各行には、行番号と、前後のテキストの中央に強調表示された一致（KWIC 形式）が示されます。クリックするとその一致へ移動します。プロジェクト全体 にチェックを入れると、プロジェクトのすべての文書が対象になり、「文書」列が加わります。別の文書の一致をクリックすると、その文書が表示されます。開いたパネルは、新しい検索、オプション、テキストの変更、表示中の文書に追従します。一致が 2,000 を超える場合は、最初のものだけが表示されます。× で閉じます。
  • 大文字と小文字を区別 と 正規表現：検索 メニューの2つのチェック項目で、検索フィールドの近くにある Aa と .* ボタンでも切り替えられます。XML と断片に適用され（XSLT / CSSビュー の検索は文字どおりのまま）、次のセッションにも引き継がれます。正規表現は Python のもの（モジュール re）です。^ と $ は各行に適用され、\b は語の境界を表します。正しくない式はステータスバーに示されます。
  • 検索と置換（Ctrl+H）は、XML エディタの下にバーを開きます。フォーカスが断片にあるときは、その検索の下に 置換後 の行を開きます。置換 は強調表示された一致を置き換えて次へ進み、すべて置換 は文書全体（または断片全体）を置き換えます。これは1回の Ctrl+Z で元に戻せます。検索する文字列は、空白も含めて入力どおりに扱われます。置き換えるのは見つかったものだけです。開始タグを置き換えても、その終了タグの名前は変わらず、削除もされません。Esc でバーを閉じます。
  • 正規表現では、置換テキストで括弧のグループを使えます：\1、\2…、名前付きグループ (?P<nom>…) には \g<nom>。\n で改行します。例：wit="#(\w+)" を wit="#\1 #T3" で置き換えると、伝本が一つだけの各読みに T3 が加わります。<(rdg|lem)\b は両方の要素を、<lb n="\d+"/> は番号付きの改行を見つけます。
  • XPath 検索（Ctrl+Shift+F）：XPath検索を参照してください。ツールバーの XPath ボタンでも開きます。
  • ヘルプ内の検索：このヘルプウィンドウの上部のフィールド（Ctrl+F）は、アクセントや大文字・小文字を区別せずにヘルプ全体を検索します。複数の語を入力すると、それらをすべて含む節を、語の順序に関係なく探します。引用符で囲むと、その表現そのものを探します（"すべて置換"）。左側には見つかった節の一覧が抜粋とともに表示され、クリックするとその節へ移動します。一致は強調表示され、Enter、F3、Shift+F3、または ◀ ▶ で順にたどれます。

XPath検索

検索 → XPath 検索（XPath ボタン、Ctrl+Shift+F）は、エディタの下にパネルを開きます。そこでは XPath 1.0 式で表示中の文書を検索します。たとえば //note は <note> 要素を探します。標準の名前空間を使う TEI では、接頭辞のない単純なクエリは tei: 接頭辞を付けて再試行されます。

結果には、行、要素、そのパス、抜粋が表示されます。結果をクリックすると、開始タグから終了タグまで、複数行にわたる場合でも要素全体が選択されます。この選択は XSLT / CSSビューに切り替えても保たれ、ソースに戻ると元どおりに選択されています。count(//tei:note) のように値を返す式では、その値が表示されます。

6. 検証

Variansは、表示中の文書をその RELAX NG スキーマと Schematron ルールにもとづいて検証します。XSLT スタイルシートや Schematron ルールのファイルも、表示されているときには検査されます。XSLTスタイルシートの編集とSchematron ルールを参照してください。

RELAX NG 検証

文書のスキーマは、その <?xml-model?> が宣言するもの、または ファイル → プロジェクト設定… で指定したものです（ここで検証を無効にすることもできます）。Variansは、開くとき、保存するとき、そして求めに応じて文書を検証します：RNG検証（F8）。エラーは、エディタの下の RELAX NG・Schematron検証 パネルに、レベル、行、列とともに一覧表示されます。ダブルクリックするとそのエラーへ移動します。このパネルを一度使うと、入力が少し止まるたびに検証が自動的にやり直され、修正したエラーは一覧から消えます。ステータスバーには結果がまとめられ、整形式でない文書のタブ名は赤に、妥当でない文書のタブ名はオレンジ色になります。

リモートのスキーマ（http のアドレス）は、初めて使うときにダウンロードされ、スキーマのキャッシュに保存されます。パネルの リモートスキーマを更新して再検証 ボタンで、もう一度ダウンロードします。

ウィンドウを止めずに。 検証は別プロセスで行われ、このプロセスは必要になったときにVariansが起動します。TEI_ALL のような大きなスキーマの最初のコンパイルには10秒ほどかかりますが、その間もウィンドウは使え、ステータスバーの RNG：検証中… の横で小さな光が回ります。コンパイル済みのスキーマはその後、別のプロジェクトを開いても、セッション中ずっと保持されます。自動検証が作業を中断することはありません。一方、RNG検証（F8）と保存は結果を待ちます。ウィンドウの表示は続きますが、応答が届くまでクリックとキー入力は無視されます。検証プロセスを起動できない場合は、Varians自身が検証し、そのことをステータスバーに表示します。その場合、コンパイル中はウィンドウが応答しなくなることがあります。

Schematron ルール

RELAX NG スキーマは、どの要素と属性がどこで許されるかを定めます。Schematron ルール は、それでは表せないことを検査します。たとえば TEI では、<lg> が少なくとも一つの詩行を含むこと、@target と @cRef を同時に使わないことなどです。Variansは RNG と同時にこれらを適用します。開くとき、入力中、RNG検証（F8）のとき、保存のときに、同じ別プロセスで行います（RELAX NG 検証を参照）。

どのルールか。 まず、使用する RELAX NG スキーマに埋め込まれたルールです。スキーマが文書で宣言されていても、プロジェクトの設定で選ばれていても同じです。tei_all.rng には 91 のルール群があり、ODD によるカスタマイズにはそれぞれのルールがあります。次に、文書の各 Schematron 宣言（.sch ファイルまたは RNG へのもの）のルールです。

<?xml-model href="regles.sch" type="application/xml"
    schematypens="http://purl.oclc.org/dsdl/schematron"?>

相対アドレスは文書を起点とします。http のアドレスは一度だけダウンロードされ、スキーマのキャッシュに保存されます。同じルールが二度検査されることはありません。TEI 文書の Schematron 宣言は、その RNG と同じ tei_all.rng を指しています。新しいプロジェクトには両方の宣言が書かれます。部分に分かれた版では、RNG と同じく、ルールは組み立てられた版に適用されます。

XSD スキーマ。 Schematron として宣言された XSD スキーマ（同じ schematypens）からは、その xs:appinfo に埋め込まれたルールが、取り込みや読み込みをしたファイル（xs:include、xs:import）のものも含めて適用されます。Variansは XSD そのものによる文書の検証は行いません。

フェーズ。 Schematron ファイルは、ルールのグループ（sch:pattern）をフェーズ（sch:phase）にまとめることができます。指定がなければ、Variansはファイルの既定のフェーズ（defaultPhase）を、それもなければすべてのルールを検査します。フェーズを選ぶには、Oxygen と同じく、宣言に標準の phase 属性を加えます。

<?xml-model href="regles.sch" type="application/xml"
    schematypens="http://purl.oclc.org/dsdl/schematron" phase="lecons"?>

#ALL はすべてのルールを、#DEFAULT は既定のフェーズを検査します。ファイルにないフェーズは誤ったルール（下記参照）となり、ファイルのフェーズの一覧が添えられます。宣言を自分で書かなくても、ステータスバーの Schematron 表示をクリックするか、検証パネルの ルール… ボタンを押すと、文書の Schematron ルール ダイアログが開きます。宣言されたルールのファイルごとに、フェーズを一覧から選べます（既定のフェーズ、すべてのルール、ファイルのフェーズ）。宣言の追加や削除もできます。変更は文書の <?xml-model?> に書き込まれ、Ctrl+Z で元に戻せます。

メッセージ。 RELAX NG・Schematron検証 パネルで、RNG のメッセージに加わります。由来 の列には Schematron と表示され、ダブルクリックすると、該当する要素の行（属性に関するルールではその要素の行）へ、その文書の中で移動します。レベルは @severity、なければ @role で決まります。warning、warn、nonfatal は 警告、info は 情報、それ以外はすべてエラーです。エラーは RELAX NG のエラーと同じく文書を無効にします。タブの名前がオレンジ色になり、保存の前に 文書が無効です という確認が出ます（このまま保存）。警告や情報は一覧に残りますが、文書を無効にはしません。

ステータスバー。 RNG の状態の隣で、Schematron の表示が結果をまとめます。Schematron：✓、エラーやメッセージの件数、またはプロジェクトで検証が無効のときは Schematron：未検査 です。ツールチップには、適用したルールのファイル名がフェーズとともに表示されます（「apparat.sch（フェーズ lecons）」）。表示をクリックすると 文書の Schematron ルール が開きます。

誤ったルール。 誤った XPath 式、不明なフェーズ、見つからない、または整形式でないルールのファイルは、Schematron：ルールに誤り となります。誤ったルールはそれぞれ、パネルの中で文書のメッセージの後に一行で示されます。由来は Schematron（ルール）、文書 列にはルールのファイルが示されます。ダブルクリックすると、そのファイルがルールの行で表示されます。プロジェクトのフォルダーにあって、まだプロジェクトの文書でないファイルは、プロジェクトに追加できます（Variansが提案します）。キャッシュ内のリモートファイルのコピーなど、プロジェクト外のファイルは開かれず、ステータスバーにその旨が表示されます。誤りはスキーマの側にあるため、文書は無効にならず、ほかのルールは適用されます。ルールのファイルを変更して保存すると、文書に戻ったときにあらためて検証されます。

Variansでルールを書く。 ファイル → プロジェクトのXML／XSLT文書… → XML文書、XSLTまたはSchematronを追加… は .sch ファイルを受け付けます。プロジェクト外のファイルは、プロジェクトの xml/ フォルダーにコピーされます。新しいSchematronファイル… は最小限のファイル（xml/regles.sch を提案）を作成します。このファイルは tei 接頭辞を宣言し、例となるルールを含みます。その後、文書にその宣言を加えてください。表示中の Schematron ファイルは、RELAX NG 検証の代わりに検査されます：Schematronルールを検査（F8）、表示時、F8 を一度使った後の入力中、保存時です。検査の対象は、未保存でも表示中のテキストです。整形式であること、ISO Schematron スキーマ（Variansに同梱）に沿った構造、取り込まれたファイル、そして Saxon による全フェーズのコンパイルを確かめます。各エラーはその行で示され、ダブルクリックでそこへ移動します。Ctrl+Space と属性の自動リストは、ファイルの接頭辞を付けた Schematron の要素と属性、および severity、role、queryBinding のよく使う値を提案します。文書は、開いているルールのファイルの表示中のテキストで、未保存でも検証されます。ルールを変更してから文書に戻ると、あらためて検証され、Schematron 表示のツールチップにその旨が示されます（「regles.sch（未保存）」）。ルールのファイルが取り込むファイル（sch:include、sch:extends）を開いて変更した場合も同様です。ツールチップがそのファイルを示し（「regles.sch（未保存: motifs.sch）」）、ルールのファイルの検査もその内容を使い、そのファイルに戻るとあらためて検査します。SchXslt2 が適用する規格の2020年版と2025年版の新要素も受け付け、補完でも提案します：sch:group、sch:rules、sch:library、スキーマ直下の sch:param、@visit-each、フェーズの @from と @when。

エンジン。 Variansは、同梱の SchXslt2（David Maus、MIT ライセンス）と Saxon（saxonche パッケージ。変換シナリオと同じく installer_dependances.bat でインストール）を使います。Saxon がない場合は Schematron：Saxonなし と表示され、RELAX NG 検証だけが行われます。ルールは最初の検査のときに1秒足らずで準備され、そのセッションの間保持され、ファイルが変わると準備し直されます。

制限。 ルールは queryBinding にかかわらず XPath 3.1 で評価されます。XPath 1.0 向けに書かれたルールも、ほとんどの場合同じように動作します。スキーマが自由に入手できない2020年版と2025年版については、.sch ファイルの検査は SchXslt2 が受け付けるものに従います。旧い Schematron 1.5 と、XSD による検証には対応していません。

7. XSLT / CSSビューと断片エディタ

プレビュー

XSLT / CSSビュー タブは、XSLT スタイルシートと CSS で整形した校訂版を表示します。使われるのはVariansのもの、またはプロジェクトのものです（ファイル → プロジェクト設定…、XSLTソース：Variansの修正に追従する エディタ既定のXSLT、またはプロジェクトのファイルである カスタムXSLT）。ビューの 表示形式 の行で、別の XSLT スタイルシートや CSS を試すことができます。プレビューは、変更の後にこのタブに戻ると更新されます。自動プレビュー は入力が止まるたびに更新し、更新 は求めに応じて更新します。サイズ で文字を拡大・縮小します。目次から見出しのある区分へ移動でき、プレビュー内を検索 の欄で語や表現を検索できます。

プレビューのテキストをクリックすると、ソースのカーソルが同じ位置に置かれ、伝本が追従します。プレビューで選択した文字列は、XMLソース タブに戻ると、同じ箇所の同じ出現位置で（<lb break="no"/> で分かれた語でも）ソースでも選択されます。逆に、ソースでの選択（たとえば XPath の結果）はプレビューでも再現されます。プレビューの選択を変えずにソースに戻ると、元の選択に戻ります。

変換はローカルファイル（たとえば典拠ファイル）を読み込めますが、ファイルの書き込みやネットワークへのアクセスはできません。スタイルシートのエラーは、そのファイルと行とともにそのまま表示されます。

断片エディタ

プレビューのブロックの先頭にある鉛筆 ✎ は、そのブロックをXMLに書かれているとおりに、プレビューの下の断片エディタで開きます。ソースと同じように修正し（補完、Ctrl+E、検索と置換）、XMLに適用 で文書のその位置に書き込みます。適用して続行 はエディタを閉じずに書き込み、断片を再読み込み は文書のテキストを取り直します。断片は整形式のままでなければなりません。終了する前に、Variansは変更された断片を適用するよう提案します。

断片エディタとの選択範囲の共有。 プレビューの要素（段落、詩節、見出しなど。編集可能な要素を参照）の先頭にある鉛筆 ✎ は、伝本の画像を動かさずに、その要素を断片エディタで開きます。プレビューのテキストをクリックすると、これまでどおり伝本が同期されます。エディタが開いているとき、プレビューのその要素で選択した文字列（マウスのドラッグまたはダブルクリック）は断片エディタでも選択され、エディタにフォーカスが移ります。修正したい箇所がすぐに見つかります。逆に、断片エディタで選択した範囲はプレビューでも選択され、プレビューはその位置までスクロールします。フォーカスはエディタに残ります。繰り返し現れる語も同じ出現箇所が選ばれ、<lb break="no"/> で分かれた語も対象になります。別の要素での選択は断片エディタを変更しません。その要素は鉛筆で開いてください。断片に入力したテキストは、XMLに適用 の後にはじめてプレビューに表示されます。鉛筆をクリックしても、プレビューの現在の選択範囲は保たれます。それがその要素の中にあれば、断片エディタでも選択されます。プレビューで F2 を押すと、選択範囲（またはカーソル）のある要素が、選択範囲ごと断片エディタで開きます。すでに開いていて修正が未適用の要素は再読み込みされません。

編集可能な要素。 鉛筆 ✎ は、<body> の区分に置かれた各ブロックを開きます。TEI のクラス model.divPart（<p>、<ab>、<lg>、<l>、<sp> など）と model.inter（<list>、<table>、<quote>、<cit>、<stage> など）のすべての要素、および <head>、<figure>、<note> です。この集合の別の要素の中にある要素には、それ自身の鉛筆はなく、外側の要素と一緒に開きます。したがって <lg> には鉛筆がありますが、その <l> にはありません。<p> には鉛筆がありますが、その中の <quote> や <note> にはありません。台詞（<sp>）には鉛筆があり、その話者の上に置かれます。二つの段落の間に置かれた <note> には鉛筆があります。クラスは、検証で見つかったプロジェクトの RELAX NG スキーマから読み取ります。ODD によるカスタマイズでこれらのクラスに加えられた要素も編集できます。スキーマがない場合や、スキーマがこれらのクラスを定義していない場合は、TEI P5 4.10.2 の一覧を使います。鉛筆は、ビューの XSLT スタイルシートにかかわらずVariansが置きます。スタイルシートの側で用意するものはなく、スタイルシートが表示しない要素には鉛筆がありません。エディタのラベルは開いた要素を示します（例：「TEI断片 · <lg> 3/40」）。

Variansのスタイルシート

Variansに付属するスタイルシート（tei-to-html.xsl。HTML 版（Varians のスタイルシート） シナリオのスタイルシートでもあります）は、次のように表示します。

  • 構造：区分の見出しは最初の <head>、なければ @n です（@xml:id が見出しになることはありません）。目次は、見出しのある区分を階層ごとに示します。各詩節（<lg>）は字下げされたブロックで、各詩行（<l>）は1行に置かれます。リストは、@rend="numbered" または @type="ordered"（あるいは numbered）を持てば番号付きになり、その見出しはリストの前に置かれます。<table> は表になり、表題、見出しセル（@role="label"）、結合されたセル（@cols、@rows）を持ちます。図はブロックになり、説明が付きます。
  • 演劇：各台詞（<sp>）はブロックで、その話者（<speaker>）が先頭にスモールキャピタルで示されます。ト書き（<stage>）は括弧に入れて斜体で示されます。二つの台詞や二つの段落の間では字下げされたブロック、詩節の中では1行、段落の中では文中に置かれます。
  • 校訂上の現象（「校訂版（HTML）」と同じ）：<choice> は一つの形（<corr>、<reg>、<expan>、なければ <sic>、<orig>、<abbr>）を示し、ほかの形はツールチップに出ます。<sic> には印が付きます。<del> と <surplus> は取り消し線、<add> は下線、<supplied> は角括弧で示されます。<gap> は「［欠落］」となります。<hi> は太字、下線、上付き、下付き、スモールキャピタルを表示します。<emph>、<title>、<foreign> は斜体です。
  • 引用：<cit> の <ref> は、引用の後に山括弧に入れて灰色で示されます。

スタイルシートの文言（ツールチップ、「［欠落］」など）は、インターフェースの言語に従います。プロジェクトの CSS（rendering/tei.css）が外観を決めます。Variansは詩節の字下げと台詞の体裁をあらかじめ与えますが、プロジェクトの CSS でそれを置き換えられます。プレビュー（Qt）が理解するのは CSS の一部だけです。@media の後に置かれた規則は無視されます。

8. 伝本とファクシミリ

プロジェクトの各伝本には、エディタの横に専用のパネルがあります。そのリソースは、ファイル → プロジェクト設定… の 伝本とリソース（追加…、編集…）で宣言します：画像、行（ALTO または PAGE XML）、整列ファイル。どれも任意で、どの順序で加えてもかまいません。

画像

伝本の 画像ソース は、次の三つのいずれかです。

  • 当面画像なし。
  • ローカル画像（JPEG、PNG、TIFF、BMP、WebP）：画像を追加…。画像をプロジェクトへコピー で、プロジェクトを持ち運べるようになります。各画像には、フォリオまたはページの名称（丁／ページ）と、その TEI surface の識別子（TEI surface）が付きます。追加したファイルは自然順（img_1r、img_1v、img_2r…）に並べられます。自然順に並べ替え で既存の一覧を並べ替え、↑ / ↓ で画像を移動できます。
  • IIIF Manifest（IIIF Presentation 2 または 3）：マニフェストのアドレスを貼り付け、読み込み／更新 を押します。

Variansは、採用した画像ごとに一つの <surface> を加えて校訂版の <facsimile> を補いますが、既存の <facsimile> を作り直すことはありません。surface、zone、そこに加えた内容は保たれ、不要になった surface が無断で削除されることはありません。

<facsimile>
  <surface xml:id="A1-p0002" n="1v">
    <graphic url="../images/A1/002.jpg"/>
  </surface>
</facsimile>

校訂版に使用するIIIF画像

マニフェストには、校訂版で使うよりもはるかに多くのページがあることがよくあります。校訂版に使用する画像のみ を選び、画像の選択と OCR ファイルの対応付け… を開きます。フォリオで絞り込み、必要なページにチェックを付けます。プレビューでページをブラウザーで開けます。チェックしたページだけがその伝本の画像コーパスとなり、TEI surface を受け取ります。その識別子には、マニフェスト内でのページの位置が反映されます。

同じダイアログで、各ページをその行と同期済みページに対応付けます。

  • OCR（ALTO または PAGE XML）。 Variansは、画像名（拡張子を除く）が同じ IIIF ページとファイルを、ファイル内で宣言された画像名も含めて、自動的に対応付けます。曖昧な対応は適用されません。自動対応付け（ファイル名の完全一致） は空欄を補います。最後の列では、名前がまったく異なる場合でも、各ページのファイルを選べます。一つのファイルが対応するのは一つのページだけです。
  • 同期済みページ。 行単位で同期する伝本では、Variansは、各 IIIF ページに対応する整列ファイルのページを、Canvas の識別子、画像サービス、画像のアドレス、確実な OCR の対応付け、または曖昧さのないフォリオ名から見つけます。見つからない場合は、同期済みページ の列で選べます。この選択は project.xml に保存されます。
  • ローカルコピー と 対応付けの状態 の列には、ページのコピーがあるかどうか、対応付けの根拠、表示に使われるソースが示されます。

一覧の中でのページの位置が、ページの特定に使われることはありません。根拠がなければ、Variansは何も対応付けません。

IIIF画像のローカルコピー

Varians で IIIF 画像のローカル作業用コピーを使用する はページをダウンロードします。対象は（取得するページ：）選択した画像全体 または ALTOまたはPAGEと対応するページのみ から選べます。ダウンロードは設定を保存した後に別ウィンドウで始まり、編集作業を妨げません。ファイル → IIIFダウンロード管理… でいつでも開き直せます。このウィンドウには、マニフェストのページ数、対象、保存済み、未取得、対象外の件数が表示されます。未取得分をダウンロード は取得済みのページを再取得せずに続きを取得し、対象画像を再取得 はすべてを取得し直します。一時停止、再開、中止 は画像と画像の間で反映されます。ウィンドウを閉じても隠れるだけで、処理は止まりません。コピーは iiif/local/<témoin>/ に保存されます。コピーされていないページは、引き続きサーバーから読み込まれます。

Web ビューアーの生成時にローカルコピーを使用する は別の設定です。チェックすると、Webビューアは存在するコピーを含み、それらのページはオフラインで表示できます。チェックしないと、元のサーバーから画像を読み込みます。画像を公開する前に、所蔵機関の複製に関する権利を確認してください。

サーバーが IIIF 画像サービスを提供している場合、Variansは画像を最大解像度で表示し、失敗した場合はマニフェストのプレビュー画像に切り替えます。ズームの割合は自動の表示範囲調整に対する比率であり、ファイルの解像度に対するものではありません。

行：ALTO と PAGE XML

伝本の行（画像上の位置とそのテキスト）は、認識ソフトウェアが作成した、ページごとの ALTO または PAGE XML ファイルから得られます。伝本のダイアログでは、文字行の配置情報（ALTO / PAGE） の節で、ALTO / PAGE の入力元 として 自動／同期ファイルのデータ または 独立した ALTO または PAGE ファイル を選べます。後者では、ALTO / PAGE ファイルを追加…（フォリオの順に）と ALTO / PAGE ファイルをプロジェクトにコピー を使います。各ファイルは個別に判別されるので、一つの伝本に両方の形式を混在させることができます。ALTO の行は通常は矩形です。PAGE の行は多角形（Coords/@points）とベースライン（Baseline/@points）を保持し、そのテキストは TextEquiv/Unicode、なければ単語から得られます。

IIIF の伝本に行を加えても、その画像は変わりません。OCR のページが画像に対応付けられるのは、その対応が証明された場合だけです。それ以外のページの数は、伝本のツールチップに示されます。

行があるだけでは同期になりません。 写本の行をピボットの行に結び付ける整列がない限り、その伝本はページ単位でたどられ、パネルはページ全体を表示します。行の枠を表示することはできますが、どの行も指定されません。

行単位の同期

伝本の整列ファイル（JSON同期（任意） と 同期データをプロジェクトへコピー）は、Varians-Synchro で作成します。ピボットの整列ファイルは、その物理的な行をページごとに記述します。ほかの各伝本の整列ファイルは、自分の行をピボットの行に結び付けます（base_keys）。形式は ALIGNMENT_FORMAT.md に記述されています。

TEI では、ピボット A の最初の <lb edRef="#A"/> が整列ファイルの最初の行に対応し、次のものが次の行に対応し、以下同様に続きます。<pb> はページを示しますが、行の番号を振り直すことはありません。ステータスバーはピボットの行を数え（例：「A：3599行 ✓」）、整列と数が異なる場合は知らせます。保存時にもあらためて知らせます。edRef="#T" を edRef="#T1" に補うといったタグ内部の変更も、すぐに反映されます。

伝本が行単位でたどられるのは、その整列が利用できる場合だけです。ピボットには実際の行が、ほかの伝本にはピボットへの実際のリンクが必要です。空や暫定のファイル、ピボットへのリンクのないファイル、リンクがピボットのどの行も指さないファイルでは、伝本はページ単位でたどられ、Variansがそのことを知らせます。

整列を再出力した後は、表示 → 同期データを再読み込み…（Ctrl+Shift+R）で、プロジェクトを開き直さずに読み直せます。ファイルは検証され、変更の一覧が確認のために示されます。誤ったファイルが読み込み済みのデータを置き換えることはありません。翻刻とその取り消し履歴は変わらず、パネルはできるだけページ、ズーム、枠を保ちます。

伝本パネル

パネルの見出しには、伝本の名前と表示中の位置（ページと行）が示されます。コマンドは次のとおりです。

  • ← → は、写本の前または次の行（またはページ）へ移動します。⤺ は、校訂版の箇所に対応する位置に戻ります。開いた本のボタンは、これらの矢印が校訂版を導くかどうかを決めます（写本を自身の順序でたどるを参照）。
  • − と + でズームを調整し、その間のボタンで 100 % に戻します。マウスホイールでもズームでき、画像をダブルクリックすると 100 % に戻ります。
  • 枠 は、この伝本の行の輪郭を表示します。同期された行はオレンジ色、参照中の行は青色です。PAGE の多角形はそのまま描かれます。座標情報がない場合はメッセージで知らせます。
  • ページ ↗ は、ページの画像全体を既定のアプリケーションまたはブラウザーで開きます。
  • ページをマーク と 見開き設定…、それに 葉番号： の一覧は、ページ単位でたどる伝本で使います。
  • ↗ は、パネルを独立したウィンドウに切り離します（パネルの配置を参照）。

幅の狭いパネルでは、枠、ページ ↗、ページをマーク、見開き設定… は ▣、□、pb、↔ に縮められます。ツールチップにその名前が表示されます。

行の切り出しには近くの行も含まれますが、別の段や別のページの行は含まれません。ピボットの一行がある伝本の複数の行に対応する場合、パネルは実際に結び付けられた行を中心に表示します。

ページをマーク は、表示中のページの始まりをカーソル位置に挿入します。

<pb n="1v" edRef="#A1" facs="#A1-p0002"/>

@n はフォリオの名称を、@edRef は伝本を、@facs は TEI の surface（または zone）を示します。カーソルは、タグの中ではなく、テキストの中かタグとタグの間になければなりません。ページ単位でたどる伝本は、カーソルより前にあるその伝本の最後の <pb> のページを表示します。そのページは @facs で指定され、それがなければ、その伝本の一つのページだけを指す @n で指定されます。二つの伝本が同じフォリオ番号を持つこともありますが、@edRef で区別されます。

見開き設定… は、二つのフォリオまたは二つのページを写した画像を記述します。ダイアログには画像の縮小版が表示されるので、赤い線を境目に置き、左側の名称： と 右側の名称： を入力します。Variansは画像には手を加えず、その画像の surface に二つの <zone> を書き込みます。以後、ページをマーク は表示中の行を含む側を対象にするか、どちらを選ぶかを尋ねます。葉番号： の一覧と矢印で左右を行き来でき、画像全体 で画像全体を表示します。ダイアログを取り消すと、何も追加されません。

写本を自身の順序でたどる

各伝本パネルの ← と → の矢印は、校訂版を導きます。伝本は自身の順序で前後に進み、校訂版のカーソルは対応する箇所へ移ります。必要に応じて、その箇所を含む部分またはテキストが表示されます。ほかの伝本は、カーソルが動いたときと同じようにピボットに従います。補助文書を表示しているときは、矢印は伝本をめくるだけです。

行単位で同期される伝本。 パネルは伝本の次の行へ進み、校訂版はその行が指すピボットの行へ移ります。ピボットに結び付けられていない行では、校訂版はその前の結び付けられた行にとどまり、ステータスバーにそのことが表示されます。⤺ ボタンは、パネルをピボットの行に結び付けられた行に戻します。

ページ単位でたどる伝本。 矢印とフォリオの一覧は、校訂版を選んだページへ導きます。まず、その伝本の JSON のいずれかにあるこのページの最初の行へ、なければその <pb edRef="#M" n="45v"/> の終わりへ、それもなければ伝本の <locus from> がこのページであるテキストの冒頭へ移ります。これらの手がかりがどれもない場合、校訂版は動かず、ステータスバーにそのことが表示されます。

テキストからテキストへ。 テキストの終わりで、矢印は写本の中の次のテキストへ進みます。そのテキストが通し番号に従うものでも、別に同期されるものでも同じです。ピボットのパネルも同様で、複数のテキストに共通のピボットは一続きにたどれます。あるテキストの終わりと別のテキストの始まりを載せたページは、表示されたままです。表示中のテキストにない伝本のパネル（「この伝本には、このテキストの整列がありません。」）では、矢印は、校訂版の順序で、この伝本を含む次または前のテキストへ導きます。

写本の中のテキストの順序。 Variansは、伝本のページから順序を導きます。

  • 伝本の宣言された画像一覧（IIIF マニフェストまたはファイル、ファイル → プロジェクト設定…）におけるページの位置。
  • それがなければ、その JSON に共通するページ。各 JSON はすでに写本の順序に並んでおり、あるテキストの終わりと別のテキストの始まりを載せたページが両者を結び付けます。
  • それもなければ、そのテキストに対する伝本の <locus from>、またはテキストの最初のページのフォリオ番号（r または v の付いた数字）を、ほかのページと比べて用います。
  • それでも決まらなければ、テキストは校訂版の順序での位置を保ち、Variansがそのことを知らせます。

表示 → 写本の状態を診断… は、複数のテキストにまたがる写本ごとにテキストの順序を示し、不確かな位置を知らせます。位置を確実にするには、伝本の画像を宣言するか、その <witness> に <locus from="80r" target="#s04"> を加えてください。

校訂版を導くか、めくるか。 ← → ⤺ のすぐ後ろにある開いた本のボタンで、写本の矢印が校訂版を導くかどうかを決めます。押した状態（青灰色の背景）では、この写本の矢印とフォリオの選択で、上で述べたように校訂版のカーソルも移動します。押していない状態では、校訂版には触れずに写本をめくるだけになります。既定では、ピボット伝本のボタンだけが押されています。カーソルが校訂版の中で動くと、パネルは常にそれに従います。各写本の状態はプロジェクトごとに記憶され、project.xml は変更されません。

伝本の欠落部

伝本に欠けている箇所（失われた葉、途切れた本文）は、TEI では <lacunaStart/> と <lacunaEnd/> で囲みます。TEI では、これらの要素を読みの中に置きます。その伝本は、それを含む <rdg>（または <lem>）の伝本、複数の伝本の読みの中では要素自身の @wit の伝本です。

<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaStart/></rdg></app>
…
<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaEnd/></rdg></app>

<rdg wit="#T2 #P">… <lacunaStart wit="#P"/></rdg>

Variansは、読みの外にある @wit 付きのこれらの要素も認識しますが、TEI の検証ではそこでエラーとして報告されます。

パネルでは。 カーソルが伝本の欠落部にあるとき、そのパネルは本文が途切れる行（ページ単位でたどる伝本ではページ）を表示したまま、「この伝本の欠落部：本文はここで途切れています。」という帯を示します。カーソルがピボット伝本の欠落部にあるとき、行単位で同期される伝本はピボットの最後の行にとどまり、「ピボット伝本の欠落部：この箇所では行は同期されません。」という帯を示します。ステータスバーにも表示されます。ページ単位でたどる伝本は、ピボットに依存しない自分の <pb> をたどり続けます。

校異をデバッグ。 「不完全な <app>（読みのない伝本がある）」の検査は、欠落部にある伝本に読みを求めません。

<lacunaEnd/> のない欠落部は、テキストの終わりまで続きます。部分に分かれた版では、欠落部がある部分で始まり、別の部分で終わることがあります。別に同期されるテキストでは、そのテキストの欠落部だけが数えられます。Webビューアにも同じ帯が表示されます。

パネルの配置

表示 → 表示する伝本を選択…：表示する伝本にチェックを付け、上へ と 下へ で並べ替えます。表示する伝本がなければ、画像の領域は消えます。パネルは高さを分け合い、その配分は調整できます。伝本の見出しをダブルクリックするとその伝本が拡大され、もう一度ダブルクリックすると元の配分に戻ります。Webビューアは、表示する伝本をこの順序で公開します。

表示 → 伝本の配置：縦に並べる、横に並べる、グリッド（2列） から選べ、ズーム、枠、同期は失われません。伝本を別ウィンドウに表示（またはその見出しの ↗）で伝本を独立したウィンドウに開き、別の画面に置くことができます。そのウィンドウには 常に手前に表示 のチェックボックスがあります。このウィンドウを閉じるか ↙ を押すと、伝本は元に戻ります（元に戻す）。すべての伝本を元の位置に戻す で、すべての伝本を戻します。エディタと画像の間の仕切りは移動でき、エディタを幅の5分の1まで狭くできます。画像を再読み込み（F5）で画像を読み直します。

これらの設定は、お使いのコンピュータにプロジェクトごとに保存されます。TEI、project.xml、整列のいずれも変更しません。

伝本の状態の診断

表示 → 写本の状態を診断… は、各伝本について、ページ、画像、行、ピボットへの有効なリンクを示します。その警告では、整列がない通常の状態と、不具合（整列ファイルが見つからない、ピボットが異なる、未知の行へのリンク、IIIF 画像に対応付けられていない ALTO または PAGE の行）とを区別します。部分に分かれた版では、対象範囲（版全体または表示中のテキスト）、別に同期されるテキスト、各写本の中のテキストの順序も示します。

9. 校異

校異の符号化

Variansは parallel segmentation による校異を前提とします（基本概念を参照）。テキストの中に、異読箇所ごとに一つの <app> を置き、採用した読み（<lem>）と異読（<rdg>）を含め、その @wit で伝本を挙げます。<rdgGrp> の読みも、ほかの読みと同じように数えます。空の読み <rdg wit="#B"/> は、伝本 B の脱落です。<app> がほかの <app> を含むこともできます。

<app>
  <lem wit="#A #C">uidelicet</lem>
  <rdg wit="#B">scilicet</rdg>
  <rdg wit="#D"/>
</app>
  • 入力。 @wit の中で # を入力すると、<listWit> の伝本の一覧が説明付きで開きます。複数の伝本は空白で区切り、すでに挙げた伝本は再び提案されません。
  • 挙げられた伝本。 <listWit> で宣言されずに挙げられた伝本は、編集 → 参照 で報告されます（文書間の参照を参照）。
  • 欠落部。 伝本にない箇所は、その伝本の読みの一つの中で <lacunaStart/> と <lacunaEnd/> で囲みます。伝本の欠落部を参照してください。
  • 校訂本文。 Variansが校訂本文を公開するところではどこでも、<lem> が優先します。<lem> のない <app> では、選んだ伝本（既定ではピボット）の読みが採られます。

校異をデバッグ

ヘルプ → 校異をデバッグ… は、parallel segmentation で符号化された表示中の文書の校異から誤りを見つけるための、既製の XPath クエリを提供します。各 <app> はその読み（<lem>、<rdg>。<rdgGrp> 内のものを含む）をまとめ、その @wit は伝本を #A の形で挙げます。伝本は、文書の <listWit> にあるものです。

  • 複数回挙げられた伝本：同じ伝本が、一つの <app> の二つの読みに、または同じ @wit に二度現れます。その伝本の読みは曖昧です。
  • 不完全な <app>：読みのない伝本があります。最上位の <app> では <listWit> のすべての伝本が、入れ子の <app> ではそれを含む読みの伝本が期待されます。@wit のない <lem> は、<rdg> にない伝本を含むものとみなされ、その <app> は報告されません。
  • <lem> のない <app>：<lem> を持たない <app>。<app> の <rdgGrp> 内に置かれた <lem> も数えます。この検索は伝本に依存しないため、<listWit> がなくても使えます。
  • 指定した伝本：一覧から選んだ伝本が、<lem> または <rdg> に、あるいは <rdg> だけに現れる（または現れない）<app>。
  • 保存済みのクエリ：ご自身の符号化に特有の検査のための、名前付きの独自の XPath クエリです。追加… は XPath パネルの現在のクエリを提案し、編集… と 削除 で管理します。クエリは project.xml（<xpathQueries> 要素）に保存され、プロジェクトとともに移動します。

検索 を押すと、クエリが XPath パネルで実行され、結果をクリックするとその <app> が選択されます。クエリは XPath 欄に残ります。tei: 接頭辞を使った通常の XPath 1.0 なので、ほかの XML ツールにコピーして使えます。伝本ごとに条件が一つあるため、長くなることがあります。

制限：伝本のグループ（@wit で挙げられた <listWit xml:id="…">）は展開されません。<listWit> にない伝本が挙げられている場合は、編集 → 参照 コマンドで報告されます。<listWit> の一部の伝本が校異で照合されていない場合、すべての <app> が不完全に見えます。

校異の公開

  • 校訂版（HTML）：校訂本文と、各区分の後に置かれ、数字で呼び出される校異。校訂版を参照してください。
  • TEI：DOCX（Word） と TEI：ODT（LibreOffice）：同じ規則による脚注の校異。TEI Stylesheetsを参照してください。
  • Webビューア：各異読箇所の紫の丸が、読みとその伝本を示します。表示する本文は、校訂本文か、ある伝本の翻刻かを選べます。Webビューアを参照してください。

10. 部分に分かれた版（XInclude）

長い版、コレクション、コーパスは、テキストごとに1つのファイルに分け、それを版が XInclude で組み立てるようにできます。Variansは全体を一つの文書として扱いながら、各ファイルを個別に編集できるようにします。この章では、まず仕組みを説明し、次に段階を追って準備の方法を説明します。

仕組み

このようなプロジェクトを段階的に準備する方法は、手引きを参照してください。

版は、XInclude 規格によって部分（たとえば説教ごとに1ファイル）を取り込むことができます。project.xml で宣言された版が親文書のままで、部分はその xi:include から導かれ、ほかの宣言は要りません。

<TEI xmlns="http://www.tei-c.org/ns/1.0"
     xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
    <xi:include href="sermons/s03.xml" xpointer="element(/1/2/1/1)"/>
  </body>

部分は、断片（ファイル全体。そのルートはたとえば説教の <div>）か、xpointer で指定される完全な TEI 文書の要素です。指定は、識別子（s02 または element(s02)）か、パス（element(/1/2/1/1)：TEI、その2番目の子 text、body、最初の div）で行います。部分がさらにほかの部分を取り込むこともできます。部分の中に書かれた相対パスは、その部分のフォルダーを起点とします。

部分とタブ

各部分には、ファイル名を付けた専用のタブがあり、版のタブの後に取り込みの順で並びます。部分は単独で編集・保存でき（Ctrl+S）、取り消し履歴も別々です。終了する前に、Variansは変更された部分の保存を提案します。部分の一覧は、版または部分を保存するたびに読み直されます。「タブの名前を変更…」と「文書をプロジェクトから外す」は、補助文書だけが対象です。XSLT / CSSビューは部分を表示している間も開いたままで、版全体を表示します（組み立てられた版の XSLT / CSSビューを参照）。伝本も表示されたままです（下記参照）。版を別のフォルダーに保存すると xi:include のパスが切れてしまうため、Variansは事前に警告します。

検証

版とその各部分は、いずれも、版のスキーマを用い、部分の未保存の変更も含めて、組み立てられた版を検証させます。このとき RELAX NG パネルに 文書 列が加わり、エラーをダブルクリックすると、該当する部分の該当行が開きます。各部分のタブは、その部分自身のエラーに応じた色になります。部分が見つからない、または整形式でない場合、循環した取り込み、対応していない形式（parse="text"、xi:fallback、ほかの xpointer スキーム）は、その xi:include の行で報告されます。

参照と伝本

版とその部分は一つの文書を成します。#id は、まずそれを含むファイル（ヘッダーを含む）で探され、次にほかの部分で探されます。F12、参照 コマンド、補完はこの規則に従います。組み立てられた版に属するのは、部分の取り込まれた要素の識別子だけです。xpointer で取り込まれた説教の <teiHeader> だけで宣言された伝本は、Variansではその説教の中に見つかりますが、組み立てられた版だけを読むツールからは見えません。部分の中では、ヘルプ → 校異をデバッグ… はその部分自身の伝本を使います。すなわちその <listWit>、なければ部分を指す <locus target="#s01"> を持つ版の伝本、それもなければその @wit に挙げられた伝本です。

伝本の同期

版を便宜上ファイルに分けている場合（テキストがピボット伝本と同じ順に並ぶコレクション）、伝本は一つのファイルからなる版と同じように同期します。ピボットの行（<lb edRef="#A"/>）は、組み立てられた版の順に、部分から部分へと数えられ、整列ファイルはこれまでどおり、一つのファイルからなる版と同じく、版全体について伝本ごとに1つです。版または部分のカーソルに伝本が追従し、ピボットでクリックやスクロールをすると、その行を含む部分にカーソルが移り、そのタブが開きます（「タブを隠す」の後でも開きます）。構造の状態（ステータスバー）は組み立てられた版全体でピボットの行を数え、版または部分を保存するとき、この数がピボットの整列と異なれば警告します。コメントの中や、部分の取り込まれた要素の外にある <lb/> は、ほかの XML ツールと同じく数えません。

条件：ピボットは、これらのテキストを版の順に含んでいなければなりません。Variansが確かめるのは行の数で、順序ではありません。ほかの伝本は、順序が違っていても、あるテキストを欠いていてもかまいません。その整列はすでにピボットの行を指しています。ページ単位で同期する伝本は、自分に関わる最後の <pb> を版の順にたどり、それが前の部分にあっても従います。この伝本がテキストを別の順に持つ場合は、各テキストの冒頭にそのページをマークしてください。

部分の中では、「ページをマーク」は <pb> をカーソル位置の部分に挿入し、版の <facsimile> を補います。「見開き設定…」は zone を版の <facsimile> に書き込みます。版は表示されないまま変更され、そのタブに「*」が付きます。部分で取り消すと <pb> は消えますが、<facsimile> への追加は残ります。

別に同期されるテキスト

テキストごとに伝える伝本やその順序が異なるコーパスでは、テキストが独自の整列を持つことができます。伝本ごとに1つの JSON（通常の形式）を、そのテキストのファイル名（拡張子なし）のフォルダーに置きます（xml/sermons/s02.xml なら alignments/s02/B.json）。宣言は不要です。フォルダーを持つテキストは別に同期され、ほかのテキストは通し番号に従います。テキストのピボットはプロジェクトのピボットですが、project.xml で例外を宣言できます：<part name="s02" base="B"/>。

このようなテキストを表示すると、伝本パネルはその整列とピボットに切り替わります。配置、ズーム、切り離したウィンドウは変わりません。このテキストの JSON がない伝本はパネルを保ち、「この伝本には、このテキストの整列がありません。」と表示します。行はそのテキストだけで数えられ（例：「B：8行 ✓」）、ピボットでのクリックはテキスト内にとどまります。伝本の診断と同期データの再読み込みは、表示中のテキストが対象です。

ページ単位でたどる伝本。 このテキストの JSON を持たないが、テキストを含む伝本――テキスト中の <pb edRef="#C"/>、または <listWit> の自分の <witness> にある <locus target="#s04"> があるもの――は、そこで自分のページをたどります。テキスト中の最初の <pb> より前では、開始ページを表示します。それはこの locus の @from（<locus from="13r" to="14r" target="#s04">）、なければ伝本のページ順で、その最初の <pb> のページの直前のページです。「ページをマーク」もそこで使えます。伝本の診断は、テキストごとに、ページ単位でたどる伝本を示します。JSON のないほかの伝本は、不在のメッセージを表示したままです。

組み立てられた版の XSLT / CSSビュー

XSLT / CSSビューは、表示中の文書にかかわらず、部分を含む版全体を表示し、一つのファイルからなる版と同じように使えます。版から部分に切り替えてもビューは閉じません。補助文書を表示したときだけ閉じます。

  • 断片の編集。 要素の鉛筆 ✎ は、その要素を、それを含むファイルに書かれているとおりに断片エディタで開きます。ラベルはそのファイルを示します（例：「TEI断片 · <p> 10/16 · s03.xml」）。適用した断片は、そのファイルが表示されていなくても、一度も開かれていなくても、そのファイルに書き込まれます。そのタブには「*」が付き、部分で一度取り消すと変更が元に戻ります。ファイルは整形式のままでなければなりません。断片エディタで Ctrl+S を押すと、そのファイルを保存し、続いて表示中の文書が変更されていればそれも保存します。終了する前に、Variansは、適用していない断片をそのファイルとともに保存するよう提案します。
  • クリック、目次、検索。 行をクリックすると、その行を含むファイルのその行にカーソルが移り、そのタブが開きます。プレビューは表示されたままです。伝本が追従し、別に同期されるテキストではそのテキスト独自の番号が使われます。プレビューの目次と検索も同様に動作します。
  • 選択範囲。 プレビューで選択した文字列は、XMLソース タブに戻ると、そのテキストを含むファイル（部分または版）で、同じ段落の同じ出現位置が選択されます。選択がない場合は、表示中の行にカーソルが移ります。逆に、部分での選択範囲や位置はプレビューでも再現されます。プレビューと断片エディタの間では、一つのファイルからなる版と同じように選択範囲が対応します。
  • 制限。 xi:include を含む段落は、そのタグがあるファイルで編集します。取り込まれたテキストは、その部分で編集します。一つのファイルからなる版と同様に、XSLT が出力しない段落や行があると、その後の鉛筆や行の目印がずれます。

組み立てられた版の Web 書き出し

Webビューアを生成 は、部分を含む版全体を、ウィンドウと同じつながりを保って書き出します。

  • 本文と行。 部分の本文はビューアに含まれ、ピボットの行はウィンドウと同じく部分から部分へと通して数えられます。別に同期されるテキストは、そのピボットと JSON（alignments/s02/）を保ちます。選んだ行がそのテキストに入ると、各パネルはそのテキストでの伝本を、その行、開始ページからのページ、または「この伝本には、このテキストの整列がありません。」で示します。各パネルのズームと枠は、テキストからテキストへ保たれます。ヘッダーのボタンは、読む順にすべての行をテキストからテキストへたどります。
  • パネルの矢印。 ウィンドウと同じく、すべてのパネルの ← → 矢印は、写本自身の順序で、部分やテキストを越えて本文を導きます。ページ単位でたどる伝本のフォリオの一覧も同様です。⤺ はパネルを結び付けられた行に戻します。ウィンドウのステータスバーのメッセージ（写本の始まりや終わり、結び付けられていない行、位置の分からないページ、不確かな位置）は、ビューアの題の下に表示されます。
  • 欠落部。 帯はウィンドウと同じです（伝本の欠落部を参照）。欠落部は部分から部分へ続き、別に同期されるテキストは欠落部なしで始まります。
  • 保存。 書き出しは保存されたファイルを読みます。Variansはまず、版、変更された各部分、部分の未適用の断片を保存します。そのいずれかを保存できないと、書き出しは取り消されます。見つからない部分や、対応していない取り込み（parse="text"、xi:fallback）は書き出しの報告に示され、該当するテキストはビューアにありません。
  • 制限。 用いられる位置は、クリックされた本文の断片の位置です。採用されていない読みや注の中に置かれた <pb> や <lb> は、ビューアには見えません。「写本の状態を診断…」「同期データを再読み込み…」「ページをマーク」「見開き設定…」はウィンドウ専用です。版を変更したら、ビューアを生成し直してください。

制限

写本の中のテキストの順序は、そのページから導かれます。ページで結び付けられないテキストは、校訂版の順序での位置を保ちます（写本を自身の順序でたどるを参照）。Web 書き出しには独自の制限があります。組み立てられた版の Web 書き出しを参照してください。xi:include のないプロジェクトには影響ありません。

手引き

この手引きでは、版を複数のファイル（たとえば説教ごとに1ファイル）に分けたプロジェクトの準備を、段階を追って説明します。各機能の詳細は、上の仕組みにあります。

1. ファイルを整理する

版のファイルは1つだけにし、project.xml で宣言します（例：xml/edition.xml）。これが親文書で、ヘッダー、伝本の一覧、テキストの順序を持ちます。テキストは隣のフォルダーに、テキストごとに1ファイルで置きます。各ファイルにはプロジェクト全体で一意の名前を付けます。拡張子を除いたこの名前は、別に同期されるテキストの整列フォルダー名にも使われます（手順 4）。パスは、それを含むファイルからの相対パスです：版からは sermons/s01.xml、説教からは ../personnes.xml#augustinus。

project.xml
alignments/T1.json, T2.json …
alignments/s02/B.json, D.json
xml/edition.xml
xml/sermons/s01.xml, s02.xml, s03.xml …

2. xi:include を書く

版のルート要素で XInclude の名前空間を宣言し、各テキストの位置に xi:include を置きます。

<TEI xmlns="http://www.tei-c.org/ns/1.0" xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
  </body>
</TEI>

テキストは、断片（ファイル全体。ルートが取り込まれる要素で、TEI の名前空間を持ちます：<div xmlns="http://www.tei-c.org/ns/1.0" xml:id="s01">）か、完全な TEI 文書（その1要素だけを、識別子 xpointer="s02" またはパス xpointer="element(/1/2/1/1)" で取り込みます）のどちらかです。完全な文書は単独でも検証でき、そのヘッダーは版に入りません。テキストがさらに別のテキストを取り込むこともできます。parse="text" と xi:fallback は使わないでください。Variansはそれらを報告しますが、扱いません。版を保存すると、各テキストにタブができます。

3. 伝本を宣言する

各写本は、ファイル → プロジェクト設定… で一度だけ、コレクション全体に共通のシグラムで宣言します。TEI では、伝本を版の <listWit>、各テキスト（完全な TEI 文書）の <listWit>、またはその両方で宣言します。xpointer で取り込まれたテキストのヘッダーだけで宣言された伝本は、Variansでは見つかりますが、組み立てられた版だけを読むツールには見えません。

4. 各テキストの同期方法を選ぶ

  • テキストがピボットと同じ順に並び、伝本も同じ場合（便宜上分けたコレクション）：通し番号。一つのファイルからなる版と同じく、版全体について伝本ごとに1つの JSON を、プロジェクト設定で宣言します。ピボットの行は版の順にテキストからテキストへと数えられ、ピボットはこの順でテキストを含んでいなければなりません。
  • テキストごとに伝本が変わる場合（コーパス）：別に同期されるテキスト。フォルダー alignments/<nom du fichier du texte>/ を作り、そのテキストについて伝本ごとに1つの JSON（通常の形式）を置きます：alignments/s02/B.json、alignments/s02/D.json。これらの JSON は、Varians-Synchro でテキストのファイルから作ります。宣言は不要で、フォルダーがあれば十分です。このテキストの JSON はないが、テキスト中に自分の <pb edRef> を持つか、自分の <witness> に <locus target> を持つ伝本は、そこで自分のページをたどります。別に同期されるテキストを参照してください。
  • 両方を組み合わせることもできます：フォルダーを持つテキストは別に同期され、ほかのテキストは通し番号に従います。各伝本の全体用の JSON には、それらのテキストの行だけを含めます。

5. テキスト固有のピボットを宣言する

別に同期されるテキストのピボットは、プロジェクトのピボットです。プロジェクトのピボットがこのテキストを持たない場合や、別の伝本を基準にする場合は、project.xml の </teiManuscriptProject> の前に例外を手で書き、プロジェクトを開き直します。

<parts>
  <part name="s02" base="B"/>
</parts>

name はテキストのファイル名（拡張子なし）、base はピボットのシグラムです。このテキストの行はその <lb edRef="#B"/> になり、フォルダーには B.json が必要です。プロジェクト設定を保存しても、Variansはこの要素を保持します。

6. 確認する

  • 各テキストを表示し、ステータスバーの構造の状態が正しいことを確かめます（例：「B：8行 ✓」）。そのツールチップは、数えたのが組み立てられた版か、別に同期されるテキストかを示します。
  • 表示 → 写本の状態を診断… は、対象範囲（版または表示中のテキスト）、別に同期されるテキストとそのピボット・伝本、そして問題（宣言されていない伝本の JSON、未知のピボット、ピボットの JSON の欠如など）を示します。
  • RELAX NG 検証は組み立てられた版が対象で、「文書」列が各エラーのファイルを示します。
  • 参照 コマンドは、テキスト間の参照を確かめます。
  • ほかの XML ツールでも、Variansなしでプロジェクトを組み立てられます：xmllint --xinclude --noout xml/edition.xml、または検証設定で XInclude を有効にした oXygen。
  • 表示 → 写本の状態を診断… は、写本ごとのテキストの順序も示し、不確かな位置を知らせます。写本を自身の順序でたどるを参照してください。

7. 日々の作業

  • 各テキストはそのタブで編集し、単独で保存します（Ctrl+S）。終了する前に、Variansは変更されたテキストの保存を提案します。
  • テキストを追加するには：そのファイルを作り、版にその xi:include を加え、版を保存します。そのタブが現れます。別に同期されるテキストでは整列フォルダーも加え、表示 → 同期データを再読み込み… を実行します。
  • タブが多い場合：タブを右クリック → タブを隠す。ピボットでクリックすると、必要なテキストのタブが再び現れます。
  • 版を別のフォルダーに保存すると xi:include が切れるため、Variansは事前に警告します。
  • XSLT / CSSビューは版全体を表示します。鉛筆 ✎ でどのテキストの要素も開くことができ、クリックするとその行を含むテキストに移動します。組み立てられた版の XSLT / CSSビューを参照してください。Web 書き出しは版全体を含みます。組み立てられた版の Web 書き出しを参照してください。
  • 写本をテキストからテキストへ読むには、そのパネルの矢印を使ってください。校訂版が正しいテキストを表示します。

11. Webビューア

Webビューアは、校訂版をそのファクシミリとともに公開します。左にテキスト、右に写本が表示され、Variansと同じように同期します。これは独立した HTML ページで、サーバーもVariansもなしにどのブラウザーでも開け、そのままオンラインで公開できます。

ビューアを生成する

Webビューアを生成（ツールバー、または ファイル → Webビューアを生成）は、まず表示する本文を尋ね（本文の選択を参照）、次にビューアを web_output/（viewer.html）に、それが使うローカル画像（web_output/images/）とともに書き出します。フォルダーとファイル名は、ファイル → プロジェクト設定… で設定します。

書き出しの前に、Variansは校訂版、変更された部分、部分の未適用の断片を保存します。そのいずれかを保存できないと、書き出しは取り消されます。ビューアは、表示されている伝本をその順序で公開します（表示 → 表示する伝本を選択…）。非表示のピボットは、同期のためだけに使われます。書き出しの報告には、見つからない画像と、選んだ伝本の読みがない箇所が示されます。ビューアはコピーです。校訂版を変更したら、生成し直してください。

Variansを開かずに、プロジェクトの project.xml を generer_viewer_web.bat にドロップするか、python -m web_viewer.generator project.xml を実行することもできます。できるビューアは同じもので、プロジェクトに保存された本文の選択が使われます。

本文

読み本文。 ビューアは、校訂版のすべてのテキストを読みます。<front>、<body>、<back>、そして <group> の各テキストです。区分の見出しは最初の <head>、なければ @n です。@xml:id は見出しになりません。見出しのない前付けや後付けは「前付け」「後付け」と表示されます。目次は見出しのある区分を、それを含む見出し付きの区分の下に字下げして示します。各 <lg> は詩節で、各 <l> は1行に置かれ、その @n が余白に表示されます。リストは下位リストを保ちます。<table> は表になり、表題、見出しセル（@role="label"）、結合されたセル（@cols、@rows）を持ちます。二つの段落の間に置かれた <note> は注の印になり、注と一緒に非表示にできます。各台詞（<sp>）はブロックで、その話者（<speaker>）が先頭にスモールキャピタルで示されます。ト書き（<stage>）は括弧に入れて斜体で示され、二つの台詞の間や台詞の中ではブロックに、段落の中では文中に置かれます。「校訂版（HTML）」と同じく、<choice> は一つの形（訂正、正規化、展開）を示し、もう一方はツールチップに出ます。<del> は取り消し線、<add> は点線の下線、<supplied> は角括弧で示され、<gap> は「[…]」となり、その理由と範囲がツールチップに出ます。<rdgGrp> の読みも、ほかの読みと同じように数えます。本文は @xml:lang の言語を受け取り、それがハイフネーションに使われます。「校訂版（HTML）」と同じく、type="bible" を持つ <cit> の <ref> は引用の後に山括弧で示され、それ以外の <cit> の <ref> は注になります。

本文の選択。 「Webビューアを生成」は、まずどの本文を表示するかを尋ねます。校訂本文（<lem>、なければ選んだ伝本の読み。「校訂版（HTML）」と同じ）か、選んだ伝本の本文（<lem> でない場合も含む。その伝本の翻刻を再構成します）です。選んだ伝本は、既定では各テキストのピボットです。その伝本に読みがない箇所（<app> のどの読みもその伝本を挙げていない：欠けた箇所、欠落部、不完全な校異）では、ビューアは <lem>、なければピボットの読みを、灰色の背景と点線の枠で、「ここには … の読みがありません」というツールチップ付きで表示します。そのような空の箇所は「∅」で示されます。脱落（<rdg wit="#T2"/>）は読みであり、示されません。ビューアのヘッダーと書き出しの報告に、そのような箇所の数が示されます。同期は常にピボットの行に従います。表示されない読みの中の行は表示された本文に配分され、伝本がその箇所を欠く場合は、見えない目印が行の位置を保ちます。校訂本文を選んだ場合、同じダイアログの <lem> に由来しない読みを黄色で強調表示する チェックボックスは、<lem> がないために採られた読み、つまりまだ決定すべき読みを、最初から強調表示します。ビューアでは、閲覧者がヘッダーの <lem> 以外の読み チェックボックスでそれらを表示したり隠したりできます。この選択は project.xml に保存され（<webViewer text="established|witness" textWitness="T2" highlightNonLem="true"/>）、generer_viewer_web.bat もそれに従います。

テキストでは、紫の丸 v が各異読を示し、クリックすると読みとその伝本が表示されます。丸 n は注を示します。ヘッダーの 異読 と 注 のチェックボックスで、これらの印を隠せます。<lem> 以外の読み のチェックボックスは、校訂本文で、<lem> に由来しない読みを黄色で強調表示します。A− と A+ で文字の大きさを調整し、言語 でビューアの言語を切り替えます。

本文と写本

各伝本には右側にカードがあり、Variansのパネルと同じコマンドを持ちます：矢印、ズーム（マウスホイールでも操作でき、ダブルクリックで 100 % に戻ります）、枠、ページ ↗、⤺。画像のないプロジェクトは、ファクシミリの列なしで公開されます。

  • 行単位。 テキストをクリックするとピボットの行が選ばれ、同期された各伝本はその行を切り出して、青い輪郭付きで表示します。ほかの枠を隠していても、この輪郭は表示されます。ヘッダーの ← 行 と 行 → で、読む順に行をたどります。
  • ページ単位。 テキストをクリックすると、ページ単位でたどる各伝本について、その最後の <pb> のページが表示されます。整列がまったくない場合、ヘッダーのボタンは ← ページ と ページ → になります。
  • 写本の順序で。 Variansと同じく、どのカードの ← → 矢印もテキストを導きます。伝本は自身の順序で進み、テキストはその行が指すピボットの行へ、ページ単位でたどる伝本ではその <pb> へ移ります。そのフォリオの一覧もテキストを導きます。⤺ はカードを結び付けられた行に戻します。メッセージ（写本の始まりや終わり、結び付けられていない行…）は題の下に表示されます。
  • 欠落部。 伝本の欠落部には、Variansと同じく帯が表示されます（伝本の欠落部を参照）。

行の目印のないテキストや、書き出しに含まれない行は、そのことが示されます。ビューアが不確かな対応を推測することはありません。部分に分かれた版については、組み立てられた版の Web 書き出しを参照してください。

検索

ヘッダーの 検索… 欄は、表示中のテキスト全体（見出し、詩行、リストの項目、セル、話者、ト書きを含む）から語や表現を検索します。ほかに何も選ばなければ、大文字・小文字を区別しない完全一致の検索です。中世の異綴りを許容 の下にある u/v、i/j、c/t のチェックボックスで、これらの文字を同等に扱えます。結果は一覧表示され、強調表示されます。結果を選ぶと、その箇所と写本の行に移動します。

画像

ローカル画像はビューアとともにコピーされます。IIIF 画像はそれぞれのサーバーから読み込まれます。ビューアはそのつど必要な大きさを要求し（IIIF Image サービス 1、2、3）、サーバーが拒否した場合は、より小さい画像、次に画像全体、最後にマニフェストのプレビュー画像に切り替えます。したがって、ローカルコピーを公開するページ（IIIF画像のローカルコピーを参照）を除き、インターネット接続と必要な権利が求められます。枠は、元画像の座標で、PAGE の輪郭と見開きの zone に従います。

12. XSLTによる公開

Webビューアのほかに、Variansは XSLT スタイルシートで校訂版を公開します。Variansのスタイルシート（校訂版、HTML 版）、TEI Consortium のスタイルシート（DOCX、ODT、EPUB、HTML、LaTeX…）、そしてご自身のスタイルシートです。それぞれの公開方法は シナリオ で、クリック一つで再実行できます。

XSLT 変換シナリオ

変換シナリオ は、校訂版またはプロジェクトの別の文書に XSLT スタイルシートを適用し、結果をファイルに書き出します。HTML 版、索引、引用の一覧、変換した XML などです。シナリオには名前があり、プロジェクトに保存され、同じように何度でも実行できます。Webビューアは別の公開手段であり、シナリオがそれを変えることはありません。

ファイル → 変換シナリオ… は、二つのグループを表示します。

  • プロジェクトのシナリオ：project.xml（<transformations> 要素）に保存されます。追加…、編集…、複製…、削除 で管理します。
  • 定義済みシナリオ：Variansが用意するシナリオです。HTML 版（Varians のスタイルシート） は、Variansのプレビューのスタイルシートと CSS で校訂版を publications/edition.html に書き出します。校訂版（HTML） は、ピボット伝本にもとづく校異付きの校訂版です（校訂版を参照）。サブグループ TEI Stylesheets は最初は折りたたまれていて（矢印をクリックすると開きます）、TEI-C のスタイルシートのシナリオをまとめています（TEI Stylesheetsを参照）。変換 ボタンのメニューでは、これらはサブメニューになります。定義済みシナリオは、そのまま実行することも、プロジェクトに複製して調整することもできます。

各行には、入力、プロセッサ、そしてシナリオの実行を妨げる問題（スタイルシートが見つからない、Saxon がインストールされていないなど）が赤で表示されます。実行 は選んだシナリオを実行し、プレビュー は一時フォルダーで実行して結果を開きます。シナリオの出力ファイルには触れません。

シナリオの設定

  • 入力：校訂本文（プロジェクトの校訂版。部分がある場合は組み立てられます。各部分は元の場所を保つので、相対的な document() はそこでファイルを見つけます）、表示中の文書（現在のタブの文書。たとえば補助文書。補助XML文書を参照。校訂版の場合は組み立てられたもの）、または ファイル（そのまま読み込むファイル）。
  • プロセッサ：XSLT 1.0（lxml）、または XSLT 2.0・3.0 のスタイルシートには XSLT 3.0（Saxon）。Saxon-HE（パッケージ saxonche）は Variansと一緒にインストールされます：installer_dependances.bat、または pip install -r requirements.txt。
  • XSLT スタイルシート と任意の CSS：プロジェクトからの相対パスです。${varians}/ は、Variansに付属するスタイルシートを指します。CSS は出力の隣にコピーされ、その名前がパラメータ css でスタイルシートに渡されます（Variansのスタイルシートはそれを <link> に入れます）。新しいシナリオには、プレビューのスタイルシートと CSS が提案されます。
  • 出力：書き出すファイルで、実行のたびに置き換えられます（publications/<nom>.html が提案されます）。プロジェクトのソース（project.xml、校訂版とその部分、文書、スタイルシート、スキーマ、整列 JSON）にはできません。Saxon では、スタイルシートが xsl:result-document でほかのファイル（たとえば説教ごとのページ）を書き出せますが、出力のフォルダーとそのサブフォルダーの中だけです。それ以外の場所なら、実行は拒否されます。
  • 出力形式（Saxon の場合）：ふつうは 単一のファイル。スタイルシートが xsl:result-document で index.html と各ページを書くときは HTML ページ（区分ごとに 1 ページ）。TEI-C のスタイルシートのように、受け取ったアドレスのフォルダーにアーカイブのファイルを書くときは DOCX（Word）、ODT（LibreOffice）、EPUB。このときはVariansがアーカイブを作り、それが結果になります（TEI Stylesheetsを参照）。
  • 事前処理 TEI → TEI（任意）（Saxon の場合）：シナリオのスタイルシートの前に、同じパラメータでソースに適用するスタイルシートです。DOCX と ODT のシナリオは、これで校異を脚注にします。
  • パラメータ：名前と値の組で、スタイルシートに渡されます（<xsl:param name="titre"/>）。Saxon では、そのコマンドラインと同じく型なしで渡されます。「false」は xs:boolean のパラメータに、「3」は xs:integer に合い、それ以外では値は文字列のままです。lxml では文字列です。値の中の ${pivot} はプロジェクトのピボット伝本の識別子に、${tei}/ はインストール済みの TEI Stylesheets のフォルダーのアドレスになります。シナリオが指定しない限り、Varians はスタイルシートに langue（インターフェースの言語。値の中では ${langue}）と catalogues（翻訳カタログのアドレス）も渡します。Varians 自身のスタイルシートは、そこから文言を読み込みます。

実行

Webビューアを生成 の隣にある 変換 ボタンは、プロジェクトで最後に実行したシナリオをもう一度実行します（Ctrl+Shift+T も同じ）。その矢印でシナリオの一覧が出ます。実行の前に、Variansはシナリオが読むものを保存します。Web 書き出しと同じく、校訂版、変更された部分、未適用の断片、そして開いていて変更されていれば、入力の文書、スタイルシート、CSS です。変換は別のプロセスで実行されるので、その間もVariansを使え、キャンセル で止められます。

報告には、書き出したファイルと所要時間が示されます。開く で出力を既定のアプリケーション（HTML ならブラウザー）で開き、フォルダを開く でそれを含むフォルダーを開けます。詳細にはログがあります：プロセッサとバージョン、パラメータ、xsl:message、ネットワークからの読み込み（lxml の場合）、拒否された書き込み。エラーの場合は、原因となったファイルと行がメッセージに示され、以前の出力はそのまま残ります。

安全性：スタイルシートは、ローカルのどのファイルも、http や https のアドレスも読み込めます（その場合、出力はサーバーに左右されることがあります）。書き出すのは出力だけです（Saxon では、出力のフォルダー内のファイルも）。入力の外部実体は読み込まれません。

校訂版

定義済みシナリオ 校訂版（HTML） は、校訂版（部分に分かれている場合は組み立てた版）を、画面で読むことも印刷することもできる単独の HTML ページ publications/edition-critique.html として出力します。そのスタイルシート edition-critique.xsl（${varians}/、XSLT 3.0：Saxon プロセッサ）は、TEI の校訂版用スタイルシートを Varians 向けに手直ししたものです。

  • 校訂本文。 校異の <lem> がつねに優先します（空の <lem/> は確定した脱落です）。<lem> がないときは、パラメータ temoin-de-base で選んだ伝本の読みを採ります。その値は ${pivot}、つまりプロジェクトのピボット伝本です。複製したシナリオのダイアログでは、一覧から選びます：先頭にピボット伝本（「T1（ピボット）」）、続いてプロジェクトと <listWit> のほかの伝本、最後に「aucun（レンマのみ）」です。別の書き方の値（#B）はそのまま保たれます。値がなければ、<listWit> の最初の <witness> です。aucun では本文は <lem> だけに従い、すべての <app> に <lem> が必要です。未知の伝本、またはレンマのない校異に対する aucun は、分かりやすいメッセージとともに実行を止めます。選んだ伝本の読みがない校異は、「［伝本の読みなし］」となります。校訂本文に <lem> に由来しない読みが含まれる場合、ページには <lem> 以外の読みを強調表示チェックボックスが付きます。チェックすると、それらの読みが黄色で強調表示され、まだ決定すべきものが分かります。
  • 校異。 各区分の後に二つの系列で置かれます。本文中で数字で呼び出される 校異と、文字（a、b… z、aa…）で呼び出される、より少ない編者の 注です。項目は、採用した読み、「]」、続いてほかの各読みとそのシグラム（斜体）を示します。<rdgGrp> の読みも、ほかの読みと同じように数えます。空の読みは om. となり、校訂本文がその箇所を欠くときは、ほかの読みは追加（add.）となります。<lacunaStart/> または <lacunaEnd/> だけを含む読みは、「lacuna incipit T1」または「lacuna desinit T1」となります（伝本の欠落部を参照）。伝本に由来しない校異のテキストはすべて斜体です：シグラム、om.、add.、lacuna incipit と desinit、注記。読みは、<sic>（後に斜体の「sic」が付きます）、引用、強調を含め、立体のままです。呼び出し記号と項目は、双方向にリンクされます。
  • 本文。 <head> のない区分は @n を見出しにし、それもなければ見出しを持ちません。表示される <pb> は、選んだ伝本のものと @edRef のないものだけで（⟨12r⟩）、aucun ではすべてです（⟨T1 : 12r⟩）。複数の伝本の隣り合う <lb> は一つの区切りになり、そのどれかに break="no" があれば語をつなぎます。詩行と詩節（<l>、<lg>）は、構造と番号を保ちます。各台詞（<sp>）はブロックで、その話者（<speaker>）はスモールキャピタルで示されます。ト書き（<stage>）は括弧に入れて斜体で示され、二つの台詞や二つの詩行の間ではブロックに、段落の中では文中に置かれます。
  • パラメータ（複製… の後、シナリオのダイアログで。temoin-de-base と langue 以外はチェックボックス）：montrer-folios と montrer-numeros-de-vers。sauts-lb（チェック時：選んだ伝本の改行がページの改行になります）。surligner-hors-lemme（チェック時：ページのチェックボックスが最初からチェックされます。既定ではチェックなし）。langue（一覧から選びます。既定は「インターフェースの言語」、つまり ${langue} で、続いて Varians の各言語が並びます。ページを別の言語で公開するときに使います）。

同じ規則で、DOCX と ODT のシナリオは校異を脚注にします（TEI Stylesheetsを参照）。ページの文言（見出し、文、ツールチップ）とエラーメッセージは、インターフェースの言語、またはパラメータ langue の言語で表示されます。校異のラテン語の略語（om.、add.、lacuna incipit と desinit、sic）はラテン語のままです。スタイルシートを手直しするには、シナリオを複製してから スタイルシートを開く を使います。スタイルシートは、規則をまとめた apparat-commun.xsl とともに xslt/ にコピーされます（XSLT 変換シナリオを参照）。

TEI Stylesheets

TEI Stylesheets は TEI Consortium の XSLT スタイルシート（github.com/TEIC/Stylesheets）で、Oxygen などのツールも使っているものです。Variansはこれを同梱し、初めて使うときに、すべてのプロジェクト共通で一度だけ、ユーザーのデータフォルダーにインストールします。ネットワークなしで動作します。XSLT 3.0 で書かれているため、そのシナリオは Saxon を使います。

定義済みシナリオ。 ファイル → 変換シナリオ… では、定義済みシナリオのサブグループ TEI Stylesheets に、校訂版（部分に分かれている場合は組み立てた版）を出力する八つのシナリオがあります：TEI：HTML、TEI：複数ファイルの HTML、TEI：DOCX（Word）、TEI：ODT（LibreOffice）、TEI：EPUB、TEI：テキスト、TEI：Markdown、TEI：LaTeX。このサブグループは最初は折りたたまれていて、変換 ボタンではサブメニューになります。結果は publications/tei/ に書き出されます（edition.html、pages/index.html、edition.docx、edition.odt、edition.epub、edition.txt、edition.md、edition.tex）。HTML の隣には TEI Stylesheets の CSS（tei.css）が置かれ、TEI-C のサイトへのリンクはありません。スタイルシートが加える文言（「目次」など）は、パラメータ lang と documentationLanguage により、インターフェースの言語に従います。シナリオでは、${tei}/ はインストール済みの TEI Stylesheets のファイルを表します（例：${tei}/profiles/default/html/to.xsl）。XSLT 変換シナリオを参照してください。実行のログには、使ったバージョンが記録されます（「ライブラリ：TEI Stylesheets 7.61.0」）。

複数ファイルの形式。 このうち四つのシナリオには、固有の 出力形式 があります（XSLT 変換シナリオを参照）。

  • TEI：複数ファイルの HTML は、目次である publications/tei/pages/index.html と、区分・下位区分ごとのページ（@xml:id にもとづく s02.html など）を、tei.css とともに書き出します。分割はパラメータ splitLevel で決まります。シナリオの値である 1 は区分とその下位区分を分けるので、本文がそれらをまとめる一つの区分である場合でも、作品ごとに1ページになります。0 は最上位の区分だけを分けます。TEI Stylesheets の規則により、前に何もない（<front> がない）場合、最初の区分は目次のページに残ります。
  • TEI：DOCX（Word） と TEI：ODT（LibreOffice） は、TEI Stylesheets のひな形から edition.docx と edition.odt を書き出します。TEI Stylesheets のままでは校異がうまく表示されず（すべての読みが続けて、それぞれ別の段落に出ます）、<pb> ごとに改ページ、<lb> ごとに改行が入ります。そこで、Variansの事前処理 apparat-en-notes.xsl が、まずピボット伝本にもとづいて本文を整えます（パラメータ temoin-de-base、値は ${pivot}）。各 <app> は採用した読みになり、その後に脚注（<note place="foot" type="apparatus">）が付きます：「読み ] 異読 シグラム；…」。om.、add.、lacuna incipit、lacuna desinit の扱いは、校訂版の規則と同じです。@place のない編者注は文末脚注（place="end"）になり、校異と注は二つの系列になります。ピボット伝本のフォリオだけが本文中の ⟨12r⟩ という目印として残り、各伝本の改行は本文に溶け込みます。
  • TEI：EPUB は、インストール済みの TEI Stylesheets の CSS（${tei}/tei.css）をネットワークなしで読み込み、edition.epub を書き出します。
  • ローカルの画像（<graphic url="…"/>）は、寸法とともに DOCX、ODT、EPUB のアーカイブに入ります。リモートの画像はダウンロードされず、ログにそのことが記録されます。

スタイルシートのカスタマイズ。 TEI Stylesheets 自体は変更せず、プロジェクトのスタイルシートで 上書き します。TEI シナリオを複製し（複製…）、その複製を選んで スタイルシートを開く を押すと、Variansは xslt/ にカスタマイズ用スタイルシート（例：xslt/tei-html.xsl）を作成することを提案します（カスタマイズ用スタイルシートを作成）。以後、シナリオはこのスタイルシートを使います。このスタイルシートは TEI-C のスタイルシートを公式アドレス http://www.tei-c.org/release/xml/tei/stylesheet/… でインポート（xsl:import）し、Variansはそれをインストール済みの TEI Stylesheets からネットワークなしで読み込みます。Oxygen も同じように扱うため、このスタイルシートは Oxygen でもそのまま有効です。ここに書いたパラメータ（xsl:param）とテンプレート（xsl:template）はインポートしたものより優先され、それ以外はすべて TEI Stylesheets から取られます。例：

<xsl:stylesheet version="3.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:tei="http://www.tei-c.org/ns/1.0" xmlns="http://www.w3.org/1999/xhtml"
    exclude-result-prefixes="#all">
  <xsl:import href="http://www.tei-c.org/release/xml/tei/stylesheet/profiles/default/html/to.xsl"/>
  <!-- 見出しに番号を付けない。 -->
  <xsl:param name="numberHeadings">false</xsl:param>
  <!-- 人名を太字にする。 -->
  <xsl:template match="tei:persName"><b><xsl:apply-templates/></b></xsl:template>
</xsl:stylesheet>

HTML 出力では、xmlns="http://www.w3.org/1999/xhtml" により、追加した要素（ここでは <b>）も、TEI Stylesheets の要素と同じく XHTML になります。カスタマイズ用スタイルシートは、ほかのスタイルシートと同じく編集、検査（F8）、補完ができます。XSLTスタイルシートの編集を参照してください。TEI Stylesheets を更新しても、このスタイルシートは変わらず、引き続き適用されます。

更新。 TEI-C は年に二回ほど新しいバージョンを公開します。Variansは起動時に、月に一度まで、ウィンドウを止めずに新しいバージョンが公開されたかを確認します。新しいものがない場合やネットワークがない場合は、何も表示しません。新しいバージョンがあれば、インストールを提案します：インストール または 後で（次の確認で再び尋ねます）。インストールは進行状況を表示し、取り消すこともできます。アーカイブが正しくない場合や取り消した場合は、インストール済みのバージョンが残ります。新しいバージョンは次の変換から、すべてのプロジェクトで使われ、古いバージョンは次回の起動時に削除されます。ファイル → TEI Stylesheets…、またはシナリオ一覧の TEI Stylesheets… ボタンで、インストール済みのバージョン、入手元、フォルダー、ライセンス、最終確認日を表示できます。更新を確認 を押すと、すぐに確認します。インストールされるバージョンは一つだけなので、更新後に作り直した出力は以前のものと異なることがあります。バージョンはログに記録されます。

制限。 LaTeX を PDF にするには、Variansの外で TeX（xelatex）を使います。テキストと Markdown では、TEI Stylesheets はレンマと異読を続けて書きます。カスタマイズ用スタイルシートで、この TEI-C の選択を変えられます。DOCX と ODT では、校異はページ下に 1、2、3 と番号付けされ、編者注は文書の末尾に i、ii… と番号付けされます。Word では、TEI Stylesheets が文末脚注の参照記号の後に空白を加えます。HTML のページは画像を持ち出しません。画像のアドレスはソースのままです。

XSLTスタイルシートの編集

XSLT スタイルシートは XML 文書です。Variansはこれをプロジェクトの文書として専用のタブで開き（補助XML文書を参照）、外部ツールなしで検査し、記述を支援します。

  • スタイルシートの追加：ファイル → プロジェクトのXML／XSLT文書… → XML文書、XSLTまたはSchematronを追加… は、.xsl と .xslt のファイルを受け付けます。プロジェクトフォルダーの外にあるスタイルシートは、xslt/ フォルダー（xml/ と同じ階層）にコピーされ、既存のファイルを置き換えることはありません。すでにプロジェクト内にあるスタイルシートは、その場所のままです。
  • 新しいXSLTスタイルシート…（同じメニュー）は、XSLT 1.0（lxml） または XSLT 3.0（Saxon） の最小限のスタイルシートを作成し、xslt/ に置くことを提案します。TEI 名前空間の宣言、HTML 出力、文書のルート用のテンプレートを含みます。
  • シナリオから（XSLT 変換シナリオを参照）：シナリオの一覧、またはシナリオのダイアログ（このときシナリオは保存されます）の スタイルシートを開く は、プロジェクトのシナリオのスタイルシートを表示します。Variansに付属するスタイルシート（${varians}/…）は、まず xslt/ にコピーされます。プロジェクト外のスタイルシートもコピーできますが、コピーせずに開くこともできます。コピーした後は、シナリオがそのコピーを使います。定義済みシナリオの場合は、まず 複製… を使ってください。ほかのスタイルシートを取り込む（xsl:include、xsl:import）Variansのスタイルシートは、それらと一緒にコピーされます。すでにあるファイルは置き換えません：edition-critique.xsl は apparat-commun.xsl と一緒にコピーされます。

検査。 スタイルシートでは、XSLTスタイルシートを検査（F8。RNG検証 の代わり）が、スタイルシートを実行せずにコンパイルします。使用するプロセッサは、そのスタイルシートを使うプロジェクトのシナリオのプロセッサです（異なる場合は両方）。どのシナリオにも使われていないスタイルシートは、そのバージョンに従って検査されます：version="1.0" は lxml、それ以外は Saxon です。RELAX NG 検証と同様に、スタイルシートは最初の表示時、F8 を一度使った後は変更のたび、そして保存時に検査されます。エラーがある場合、保存時に確認を求めます。検証パネルには各エラーが行とともに表示され、ダブルクリックでその行に移動します。インポート（xsl:import）またはインクルード（xsl:include）されたスタイルシートのエラーは「文書」列にそのファイル名が示され、そのスタイルシートがプロジェクトに含まれていれば、ダブルクリックでそこへ移動します。ステータスバーに結果が表示され、スタイルシートのタブは妥当でない文書と同じ色になります。

補完。 Ctrl+Space は、その位置で許される XSLT の要素と属性を、スタイルシートの接頭辞（xsl:）付きで提案します。属性の一覧は入力中にも開きます。結果の要素（<div>、<tei:p>…）の中では、XSLT の命令と xsl:* 属性が提案されます。version="1.0" のスタイルシートには、XSLT 1.0 の要素と属性だけが提案されます。提案は、Variansに付属する W3C の XSLT 3.0 RELAX NG スキーマ（BSD ライセンス）にもとづきます。プロジェクトのカスタム要素（custom-elements.xml）は、スタイルシートでは提案されません。

関連ファイル。 Variansがコピーするのはスタイルシート本体だけです。完全な結果に必要なファイル（xsl:import でインポートされる、または xsl:include でインクルードされるスタイルシート、画像、CSS、JavaScript…）は、スタイルシートが使う相対パスを保ったまま、ご自身でプロジェクトの xslt/ フォルダーに置いてください。インポートまたはインクルードされたスタイルシートが見つからない場合は、検査で報告されます。一方、シナリオの CSS は結果の隣に自動的にコピーされます。

制限：インポートまたはインクルードされるためのスタイルシートは単独で検査されるため、主スタイルシートの宣言への参照がエラーとして報告されることがあります。XSLT 2.0 のスタイルシートには XSLT 3.0 の提案が表示されます。スタイルシート内で宣言された名前（テンプレート、モード、キー）と XPath 式は補完されません。
