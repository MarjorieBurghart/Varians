1. プロジェクトと起動

初回起動時にはプロジェクトは開かれません。以後は、アプリ終了時に開いていたプロジェクトをVariansが再度開くことがあります。ファイル → プロジェクトを閉じる（Ctrl+W）を使うと開始画面に戻り、そのプロジェクトは次回自動的には開かれません。

ファイル → 新規プロジェクト…では、既存のTEIファイルから始めることも、新しい翻刻を始めることもできます。後者では最小限のxml/edition.xmlが作成され、プロジェクトの伝本情報からTEIの<listWit>が生成されます。伝本は画像・ALTO・同期なしで作成し、あとから必要な資源を追加できます。

project.xml
xml/edition.xml
images/
alto/
alignments/
rendering/
i18n/
web_output/

ルート直下にedition.xmlを置く旧形式のプロジェクトにも対応しています。

2. XML編集とXSLT/CSSプレビュー

XMLソースにはTEI文書そのものが表示されます。画面上の折り返しはXMLや論理行番号を変更しません。XSLT / CSSビューは編集用プレビューです。ソースとプレビューの選択範囲は可能な限り同期され、同じ語が一つの箇所に複数回現れる場合も位置関係を考慮します。

断片エディタでは限定した範囲を編集し、その内容をメイン文書へ反映できます。

断片エディタとの選択範囲の共有。プレビューの段落の先頭にある鉛筆 ✎ は、伝本の画像を動かさずに、その段落を断片エディタで開きます。プレビューの本文をクリックすると、これまでどおり伝本が同期されます。エディタが開いているとき、プレビューのその段落で選択した文字列（マウスのドラッグまたはダブルクリック）は断片エディタでも選択され、エディタにフォーカスが移ります。修正したい箇所がすぐに見つかります。逆に、断片エディタで選択した範囲はプレビューでも選択され、プレビューはその位置までスクロールします。フォーカスはエディタに残ります。繰り返し現れる語も同じ出現箇所が選ばれ、<lb break="no"/> で分かれた語も対象になります。別の段落での選択は断片エディタを変更しません。その段落は鉛筆で開いてください。断片に入力した文字は、XMLに適用 の後にはじめてプレビューに表示されます。

3. マークアップ支援、RNG、custom-elements.xml

Ctrl+Eは選択範囲を要素で囲む、またはカーソル位置に新しい要素を挿入します。Ctrl+SpaceはRELAX NGスキーマとcustom-elements.xmlを使い、要素名・属性・一部の属性値を補完します。候補には由来が表示されます。

@witのようなポインタ列はトークン単位で補完されます。動的ソースwitnessesを使えば、#A1や#B1など、プロジェクトに実在する伝本識別子を候補にできます。

重要：プロジェクト固有の入力支援はRELAX NG上の妥当性を変更しません。完全な検証はF8が基準です。

検証結果は画面下部に表示されます。プロジェクトを切り替えると消去され、以前の文書の診断が残らないようになっています。

4. XPath検索

XPath（Ctrl+Shift+F）ではTEIに対してXPath 1.0を実行します。//noteのような単純な式は、必要に応じてTEI名前空間で自動的に再解釈されます。高度な式ではtei:接頭辞を明示できます。

結果にはソース行、要素名、XPath、内容のプレビューが表示されます。結果をクリックすると、開始タグから終了タグまで、該当するXML要素全体が選択されます。複数行にまたがる要素にも対応します。自己終了要素もタグ全体が選択されます。

count(//tei:note)のように要素以外の値を返す式では、その値を直接表示します。

校異を検査するには、ヘルプ → 校異をデバッグ… に既製のクエリがあります。校異をデバッグを参照してください。

5. タグの対応と安全な整形

VariansはXMLの開始タグと終了タグの対応を認識します。開始タグ内にカーソルがあると、対応する終了タグも強調表示されます。対応が曖昧でない場合、QNameの変更や開始タグ全体の削除を終了タグにも反映できます。

インデントは構造的に安全な範囲だけを慎重に整形し、混在内容を保護します。<lb/>の前後に新しい空白を追加せず、xml:space="preserve"を尊重し、曖昧な箇所や混在内容は変更しません。custom-elements.xmlではformatting="inline"、block、preserveを指定できます。

6. 伝本・画像・ファクシミリ・ページ

伝本には画像を設定しないことも、ローカルのJPEG/PNG/TIFF/BMP/WebPを設定することも、IIIF Presentation 2/3 Manifestを設定することもできます。ローカル画像はプロジェクトへコピーするか、元の場所への参照のまま使えます。

画像ページは、安定した<surface>識別子を使ってTEI内に記述できます。

<facsimile>
  <surface xml:id="A1-p0002" n="1v">
    <graphic url="../images/A1/002.jpg"/>
  </surface>
</facsimile>
安全性：Variansは既存の<facsimile>を丸ごと作り直しません。必要な情報だけを段階的に追加し、手作業で追加した<zone>やメタデータを保持します。

ページをマークは、現在表示中の伝本ページに対応する改ページを本文へ挿入します。

<pb n="1v" edRef="#A1" facs="#A1-p0002"/>

カーソルがXMLタグ内部にある場合、この操作は実行されません。本文中またはタグとタグの間にカーソルを置いてください。

7. ALTOと行同期

ALTOは任意で、画像ソースとは独立しています。OCR文字列とページ上の位置情報を提供しますが、ALTOがあるだけでは行同期にはなりません。TEIと物理行の実際の対応付けがなければ、Variansはページモードのままページ全体を表示します。

行モードが有効になるのは、同期が実際に利用可能な場合だけです。すなわち、ピボット伝本には参照行があり、対校本には実際のbase_keysが必要です。空または暫定的なアラインメントJSONが存在するだけでは行モードに切り替わりません。

8. 伝本表示

表示メニューには画像を再読み込み、表示する伝本を選択…、言語メニューがあります。表示する伝本は0件から任意の数まで選べます。この選択はプロジェクトごとのローカル設定として保存され、project.xmlは変更しません。

伝本パネルは縦方向のスプリッタで区切られ、高さを自由に変更できます。伝本ヘッダーをダブルクリックするとその伝本を一時的に最大化し、もう一度ダブルクリックすると以前の比率に戻ります。

V0.8.5.16 — 表示・並び順。 表示 → 表示する伝本を選択…で表示する伝本にチェックを付け、対象の行を選んで上へまたは下へを押すと、画像パネルの上下順を変更できます。非表示の伝本も一覧での位置を保持します。設定はプロジェクトごとにローカル保存され、Variansの再起動後も復元されます。追加した伝本は末尾に並びます。ピボット伝本、同期データ、project.xml、生成されるWebビューアの順序は変更しません。

9. Webビューア

Webビューアを生成すると、通常はweb_output/以下に独立して閲覧できる出力が作られます。必要なローカル画像も出力パッケージへコピーされます。

行同期がない場合、ビューアはページモードとなり、← ページとページ →で移動します。校訂本文をクリックすると、各伝本について直前の該当<pb>を独立に解決し、そのページを表示します。利用可能な行同期がある場合は行移動になります。画像のないプロジェクトでは空の画像欄を出力しません。

10. 保存と安全性

Ctrl+Sで校訂本文を保存します。XMLの整形式性は自動確認され、コンパイル済みRNGスキーマはキャッシュされます。重要な書き込みでは、必要に応じてアトミックな置換や.bakバックアップを使います。解釈が曖昧な自動編集は、編集者のTEIを黙って書き換えるのではなく拒否する方針です。

ALTO・PAGE XML と IIIF 画像のローカルコピー（0.8.5）

写本の行配置情報

プロジェクト設定 → 写本 → 編集の文字行の配置情報（ALTO / PAGE）で、XML ファイルをページ順に追加します。形式はファイルごとに自動判別されます。同じプロジェクトに ALTO と PAGE の写本を混在させることも、同じ写本で両形式を使用することもできます。プロジェクトを移動する場合は、XML ファイルをプロジェクト内にコピーしてください。

ALTO の行は通常、矩形座標で表されます。一方、PAGE の行領域は Coords/@points に記録された多角形で表され、Baseline/@points のベースラインも保持されます。ビューアーの枠の表示を有効にすると輪郭を確認できます。PAGE の行テキストには TextEquiv/Unicode を使用し、なければ単語ごとのテキストを結合します。配置情報を読み込んだだけでは TEI の <lb> との対応付けは行われません。行同期は別のデータです。

IIIFダウンロード管理

プロジェクト設定 → 写本 → 編集でローカル作業用コピーを有効にし、取得範囲をマニフェスト内の全ページまたはALTOまたはPAGEと対応するページのみから選びます。写本ごとに設定できます。選択取得を使う場合は、先に該当写本のALTO/PAGEファイルを登録してください。Variansは画像ファイル名、ページ表示名、丁付けをIIIFキャンバスと照合します。ファイルの順序だけを根拠にはせず、対応が不明確なページは取得せず警告します。

設定保存後、別ウィンドウでダウンロードが始まり、編集作業を続けられます。ファイル → IIIFダウンロード管理…からいつでも開き直せます。マニフェストの総ページ数、対象、保存済み、未取得、対象外の件数が表示されます。未取得分をダウンロードでは保存済み画像を再取得しません。対象画像を再取得は更新を強制します。一時停止・再開・中止は画像単位で反映されます。処理中の通信はタイムアウトまで続く場合があります。ウィンドウを閉じてもダウンロードは継続します。

画像はiiif/local/<写本識別子>/に保存され、処理完了後にプロジェクトを開き直さず利用できます。未取得のページは引き続き配信元への接続が必要です。Webビューアーでローカル画像を利用するかどうかは別設定で、実際に保存済みの画像のみ同梱できます。

Web ビューアーでの独立した選択

Web ビューアーの生成時にローカルコピーを使用するを有効にすると、取得済み画像が web_output/images/ に組み込まれます。無効の場合、Varians 本体がローカル画像を使用していても、Web ビューアーは元の IIIF URL を参照します。未取得ページを含む場合はネット接続が必要です。画像を公開・再配布する際は所蔵機関の利用条件と権利関係をご確認ください。

IIIF 画像の個別選択と OCR ファイルの手動対応付け（0.8.5.4）

「プロジェクト設定 → 伝本 → 編集」で「校訂版に使用する画像のみ」を選び、「画像の選択と OCR ファイルの対応付け…」を開きます。IIIF マニフェストは全画像の目録として保持され、チェックしたキャンバスだけがこの伝本の編集対象となります。丁付けで検索し、表示中の行をまとめて選択・解除できます。「プレビュー」はブラウザーで IIIF 画像を開きます。

画像のベースファイル名（拡張子を除く）が完全に一致する場合、Varians は IIIF Canvas と ALTO/PAGE の対応付けを自動的に提案します。OCR XML 内に記録された元画像のファイル名も照合するため、XML ファイル名が変更されていても検出できます。候補が曖昧な場合は自動登録せず、既存の手動設定を優先します。「自動対応付け（ファイル名の完全一致）」で空欄を補完できます。提案は変更・解除でき、ファイルの順番や曖昧な丁付による推測はしません。

ローカルの ALTO/PAGE ファイルを登録した後、各キャンバスに対応する OCR を最終列で指定できます。ファイル名が異なっていても対応付け可能です。現在の手動対応付けは、画像ごとに OCR ファイルが一つある場合を想定しています。

この選択モードでは、ダウンロード管理の「全ページ」は校訂版用に選択した画像だけを意味します。「ALTO/PAGE に対応するページのみ」では、OCR と結び付いた画像にさらに限定します。選択していないキャンバスについては、画像取得も新規 TEI <surface> の生成も行いません。サーフェス ID にはマニフェスト内の元の位置が反映されるため、選択を変更しても安定します。

既存の TEI サーフェスや取得済みの画像は自動削除しません。本文中で参照されている可能性があるため、未使用のサーフェスは確認のうえ手作業で整理してください。ローカル画像と ALTO/PAGE を追加するときは、1r、1v、2r のような自然順で並べます。既存の一覧も「自然順に並べ替え」で整理でき、手動の順序調整も可能です。

同期済みページとIIIF Canvas（0.8.5.6）

IIIFを使用する写本資料では、Varians-Synchroから書き出したJSONを読み込み、画像の選択とOCRの対応付け…を開きます。JSONに含まれるページIDと行IDは変更されません。Manifestに数百のCanvasがあっても、画像選択で校訂に使用する葉のみを指定できます。

Variansは、Canvasの正確なID、IIIF Imageサービス、慎重に正規化した画像URL、信頼できるALTO/PAGEの対応関係、または一意な葉番号から画像を特定します。ファイル名が完全に一致する場合は自動対応します。確定できない場合は、同期済みページ列でCanvasに対応するJSONのページを手動選択してください。リスト内の順番から対応関係を推測することはありません。手動指定は自動判定より優先され、project.xmlに保存されます。

ローカルコピー列と対応付けの状態列には、画像の保存状況、判定根拠、表示に使用する画像源が示されます。オフライン閲覧にはローカルコピーが必要です。コピーがなければIIIFサービスに戻ります。候補が複数ある場合は自動で選びません。新たにTEIのsurfaceを生成するのは校訂対象として選択したCanvasだけで、既存のsurfaceが無断で削除されることはありません。

ピボット伝本から空のTEI転写を準備する

「新規プロジェクト」または「プロジェクト設定」で、ピボット伝本の <pb/> を生成し、必要に応じて <lb/> も生成できます。対象は編集用に選択されたページだけです。<pb/> の @facs は対応する <surface> を、@edRef はピボット伝本を示します。生成される <lb/> には @edRef のみを付け、@n による行番号や画像領域への自動リンクは付けません。行数はまず確実に対応する ALTO/PAGE から数え、それがない場合は同期 JSON に実際に記載された物理行から数えます。行番号が41から始まる抜粋も扱えます。記載されていない行を推測して補うことはありません。行の記載がないページでも、画像が選択されていれば <pb/> を生成します。プレビュー・確認・日時付きバックアップにより既存の本文を保護し、OCR本文は挿入しません。

ピボット伝本からTEI転写の骨組みを生成（0.8.5.7）

ファイル → 新規プロジェクトで新しい転写を開始を選びます。「ピボット伝本から転写の枠組みを準備」は「開始方法」のすぐ下、写本一覧の前にあります。<pb/> の生成を選択すると、初期状態でチェックされている <lb/> の生成も有効になります。既存プロジェクトの設定画面では、この項目は写本一覧より上にあります。小さい画面ではスクロールできます。ウィンドウのタイトルに「Varians 0.8.5.7」と表示されることを確認してください。

Varians 0.8.5.8 — 部分ページの行

0.8.5.8 の修正：41〜68行のみが記載されたページでは、<lb/> を28個生成します（0個や68個にはしません）。<lb/> に @n は付けません。同期 JSON の lines が空でも、当該画像が編集対象として選択されていれば <pb/> は残ります。選択されていなければ画像・surface の未対応を警告します。

段・ページの境界での画像切り出し (0.8.5.9)

同期で段やページの切り替わり付近の行を選択した場合、Varians は別の段やページに属する前後の行を画像の切り出し範囲に含めません。画像は物理的に隣接する行を中心に表示されます。行番号、JSON の対応情報、同期キーは変更されません。「ページ ↗」から元画像全体を開くことができます。

同期された行の輪郭表示（0.8.5.10）

「枠」ボタンは写本ごとに独立しており、有効状態が分かりやすくなりました。オレンジ色の輪郭は同期された行を、青色は編集上の対応関係を追加せずに手動選択した行を示します。ピボット伝本の一行が別の写本の複数行に対応する場合も、段の境界を含め、実際に対応する行を中心に表示します。PAGE XML の多角形は多角形として、一般的な ALTO の行は矩形として描画します。座標情報がない場合は診断メッセージを表示します。生成される Web ビューアの強調表示は、現時点では矩形です。

伝本ごとの行・ページ混在ナビゲーション（0.8.5.11）

文書間の参照

ポインター属性（@ref, @corresp, @target, @who, @wit, @edRef, @sameAs, @ana, @resp, @source, @hand, @facs, @prev, @next, @synch, @copyOf）は、要素をその @xml:id で指し示します。標準のTEIと同じく、したがってどのXMLツールにとっても、短い形式 #bernard は文書自身の中の要素を指します。プロジェクトの別の文書（補助XML文書を参照）を指すには personnes.xml#bernard と書きます。パスは参照を含む文書からの相対パスです。Webアドレス（https://…）や「#」を含まない値は処理されません。一つの値に、空白で区切った複数のポインターを書くことができます：wit="#T1 #T2"。

入力。このような属性の値の中で # を入力すると、識別子の一覧が自動的に開き、各項目のテキストとファイルが表示されます（例：「personnes.xml#bernard — Bernardus」）。続けて文字を入力すると一覧が絞り込まれ、EnterまたはTabで値が挿入され、Escで一覧が閉じます。@wit と @edRef では、TEIに記述された伝本（<listWit> の <witness>）が一覧に表示されます。Ctrl+Spaceは同じ値をダイアログ（「プロジェクト内の識別子」）で開きます。そこでは説明文も絞り込みの対象になり、「Bern」で personnes.xml#bernard が見つかります。提示される識別子は要素によって異なります。persName/@ref では person、personGrp、persona、placeName/@ref では place、orgName/@ref では org、@who では人物が提示されます。それ以外では、すべての識別子が提示されます。custom-elements.xml では、<values source="ids" elements="person personGrp" prefix="#"/> によって属性ごとにこの一覧を指定できます。別の文書の識別子は file.xml#id の形式で、文書自身の識別子は #id の形式で挿入されます。

移動。参照の上でF12を押すか、Ctrl+クリックするか、右クリックメニューの参照先へ移動を選ぶと、参照先を含む文書が表示され、その要素が選択されます。識別子が複数回定義されている場合は、どの参照先を表示するかをVariansが尋ねます。Alt+←（または右クリックメニューの戻る）で、別の文書からでも元の位置に戻ります。見つからない参照先はステータスバーに表示されます。参照先が別の文書にしかない短い形式の場合も、Variansはそこへ移動し、書くべき形式を示します。

検査。ツールバーの参照ボタンは、プロジェクトのすべての文書の参照を検査します。ソースの下に開くパネルには参照の数が示され、問題のある参照（参照先が見つからない、参照先が別の文書にある短い形式＝書くべき形式を表示、参照先が複数ある＝参照先の文書で識別子が複数回定義されている、ファイルが見つからない）が、文書・行・属性・値・問題の列とともに一覧表示されます。ダブルクリックするとその参照へ移動します。修正後は再検査で検査をやり直せます。この検査は補助機能であり、保存を妨げることはなく、どのファイルも変更しません。

ヘルプ → 校異をデバッグ… は、parallel segmentation で符号化された表示中の文書の校異から誤りを見つけるための既製の XPath クエリを提供します。各 <app> はその読み（<lem>、<rdg>、<rdgGrp> 内のものを含む）をまとめ、@wit は伝本を #A の形で挙げます。伝本は文書の <listWit> にあるものです。

  • 不完全な <app>：読みのない伝本があります。最上位の <app> では <listWit> のすべての伝本が、入れ子の <app> ではそれを含む読みの伝本が期待されます。@wit のない <lem> は <rdg> にない伝本を含むものとみなされ、その <app> は報告されません。
  • 指定した伝本：一覧から選んだ伝本が、<lem> または <rdg>、あるいは <rdg> のみに現れる（または現れない）<app>。
  • 保存済みのクエリ：自分の符号化に特有の検査のための、名前付きの XPath クエリです。追加… は XPath パネルの現在のクエリを提案し、編集… と 削除 で管理します。クエリは project.xml（<xpathQueries> 要素）に保存され、プロジェクトとともに移動します。

検索 を押すとクエリが XPath パネルで実行され、結果をクリックするとその <app> が選択されます。クエリは XPath 欄に残ります。tei: 接頭辞を使った通常の XPath 1.0 なので、他の XML ツールにそのまま貼り付けられます。伝本ごとに条件が一つあるため、長くなることがあります。

伝本の欠落部

伝本に欠けている箇所（失われた葉、途切れた本文）は、TEI では <lacunaStart/> と <lacunaEnd/> で囲みます。TEI ではこれらの要素を読みの中に置きます。伝本は、それを含む <rdg>（または <lem>）の伝本、複数の伝本の読みの中では要素自身の @wit の伝本です：

<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaStart/></rdg></app>
…
<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaEnd/></rdg></app>

<rdg wit="#T2 #P">… <lacunaStart wit="#P"/></rdg>

Varians は読みの外にある @wit 付きのこれらの要素も認識しますが、TEI の検証ではそこでエラーとして報告されます。

パネルでは。カーソルが伝本の欠落部にあるとき、そのパネルは本文が途切れる行（ページ単位でたどる伝本ではページ）を表示したまま、「この伝本の欠落部：本文はここで途切れています。」という帯を示します。カーソルがピボット伝本の欠落部にあるとき、行単位で同期される伝本はピボットの最後の行にとどまり、「ピボット伝本の欠落部：この箇所では行は同期されません。」という帯を示します。ステータスバーにも表示されます。ページ単位でたどる伝本は、ピボットに依存しない自分の <pb> をたどり続けます。

校異をデバッグ。「不完全な <app>（読みのない伝本がある）」の検査は、欠落部にある伝本に読みを求めません。

<lacunaEnd/> のない欠落部はテキストの終わりまで続きます。部分に分かれた版では、欠落部はある部分で始まり別の部分で終わることがあります。別に同期されるテキストでは、そのテキストの欠落部だけが数えられます。Web 書き出しはまだ欠落部を表示しません。

写本を自身の順序でたどる

各伝本パネルの ← と → の矢印は校訂版を動かします。伝本は自身の順序で前後に進み、校訂版のカーソルは対応する箇所へ移ります。必要ならその箇所を含むパートまたはテキストを表示します。ほかの伝本は、カーソルが動いたときと同じようにピボットに従います。補助文書を表示しているときは、矢印は伝本をめくるだけです。

行ごとに同期される伝本。パネルは伝本の次の行へ進み、校訂版はその行が指すピボットの行へ移ります。ピボットに結び付けられていない行では、校訂版はその前の結び付けられた行にとどまり、ステータスバーにそのことが表示されます。⤺ ボタンはパネルを、ピボットの行に結び付けられた行に戻します。

ページごとにたどられる伝本。矢印とフォリオの一覧は、校訂版を選んだページへ導きます。まず、その伝本の JSON のいずれかにあるこのページの最初の行へ、なければその <pb edRef="#M" n="45v"/> の終わりへ、それもなければ伝本の <locus from> がこのページであるテキストの冒頭へ移ります。これらの手がかりがどれもない場合、校訂版は動かず、ステータスバーにそのことが表示されます。

テキストからテキストへ。テキストの終わりで、矢印は写本の中の次のテキストへ進みます。そのテキストが通し番号に従うものでも、別に同期されるものでも同じです。ピボットのパネルも同様で、複数のテキストに共通のピボットは一続きにたどれます。あるテキストの終わりと別のテキストの始まりを載せたページは表示されたままです。表示中のテキストにない伝本のパネル（「この伝本には、このテキストの整列がありません。」）では、矢印は校訂版の順序で、この伝本を含む次または前のテキストへ導きます。

写本の中のテキストの順序。Varians は伝本のページから順序を導きます。

  • 伝本の宣言された画像一覧（IIIF マニフェストまたはファイル、ファイル → プロジェクト設定…）におけるページの位置。
  • それがなければ、その JSON に共通するページ。各 JSON はすでに写本の順序に並んでおり、あるテキストの終わりと別のテキストの始まりを載せたページが両者を結び付けます。
  • それもなければ、そのテキストに対する伝本の <locus from>、またはテキストの最初のページのフォリオ番号（r または v の付いた数字）を、ほかのページと比べて用います。
  • それでも決まらなければ、テキストは校訂版の順序での位置を保ち、Varians がそのことを知らせます。

表示 → 写本の状態を診断… は、複数のテキストにある写本ごとにテキストの順序を示し、不確かな位置を知らせます。確実にするには、伝本の画像を宣言するか、その <witness> に <locus from="80r" target="#s04"> を加えてください。

組み立てられた版（XInclude）

このようなプロジェクトを段階的に準備する方法は手引きを参照してください。

版は、XInclude 規格によって部分（たとえば説教ごとに 1 ファイル）を取り込むことができます。project.xml で宣言された版が親文書のままで、部分はその xi:include 要素から導かれ、ほかの宣言は要りません。

<TEI xmlns="http://www.tei-c.org/ns/1.0"
     xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
    <xi:include href="sermons/s03.xml" xpointer="element(/1/2/1/1)"/>
  </body>

部分は、断片（ファイル全体。そのルートはたとえば説教の <div>）か、xpointer で指定される完全な TEI 文書の要素です。指定は識別子（s02 または element(s02)）か、パス（element(/1/2/1/1)：TEI、その 2 番目の子 text、body、最初の div）で行います。部分がさらにほかの部分を取り込むこともできます。部分の中に書かれた相対パスは、その部分のフォルダーを起点とします。

部分とタブ

各部分には、ファイル名を付けた専用のタブがあり、版のタブの後に取り込みの順で並びます。部分は単独で編集・保存でき（Ctrl+S）、取り消し履歴も別々です。終了する前に、Varians は変更された部分の保存を提案します。部分の一覧は、版または部分を保存するたびに読み直されます。「タブの名前を変更…」と「文書をプロジェクトから外す」は補助文書だけが対象です。XSLT / CSSビューは版だけで使えます。一方、伝本は部分を表示している間も表示されたままです（下記参照）。版を別のフォルダーに保存すると xi:include のパスが切れてしまうため、Varians は事前に警告します。

検証

版とその各部分は、版のスキーマを用い、部分の未保存の変更も含めて、組み立てられた版を検証させます。このとき RELAX NG パネルに文書列が加わり、エラーをダブルクリックすると、該当する部分の該当行が開きます。各部分のタブは、その部分自身のエラーに応じた色になります。部分が見つからない、整形式でない、循環した取り込み、対応していない形式（parse="text"、xi:fallback、ほかの xpointer スキーム）は、その xi:include の行で報告されます。

参照と伝本

版とその部分は一つの文書を成します。#id はまずそれを含むファイル（ヘッダーを含む）で探され、次にほかの部分で探されます。F12、参照コマンド、補完はこの規則に従います。組み立てられた版に属するのは、部分の取り込まれた要素の識別子だけです。xpointer で取り込まれた説教の <teiHeader> だけで宣言された伝本は、Varians ではその説教の中に見つかりますが、組み立てられた版だけを読むツールからは見えません。部分の中では、ヘルプ → 校異をデバッグ… はその部分自身の伝本を使います。すなわちその <listWit>、なければ部分を指す <locus target="#s01"> を持つ版の伝本、それもなければその @wit に挙げられた伝本です。

伝本の同期

版を便宜上ファイルに分けている場合（テキストがピボット伝本と同じ順に並ぶコレクション）、伝本は 1 つのファイルの版と同じように同期します。ピボットの行（<lb edRef="#A"/>）は組み立てられた版の順に、部分から部分へと数えられ、整列ファイルはこれまでどおり、版全体について伝本ごとに 1 つです。版または部分のカーソルに伝本が追従し、ピボットでクリックやスクロールをすると、その行を含む部分にカーソルが移り、そのタブが開きます（「タブを隠す」の後でも開きます）。構造の状態（ステータスバー）は組み立てられた版全体のピボットの行を数え、版または部分を保存するとき、この数がピボットの整列と異なれば警告します。コメントの中や、部分の取り込まれた要素の外にある <lb/> は、他の XML ツールと同じく数えません。

条件：ピボットはこれらのテキストを版の順に含んでいなければなりません。Varians が確かめるのは行の数で、順序ではありません。ほかの伝本は順序が違っていても、あるテキストを欠いていてもかまいません。その整列はすでにピボットの行を指しています。ページ単位で同期する伝本は、自分に関わる最後の <pb> を版の順にたどり、それが前の部分にあっても従います。この伝本がテキストを別の順に持つ場合は、各テキストの冒頭にそのページをマークしてください。

部分の中では、「ページをマーク」は <pb> をカーソル位置の部分に挿入し、版の <facsimile> を補います。「見開き設定…」はゾーンを版の <facsimile> に書き込みます。版は表示されないまま変更され、そのタブに「*」が付きます。部分で取り消すと <pb> は消えますが、<facsimile> への追加は残ります。

別に同期されるテキスト

テキストごとに伝える伝本やその順序が異なるコーパスでは、テキストが独自の整列を持つことができます。伝本ごとに 1 つの JSON（通常の形式）を、そのテキストのファイル名（拡張子なし）のフォルダーに置きます（xml/sermons/s02.xml なら alignments/s02/B.json）。宣言は不要です。フォルダーを持つテキストは別に同期され、ほかのテキストは連続番号に従います。テキストのピボットはプロジェクトのピボットですが、project.xml で例外を宣言できます：<part name="s02" base="B"/>。

このようなテキストを表示すると、伝本パネルはその整列とピボットに切り替わります。配置、ズーム、切り離したウィンドウは変わりません。このテキストの JSON がない伝本はパネルを保ち、「この伝本には、このテキストの整列がありません。」と表示します。行はそのテキストだけで数えられ（例：「B：8行 ✓」）、ピボットでのクリックはテキスト内にとどまります。伝本の診断と同期の再読み込みは表示中のテキストが対象です。

ページ単位でたどる伝本。このテキストの JSON を持たないがテキストを含む伝本――テキスト中の <pb edRef="#C"/>、または <listWit> の自分の <witness> にある <locus target="#s04">――は、そこで自分のページをたどります。テキスト中の最初の <pb> より前では、開始ページを表示します。それはこの locus の @from（<locus from="13r" to="14r" target="#s04">）、なければ伝本のページ順でその最初の <pb> のページの直前のページです。「ページをマーク」もそこで使えます。伝本の診断は、テキストごとにページ単位でたどる伝本を示します。JSON のないほかの伝本は不在のメッセージのままです。

このバージョンの制限

写本の中のテキストの順序はそのページから導かれます。ページで結び付けられないテキストは、校訂版の順序での位置を保ちます（写本を自身の順序でたどるを参照）。XSLT / CSSビューは部分を含む組み立てられた版を表示しますが、読み取り専用で、断片の編集、クリックによる同期、ソースとプレビューの間の選択範囲の引き継ぎはまだできません。Web 書き出しはまだ部分を含みません。書き出しの前に、Varians は「それでも書き出す」を提案します。xi:include のないプロジェクトには影響ありません。

部分に分かれた版を準備する（XInclude）：手引き

この手引きは、版を複数のファイル（たとえば説教ごとに 1 ファイル）に分けたプロジェクトの準備を、段階を追って説明します。各機能の詳細は組み立てられた版（XInclude）にあります。

1. ファイルを整理する

版のファイルは 1 つだけにし、project.xml で宣言します（例：xml/edition.xml）。これがマスター文書で、ヘッダー、伝本の一覧、テキストの順序を持ちます。テキストは隣のフォルダーに、テキストごとに 1 ファイルで置きます。各ファイルにはプロジェクト全体で一意の名前を付けます。拡張子を除いたこの名前は、別に同期されるテキストの整列フォルダー名にも使われます（手順 4）。パスはそれを含むファイルからの相対パスです：版からは sermons/s01.xml、説教からは ../personnes.xml#augustinus。

project.xml
alignments/T1.json, T2.json …
alignments/s02/B.json, D.json
xml/edition.xml
xml/sermons/s01.xml, s02.xml, s03.xml …

2. xi:include を書く

版のルート要素で XInclude の名前空間を宣言し、各テキストの位置に xi:include を置きます：

<TEI xmlns="http://www.tei-c.org/ns/1.0" xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
  </body>
</TEI>

テキストは断片（ファイル全体。ルートが取り込まれる要素で、TEI の名前空間を持ちます：<div xmlns="http://www.tei-c.org/ns/1.0" xml:id="s01">）か、完全な TEI 文書（その 1 要素だけを識別子 xpointer="s02" またはパス xpointer="element(/1/2/1/1)" で取り込みます）のどちらかです。完全な文書は単独でも検証でき、そのヘッダーは版に入りません。テキストがさらに別のテキストを取り込むこともできます。parse="text" と xi:fallback は使わないでください。Varians はそれらを報告しますが、扱いません。版を保存すると、各テキストにタブができます。

3. 伝本を宣言する

各写本は ファイル → プロジェクト設定… で一度だけ、コレクション全体に共通の略号で宣言します。TEI では、伝本を版の <listWit>、各テキスト（完全な TEI 文書）の <listWit>、またはその両方で宣言します。xpointer で取り込まれたテキストのヘッダーだけで宣言された伝本は Varians では見つかりますが、組み立てられた版だけを読むツールには見えません。

4. 各テキストの同期方法を選ぶ

  • テキストがピボットと同じ順に並び、伝本も同じ場合（便宜上分けたコレクション）：連続番号。1 つのファイルの版と同じく、版全体について伝本ごとに 1 つの JSON を、プロジェクト設定で宣言します。ピボットの行は版の順にテキストからテキストへと数えられ、ピボットはこの順でテキストを含んでいなければなりません。
  • テキストごとに伝本が変わる場合（コーパス）：別に同期されるテキスト。フォルダー alignments/<テキストのファイル名>/ を作り、そのテキストについて伝本ごとに 1 つの JSON（通常の形式）を置きます：alignments/s02/B.json、alignments/s02/D.json。これらの JSON は VariansSynchro でテキストのファイルから作ります。宣言は不要で、フォルダーがあれば十分です。このテキストの JSON はないが、テキスト中に自分の <pb edRef> を持つか、自分の <witness> に <locus target> を持つ伝本は、そこで自分のページをたどります。別に同期されるテキストを参照してください。
  • 両方を組み合わせられます：フォルダーを持つテキストは別に同期され、ほかのテキストは連続番号に従います。各伝本のグローバル JSON はそれらのテキストの行だけを含みます。

5. テキスト固有のピボットを宣言する

別に同期されるテキストのピボットはプロジェクトのピボットです。プロジェクトのピボットがこのテキストを持たない場合や、別の伝本を基準にする場合は、project.xml の </teiManuscriptProject> の前に例外を手で書き、プロジェクトを開き直します：

<parts>
  <part name="s02" base="B"/>
</parts>

name はテキストのファイル名（拡張子なし）、base はピボットの略号です。このテキストの行はその <lb edRef="#B"/> になり、フォルダーには B.json が必要です。プロジェクト設定を保存しても、Varians はこの要素を保持します。

6. 確認する

  • 各テキストを表示し、ステータスバーの構造の状態が正しいことを確かめます（例：「B：8行 ✓」）。そのツールチップは、組み立てられた版と別に同期されるテキストのどちらを数えたかを示します。
  • 表示 → 写本の状態を診断… は、対象（版または表示中のテキスト）、別に同期されるテキストとそのピボット・伝本、そして問題（宣言されていない伝本の JSON、未知のピボット、ピボットの JSON の欠如など）を示します。
  • RELAX NG 検証は組み立てられた版が対象で、「文書」列が各エラーのファイルを示します。
  • 参照 コマンドはテキスト間の参照を確かめます。
  • ほかの XML ツールでも Varians なしでプロジェクトを組み立てられます：xmllint --xinclude --noout xml/edition.xml、または検証設定で XInclude を有効にした oXygen。
  • 表示 → 写本の状態を診断… は、写本ごとのテキストの順序も示し、不確かな位置を知らせます。写本を自身の順序でたどるを参照してください。

7. 日々の作業

  • 各テキストはそのタブで編集し、単独で保存します（Ctrl+S）。終了前に、Varians は変更されたテキストの保存を提案します。
  • テキストを追加するには：ファイルを作り、版にその xi:include を加え、版を保存するとタブが現れます。別に同期されるテキストでは整列フォルダーも加え、表示 → 同期データを再読み込み… を実行します。
  • タブが多い場合：タブを右クリック → タブを隠す。ピボットでクリックすると、必要なテキストのタブが再び現れます。
  • 版を別のフォルダーに保存すると xi:include が切れるため、Varians は事前に警告します。
  • Web 書き出しはまだ取り込まれたテキストを含みません。XSLT / CSSビューは読み取り専用で表示します。
  • 写本をテキストからテキストへ読むには、そのパネルの矢印を使ってください。校訂版が正しいテキストを表示します。

バージョン 0.9.0.0 — 組み立てられた版（XInclude）

版は XInclude で部分を取り込めるようになりました。各部分には専用のタブがあり、検証は組み立てられた版を対象として各エラーのファイルを示し、参照と補完は部分をまたいで働きます。組み立てられた版（XInclude）を参照してください。このような版では伝本の同期は一時停止中です。xi:include のないプロジェクト、そのデータ、project.xml の形式は変わりません。

バージョン 0.9.1.0 — 部分をまたぐ伝本の同期

XInclude で組み立てた版でも、伝本が再び同期するようになりました。ピボットの行は組み立てられた版の順に数えられ、部分のカーソルに伝本が追従し、ピボットからその行を含む部分が開きます。部分を表示している間も伝本は表示されたままで、「ページをマーク」と「見開き設定…」も使えます。組み立てられた版（XInclude）を参照してください。xi:include のないプロジェクト、そのデータ、project.xml の形式は変わりません。

バージョン 0.9.1.1 — 別に同期されるテキスト

部分に分かれた版で、整列フォルダー（alignments/s02/、伝本ごとに 1 つの JSON）を持つテキストは別に同期されます。project.xml が宣言すれば独自のピボットも使えます（<part name="s02" base="B"/>）。このテキストの JSON がない伝本は、そのパネルでそれを示します。部分に分かれた版の準備は手引きで説明しています：部分に分かれた版を準備するを参照してください。テキストごとのフォルダーがないプロジェクトは変わりません。

バージョン 0.9.1.2 — プレビューと断片エディタの選択範囲の共有

XSLT / CSSビューでは、鉛筆 ✎ は伝本の画像を動かさずに段落を断片エディタで開きます。プレビューで選択した文字列は開いている断片エディタでも選択され、その逆も同様です。XML編集とXSLT/CSSプレビューを参照してください。XMLソースとプレビューの間の選択範囲の引き継ぎは変わりません（部分のない版）。欠落部（lacuna）、別に同期されるテキストでのページ単位の伝本、写本自身の順序でのたどり方は、バージョン 0.9.1.3 で対応します。

バージョン 0.9.1.3 — 欠落部、別に同期されるテキストでのページ単位の伝本

伝本の欠落部（<lacunaStart/> … <lacunaEnd/>）が認識されます。欠落部にある伝本のパネルは、本文が途切れる行またはページを帯とともに表示したままにします。ピボットの欠落部では行は同期されません。伝本の欠落部を参照してください。別に同期されるテキストでは、JSON を持たずにテキストを含む伝本が、開始ページ（<locus from>）から自分のページをたどります。写本自身の順序でのたどり方は、バージョン 0.9.1.4 で対応します。

バージョン 0.9.1.4 — 写本を自身の順序でたどる

ピボットだけでなく、すべての伝本パネルの矢印が校訂版を動かすようになりました。伝本は自身の順序で、パートやテキストをまたいでたどられます。ページごとにたどられる伝本（矢印とフォリオの一覧）も同様です。ピボットは、別に同期されるテキストから次のテキストへ進みます。写本ごとのテキストの順序はそのページから導かれ、「写本の状態を診断…」に示されます。写本を自身の順序でたどるを参照してください。校訂版を動かさずに伝本をめくれるのは、補助文書を表示している間だけになりました。
