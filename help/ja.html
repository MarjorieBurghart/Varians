Varians — 本文校訂のためのTEI XMLエディタ

ユーザーガイド — バージョン 0.8.5.24

Variansは、TEIによる本文校訂・翻刻のための作業環境です。XML編集、RELAX NG検証、XSLT/CSSプレビュー、伝本と画像の管理、任意のALTO、伝本間同期、Webビューア生成を一つにまとめています。

1. プロジェクトと起動

初回起動時にはプロジェクトは開かれません。以後は、アプリ終了時に開いていたプロジェクトをVariansが再度開くことがあります。ファイル → プロジェクトを閉じる（Ctrl+W）を使うと開始画面に戻り、そのプロジェクトは次回自動的には開かれません。

ファイル → 新規プロジェクト…では、既存のTEIファイルから始めることも、新しい翻刻を始めることもできます。後者では最小限のxml/edition.xmlが作成され、プロジェクトの伝本情報からTEIの<listWit>が生成されます。伝本は画像・ALTO・同期なしで作成し、あとから必要な資源を追加できます。

project.xml
xml/edition.xml
images/
alto/
alignments/
rendering/
i18n/
web_output/

ルート直下にedition.xmlを置く旧形式のプロジェクトにも対応しています。

2. XML編集とXSLT/CSSプレビュー

XMLソースにはTEI文書そのものが表示されます。画面上の折り返しはXMLや論理行番号を変更しません。XSLT / CSSビューは編集用プレビューです。ソースとプレビューの選択範囲は可能な限り同期され、同じ語が一つの箇所に複数回現れる場合も位置関係を考慮します。

断片エディタでは限定した範囲を編集し、その内容をメイン文書へ反映できます。

3. マークアップ支援、RNG、custom-elements.xml

Ctrl+Eは選択範囲を要素で囲む、またはカーソル位置に新しい要素を挿入します。Ctrl+SpaceはRELAX NGスキーマとcustom-elements.xmlを使い、要素名・属性・一部の属性値を補完します。候補には由来が表示されます。

@witのようなポインタ列はトークン単位で補完されます。動的ソースwitnessesを使えば、#A1や#B1など、プロジェクトに実在する伝本識別子を候補にできます。

重要：プロジェクト固有の入力支援はRELAX NG上の妥当性を変更しません。完全な検証はF8が基準です。

検証結果は画面下部に表示されます。プロジェクトを切り替えると消去され、以前の文書の診断が残らないようになっています。

4. XPath検索

XPath（Ctrl+Shift+F）ではTEIに対してXPath 1.0を実行します。//noteのような単純な式は、必要に応じてTEI名前空間で自動的に再解釈されます。高度な式ではtei:接頭辞を明示できます。

結果にはソース行、要素名、XPath、内容のプレビューが表示されます。結果をクリックすると、開始タグから終了タグまで、該当するXML要素全体が選択されます。複数行にまたがる要素にも対応します。自己終了要素もタグ全体が選択されます。

count(//tei:note)のように要素以外の値を返す式では、その値を直接表示します。

5. タグの対応と安全な整形

VariansはXMLの開始タグと終了タグの対応を認識します。開始タグ内にカーソルがあると、対応する終了タグも強調表示されます。対応が曖昧でない場合、QNameの変更や開始タグ全体の削除を終了タグにも反映できます。

インデントは構造的に安全な範囲だけを慎重に整形し、混在内容を保護します。<lb/>の前後に新しい空白を追加せず、xml:space="preserve"を尊重し、曖昧な箇所や混在内容は変更しません。custom-elements.xmlではformatting="inline"、block、preserveを指定できます。

6. 伝本・画像・ファクシミリ・ページ

伝本には画像を設定しないことも、ローカルのJPEG/PNG/TIFF/BMP/WebPを設定することも、IIIF Presentation 2/3 Manifestを設定することもできます。ローカル画像はプロジェクトへコピーするか、元の場所への参照のまま使えます。

画像ページは、安定した<surface>識別子を使ってTEI内に記述できます。

<facsimile>
  <surface xml:id="A1-p0002" n="1v">
    <graphic url="../images/A1/002.jpg"/>
  </surface>
</facsimile>
安全性：Variansは既存の<facsimile>を丸ごと作り直しません。必要な情報だけを段階的に追加し、手作業で追加した<zone>やメタデータを保持します。

ページをマークは、現在表示中の伝本ページに対応する改ページを本文へ挿入します。

<pb n="1v" edRef="#A1" facs="#A1-p0002"/>

カーソルがXMLタグ内部にある場合、この操作は実行されません。本文中またはタグとタグの間にカーソルを置いてください。

7. ALTOと行同期

ALTOは任意で、画像ソースとは独立しています。OCR文字列とページ上の位置情報を提供しますが、ALTOがあるだけでは行同期にはなりません。TEIと物理行の実際の対応付けがなければ、Variansはページモードのままページ全体を表示します。

行モードが有効になるのは、同期が実際に利用可能な場合だけです。すなわち、ピボット写本には参照行があり、対校本には実際のbase_keysが必要です。空または暫定的なアラインメントJSONが存在するだけでは行モードに切り替わりません。

8. 伝本表示

表示メニューには画像を再読み込み、表示する伝本を選択…、言語メニューがあります。表示する伝本は0件から任意の数まで選べます。この選択はプロジェクトごとのローカル設定として保存され、project.xmlは変更しません。

伝本パネルは縦方向のスプリッタで区切られ、高さを自由に変更できます。伝本ヘッダーをダブルクリックするとその伝本を一時的に最大化し、もう一度ダブルクリックすると以前の比率に戻ります。

V0.8.5.16 — 表示・並び順。 表示 → 表示する伝本を選択…で表示する伝本にチェックを付け、対象の行を選んで上へまたは下へを押すと、画像パネルの上下順を変更できます。非表示の伝本も一覧での位置を保持します。設定はプロジェクトごとにローカル保存され、Variansの再起動後も復元されます。追加した伝本は末尾に並びます。ピボット写本、同期データ、project.xml、生成されるWebビューアの順序は変更しません。

9. Webビューア

Webビューアを生成すると、通常はweb_output/以下に独立して閲覧できる出力が作られます。必要なローカル画像も出力パッケージへコピーされます。

行同期がない場合、ビューアはページモードとなり、← ページとページ →で移動します。校訂本文をクリックすると、各伝本について直前の該当<pb>を独立に解決し、そのページを表示します。利用可能な行同期がある場合は行移動になります。画像のないプロジェクトでは空の画像欄を出力しません。

10. 保存と安全性

Ctrl+Sで校訂本文を保存します。XMLの整形式性は自動確認され、コンパイル済みRNGスキーマはキャッシュされます。重要な書き込みでは、必要に応じてアトミックな置換や.bakバックアップを使います。解釈が曖昧な自動編集は、編集者のTEIを黙って書き換えるのではなく拒否する方針です。

ALTO・PAGE XML と IIIF 画像のローカルコピー（0.8.5）

写本の行配置情報

プロジェクト設定 → 写本 → 編集の文字行の配置情報（ALTO / PAGE）で、XML ファイルをページ順に追加します。形式はファイルごとに自動判別されます。同じプロジェクトに ALTO と PAGE の写本を混在させることも、同じ写本で両形式を使用することもできます。プロジェクトを移動する場合は、XML ファイルをプロジェクト内にコピーしてください。

ALTO の行は通常、矩形座標で表されます。一方、PAGE の行領域は Coords/@points に記録された多角形で表され、Baseline/@points のベースラインも保持されます。ビューアーの枠の表示を有効にすると輪郭を確認できます。PAGE の行テキストには TextEquiv/Unicode を使用し、なければ単語ごとのテキストを結合します。配置情報を読み込んだだけでは TEI の <lb> との対応付けは行われません。行同期は別のデータです。

IIIFダウンロード管理

プロジェクト設定 → 写本 → 編集でローカル作業用コピーを有効にし、取得範囲をマニフェスト内の全ページまたはALTOまたはPAGEと対応するページのみから選びます。写本ごとに設定できます。選択取得を使う場合は、先に該当写本のALTO/PAGEファイルを登録してください。Variansは画像ファイル名、ページ表示名、丁付けをIIIFキャンバスと照合します。ファイルの順序だけを根拠にはせず、対応が不明確なページは取得せず警告します。

設定保存後、別ウィンドウでダウンロードが始まり、編集作業を続けられます。ファイル → IIIFダウンロード管理…からいつでも開き直せます。マニフェストの総ページ数、対象、保存済み、未取得、対象外の件数が表示されます。未取得分をダウンロードでは保存済み画像を再取得しません。対象画像を再取得は更新を強制します。一時停止・再開・中止は画像単位で反映されます。処理中の通信はタイムアウトまで続く場合があります。ウィンドウを閉じてもダウンロードは継続します。

画像はiiif/local/<写本識別子>/に保存され、処理完了後にプロジェクトを開き直さず利用できます。未取得のページは引き続き配信元への接続が必要です。Webビューアーでローカル画像を利用するかどうかは別設定で、実際に保存済みの画像のみ同梱できます。

Web ビューアーでの独立した選択

Web ビューアーの生成時にローカルコピーを使用するを有効にすると、取得済み画像が web_output/images/ に組み込まれます。無効の場合、Varians 本体がローカル画像を使用していても、Web ビューアーは元の IIIF URL を参照します。未取得ページを含む場合はネット接続が必要です。画像を公開・再配布する際は所蔵機関の利用条件と権利関係をご確認ください。

IIIF 画像の個別選択と OCR ファイルの手動対応付け（0.8.5.4）

「プロジェクト設定 → 伝本 → 編集」で「校訂版に使用する画像のみ」を選び、「画像の選択と OCR ファイルの対応付け…」を開きます。IIIF マニフェストは全画像の目録として保持され、チェックしたキャンバスだけがこの伝本の編集対象となります。丁付けで検索し、表示中の行をまとめて選択・解除できます。「プレビュー」はブラウザーで IIIF 画像を開きます。

画像のベースファイル名（拡張子を除く）が完全に一致する場合、Varians は IIIF Canvas と ALTO/PAGE の対応付けを自動的に提案します。OCR XML 内に記録された元画像のファイル名も照合するため、XML ファイル名が変更されていても検出できます。候補が曖昧な場合は自動登録せず、既存の手動設定を優先します。「自動対応付け（ファイル名の完全一致）」で空欄を補完できます。提案は変更・解除でき、ファイルの順番や曖昧な丁付による推測はしません。

ローカルの ALTO/PAGE ファイルを登録した後、各キャンバスに対応する OCR を最終列で指定できます。ファイル名が異なっていても対応付け可能です。現在の手動対応付けは、画像ごとに OCR ファイルが一つある場合を想定しています。

この選択モードでは、ダウンロード管理の「全ページ」は校訂版用に選択した画像だけを意味します。「ALTO/PAGE に対応するページのみ」では、OCR と結び付いた画像にさらに限定します。選択していないキャンバスについては、画像取得も新規 TEI <surface> の生成も行いません。サーフェス ID にはマニフェスト内の元の位置が反映されるため、選択を変更しても安定します。

既存の TEI サーフェスや取得済みの画像は自動削除しません。本文中で参照されている可能性があるため、未使用のサーフェスは確認のうえ手作業で整理してください。ローカル画像と ALTO/PAGE を追加するときは、1r、1v、2r のような自然順で並べます。既存の一覧も「自然順に並べ替え」で整理でき、手動の順序調整も可能です。

同期済みページとIIIF Canvas（0.8.5.6）

IIIFを使用する写本資料では、Varians-Synchroから書き出したJSONを読み込み、画像の選択とOCRの対応付け…を開きます。JSONに含まれるページIDと行IDは変更されません。Manifestに数百のCanvasがあっても、画像選択で校訂に使用する葉のみを指定できます。

Variansは、Canvasの正確なID、IIIF Imageサービス、慎重に正規化した画像URL、信頼できるALTO/PAGEの対応関係、または一意な葉番号から画像を特定します。ファイル名が完全に一致する場合は自動対応します。確定できない場合は、同期済みページ列でCanvasに対応するJSONのページを手動選択してください。リスト内の順番から対応関係を推測することはありません。手動指定は自動判定より優先され、project.xmlに保存されます。

ローカルコピー列と対応付けの状態列には、画像の保存状況、判定根拠、表示に使用する画像源が示されます。オフライン閲覧にはローカルコピーが必要です。コピーがなければIIIFサービスに戻ります。候補が複数ある場合は自動で選びません。新たにTEIのsurfaceを生成するのは校訂対象として選択したCanvasだけで、既存のsurfaceが無断で削除されることはありません。

ピボット写本から空のTEI転写を準備する

「新規プロジェクト」または「プロジェクト設定」で、ピボット写本の <pb/> を生成し、必要に応じて <lb/> も生成できます。対象は編集用に選択されたページだけです。<pb/> の @facs は対応する <surface> を、@edRef はピボット写本を示します。生成される <lb/> には @edRef のみを付け、@n による行番号や画像領域への自動リンクは付けません。行数はまず確実に対応する ALTO/PAGE から数え、それがない場合は同期 JSON に実際に記載された物理行から数えます。行番号が41から始まる抜粋も扱えます。記載されていない行を推測して補うことはありません。行の記載がないページでも、画像が選択されていれば <pb/> を生成します。プレビュー・確認・日時付きバックアップにより既存の本文を保護し、OCR本文は挿入しません。

ピボット写本からTEI転写の骨組みを生成（0.8.5.7）

ファイル → 新規プロジェクトで新しい転写を開始を選びます。「ピボット写本から転写の枠組みを準備」は「開始方法」のすぐ下、写本一覧の前にあります。<pb/> の生成を選択すると、初期状態でチェックされている <lb/> の生成も有効になります。既存プロジェクトの設定画面では、この項目は写本一覧より上にあります。小さい画面ではスクロールできます。ウィンドウのタイトルに「Varians 0.8.5.7」と表示されることを確認してください。

Varians 0.8.5.8 — 部分ページの行

0.8.5.8 の修正：41〜68行のみが記載されたページでは、<lb/> を28個生成します（0個や68個にはしません）。<lb/> に @n は付けません。同期 JSON の lines が空でも、当該画像が編集対象として選択されていれば <pb/> は残ります。選択されていなければ画像・surface の未対応を警告します。

段・ページの境界での画像切り出し (0.8.5.9)

同期で段やページの切り替わり付近の行を選択した場合、Varians は別の段やページに属する前後の行を画像の切り出し範囲に含めません。画像は物理的に隣接する行を中心に表示されます。行番号、JSON の対応情報、同期キーは変更されません。「ページ ↗」から元画像全体を開くことができます。

同期された行の輪郭表示（0.8.5.10）

「枠」ボタンは写本ごとに独立しており、有効状態が分かりやすくなりました。オレンジ色の輪郭は同期された行を、青色は編集上の対応関係を追加せずに手動選択した行を示します。ピボット写本の一行が別の写本の複数行に対応する場合も、段の境界を含め、実際に対応する行を中心に表示します。PAGE XML の多角形は多角形として、一般的な ALTO の行は矩形として描画します。座標情報がない場合は診断メッセージを表示します。生成される Web ビューアの強調表示は、現時点では矩形です。

伝本ごとの行・ページ混在ナビゲーション（0.8.5.11）

行単位で同期した伝本と、ローカル画像だけを持つ伝本を同じ校訂プロジェクトで扱えます。各伝本の画像パネルは、それぞれ独立した同期方式に従います。利用可能な同期 JSON がある伝本では、基準伝本の <lb/> と base_keys による行単位の追従を維持します。同期情報のない伝本では、その伝本を示す @edRef と <surface> への @facs を持つ <pb/> に従ってページを切り替えます。@facs がない場合でも、@n が当該伝本のページ表示名と完全かつ一意に一致するときに限り使用します。画像の並び順から推測することはありません。ある伝本の改ページ指定によって、他の伝本の表示が不意に変わることもありません。この動作は整形表示、行ナビゲーション、書き出した Web ビューアーにも適用されます。

V0.8.5.12 — 複数写本の表示。 画像パネルの領域を縦にスクロールでき、４番目の写本が極端に小さくなることを防ぎます。「ピボット写本」は同期のための技術的な基準であり、校訂における底本の指定ではありません。<pb/> に @facs がない場合は @edRef と @n の組合せでページを特定します。異なる写本に同じ葉番号があっても問題ありません。

終了タグの自動補完

XMLソースエディターと断片エディターでは、</ と入力すると、その位置でまだ閉じられていない最も内側の要素名が候補として表示されます。たとえば <div><p>…</p></ の後には div> が提示され、Enter または Tab で </div> を挿入できます。</di のように名前を途中まで入力しても補完できます。Esc は候補の表示だけを閉じ、Ctrl+Space で再表示できます。tei:div のような名前空間付き要素名にも対応します。空要素（<lb/>）、コメント、CDATA、未完成の属性を開いた要素と誤認しません。入れ子関係が不明確な場合は候補を推測しません。

IIIF画像に後からALTO/PAGEを追加する場合（0.8.5.14）

行同期のないIIIF写本にALTO/PAGEファイルを追加しても、画像は表示されたままになります。ローカル作業用コピーがある場合も、選択したCanvasがページの基準です。OCRの行形状は、Canvasの厳密な識別子、手動の対応付け、一意の丁付け表示、または同一のローカル画像が確認できる場合にのみ結び付けられます。未対応のOCRページは派生キャッシュに保持され、その件数が写本パネルのツールチップに表示されます。順番だけによる推定は行いません。対応付けは写本設定の画像・OCR関連付け画面で行ってください。同期JSONとTEIは変更されません。

行同期と IIIF 画像の解像度（0.8.5.15）

ALTO/PAGE の枠が表示されても、行単位の同期が成立しているとは限りません。写本の JSON にピボット写本への base_keys がなければ、Varians はその旨を表示し、ページ単位の移動を継続します。リンクが存在してもピボット写本の行に一致しない場合も通知します。IIIF Image API のサービスが利用できる場合、マニフェストの縮小画像より元の解像度の画像を優先し、取得できない場合は縮小画像に切り替えます。ローカル画像が Canvas より小さくても、枠は表示画像の実寸に合わせて縮尺補正されます。ズーム率は自動調整との比率であり、ファイルの解像度ではありません。

V0.8.5.18 — 写本の状態診断と同期データの更新

表示 → 写本の状態を診断…から、各写本のページ、画像、物理行、およびピボット写本への有効な対応関係を確認できます。同期を行わない通常のページ閲覧と、JSONの欠落、ピボット写本の不一致、不明なbase_keys、IIIF画像に対応しないALTO/PAGEを区別して表示します。

Web書き出し：画像座標と切り出し (0.8.5.24)

バージョン0.8.5.24では、Webビューアの画像表示をデスクトップ版の座標規則に合わせました。PAGE XMLの行輪郭は、凹多角形や従来の外接矩形からはみ出す点を含め、すべての頂点を保持します。前後の行を含めた切り出しが、物理的な段やページの境界を越えることはありません。座標がない場合、画像の左上に架空の枠を描くこともありません。

見開きは1枚の元画像として扱い、TEIの<zone>と<pb facs>で表示する部分を指定します。座標は元画像を基準とし、OCRや縮小プレビューの解像度には左右されません。有効なbase_keysがなければページ単位の移動を維持します。存在するローカル画像は書き出し先にコピーされ、不足ファイルは記録されます。外部IIIF画像の閲覧には引き続きサーバーへの接続とアクセス権が必要です。

Web書き出し：IIIF高解像度画像と読み込み時の復旧（0.8.5.25）

WebビューアはIIIF Image APIのv1・v2・v3に対応します。表示領域、拡大率、画面の画素密度に応じて画像を要求し、マニフェストまたは取得可能なinfo.jsonに示されたサイズ制限を考慮します。領域画像を取得できない場合は、より小さい画像、全体画像のローカル切り出し、最後にマニフェストのプレビュー画像へと切り替えます。PAGE XMLの輪郭とTEIの領域座標は保持されます。ページを切り替えると古い読み込みを中止します。

単独のHTMLにはビューアのプログラムが含まれますが、外部IIIF画像そのものが自動的に保存されるわけではありません。表示にはネットワーク接続と適切な利用権限が必要です。利用可能なローカル画像は書き出し先に別途コピーされます。許可のない遠隔画像の複製や根拠のない行対応付けは行いません。

Webビューアの行表示に関する修正（0.8.5.25.1）

Webビューアの本文クリックによる同期（0.8.5.25.2）

WebビューアのTEI行対応（V0.8.5.25.3）

Webビューアはデスクトップ版と同じ規則を使用します。基準写本のTEI行マーカーを出現順に、JSONの物理行へ対応させます。ページ・丁付けの参照によって行番号が振り直されることはありません。他の写本との対応には記録済みのbase_keysのみを用います。行数が一致しない場合は警告し、対応を推測して補いません。HTMLを書き出し直してください。

補助XML文書

プロジェクトには、校訂本文のほかに、典拠ファイル（人名・地名）や注などの他のXML文書を含めることができます。ファイル → プロジェクトのXML文書を使用してください。XML文書を追加…は既存のファイルを登録します。プロジェクトフォルダーの外にあるファイルは xml/ にコピーされ、既存のファイルが置き換えられることはありません。新しいXML文書…は、ルート要素を指定して空の文書を作成します。文書をプロジェクトから外すは、表示中の文書をプロジェクトから外しますが、ファイルは削除しません。

補助文書が一つでもあると、XMLソースの上にタブの列が表示されます。校訂本文に続いて、文書ごとに一つのタブが並びます。各文書はそれぞれの取り消し履歴、位置、状態を保持します。アスタリスクは未保存の変更を示し、名前の色は整形式でない、または妥当でないXMLを示します。RELAX NG検証と補完は、表示中の文書の <?xml-model?> に従います。写本、XSLT / CSSビュー、異本のコマンドは校訂本文にのみ関わるため、別の文書を表示している間は隠され、戻るとそのまま復元されます。Ctrl+Sは表示中の文書を保存します。終了やプロジェクトの切り替えの前に、Variansは変更されたすべての文書の保存を提案します。Web書き出しは校訂本文のみを使用します。

文書は project.xml の <documents> 要素で宣言されます。補助文書のないプロジェクトは変わりません。以前のバージョンのVariansでもこのようなプロジェクトは通常どおり開けますが、そこでプロジェクト設定を保存すると、この一覧は消去されます。
