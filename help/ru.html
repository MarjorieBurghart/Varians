Varians — редактор TEI XML для текстологии

Руководство пользователя — версия 0.8.5.24

Varians — рабочая среда для критического издания текстов в TEI. Она объединяет редактирование XML, проверку RELAX NG, предпросмотр XSLT/CSS, управление свидетелями и изображениями, необязательный ALTO, синхронизацию свидетелей и создание веб-просмотрщика.

1. Проекты и запуск

При первом запуске проект не открывается. В дальнейшем Varians может снова открыть проект, который был активен при закрытии программы. Файл → Закрыть проект (Ctrl+W) возвращает на начальный экран и запрещает автоматическое открытие этого проекта при следующем запуске.

Файл → Новый проект… позволяет начать с существующего TEI либо создать новую транскрипцию. Во втором случае создаётся минимальный xml/edition.xml и TEI-<listWit> на основе свидетелей проекта. Свидетель может сначала не иметь изображений, ALTO и синхронизации; эти ресурсы можно добавить позже.

project.xml
xml/edition.xml
images/
alto/
alignments/
rendering/
i18n/
web_output/

Старые проекты, где edition.xml лежит в корне, по-прежнему поддерживаются.

2. Редактирование XML и предпросмотр XSLT/CSS

Исходный XML содержит документ TEI. Визуальный перенос длинных строк не меняет XML и логическую нумерацию строк. Представление XSLT / CSS даёт редакционный предпросмотр. Выделение в исходном тексте и предпросмотре по возможности синхронизируется, в том числе при повторении одного и того же слова в одном фрагменте.

Редактор фрагмента позволяет редактировать ограниченный отрывок и затем применить его обратно к основному документу.

Общее выделение с редактором фрагмента. Карандаш ✎ в начале абзаца предпросмотра открывает этот абзац в редакторе фрагмента, не сдвигая изображения свидетелей; щелчок по тексту предпросмотра по-прежнему их синхронизирует. Когда редактор открыт, строка, выделенная в этом абзаце предпросмотра (перетаскиванием мыши или двойным щелчком), выделяется и в редакторе фрагмента, который получает фокус: место для исправления находится сразу. И наоборот, выделение, сделанное в редакторе фрагмента, выделяется в предпросмотре, который прокручивается к нему; фокус остаётся в редакторе. Находится то же вхождение повторяющегося слова, в том числе слова, разделённого <lb break="no"/>. Выделение в другом абзаце не меняет редактор фрагмента: откройте этот абзац его карандашом. Текст, набранный во фрагменте, появляется в предпросмотре только после Применить к XML.

3. Помощь при разметке, RNG и custom-elements.xml

Ctrl+E оборачивает выделение в элемент или вставляет новый элемент в позицию курсора. Ctrl+Space дополняет имена элементов, атрибуты и некоторые значения атрибутов на основе схемы RELAX NG и custom-elements.xml. У предложений указывается источник.

Списки указателей вроде @wit дополняются по одному токену. Динамический источник witnesses может предлагать реальные идентификаторы проекта, например #A1 и #B1.

Важно: проектные подсказки ввода никогда не меняют действительность документа по RELAX NG. Полная проверка (F8) остаётся авторитетной.

Результаты проверки выводятся в нижней панели. При смене проекта они очищаются, поэтому сообщения от предыдущего документа не остаются на экране.

4. Поиск XPath

XPath (Ctrl+Shift+F) выполняет XPath 1.0 по TEI. Простое выражение вроде //note при необходимости автоматически повторяется в пространстве имён TEI; в сложных выражениях можно явно использовать префикс tei:.

В результатах показываются строка исходного XML, элемент, путь и предпросмотр. Щелчок по результату выделяет весь соответствующий XML-элемент от открывающего до закрывающего тега, даже если он занимает несколько строк. Самозакрывающийся элемент выделяется целиком.

Скалярные выражения, например count(//tei:note), показывают своё значение вместо списка элементов.

Для проверки критического аппарата команда Справка → Отладка аппарата… предлагает готовые запросы: см. Отладка аппарата.

5. Парные теги и безопасное форматирование

Varians распознаёт пары XML-тегов. Когда курсор находится внутри открывающего тега, соответствующий закрывающий тег подсвечивается. Если соответствие однозначно, изменение QName и полное удаление открывающего тега могут быть зеркально применены к закрывающему.

Отступы форматируют структурные области консервативно и защищают смешанное текстовое содержимое. Новые пробелы вокруг <lb/> не добавляются, xml:space="preserve" соблюдается, а неоднозначное или смешанное содержимое остаётся без изменений. В custom-elements.xml можно задавать formatting="inline", block или preserve.

6. Свидетели, изображения, факсимиле и страницы

Свидетель может быть без изображений, использовать локальные JPEG/PNG/TIFF/BMP/WebP или Manifest IIIF Presentation 2/3. Локальные файлы можно копировать в проект или оставлять ссылками на исходное расположение.

Страницы изображений можно описывать в TEI с устойчивыми идентификаторами <surface>:

<facsimile>
  <surface xml:id="A1-p0002" n="1v">
    <graphic url="../images/A1/002.jpg"/>
  </surface>
</facsimile>
Безопасность: Varians обновляет данные факсимиле постепенно. Он не перестраивает существующий <facsimile> целиком и сохраняет зоны и метаданные, добавленные вручную.

Отметить страницу вставляет указание смены страницы для текущей отображаемой страницы свидетеля:

<pb n="1v" edRef="#A1" facs="#A1-p0002"/>

Если курсор находится внутри любого XML-тега, операция отменяется. Поместите курсор в текст или между тегами.

7. ALTO и синхронизация строк

ALTO необязателен и не зависит от источника изображений. Он даёт OCR-текст и геометрию страницы, но сам по себе ALTO не является синхронизацией строк. Без реального соответствия TEI ↔ физическая строка Varians остаётся в режиме страниц и показывает текущую страницу целиком.

Режим строк включается только при действительно пригодной синхронизации: у опорного свидетеля должны быть опорные строки, у вторичных — реальные base_keys. Пустой или предварительный JSON выравнивания не включает режим строк.

8. Отображение свидетелей

Меню Вид содержит Перезагрузить изображения, Выбрать отображаемых свидетелей… и меню языка. Можно показывать от нуля до любого числа свидетелей. Выбор хранится локально для проекта и не изменяет project.xml.

Панели свидетелей разделены вертикальным сплиттером, поэтому их высоту можно менять. Двойной щелчок по заголовку временно разворачивает одного свидетеля на максимум; повторный двойной щелчок восстанавливает прежние пропорции.

V0.8.5.16 — Видимость и порядок. Откройте Вид → Выбрать отображаемые рукописи…, отметьте нужные рукописи, выделите строку и кнопками Выше или Ниже задайте порядок панелей изображений сверху вниз. Скрытые рукописи сохраняют своё место в списке. Настройки хранятся локально для каждого проекта и восстанавливаются после перезапуска; новые рукописи добавляются в конец. Опорный свидетель, данные синхронизации, project.xml и порядок в создаваемом веб-просмотрщике не изменяются.

9. Веб-просмотрщик

Создать веб-просмотрщик формирует автономный результат, обычно в web_output/. Нужные локальные изображения копируются в пакет вывода.

Без синхронизации строк просмотрщик работает в режиме страниц с кнопками ← страница и страница →. Щелчок по тексту издания независимо для каждого свидетеля определяет последний подходящий <pb>. При пригодной синхронизации включается навигация по строкам. Проекты без изображений экспортируются без пустого столбца факсимиле.

Как в окне, стрелки ← → любой панели ведут текст: свидетель продвигается в собственном порядке, а текст переходит к строке пивота, на которую указывает его строка, или, для свидетеля, отслеживаемого по страницам, к его <pb>; список его листов тоже ведёт текст; ⤺ возвращает панель к связанной строке. Лакуны свидетелей отмечаются полосами. Об издании из частей см. Веб-экспорт собранного издания.

10. Сохранение и безопасность

Ctrl+S сохраняет издание. Корректность формирования XML проверяется автоматически, скомпилированные схемы RNG кэшируются, а важные записи при необходимости используют атомарную замену и/или резервные копии .bak. Неоднозначные автоматические изменения следует отвергать, а не применять молча к редакционному TEI.

ALTO, PAGE XML и локальные копии изображений IIIF (0.8.5)

Геометрическая разметка рукописей

В разделе Настройки проекта → Свидетели → Изменить → Геометрическая разметка текста (ALTO / PAGE) добавьте файлы XML в порядке страниц. Varians автоматически определяет формат каждого файла. В одном проекте могут быть свидетели с ALTO и PAGE; оба формата допустимы даже у одного свидетеля. Для переноса проекта между компьютерами скопируйте файлы в его каталог.

Строки ALTO обычно описаны прямоугольниками, а контуры строк PAGE сохраняются как многоугольники (Coords/@points); при наличии сохраняется и базовая линия (Baseline/@points). Включите отображение Рамок, чтобы увидеть контуры. Текст строки PAGE берётся из TextEquiv/Unicode, а при его отсутствии — из отдельных слов. Импорт геометрии сам по себе не создаёт синхронизацию со строками TEI <lb>; это отдельные данные.

Менеджер загрузок IIIF

В разделе Параметры проекта → Свидетели → Изменить включите локальную рабочую копию и выберите Все страницы манифеста либо Только страницы с соответствующими файлами ALTO или PAGE. Для каждого свидетеля действует собственная настройка. При выборочной загрузке сначала укажите его файлы ALTO/PAGE. Varians сопоставляет имена изображений, подписи страниц и фолиацию с холстами IIIF. Один лишь порядок файлов не считается доказательством соответствия; неоднозначные или нераспознанные страницы пропускаются с предупреждением.

После сохранения параметров загрузка запускается в отдельном окне и не блокирует редактирование. Менеджер можно вновь открыть через Файл → Менеджер загрузок IIIF…. Он показывает общее число страниц, выбранные, уже сохранённые, недостающие и исключённые. Загрузить недостающие продолжает работу без повторной загрузки имеющихся файлов; Обновить выбранные запрашивает изображения заново. Пауза, продолжение и остановка действуют между изображениями. Закрытие окна скрывает его, не останавливая загрузку.

Файлы сохраняются в iiif/local/<рукопись>/ и после завершения операции доступны без повторного открытия проекта. Страницы без локальной копии по-прежнему требуют соединения с сервером. Настройка экспорта веб-просмотрщика независима: включить можно лишь изображения, уже сохранённые локально.

Независимая настройка веб-просмотрщика

Включите Использовать локальную копию при создании веб-просмотрщика, чтобы включить доступные изображения в web_output/images/. Если флажок снят, веб-просмотрщик использует исходные URL IIIF, даже когда сама программа Varians работает с локальными файлами. Страницы без локальной копии могут требовать сети. Перед распространением изображений проверьте права и условия лицензирования учреждения-хранителя.

Явный выбор IIIF-изображений и привязка файлов OCR (0.8.5.4)

В настройках проекта откройте редактирование свидетеля, выберите «Только выбранные для издания изображения», затем «Выбрать изображения и связать файлы OCR…». Манифест остаётся полным каталогом; в издание включаются лишь отмеченные канвасы. Можно фильтровать листы, выделять или снимать выделение с видимых строк и открывать изображение IIIF в браузере для просмотра.

Varians автоматически предлагает связь между Canvas IIIF и ALTO/PAGE, если базовые имена файлов изображений полностью совпадают (без учёта расширения). Также проверяется исходное имя изображения, указанное в OCR XML, даже если XML-файл переименован. Неоднозначные совпадения не применяются, а существующие ручные привязки имеют приоритет. Кнопка «Сопоставить автоматически (точные имена)» заполняет пустые поля; любое предложение можно изменить или удалить. Порядок файлов и приблизительное сходство обозначений листов не используются.

После добавления локальных файлов ALTO/PAGE назначьте каждому выбранному канвасу соответствующий OCR-файл в последнем столбце. Совпадение имён не требуется. В текущей версии ручная привязка предполагает один OCR-файл на изображение.

При явном выборе режим «Все страницы» в диспетчере загрузок означает только выбранные для издания изображения, а «Страницы с ALTO/PAGE» дополнительно ограничивает загрузку изображениями с привязанными OCR. Для невыбранных канвасов не выполняется загрузка и не создаются новые TEI <surface>. Идентификаторы поверхностей основаны на исходных позициях канвасов в манифесте.

Существующие TEI-поверхности и уже загруженные изображения автоматически не удаляются: на них могут ссылаться редакторские данные. Проверьте неиспользуемые поверхности до удаления вручную. Новые локальные изображения и файлы ALTO/PAGE сортируются в естественном порядке (1r, 1v, 2r). К существующему списку можно применить «Естественная сортировка», сохраняя возможность менять порядок вручную.

Синхронизированные страницы и Canvas IIIF (0.8.5.6)

Для свидетеля с изображениями IIIF импортируйте JSON из Varians-Synchro и откройте Выбрать изображения и связать OCR…. Идентификаторы страниц и строк в JSON остаются неизменными; выбор IIIF определяет только нужные для издания изображения, даже если манифест содержит сотни Canvas.

Varians сопоставляет страницы по точному идентификатору Canvas, адресу сервиса IIIF Image, осторожно нормализованному URL изображения, достоверной связи с ALTO/PAGE либо однозначной метке листа. При полном совпадении имён файлов связь устанавливается автоматически. Если однозначной связи нет, выберите страницу JSON в столбце Синхронизированная страница вручную. Положение в списке никогда не считается доказательством идентичности. Ручные связи имеют приоритет и сохраняются в project.xml.

Столбцы Локальная копия и Состояние связи показывают наличие скачанного файла, основание сопоставления и предпочтительный источник изображения. Для работы без сети нужна локальная копия; иначе используется сервис IIIF. Неоднозначные совпадения не выбираются произвольно. Новые элементы surface в TEI создаются только для выбранных Canvas; существующие элементы автоматически не удаляются.

Подготовка пустой TEI-транскрипции по опорному списку

В окне создания проекта или в его настройках можно сформировать <pb/> для опорного свидетеля и, по желанию, <lb/>. <pb/> добавляются только для страниц, выбранных для издания: @facs ссылается на соответствующую <surface>, а @edRef обозначает список. Создаваемые <lb/> имеют @edRef, но не имеют @n и автоматических ссылок на области изображения. Число строк прежде всего берётся из однозначно сопоставленных ALTO/PAGE; при их отсутствии учитываются физические строки, действительно перечисленные в JSON синхронизации, даже если нумерация начинается с 41. Пропущенные строки отмечаются, но не выдумываются. Выбранная страница без перечисленных строк всё равно получает <pb/>. Предварительный просмотр, подтверждение и датированная резервная копия защищают текст; OCR-текст не вставляется.

Ссылки между документами

Атрибут-указатель (@ref, @corresp, @target, @who, @wit, @edRef, @sameAs, @ana, @resp, @source, @hand, @facs, @prev, @next, @synch, @copyOf) обозначает элемент по его @xml:id. Как и в стандартном TEI, а значит, для всех XML-инструментов, краткая форма #bernard обозначает элемент самого документа. Чтобы указать на другой документ проекта (см. Вспомогательные XML-документы), пишут personnes.xml#bernard, с путём относительно документа, содержащего ссылку. Веб-адреса (https://…) и значения без «#» не обрабатываются. Значение может содержать несколько указателей, разделённых пробелами: wit="#T1 #T2".

Ввод. В значении такого атрибута введите #: список идентификаторов откроется сам, с текстом каждой записи и её файлом, например «personnes.xml#bernard — Bernardus». Следующие буквы фильтруют список; Enter или Tab вставляет значение; Esc закрывает список. Для @wit и @edRef список предлагает свидетелей, описанных в TEI (<witness> в <listWit>). Ctrl+Space открывает те же значения в окне («Идентификаторы проекта»), где фильтр учитывает и описания: «Bern» находит personnes.xml#bernard. Предлагаемые идентификаторы зависят от элемента: persName/@ref предлагает person, personGrp и persona, placeName/@ref — place, orgName/@ref — org, @who — лица. В остальных случаях предлагаются все идентификаторы. В custom-elements.xml элемент <values source="ids" elements="person personGrp" prefix="#"/> задаёт этот список для атрибута. Идентификатор другого документа вставляется в виде файл.xml#id, идентификатор самого документа — в виде #id.

Переход. На ссылке нажмите F12, щёлкните с нажатой клавишей Ctrl или выберите Перейти к цели в контекстном меню: откроется документ, содержащий цель, и элемент будет выделен. Если идентификатор определён несколько раз, Varians спросит, какую цель показать. Alt+← (или Вернуться в контекстном меню) возвращает к исходному месту, даже из другого документа. Ненайденная цель отображается в строке состояния. Для краткой формы, цель которой находится только в другом документе, Varians тоже переходит к ней и указывает, какую форму написать.

Проверка. Кнопка Ссылки на панели инструментов проверяет ссылки во всех документах проекта. Панель, открывающаяся под исходным текстом, указывает их число и перечисляет проблемные: цель не найдена, краткая форма с целью в другом документе (с формой, которую нужно написать), неоднозначная цель (идентификатор определён несколько раз в целевом документе) или файл не найден, со столбцами «Документ», «Строка», «Атрибут», «Значение» и Проблема. Двойной щелчок ведёт к ссылке. После исправления Проверить снова повторяет проверку. Эта проверка — подсказка: она никогда не мешает сохранению и не изменяет файлы.

Отладка аппарата

Справка → Отладка аппарата… предлагает готовые запросы XPath для поиска ошибок в критическом аппарате отображаемого документа, закодированного методом parallel segmentation: каждый <app> объединяет свои чтения (<lem>, <rdg>, в том числе внутри <rdgGrp>), а @wit указывает свидетелей в виде #A. Свидетели — это свидетели из <listWit> документа.

  • Свидетель указан несколько раз: один и тот же свидетель встречается в двух чтениях одного <app> или дважды в одном @wit; его чтение неоднозначно.
  • Неполные <app>: у свидетеля нет чтения. Для <app> верхнего уровня ожидаются все свидетели из <listWit>, для вложенного <app> — свидетели содержащего его чтения. <lem> без @wit считается чтением свидетелей, отсутствующих в <rdg>: такой <app> не сообщается.
  • Заданный свидетель: <app>, в которых выбранный из списка свидетель встречается или не встречается в <lem> или <rdg> либо только в <rdg>.
  • Мои запросы: собственные именованные запросы XPath для проверок, свойственных вашей разметке. Добавить… предлагает текущий запрос панели XPath; Изменить… и Удалить управляют ими. Они сохраняются в project.xml (элемент <xpathQueries>) и переносятся вместе с проектом.

Найти выполняет запрос в панели XPath: щелчок по результату выделяет <app>. Запрос остаётся в поле XPath: это обычный XPath 1.0 с префиксом tei:, который можно скопировать в другие XML-инструменты. Он может быть длинным, так как содержит по одному условию на каждого свидетеля.

Ограничения: группы свидетелей (<listWit xml:id="…">, указанный в @wit) не раскрываются; свидетеля, указанного, но отсутствующего в <listWit>, сообщает кнопка Ссылки; если часть свидетелей из <listWit> не сличена в аппарате, все <app> выглядят неполными.

Проверка RELAX NG без ожидания

Начиная с версии 0.8.9.2 проверка RELAX NG выполняется в отдельном процессе, который Varians запускает при первой необходимости. При первой проверке после запуска компиляция большой схемы, например TEI_ALL, занимает около десяти секунд; всё это время окном можно пользоваться, а рядом с состоянием RNG: идёт проверка… в строке состояния вращается маленький огонёк. Скомпилированная схема затем сохраняется на весь сеанс, даже если открыть другой проект.

Автоматическая проверка (открытие, переключение документа, правка) никогда не прерывает работу. Проверить RNG (F8) и сохранение, напротив, ждут результата: окно продолжает отрисовываться, но щелчки и нажатия клавиш до ответа игнорируются. Поэтому сохранение во время первой компиляции дожидается её окончания, а затем, как обычно, предупреждает, если документ недействителен.

Если процесс проверки не удаётся запустить, Varians проверяет сам, как раньше, и один раз сообщает об этом в строке состояния; тогда окно может зависнуть во время компиляции. Загрузка удалённой схемы при самом первом её использовании по-прежнему выполняется в Varians.

Правила Schematron

Схема RELAX NG определяет, какие элементы и атрибуты допустимы и где. Правила Schematron проверяют то, что схема выразить не может: например, в TEI — что <lg> содержит хотя бы один стих или что @target и @cRef не используются вместе. Начиная с версии 0.9.2.3 Varians применяет их вместе с RNG: при открытии, во время ввода, по команде Проверить RNG (F8) и при сохранении, в том же отдельном процессе (см. Проверка RELAX NG без ожидания).

Какие правила. Сначала встроенные в используемую схему RELAX NG — объявлена ли она документом или выбрана в параметрах проекта: tei_all.rng содержит 91 группу правил, настройка ODD — свои. Затем правила каждого объявления Schematron в документе, указывающего на файл .sch или на RNG:

<?xml-model href="regles.sch" type="application/xml"
    schematypens="http://purl.oclc.org/dsdl/schematron"?>

Относительный адрес отсчитывается от документа; адрес http загружается один раз и затем хранится в кэше схем. Одни и те же правила никогда не проверяются дважды: объявление Schematron в документах TEI указывает на тот же tei_all.rng, что и их RNG. Новые проекты получают оба объявления. Для издания из частей правила, как и RNG, применяются к собранному изданию.

Схема XSD. Схема XSD, объявленная как Schematron (тот же schematypens), даёт правила, встроенные в её xs:appinfo, включая правила файлов, которые она включает или импортирует (xs:include, xs:import). Varians не проверяет документ по самой XSD.

Фазы. Файл Schematron может объединять свои группы правил (sch:pattern) в фазы (sch:phase). Без других указаний Varians проверяет фазу файла по умолчанию (defaultPhase), а если её нет — все его правила. Чтобы выбрать фазу, добавьте к объявлению стандартный атрибут phase, как в Oxygen:

<?xml-model href="regles.sch" type="application/xml"
    schematypens="http://purl.oclc.org/dsdl/schematron" phase="lecons"?>

#ALL проверяет все правила, #DEFAULT — фазу по умолчанию. Фаза, которой нет в файле, — ошибка в правилах (см. ниже); к ней прилагается список фаз файла. Без ручного написания объявления: щелчок по индикатору Schematron в строке состояния или кнопка Правила… панели проверки открывает окно Правила Schematron документа. Для каждого объявленного файла правил оно предлагает фазу в списке (фаза по умолчанию, все правила, фазы файла); оно также добавляет или удаляет объявление. Изменения записываются в объявления <?xml-model?> документа, и Ctrl+Z их отменяет.

Сообщения. Они добавляются к сообщениям RNG на панели Проверка RELAX NG и Schematron: в столбце Источник указано Schematron, а двойной щелчок ведёт к строке соответствующего элемента (для правила об атрибуте — к строке его элемента) в его документе. Уровень задаётся @severity, иначе @role: warning, warn или nonfatal дают Предупреждение, info — Информация, всё остальное — ошибку. Ошибка делает документ недействительным, как ошибка RELAX NG: имя вкладки становится оранжевым, а перед сохранением появляется вопрос Документ недействителен (Всё равно сохранить). Предупреждение или информация остаются в списке, не делая документ недействительным.

Строка состояния. Рядом с состоянием RNG надпись Schematron подводит итог: Schematron: ✓, число ошибок или сообщений либо Schematron: не проверяется, когда проверка для проекта отключена. Её подсказка называет файлы применённых правил и их фазу: «apparat.sch (фаза lecons)». Щелчок по индикатору открывает окно Правила Schematron документа.

Ошибки в правилах. Неверное выражение XPath, неизвестная фаза или файл правил, который не найден или сформирован некорректно, дают Schematron: ошибки в правилах. Каждое ошибочное правило занимает строку в панели, после сообщений документа: источник Schematron (правила), а в столбце Документ — файл правил. Двойной щелчок показывает этот файл на строке правила; файл из папки проекта, который ещё не является документом проекта, можно добавить (Varians это предлагает); файл вне проекта, например копия удалённого файла в кэше, не открывается, о чём сообщает строка состояния. Ошибка — в схеме: документ не становится недействительным, а остальные правила применяются. Когда файл правил изменён и сохранён, документ проверяется заново, как только вы к нему возвращаетесь.

Правила в Varians. Файл → XML-/XSLT-документы проекта… → Добавить XML-, XSLT- или Schematron-документ… принимает файлы .sch; файл вне проекта копируется в его папку xml/. Новый файл Schematron… создаёт минимальный файл (предлагается xml/regles.sch), который объявляет префикс tei и содержит правило-пример; затем добавьте его объявление в документ. Показанный файл Schematron проверяется вместо проверки RELAX NG: Проверить правила Schematron (F8), при показе, при наборе после первого использования F8 и при сохранении. Проверяется показанный текст, даже несохранённый: корректность XML, структура по схеме ISO Schematron (поставляется с Varians), включённые файлы, затем компиляция всех фаз в Saxon; каждая ошибка указывается на своей строке, и двойной щелчок ведёт к ней. Ctrl+Space и автоматический список атрибутов предлагают элементы и атрибуты Schematron с префиксом файла, а также обычные значения для severity, role и queryBinding. Документ проверяется по показанному тексту открытого файла правил, даже несохранённому: при возврате к документу после изменения правил он проверяется заново, и подсказка индикатора Schematron сообщает об этом («regles.sch, не сохранён»). То же относится к файлу, который он включает (sch:include, sch:extends), если он открыт и изменён: подсказка называет его («regles.sch (не сохранено: motifs.sch)»), и проверка файла правил учитывает его, снова при возврате к этому файлу. Новшества редакций стандарта 2020 и 2025 годов, которые применяет SchXslt2, принимаются и предлагаются автодополнением: sch:group, sch:rules, sch:library, sch:param на уровне схемы, @visit-each, @from и @when фаз.

Механизм. Varians использует SchXslt2 (David Maus, лицензия MIT), поставляемый вместе с ним, и Saxon (пакет saxonche, устанавливается файлом installer_dependances.bat, как и для сценариев преобразования). Без Saxon надпись показывает Schematron: нет Saxon, и выполняется только проверка RELAX NG. Правила подготавливаются при первой проверке менее чем за секунду, затем хранятся до конца сеанса и подготавливаются заново, если их файл изменился.

Ограничения. Правила вычисляются в XPath 3.1, каким бы ни был их queryBinding: правило, написанное для XPath 1.0, почти всегда ведёт себя так же. Для редакций 2020 и 2025 годов, схема которых не находится в свободном доступе, проверка файла .sch следует тому, что принимает SchXslt2. Старый Schematron 1.5 не поддерживается, как и проверка по XSD.

Проверка RELAX NG без ожидания. Результаты проверки, данные и формат project.xml не изменились.

Лакуны свидетелей

Отрывок, которого нет у свидетеля (утраченный лист, оборванный текст), в TEI заключается между <lacunaStart/> и <lacunaEnd/>. TEI помещает эти элементы в чтение: свидетель — это свидетель содержащего их <rdg> (или <lem>), а в чтении нескольких свидетелей — свидетель их собственного @wit:

<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaStart/></rdg></app>
…
<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaEnd/></rdg></app>

<rdg wit="#T2 #P">… <lacunaStart wit="#P"/></rdg>

Varians распознаёт эти элементы и вне чтения, с @wit, но проверка TEI отмечает их там как ошибки.

В панелях. Когда курсор находится в лакуне свидетеля, его панель сохраняет строку (для свидетеля, отслеживаемого по страницам, — страницу), на которой его текст обрывается, с плашкой «Лакуна этого свидетеля: его текст здесь обрывается.». Когда курсор находится в лакуне опорного свидетеля, свидетели, синхронизируемые по строкам, остаются на последней строке опорного свидетеля с плашкой «Лакуна опорного свидетеля: в этом отрывке строки не синхронизируются.»; об этом сообщает и строка состояния. Свидетели, отслеживаемые по страницам, продолжают следовать своим <pb>, которые от опорного свидетеля не зависят.

Отладка аппарата. Проверка «Неполные <app> (у свидетеля нет чтения)» не ожидает чтения от свидетеля внутри его лакуны.

Лакуна без <lacunaEnd/> длится до конца текста. В издании из частей лакуна может начаться в одной части и закончиться в другой; в тексте, синхронизируемом отдельно, учитываются только лакуны этого текста. Веб-просмотрщик показывает те же полосы.

Следовать рукописи в её собственном порядке

Стрелки ← и → каждой панели свидетеля ведут издание: свидетель продвигается вперёд или назад в своём собственном порядке, а курсор издания переходит к соответствующему месту, при необходимости показывая часть или текст, где оно находится. Остальные свидетели следуют за опорным, как при движении курсора. Когда показан вспомогательный документ, стрелки только листают свидетеля.

Свидетель, синхронизируемый по строкам. Панель переходит к следующей строке свидетеля; издание переходит к строке опорного свидетеля, на которую указывает эта строка. Строка, не связанная с опорным свидетелем, оставляет издание на предшествующей ей связанной строке, и строка состояния сообщает об этом. Кнопка ⤺ возвращает панель к строке, связанной со строкой опорного свидетеля.

Свидетель, отслеживаемый по страницам. Стрелки и список листов ведут издание к выбранной странице: к первой строке свидетеля на этой странице в одном из его JSON, иначе к концу его <pb edRef="#M" n="45v"/>, иначе к началу текста, для которого <locus from> свидетеля — эта страница. Без этих ориентиров издание не сдвигается, и строка состояния сообщает об этом.

От текста к тексту. В конце текста стрелки переходят к следующему тексту в рукописи — со сквозной нумерацией или синхронизируемому отдельно. Панель опорного свидетеля делает то же самое: опорный свидетель, общий для нескольких текстов, проходится целиком. Страница, на которой кончается один текст и начинается другой, остаётся на экране. Панель свидетеля, которого нет в показанном тексте («Для этого текста нет выравнивания этого свидетеля.»), своими стрелками ведёт к следующему или предыдущему тексту, где этот свидетель есть, в порядке издания.

Порядок текстов в рукописи. Varians выводит его из страниц свидетеля:

  • место страниц в объявленном списке изображений свидетеля (манифест IIIF или файлы, в Файл → Параметры проекта…);
  • иначе — общие страницы его JSON: каждый JSON уже идёт в порядке рукописи, а страница, на которой кончается один текст и начинается другой, связывает их;
  • иначе — <locus from> свидетеля для текста или фолиация первой страницы текста (число с r или v), сравнённая с фолиацией других страниц;
  • иначе текст сохраняет своё место в порядке издания, и Varians сообщает об этом.

Вид → Диагностика рукописей… показывает порядок текстов в каждой рукописи, присутствующей в нескольких текстах, и сообщает о неустановленном месте. Чтобы установить его надёжно, объявите изображения свидетеля или добавьте в его <witness> элемент <locus from="80r" target="#s04">.

Собранные издания (XInclude)

Как пошагово подготовить такой проект, описано в руководстве.

Издание может включать свои части, например по файлу на проповедь, по стандарту XInclude. Издание, объявленное в project.xml, остаётся главным документом; его части определяются по его элементам xi:include, без других объявлений:

<TEI xmlns="http://www.tei-c.org/ns/1.0"
     xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
    <xi:include href="sermons/s03.xml" xpointer="element(/1/2/1/1)"/>
  </body>

Часть — это либо фрагмент (весь файл, корнем которого служит, например, <div> проповеди), либо элемент полного документа TEI, указанный через xpointer: его идентификатором (s02 или element(s02)) или путём (element(/1/2/1/1): TEI, затем его 2-й дочерний элемент text, затем body, затем первый div). Часть сама может включать другие части. Относительные пути, записанные в части, отсчитываются от папки этой части.

Части и вкладки

У каждой части своя вкладка, названная по имени её файла, после вкладки издания и в порядке включения. Часть редактируется и сохраняется отдельно (Ctrl+S), со своей историей отмены; перед выходом Varians предлагает сохранить изменённые части. Список частей перечитывается при каждом сохранении издания или части. «Переименовать вкладку…» и «Исключить документ из проекта» относятся только к вспомогательным документам. Представление XSLT / CSS остаётся открытым при показе части: оно показывает всё издание (см. Представление XSLT / CSS собранного издания); свидетели тоже остаются на экране (см. ниже). Сохранение издания в другую папку нарушило бы пути его элементов xi:include: Varians заранее предупреждает об этом.

Проверка

Издание и каждая его часть запускают проверку собранного издания — по схеме издания и с учётом несохранённых изменений частей. Панель RELAX NG тогда добавляет столбец Документ; двойной щелчок по ошибке открывает нужную часть на нужной строке. Вкладка каждой части окрашивается по её собственным ошибкам. Отсутствующая или неправильно сформированная часть, циклическое включение или неподдерживаемая форма (parse="text", xi:fallback, другая схема xpointer) отмечаются на строке соответствующего xi:include.

Ссылки и свидетели

Издание и его части образуют единый документ: #id сначала ищется в файле, где он записан (включая заголовок), затем в других частях. F12, команда Ссылки и автодополнение учитывают это. К собранному изданию относятся только идентификаторы включённого элемента части: свидетель, объявленный лишь в <teiHeader> проповеди, включённой через xpointer, находится Varians в этой проповеди, но инструмент, читающий только собранное издание, его не увидит. В части команда Справка → Отладка аппарата… использует собственных свидетелей части: её <listWit>, иначе свидетелей издания, чей <locus target="#s01"> указывает на часть, иначе свидетелей, указанных в её @wit.

Синхронизация свидетелей

Если издание разделено на файлы лишь для удобства (собрание, тексты которого идут в том же порядке, что и в опорном свидетеле), свидетели синхронизируются так же, как для издания в одном файле: строки опорного свидетеля (<lb edRef="#A"/>) считаются в порядке собранного издания, от одной части к другой, а файлы выравнивания остаются прежними — по одному на свидетеля для всего издания. Курсор издания или части ведёт за собой свидетелей; щелчок или прокрутка в опорном свидетеле переносят курсор в часть, содержащую строку, и открывают её вкладку, даже после «Скрыть вкладку». Состояние структуры (строка состояния) считает строки опорного свидетеля во всём собранном издании, а при сохранении издания или части Varians предупреждает, если это число отличается от выравнивания опорного свидетеля. <lb/> в комментарии или вне включённого элемента части не учитывается, как и в других XML-инструментах.

Условие: опорный свидетель должен содержать эти тексты в порядке издания. Varians проверяет число строк, а не их порядок. Другие свидетели могут иметь иной порядок или не содержать какого-то текста: их выравнивание уже указывает на строки опорного свидетеля. Свидетель, синхронизируемый по страницам, следует последнему относящемуся к нему <pb> в порядке издания, даже в предыдущей части: если у этого свидетеля тексты идут в другом порядке, отметьте его страницу в начале каждого текста.

В части «Отметить страницу» вставляет <pb> в часть, в позицию курсора, и дополняет <facsimile> издания; «Разворот…» записывает свои зоны в <facsimile> издания. Издание при этом изменяется, не будучи показанным: на его вкладке появляется «*». Отмена в части удаляет <pb>, но не добавленное в <facsimile>.

Тексты, синхронизируемые отдельно

В корпусе, тексты которого передаются разными свидетелями и в разном порядке, текст может иметь собственные выравнивания: по одному JSON на свидетеля, в обычном формате, в папке, названной по имени файла текста без расширения (alignments/s02/B.json для xml/sermons/s02.xml). Ничего объявлять не нужно: текст, у которого есть своя папка, синхронизируется отдельно; остальные следуют сквозной нумерации. Опорный свидетель текста — опорный свидетель проекта, кроме исключения, объявленного в project.xml: <part name="s02" base="B"/>.

Когда такой текст показан, панели свидетелей переходят на его выравнивания и его опорного свидетеля; расположение, масштаб и отдельные окна не меняются. Свидетель без JSON для этого текста сохраняет свою панель, где написано «Для этого текста нет выравнивания этого свидетеля.». Строки считаются только в этом тексте (например, «B: 8 строк ✓»); щелчок в опорном свидетеле остаётся в тексте. Диагностика свидетелей и обновление синхронизации относятся к показанному тексту.

Свидетели, отслеживаемые по страницам. Свидетель, у которого нет JSON для этого текста, но который этот текст содержит — <pb edRef="#C"/> в тексте или <locus target="#s04"> в его <witness> из <listWit>, — следует там своим страницам. До своего первого <pb> в тексте он показывает начальную страницу: @from этого locus (<locus from="13r" to="14r" target="#s04">), иначе страницу, предшествующую странице этого первого <pb>, в порядке страниц свидетеля. Там работает и «Отметить страницу». Диагностика свидетелей называет для каждого текста его свидетелей, отслеживаемых по страницам. Остальные свидетели без JSON сохраняют сообщение об отсутствии.

Представление XSLT / CSS собранного издания

Представление XSLT / CSS показывает всё издание вместе с частями, какой бы документ ни был показан, и используется так же, как для издания в одном файле. Переход от издания к части не закрывает его; закрывает его только показ вспомогательного документа.

  • Редактирование фрагментов. Карандаш ✎ абзаца открывает его в редакторе фрагмента в том виде, в каком он записан в содержащем его файле; подпись называет этот файл, например «Фрагмент TEI · абзац 7/12 · s03.xml». Применённый фрагмент записывается в этот файл, даже если он не показан или ни разу не открывался: его вкладка тогда помечена «*», а одна отмена в части убирает изменение. Файл должен оставаться правильно сформированным. Ctrl+S в редакторе фрагмента сохраняет этот файл, затем показанный документ, если он изменён; перед выходом Varians предлагает сохранить неприменённый фрагмент вместе с его файлом.
  • Щелчок, оглавление, поиск. Щелчок по строке ставит курсор на эту строку в содержащем её файле, вкладка которого открывается, не покидая предпросмотра; свидетели следуют, с собственной нумерацией текста, синхронизируемого отдельно. Оглавление и поиск в предпросмотре работают так же.
  • Выделение. Строка, выделенная в предпросмотре, при возврате на вкладку Исходный XML выделяется в файле, который содержит текст (в части или в издании), на том же вхождении в том же абзаце; без выделения курсор переходит к показанной строке. И наоборот, выделение или позиция в части находится в предпросмотре. Между предпросмотром и редактором фрагмента выделения соответствуют друг другу, как для издания в одном файле.
  • Ограничения. Абзац, который сам содержит xi:include, редактируется в файле своего тега; включённый текст редактируется в своей части. Как и для издания в одном файле, абзац или строка, которые XSLT не выводит, сдвигают следующие за ними карандаши или метки строк.

Веб-экспорт собранного издания

Создать веб-просмотрщик экспортирует всё издание вместе с частями, сохраняя те же связи, что и в окне.

  • Текст и строки. Текст частей входит в просмотрщик, а строки пивота считаются в нём от одной части к другой, как в окне. Текст, синхронизируемый отдельно, сохраняет свой пивот и свои JSON (alignments/s02/): когда выбранная строка переходит в него, каждая панель показывает своего свидетеля в этом тексте — его строки, его страницы начиная с начальной страницы или сообщение «Для этого текста нет выравнивания этого свидетеля.» Масштаб и рамки каждой панели сохраняются от текста к тексту. Кнопки заголовка проходят по всем строкам в порядке чтения, от одного текста к другому.
  • Стрелки панелей. Как в окне, стрелки ← → любой панели ведут текст в собственном порядке рукописи, от одной части или текста к другому, как и список листов свидетеля, отслеживаемого по страницам; ⤺ возвращает панель к связанной строке. Сообщения строки состояния окна (начало или конец рукописи, несвязанная строка, неопределённая страница, неясное место) показываются под заголовком просмотрщика.
  • Лакуны. Полосы те же, что и в окне (см. Лакуны свидетелей): лакуна продолжается от одной части к другой, а текст, синхронизируемый отдельно, начинается без лакуны.
  • Сохранение. Экспорт читает сохранённые файлы: сначала Varians сохраняет издание, каждую изменённую часть и неприменённый фрагмент части; если что-либо из этого сохранить не удаётся, экспорт отменяется. Ненайденная часть или неподдерживаемое включение (parse="text", xi:fallback) указываются в отчёте об экспорте: соответствующий текст в просмотрщике отсутствует.
  • Ограничения. Учитывается положение фрагмента текста, по которому щёлкнули. <pb> или <lb>, помещённый в непринятое чтение или в примечание, просмотрщик не видит. «Диагностика рукописей…», «Обновить синхронизацию…», «Отметить страницу» и «Разворот…» остаются принадлежностью окна. После изменения издания создайте просмотрщик заново.

Ограничения этой версии

Порядок текстов в рукописи выводится из её страниц; текст, который не удаётся к ним привязать, сохраняет своё место в порядке издания (см. Следовать рукописи в её собственном порядке). У веб-экспорта свои ограничения: см. Веб-экспорт собранного издания. Проекта без xi:include это не касается.

Подготовка издания из частей (XInclude): руководство

Это руководство пошагово описывает, как организовать проект, издание которого разделено на несколько файлов, например по файлу на каждую проповедь. Подробности о каждой функции — в разделе Собранные издания (XInclude).

1. Упорядочить файлы

Оставьте один файл издания — тот, который объявлен в project.xml (например, xml/edition.xml): это главный документ с заголовком, списком свидетелей и порядком текстов. Поместите тексты в соседнюю папку, по файлу на текст. Дайте каждому файлу имя, уникальное во всём проекте: это имя без расширения служит и именем папки выравниваний текста, синхронизируемого отдельно (шаг 4). Пути относительны к содержащему их файлу: sermons/s01.xml из издания, ../personnes.xml#augustinus из проповеди.

project.xml
alignments/T1.json, T2.json …
alignments/s02/B.json, D.json
xml/edition.xml
xml/sermons/s01.xml, s02.xml, s03.xml …

2. Написать xi:include

Объявите пространство имён XInclude на корневом элементе издания и поставьте xi:include на место каждого текста:

<TEI xmlns="http://www.tei-c.org/ns/1.0" xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
  </body>
</TEI>

Текст — это либо фрагмент: весь файл, корень которого — включаемый элемент с пространством имён TEI (<div xmlns="http://www.tei-c.org/ns/1.0" xml:id="s01">); либо полный документ TEI, из которого включается один элемент — по идентификатору (xpointer="s02") или по пути (xpointer="element(/1/2/1/1)"). Полный документ можно проверять и отдельно; его заголовок в издание не входит. Текст может сам включать другой. Не используйте parse="text" и xi:fallback: Varians сообщает о них, но не поддерживает. Сохраните издание: каждый текст получит свою вкладку.

3. Объявить свидетелей

Объявите каждую рукопись один раз, в Файл → Параметры проекта…, с общим для всего собрания сиглом. В TEI объявляйте свидетелей в <listWit> издания, в <listWit> каждого текста (полного документа TEI) или в обоих. Свидетеля, объявленного только в заголовке текста, включённого через xpointer, Varians находит, но инструмент, читающий только собранное издание, его не видит.

4. Выбрать синхронизацию каждого текста

  • Тексты идут так же, как в опорном свидетеле, с теми же свидетелями (собрание, разделённое для удобства): сквозная нумерация. По одному JSON на свидетеля для всего издания, как для издания в одном файле, объявленному в параметрах проекта. Строки опорного свидетеля считаются от текста к тексту в порядке издания; опорный свидетель должен содержать тексты в этом порядке.
  • Свидетели меняются от текста к тексту (корпус): текст, синхронизируемый отдельно. Создайте папку alignments/<имя файла текста>/ и поместите в неё по одному JSON на свидетеля для этого текста, в обычном формате: alignments/s02/B.json, alignments/s02/D.json. Создайте эти JSON программой VariansSynchro по файлу текста. Ничего объявлять не нужно: достаточно папки. Свидетель без JSON для этого текста, но со своими <pb edRef> в нём или с <locus target> в своём <witness>, следует там своим страницам: см. Тексты, синхронизируемые отдельно.
  • Оба способа можно сочетать: тексты со своей папкой синхронизируются отдельно; остальные следуют сквозной нумерации, и глобальный JSON каждого свидетеля содержит только их строки.

5. Объявить собственного опорного свидетеля текста

Опорный свидетель текста, синхронизируемого отдельно, — опорный свидетель проекта. Если в нём нет этого текста или опорой должен служить другой свидетель, впишите исключение вручную в project.xml, перед </teiManuscriptProject>, затем снова откройте проект:

<parts>
  <part name="s02" base="B"/>
</parts>

name — имя файла текста без расширения; base — сигл опорного свидетеля. Строками этого текста становятся его <lb edRef="#B"/>, а в его папке должен быть B.json. Varians сохраняет этот элемент при сохранении параметров проекта.

6. Проверить

  • Покажите каждый текст: состояние структуры в строке состояния должно быть верным, например «B: 8 строк ✓»; всплывающая подсказка говорит, относится ли счёт к собранному изданию или к тексту, синхронизируемому отдельно.
  • Вид → Диагностика рукописей… показывает охват (издание или показанный текст), тексты, синхронизируемые отдельно, с их опорным свидетелем и свидетелями, и проблемы: JSON необъявленного свидетеля, неизвестный опорный свидетель, отсутствующий JSON опорного свидетеля…
  • Проверка RELAX NG относится к собранному изданию; столбец «Документ» указывает файл каждой ошибки.
  • Команда Ссылки проверяет ссылки между текстами.
  • Другой XML-инструмент собирает проект без Varians: xmllint --xinclude --noout xml/edition.xml или oXygen с включённым XInclude в настройках валидатора.
  • Вид → Диагностика рукописей… показывает также порядок текстов в каждой рукописи и сообщает о неустановленном месте: см. Следовать рукописи в её собственном порядке.

7. В повседневной работе

  • Каждый текст редактируется в своей вкладке и сохраняется отдельно (Ctrl+S); перед выходом Varians предлагает сохранить изменённые тексты.
  • Чтобы добавить текст: создайте его файл, добавьте его xi:include в издание, сохраните издание; появится его вкладка. Для текста, синхронизируемого отдельно, добавьте и его папку выравниваний, затем Вид → Обновить синхронизацию….
  • Если вкладок много: щелчок правой кнопкой по вкладке → Скрыть вкладку; щелчок в опорном свидетеле снова покажет вкладку нужного текста.
  • Сохранение издания в другую папку нарушило бы его xi:include: Varians заранее предупреждает об этом.
  • Представление XSLT / CSS показывает всё издание: карандаш ✎ открывает в нём абзац любого текста, а щелчок ведёт к тексту, который содержит строку; см. Представление XSLT / CSS собранного издания. Веб-экспорт содержит всё издание; см. Веб-экспорт собранного издания.
  • Чтобы читать рукопись от текста к тексту, пользуйтесь стрелками её панели: издание покажет нужный текст.

Сценарии преобразования XSLT

Сценарий преобразования применяет таблицу стилей XSLT к изданию или к другому документу проекта и записывает результат в файл: HTML-издание, указатель, список цитат, преобразованный XML… У сценария есть название, он сохраняется в проекте и повторяется в точности. Веб-просмотрщик остаётся отдельной публикацией, которую сценарий не меняет.

Файл → Сценарии преобразования… показывает две группы:

  • Сценарии проекта, сохраняемые в project.xml (элемент <transformations>): ими управляют Добавить…, Изменить…, Дублировать… и Удалить.
  • Готовые сценарии, поставляемые с Varians: пока это HTML-издание (таблица стилей Varians), который публикует издание с таблицей стилей и CSS предпросмотра Varians в publications/edition.html. Его можно выполнить как есть или продублировать в проект, чтобы изменить.

В каждой строке указаны источник, процессор и красным — то, что мешает выполнить сценарий (таблица стилей не найдена, Saxon не установлен…). Выполнить выполняет выбранный сценарий; Предпросмотр выполняет его во временной папке и открывает результат, не трогая файл сценария.

Сценарий

  • Источник: Издание (издание проекта, собранное, если у него есть части: каждая часть сохраняет своё место, и относительный document() находит там свои файлы), Открытый документ (документ текущей вкладки, например вспомогательный документ, см. Вспомогательные XML-документы; собранное издание, если это оно) или Файл (файл, читаемый как есть).
  • Процессор: XSLT 1.0 (lxml) или XSLT 3.0 (Saxon) для таблиц стилей на XSLT 2.0 или 3.0. Saxon-HE (пакет saxonche) устанавливается вместе с Varians: installer_dependances.bat или pip install -r requirements.txt.
  • Таблица XSLT и необязательный CSS: пути относительно проекта; ${varians}/ обозначает таблицы стилей, поставляемые с Varians. CSS копируется рядом с результатом, а его имя передаётся таблице стилей в параметре css (таблица Varians вставляет его в свой <link>). Новый сценарий предлагает таблицу стилей и CSS предпросмотра.
  • Результат: записываемый файл, заменяемый при каждом выполнении (предлагается publications/<название>.html). Им не может быть исходный файл проекта (project.xml, издание и его части, документ, таблица стилей, схема, JSON выравнивания). С Saxon таблица стилей может записывать другие файлы через xsl:result-document (например, по странице на каждую проповедь), но только в папке результата и её подпапках; в ином месте выполнение отклоняется.
  • Параметры: пары название / значение, передаваемые таблице стилей как строки (<xsl:param name="title"/>).

Выполнение

Кнопка Преобразовать рядом с Создать веб-просмотрщик снова выполняет последний сценарий, выполненный в проекте (также Ctrl+Shift+T); её стрелка показывает список сценариев. Перед выполнением Varians сохраняет то, что читает сценарий: издание, его изменённые части и непримененный фрагмент, как при веб-экспорте, а также исходный документ, таблицу стилей и CSS, если они открыты и изменены. Преобразование идёт в отдельном процессе: Varians остаётся доступным, а Отменить останавливает его.

Отчёт указывает записанные файлы и длительность; Открыть открывает результат в приложении по умолчанию (в браузере для HTML), Открыть папку — папку, в которой он лежит. В подробностях — журнал: процессор и версия, параметры, xsl:message, чтение из сети (с lxml), отклонённые записи. При ошибке сообщение указывает соответствующий файл и строку, а прежний результат остаётся нетронутым.

Безопасность: таблица стилей может читать любой локальный файл, а также адреса http или https (тогда результат может зависеть от сервера); записывает она только свой результат (а с Saxon — файлы в его папке). Внешние сущности источников не читаются.

Редактирование таблицы стилей XSLT

Таблица стилей XSLT — это XML-документ: Varians открывает её как документ проекта, на отдельной вкладке (см. Вспомогательные XML-документы), проверяет её и помогает её писать, без внешних инструментов.

  • Добавление таблицы стилей: Файл → XML-/XSLT-документы проекта… → Добавить XML-, XSLT- или Schematron-документ… принимает файлы .xsl и .xslt. Таблица стилей вне папки проекта копируется в неё, в папку xslt/ (рядом с xml/), никогда не заменяя существующий файл; таблица стилей, уже находящаяся в проекте, остаётся на своём месте.
  • Новая таблица стилей XSLT… (то же меню) создаёт минимальную таблицу стилей, в XSLT 1.0 (lxml) или в XSLT 3.0 (Saxon), предлагаемую в xslt/: объявленное пространство имён TEI, вывод HTML, шаблон для корня документа.
  • Из сценариев (см. Сценарии преобразования XSLT): Открыть таблицу стилей, в списке сценариев или в окне сценария (который при этом сохраняется), показывает таблицу стилей сценария проекта. Таблица стилей, поставляемая с Varians (${varians}/…), сначала копируется в xslt/; таблицу стилей вне проекта тоже можно скопировать или открыть без копирования. После копирования сценарий использует копию. Для предопределённого сценария сначала используйте Дублировать….

Проверка. Для таблицы стилей Проверить таблицу стилей XSLT (F8, вместо Проверить RNG) компилирует её, не выполняя, движком сценариев проекта, которые её используют (обоими, если они разные); таблица стилей, которую не использует ни один сценарий, проверяется по своей версии: version="1.0" — с помощью lxml, другая — с помощью Saxon. Как и при проверке RELAX NG, таблица стилей проверяется при первом показе, после каждого изменения, если F8 уже использовалась, и при сохранении, которое при ошибках просит подтверждения. Панель проверки показывает каждую ошибку с её строкой; двойной щелчок ведёт к ней. Ошибка в импортированной (xsl:import) или включённой (xsl:include) таблице стилей указывает её файл в столбце «Документ», и двойной щелчок ведёт к этой таблице, если она входит в проект. Строка состояния показывает результат, а вкладка таблицы стилей окрашивается как вкладка недействительного документа.

Автодополнение. Ctrl+Space предлагает элементы и атрибуты XSLT, допустимые в этом месте, с префиксом таблицы стилей (xsl:), а список атрибутов открывается при наборе. Внутри элемента результата (<div>, <tei:p>…) это инструкции XSLT и атрибуты xsl:*. Таблица стилей с version="1.0" получает только элементы и атрибуты XSLT 1.0. Предложения берутся из схемы RELAX NG для XSLT 3.0 консорциума W3C, поставляемой с Varians (лицензия BSD); пользовательские элементы проекта (custom-elements.xml) в таблице стилей не предлагаются.

Сопутствующие файлы. Varians копирует только саму таблицу стилей. Файлы, нужные ей для полного результата (таблицы стилей, импортируемые через xsl:import или включаемые через xsl:include, изображения, CSS, JavaScript…), нужно самостоятельно поместить в папку xslt/ проекта, сохраняя относительные пути, которые использует таблица стилей. Проверка сообщает о ненайденной импортированной или включённой таблице стилей. CSS сценария, напротив, копируется автоматически рядом с результатом.

Ограничения: таблица стилей, предназначенная для импорта или включения, проверяется отдельно, и её ссылки на объявления основной таблицы стилей могут быть отмечены как ошибки; таблица стилей XSLT 2.0 получает предложения XSLT 3.0; имена, объявленные в таблице стилей (шаблоны, режимы, ключи), и выражения XPath не дополняются.

TEI Stylesheets: готовые сценарии и настройка

TEI Stylesheets — это таблицы стилей XSLT консорциума TEI (github.com/TEIC/Stylesheets), которые используют также Oxygen и другие инструменты. Varians поставляет их и устанавливает при первом использовании, один раз для всех проектов, в папку данных пользователя: они работают без сети. Они написаны на XSLT 3.0: их сценарии используют Saxon.

Готовые сценарии. Файл → Сценарии преобразования… предлагает, помимо HTML-издания Varians, четыре сценария, публикующих издание (собранное, если оно состоит из частей): TEI: HTML, TEI: текст, TEI: Markdown и TEI: LaTeX. Их результаты записываются в publications/tei/ (edition.html, edition.txt, edition.md, edition.tex). Рядом с HTML кладётся CSS из TEI Stylesheets (tei.css), без ссылок на сайт TEI-C; тексты, которые добавляют таблицы стилей («Содержание»…), следуют языку интерфейса через параметры lang и documentationLanguage. В сценарии ${tei}/ обозначает файл установленных TEI Stylesheets, например ${tei}/profiles/default/html/to.xsl; см. Сценарии преобразования XSLT. Журнал выполнения называет использованную версию («Библиотека: TEI Stylesheets 7.61.0»).

Настройка таблицы стилей. TEI Stylesheets не изменяют: их переопределяют в таблице стилей проекта. Продублируйте сценарий TEI (Дублировать…), затем выберите копию и нажмите Открыть таблицу стилей: Varians предложит создать в xslt/ таблицу настройки, например xslt/tei-html.xsl (Создать таблицу настройки), которую затем будет использовать сценарий. Она импортирует (xsl:import) таблицу TEI-C по её официальному адресу, http://www.tei-c.org/release/xml/tei/stylesheet/…, который Varians читает из установленных TEI Stylesheets без сети; Oxygen поступает так же, и таблица остаётся в нём действительной. Параметры (xsl:param) и шаблоны (xsl:template), которые вы в ней пишете, имеют приоритет над импортированными; всё остальное берётся из TEI Stylesheets. Например:

<xsl:stylesheet version="3.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:tei="http://www.tei-c.org/ns/1.0" xmlns="http://www.w3.org/1999/xhtml"
    exclude-result-prefixes="#all">
  <xsl:import href="http://www.tei-c.org/release/xml/tei/stylesheet/profiles/default/html/to.xsl"/>
  <!-- Без нумерации заголовков. -->
  <xsl:param name="numberHeadings">false</xsl:param>
  <!-- Имена людей полужирным. -->
  <xsl:template match="tei:persName"><b><xsl:apply-templates/></b></xsl:template>
</xsl:stylesheet>

Для вывода в HTML xmlns="http://www.w3.org/1999/xhtml" делает добавленные элементы (здесь <b>) элементами XHTML, как и элементы TEI Stylesheets. Таблица настройки редактируется, проверяется (F8) и дополняется, как любая таблица стилей: см. Редактирование таблицы стилей XSLT. Обновление TEI Stylesheets её не затрагивает: она продолжает применяться.

Обновления. TEI-C выпускает около двух версий в год. При запуске Varians не чаще раза в месяц, не блокируя окно, проверяет, вышла ли новая версия; если её нет или нет сети, ничего не сообщается. Иначе он предлагает её установить: Установить или Позже (вопрос вернётся при следующей проверке). Установка показывает ход выполнения, её можно отменить; неверный архив или отмена оставляют установленную версию. Новая версия используется со следующего преобразования во всех проектах; старая удаляется при следующем запуске. Файл → TEI Stylesheets… или кнопка TEI Stylesheets… в списке сценариев показывает установленную версию, её источник, папку, лицензию и дату последней проверки; Проверить обновление проверяет сразу. Установлена только одна версия: публикация, сделанная заново после обновления, может отличаться от предыдущей; журнал называет версию.

Лицензия. Консорциум TEI распространяет TEI Stylesheets на выбор по лицензии BSD с двумя пунктами или по лицензии CC BY-SA 3.0; файл LICENCE устанавливается вместе с ними (Показать лицензию).

Ограничения. DOCX, ODT и EPUB, для которых нужно собирать архив, а также HTML из нескольких файлов появятся позже. LaTeX компилируется в PDF установленным TeX (xelatex) вне Varians. В тексте и в Markdown TEI Stylesheets пишут лемму и разночтение подряд: таблица настройки может изменить этот выбор TEI-C.

Версия 0.9.1.0 — синхронизация свидетелей между частями

Для издания, собранного через XInclude, свидетели снова синхронизируются: строки опорного свидетеля считаются в порядке собранного издания, курсор части ведёт за собой свидетелей, а опорный свидетель открывает часть, содержащую строку; свидетели остаются на экране при показе части, где доступны «Отметить страницу» и «Разворот…»; см. Собранные издания (XInclude). Проект без xi:include, его данные и формат project.xml не меняются.

Версия 0.9.1.1 — тексты, синхронизируемые отдельно

В издании из частей текст, у которого есть своя папка выравниваний (alignments/s02/, по одному JSON на свидетеля), синхронизируется отдельно, со своим опорным свидетелем, если его объявляет project.xml (<part name="s02" base="B"/>); свидетель без JSON для этого текста сообщает об этом в своей панели. Руководство описывает подготовку издания из частей: см. Подготовка издания из частей. Проект без папок для отдельных текстов не меняется.

Версия 0.9.1.2 — общее выделение в предпросмотре и редакторе фрагмента

В представлении XSLT / CSS карандаш ✎ открывает абзац в редакторе фрагмента, не сдвигая изображения свидетелей. Строка, выделенная в предпросмотре, выделяется в открытом редакторе фрагмента, и наоборот: см. Редактирование XML и предпросмотр XSLT/CSS. Перенос выделения между исходным XML и предпросмотром не изменился (издание без частей). Лакуны, свидетели, синхронизируемые по страницам, в тексте, синхронизируемом отдельно, и проход по рукописи в её собственном порядке появятся в версии 0.9.1.3.

Версия 0.9.1.3 — лакуны, свидетели по страницам в тексте, синхронизируемом отдельно

Лакуны свидетелей (<lacunaStart/> … <lacunaEnd/>) распознаются: панель свидетеля в лакуне сохраняет строку или страницу, на которой обрывается его текст, с плашкой; во время лакуны опорного свидетеля строки не синхронизируются; см. Лакуны свидетелей. В тексте, синхронизируемом отдельно, свидетель, который содержит текст, но не имеет для него JSON, следует там своим страницам, начиная со своей начальной страницы (<locus from>). Проход по рукописи в её собственном порядке появится в версии 0.9.1.4.

Версия 0.9.1.4 — следовать рукописи в её собственном порядке

Теперь издание ведут стрелки любой панели свидетеля, а не только опорного: свидетель отслеживается в своём собственном порядке, от части или текста к следующему, в том числе свидетель, отслеживаемый по страницам (стрелки и список листов); опорный свидетель переходит от текста, синхронизируемого отдельно, к следующему. Порядок текстов в каждой рукописи выводится из её страниц и показан в «Диагностике рукописей…»; см. Следовать рукописи в её собственном порядке. Листать свидетеля, не сдвигая издание, теперь можно только пока показан вспомогательный документ.

Версия 0.9.1.5 — представление XSLT / CSS собранного издания

В издании из частей представление XSLT / CSS больше не только для чтения: карандаш ✎ открывает абзац в содержащем его файле и записывает туда применённый фрагмент, щелчок по строке ведёт в нужный файл, и свидетели следуют за ним, а выделение переходит из предпросмотра в часть, которая содержит текст, и обратно; см. Представление XSLT / CSS собранного издания. Предпросмотр остаётся открытым при показе части. Веб-экспорт собранного издания появится в одной из следующих версий. Издание в одном файле не меняется.

Версия 0.9.1.6 — веб-экспорт собранного издания

Веб-просмотрщик издания из частей теперь содержит всё издание с теми же связями, что и в окне: текст частей, сквозную нумерацию строк, тексты, синхронизируемые отдельно, лакуны и путь каждой рукописи в её собственном порядке; см. Веб-экспорт собранного издания. Перед экспортом издание, его изменённые части и неприменённый фрагмент части сохраняются без дополнительных вопросов. И для издания в одном файле стрелки любой панели и список листов теперь ведут текст, а лакуны отмечаются полосами; см. Веб-просмотрщик. Чтобы воспользоваться этим, создайте просмотрщик заново.

Версия 0.9.1.7 — вкладки документов

Вкладка отображаемого документа теперь отчётливо выделяется среди других: белый фон, синяя линия сверху, название полужирным; остальные вкладки отступают на более тёмном фоне. Цвет неправильно сформированного (красный) или недействительного (оранжевый) документа остаётся видимым, даже на текущей вкладке; см. Вспомогательные XML-документы.

Версия 0.9.2.0 — сценарии преобразования XSLT
