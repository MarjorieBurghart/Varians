Varians — редактор TEI XML для текстологии

Varians — XML-редактор для критического издания текстов, дошедших в рукописях или старых печатных изданиях и закодированных в TEI. Он объединяет в одном интерфейсе транскрипцию, изображения свидетелей и представление для чтения, а также позволяет преобразовать издание в веб-формат.

1. Обзор

Что позволяет делать Varians

  • Редактировать TEI. XML-редактор, который дополняет элементы и атрибуты по схеме, помогает при разметке, ищет в тексте (регулярные выражения, XPath), следует ссылкам между документами, сворачивает элементы и расставляет отступы, не повреждая текст.
  • Проверять XML. RELAX NG и правила Schematron — во время набора, без зависания окна.
  • Читать то, что редактируете. Представление XSLT / CSS показывает оформленное издание; каждый блок открывается из него для исправления в редакторе фрагмента. Вкладка Исходный XML, открытая по умолчанию, всегда даёт доступ к исходному XML-коду.
  • Видеть рукописи. Изображения каждого свидетеля (локальные файлы или IIIF), а при наличии и их строки (ALTO, PAGE XML), сопоставляются с транскрипцией постранично или построчно, в зависимости от имеющихся данных.
  • Проверять аппарат. Готовые запросы находят частые ошибки критического аппарата (например, пропущенный или лишний свидетель); лакуны свидетелей распознаются.
  • Публиковать. Автономный веб-просмотрщик, в котором текст и факсимиле остаются синхронизированными; критическое издание в HTML с аппаратом; DOCX, ODT, EPUB, HTML, LaTeX… с помощью TEI Stylesheets, поставляемых с Varians; и любая таблица стилей XSLT по вашему выбору.

Чем он отличается от XML-редактора общего назначения

XML-редактор общего назначения обрабатывает любой XML-документ одинаково. Varians исходит из работы издателя текстов:

  • Рукописи рядом с текстом. У каждого свидетеля своя панель. Когда курсор перемещается в транскрипции, каждая панель показывает соответствующую страницу или строку своей рукописи. И наоборот, издание можно читать в порядке конкретной рукописи: стрелки её панели ведут издание к соответствующему месту.
  • Опорный свидетель. Синхронизация основана на строках свидетеля-ориентира, называемого здесь опорным; каждый другой свидетель может визуально сопоставить свои строки со строками опорного ещё до начала транскрипции. Выбор опорного свидетеля технический, он нужен для выравнивания: он ничего не предрешает ни о стемме, ни о том, какая рукопись будет выбрана основной.
  • Аппарат в центре. Дополнение @wit по списку свидетелей, проверки аппарата, лакуны, а при публикации — выбор между установленным текстом и транскрипцией конкретного свидетеля; чтения, которые пока не взяты из <lem>, можно выделить.
  • Представление для чтения, которое можно редактировать. Издание исправляется там, где его читают, блок за блоком, не теряя места в XML.
  • Издание, которое может состоять из нескольких файлов (по файлу на текст, собранных через XInclude), обрабатывается как единый документ: проверка, ссылки, синхронизация свидетелей, публикация.
  • Встроенная веб-публикация. Веб-просмотрщик, настраиваемая таблица XSLT, следующая принятым правилам оформления критического издания, и форматы TEI Stylesheets доступны в Varians без сервера и без сети.
  • Стандартный TEI. Varians записывает в ваши файлы только обычный TEI (<pb/>, <lb/>, <facsimile>…). То, что касается только проекта (свидетели, изображения, выравнивания, сценарии), хранится в отдельном файле project.xml; ваши настройки отображения остаются на вашем компьютере. Любой другой XML-инструмент может прочитать ваше издание.
  • Осторожность. Varians не угадывает: сомнительное соответствие между строкой и изображением, неоднозначное закрытие тега, ненайденная страница никогда не выдумываются, а сообщаются. При важных записях сохраняется копия .bak.
  • Семь языков интерфейса: французский, английский, немецкий, японский, чешский, итальянский и русский (Вид → Язык).

Чего Varians не делает

  • Он сам не выравнивает строки рукописей: файлы выравнивания (JSON) создаются отдельной программой Varians-Synchro.
  • Он не распознаёт строки на изображениях (сегментация): строки ALTO или PAGE XML создаются программой распознавания (eScriptorium, Transkribus, PERO OCR…).
  • Он не сличает тексты: аппарат кодируете в TEI вы сами; Varians помогает его вводить и проверять.
  • Это не текстовый процессор: редактируется XML; представление XSLT / CSS служит для чтения и для исправления одного блока за раз.

2. Быстрый старт

Этот маршрут ведёт от пустой папки к первой публикации. Каждый шаг отсылает к главе, где он описан подробно.

  1. Установка и запуск. Varians требует Python 3 и трёх библиотек (PySide6, lxml и Saxon). В Windows один раз выполните installer_dependances.bat, затем запускайте Varians файлом lancer_editeur.bat. В других системах: pip install -r requirements.txt, затем python editeur_tei.py.
  2. Создание проекта. Файл → Новый проект…: выберите пустую папку, затем в поле Исходная точка — Начать с существующего издания TEI (ваш файл копируется в проект) или Начать новую транскрипцию (Varians создаёт минимальный TEI). См. Проекты.
  3. Объявление свидетелей. В разделе Свидетели и ресурсы добавьте каждую рукопись кнопкой Добавить… и заполните поля Сигла, Отображаемое название и Источник изображений (на выбор: пока без изображений, локальные изображения или манифест IIIF). Назначьте опорного свидетеля: Назначить опорным свидетелем. Остальное можно сделать позже. См. Основные понятия и Свидетели и факсимиле.
  4. Транскрипция и разметка. На вкладке Исходный XML Ctrl+E оборачивает выделение в элемент, Ctrl+Space дополняет имя элемента или атрибута, F8 проверяет документ. На вкладке Представление XSLT / CSS щёлкните карандаш ✎ блока или выделите отрывок, который нужно изменить, и нажмите F2, чтобы открыть этот отрывок в редакторе фрагмента; Применить к XML обновляет исходный текст. См. Редактирование XML и Проверка.
  5. Связь текста с изображениями. Поставьте курсор в тексте в начало страницы (например, л. 1v) свидетеля (например, A1) и нажмите Отметить страницу в панели этого свидетеля: Varians вставит <pb n="1v" edRef="#A1" facs="#A1-p0002"/>. Теперь панель следует за текстом постранично. Чтобы она следовала за ним построчно, укажите файл выравнивания (JSON) свидетеля в Файл → Параметры проекта…. См. Свидетели и факсимиле.
  6. Кодирование и проверка аппарата. В @wit введите #, чтобы выбрать свидетеля из списка. Справка → Отладка аппарата… находит свидетелей без чтения или указанных дважды. См. Критический аппарат.
  7. Вычитка. Вкладка Представление XSLT / CSS показывает оформленное издание; карандаш ✎ открывает блок для исправления. См. Представление XSLT / CSS и редактор фрагмента.
  8. Веб-формат. Создать веб-просмотрщик создаёт в web_output/ автономный сайт с синхронизированными текстом и изображениями. Кнопка Преобразовать выполняет сценарий: Критическое издание (HTML), TEI: DOCX (Word)… См. Веб-просмотрщик и Публикация с помощью XSLT.
  9. Сохранение. Ctrl+S сохраняет отображаемый документ; перед выходом или сменой проекта Varians предлагает сохранить каждый изменённый документ.

3. Основные понятия

Проект

Проект — это папка, содержащая файл project.xml. В нём указаны издание, его свидетели и их ресурсы (изображения, строки, выравнивания), таблица стилей предпросмотра, сценарии публикации. Само издание — это файл TEI xml/edition.xml, который можно разделить на части (см. Издания из частей). К нему могут добавляться другие документы: авторитетные записи, примечания, таблицы стилей XSLT, правила Schematron.

Три вида данных — три места хранения. То, что относится к тексту, находится в TEI: страницы, строки, аппарат, факсимиле. То, что относится к проекту, — в project.xml: свидетели, изображения, выравнивания, сценарии, сохранённые запросы. Ваши рабочие настройки (показываемые свидетели и их расположение, видимые вкладки…) остаются на вашем компьютере, отдельно для каждого проекта, и не изменяют ни одного файла проекта.

Свидетели, сиглы и опорный свидетель

Свидетель — это рукопись или печатное издание, передающее текст. Его сигла (A, T1, P…) обозначает его повсюду. В TEI это идентификатор его <witness> в <listWit>, на который ссылаются @wit (в аппарате) и @edRef (страницы и строки этого свидетеля); см. Сигла и идентификатор свидетеля.

Опорный свидетель — точка отсчёта синхронизации: его строки (<lb edRef="#A"/>) задают границы в тексте, и каждый другой свидетель связывает свои строки со строками опорного. Этот выбор технический: он ничего не предрешает ни о месте свидетеля в стемме, ни о том, какая рукопись будет принята в издании за основную. В издании из частей у части может быть свой опорный свидетель.

Отслеживание свидетеля по страницам или по строкам

Панель свидетеля следует за транскрипцией одним из двух способов:

  • по страницам: <pb edRef="#B" .../> отмечает в транскрипции начало каждой страницы свидетеля B; панель показывает страницу последнего <pb> свидетеля B перед курсором. Достаточно изображений и элементов <pb> с правильным @edRef;
  • по строкам: файл выравнивания (JSON), созданный Varians-Synchro, связывает каждую строку рукописи, найденную на изображении с помощью ALTO или PAGE XML, со строкой опорного свидетеля. Тогда панель показывает соответствующую строку, кадрированную. Чтобы видеть издание сопоставленным с изображениями рукописей, нужно вставить <lb/> опорного свидетеля, и только его: остальные свидетели выравниваются по ним, а их собственные <lb/> в издание не вставляются.

У каждого свидетеля свой режим: в одном издании одни свидетели могут отслеживаться по строкам, другие — по страницам. У третьих может ещё не быть цифровых изображений.

Критический аппарат

Varians ожидает аппарат, закодированный методом parallel segmentation: каждое место разночтения в тексте — это <app>, объединяющий принятое чтение (<lem>) и разночтения (<rdg>), каждое со свидетелями, которые его передают:

<app><lem wit="#A">dixit</lem><rdg wit="#B #C">ait</rdg></app>

В работе над изданием естественно действовать поэтапно: часто сначала разночтения фиксируют нейтрально, чтобы позже, когда сложится более ясное представление о традиции, решить, что принять в качестве леммы:

<app><rdg wit="#A">dixit</rdg><rdg wit="#B #C">ait</rdg></app>

Varians позволяет видеть результат работы ещё до того, как выбраны все леммы. Так, установленный текст сценария Критическое издание (HTML) и веб-просмотрщика составляется прежде всего из <lem>; там, где их нет, — из чтения выбранного свидетеля, по умолчанию опорного. И то и другое может выделять жёлтым чтения, взятые не из <lem>, — те, по которым решение ещё не принято (см. Выбор текста и Критическое издание).

4. Проекты

Создание, открытие, закрытие

При первом запуске Varians не открывает ни одного проекта; в дальнейшем он снова открывает тот, который был открыт при закрытии. Меню Файл предлагает Новый проект… (Ctrl+N), Открыть проект… (Ctrl+O) и Открыть недавний проект…. Файл → Закрыть проект (Ctrl+W) возвращает на начальный экран, не выходя из Varians; закрытый проект не открывается при следующем запуске.

Новый проект… запрашивает пустую папку, затем в поле Исходная точка предлагает Начать с существующего издания TEI (его файл копируется в xml/edition.xml) или Начать новую транскрипцию: Varians создаёт минимальный TEI с <listWit> свидетелей проекта.

<listWit>
  <witness xml:id="A1">Assisi, Sacro convento, 541</witness>
</listWit>

Свидетеля можно объявить без изображений, без ALTO и без синхронизации: эти ресурсы при необходимости добавляются позже, в любом порядке, в Файл → Параметры проекта…. В том же окне задаются схема RELAX NG (определяемая по <?xml-model?> документа, выбранная в проекте или никакая), таблица стилей XSLT и CSS предпросмотра, настройка Ctrl+E (custom-elements.xml), папка и имя файла веб-просмотрщика.

Структура проекта

project.xml        проект
xml/edition.xml    издание (его части и другие XML-документы — рядом)
xslt/              таблицы стилей XSLT проекта
images/  alto/     локальные изображения, строки ALTO или PAGE XML, скопированные в проект
alignments/        файлы выравнивания (JSON)
iiif/local/        локальные копии изображений IIIF
rendering/         CSS предпросмотра, custom-elements.xml
i18n/              переводы интерфейса
publications/      результаты сценариев преобразования
web_output/        веб-просмотрщик

Папка i18n/ проекта содержит копию переводов интерфейса, которая имеет приоритет над переводами Varians: чтобы перейти на тексты новой версии Varians, замените её файлы файлами из папки i18n/ Varians.

Сигла и идентификатор свидетеля. Сигла свидетеля, введённая в Файл → Параметры проекта…, служит и его XML-идентификатором: xml:id его <witness>, целью @wit и @edRef. XML-идентификатор начинается с буквы или «_» и не содержит пробелов и знаков вроде «/» или «:». Если введённая сигла не соответствует этим правилам («1760», «T 2»), Varians выводит из неё допустимый идентификатор, который показан под полем: каждый недопустимый символ становится «_», а перед сиглой, начинающейся не с буквы, добавляется «_»; из «1760» получается _1760, из «T 2» — T_2. В TEI тогда пишут wit="#_1760". Сигла остаётся тем, что Varians показывает везде, где называет свидетеля; она хранится в project.xml (атрибут siglum элемента <witness>) и, в TEI, созданном вместе с проектом, в <idno type="siglum">:

<witness xml:id="_1760"><idno type="siglum">1760</idno>Troyes, BM, ms. 1760</witness>

Таблицы стилей, поставляемые с Varians (предпросмотр, Критическое издание, аппарат в сносках), и веб-просмотрщик показывают эту сиглу вместо идентификатора. Свидетель, добавленный позже в Файл → Параметры проекта…, получает <witness> того же вида в конце <listWit> издания, если она есть: Varians её не создаёт. Окно, подтверждающее сохранение параметров, сообщает, что было добавлено. Две сиглы, дающие один и тот же идентификатор («T 2» и «T/2»), не могут сосуществовать.

Подготовка пустой транскрипции по опорному свидетелю

Чтобы начать транскрипцию, Varians может заранее расставить страницы (<pb/>) и строки (<lb/>) опорного свидетеля. В Файл → Новый проект… (с вариантом Начать новую транскрипцию) или в Файл → Параметры проекта… блок Подготовка транскрипции опорного свидетеля предлагает Создать метки <pb/> опорного свидетеля в пустом TEI, а затем Также создать метки <lb/> по ALTO, PAGE или данным синхронизации.

<pb/> получают только страницы, выбранные для издания: его @facs указывает на <surface>, его @edRef — на свидетеля. У <lb/> есть только @edRef. Varians берёт строки ALTO или PAGE, однозначно связанные со страницей, иначе строки, описанные в файле выравнивания: фрагмент листа со строками с 41-й по 68-ю даёт 28 <lb/>. Страница без известных строк всё равно получает свой <pb/>; пропуски отмечаются, но никогда не заполняются. Предпросмотр, подтверждение и датированная резервная копия защищают текст; автоматическая транскрипция не импортируется.

Документы проекта и вкладки

Помимо издания, проект может включать другие XML-документы: файл авторитетных записей (лица, места), примечания и т. д. Используйте Файл → XML-/XSLT-документы проекта…. Добавить XML-, XSLT- или Schematron-документ… включает в проект существующий файл; файл, находящийся вне папки проекта, копируется в неё, в xml/, никогда не заменяя существующий файл. Новый XML-документ… создаёт пустой документ с выбранным вами корневым элементом. Исключить документ из проекта исключает отображаемый документ, не удаляя его файл.

Как только появляется вспомогательный документ, над исходным XML отображается ряд вкладок: Издание, затем по одной вкладке на каждый документ. Каждый документ сохраняет собственную историю отмены, позицию и состояние; звёздочка обозначает несохранённые изменения, а цвет названия — неправильно сформированный или недействительный XML. Проверка RELAX NG и автодополнение следуют <?xml-model?> отображаемого документа. Рукописи, представление XSLT / CSS и команды свидетелей относятся только к изданию: они скрываются, пока отображается другой документ, а затем восстанавливаются без изменений. Ctrl+S сохраняет отображаемый документ; перед выходом или сменой проекта Varians предлагает сохранить все изменённые документы. Веб-экспорт использует только издание.

Отображаемые вкладки. Команда Вид → Выбрать отображаемые документы… позволяет выбрать, у каких документов есть вкладка, и порядок вкладок. Щелчок правой кнопкой по вкладке предлагает Скрыть вкладку, Переименовать вкладку…, Выбрать отображаемые документы… и Исключить документ из проекта для документа этой вкладки, даже если он не отображается. Скрытый документ остаётся в проекте: его изменения сохраняются, и перед выходом Varians предлагает их записать. Его вкладка снова появляется, когда к нему ведёт ссылка (F12, Ctrl+щелчок, двойной щелчок в панели Ссылки). Последнюю видимую вкладку скрыть нельзя; при открытии проекта отображается издание вместе со своей вкладкой. Этот выбор сохраняется локально для проекта и не изменяет project.xml. Имя, заданное командой Переименовать вкладку…, напротив, записывается в атрибут label элемента <document> в project.xml; пустое имя восстанавливает имя файла. Когда вкладки больше не помещаются в ряд, справа от него появляется стрелка ▾ («Все вкладки»): она раскрывает список всех вкладок, в котором отмечена вкладка отображаемого документа; щелчок показывает выбранный документ. Список заканчивается командой Выбрать отображаемые документы….

Документы объявляются в project.xml элементом <documents>.

Сохранение

Файл → Сохранить издание (Ctrl+S) сохраняет отображаемый документ: издание, одну из его частей или другой документ проекта. Сохранить издание как… (Ctrl+Shift+S) записывает его в другое место. Перед выходом или сменой проекта Varians предлагает сохранить каждый изменённый документ. Неправильно сформированный или недействительный документ можно сохранить после подтверждения.

Важные записи выполняются атомарной заменой и сохраняют копию .bak. Когда автоматическая операция была бы неоднозначной, Varians воздерживается от неё, а не переписывает TEI молча.

5. Редактирование XML

Редактор

Вкладка Исходный XML (Ctrl+1) показывает отображаемый документ, вкладка Представление XSLT / CSS (Ctrl+2) — оформленное издание (см. Представление XSLT / CSS и редактор фрагмента). Переносить длинные строки визуально — чисто визуальная функция: она не меняет ни XML, ни нумерацию строк.

Парные теги. Когда курсор находится в открывающем или закрывающем теге, оба тега пары подсвечиваются светло-голубым — как из <app>, так и из </app> — с учётом вложенности, префиксов (tei:div) и пустых элементов; комментарии, CDATA и инструкции обработки пар не образуют. Переименование открывающего тега переименовывает его закрывающий тег; удаление всего открывающего тега убирает закрывающий, сохраняя содержимое. Перекрёстная или неоднозначная разметка не даёт пары.

Закрывающие теги. И в редакторе XML, и в редакторе фрагмента при вводе </ предлагается закрыть ближайший открытый элемент: после <div><p>…</p></ Varians предлагает div>; Enter или Tab вставляет его. Можно также начать имя, например </di. Esc закрывает список, Ctrl+Space открывает его снова. Пустые элементы (<lb/>), комментарии, CDATA и незавершённые атрибуты не учитываются; при неоднозначной вложенности закрывающий тег не подбирается наугад.

Сворачивание. Вид → Сворачивание XML: Свернуть / развернуть элемент (Ctrl+Alt+F), Свернуть структурные элементы, Развернуть всё (Ctrl+Alt+Shift+F); значки ▾ / ▸ на поле сворачивают или разворачивают элемент. Сворачиваются только элементы, занимающие несколько строк, у которых теги стоят на отдельных строках. Сворачивание не меняет ни XML, ни историю отмены; изменение текста разворачивает всё, а курсор, переведённый на скрытую строку, делает её видимой.

Отступы. Правка → Расставить отступы в XML осторожно расставляет отступы в структурных областях документа:

  • вокруг <lb/> пробелы не добавляются;
  • xml:space="preserve" соблюдается;
  • смешанное или неоднозначное содержимое не затрагивается;
  • элемент, который по схеме допускает текст, обрабатывается как текст.

В custom-elements.xml можно указать formatting="inline", formatting="block" или formatting="preserve"; описанные выше меры защиты имеют приоритет.

Помощь при разметке

Ctrl+E оборачивает выделение в элемент или вставляет новый элемент в позицию курсора. В списке элемент выделяется, только когда вы его выбираете (щелчком, стрелками или клавишей Tab / ↓ из поля, которые выбирают первый): Enter вставляет выделенный элемент, иначе текст, введённый в поле; новый ввод в поле отменяет выбор. Элементы, которые схема RELAX NG допускает в этом месте, предлагаются первыми.

Ctrl+Space дополняет имена элементов и атрибутов, а также некоторые значения атрибутов, в том числе имя элемента, набранное непосредственно перед другим тегом (<h перед </p>). Предложения берутся из схемы RELAX NG, из файла custom-elements.xml или из обоих, и их источник указывается. В открывающем теге начало допустимого атрибута само открывает отфильтрованный список; Enter или Tab вставляет атрибут вместе с кавычками.

В атрибуте-указателе, например @wit, ввод # открывает список свидетелей или идентификаторов проекта (см. Ссылки между документами); Varians дополняет список значений, разделённых пробелами, не предлагая повторно уже имеющиеся.

Настройка Ctrl+E. Файл → Настройка Ctrl+E… открывает файл custom-elements.xml проекта: элементы, предлагаемые по Ctrl+E, атрибуты и значения, предлагаемые по Ctrl+Space (источник witnesses даёт свидетелей проекта в виде #A1, #B1…), правила отступов. Этот файл помогает при вводе; он никогда не меняет действительность документа. Его формат описан в CUSTOM_ELEMENTS.md.

Словарь. Ctrl+? (или Справка → Словарь латинского языка) ищет выделенный текст в латинском словаре Vocabula, в браузере.

Ссылки между документами

Атрибут-указатель (@ref, @corresp, @target, @who, @wit, @edRef, @sameAs, @ana, @resp, @source, @hand, @facs, @prev, @next, @synch, @copyOf) обозначает элемент по его @xml:id. Как и в стандартном TEI, а значит, для всех XML-инструментов, краткая форма #bernard обозначает элемент самого документа. Чтобы указать на другой документ проекта (см. Вспомогательные XML-документы), пишут personnes.xml#bernard, с путём относительно документа, содержащего ссылку. Веб-адреса (https://…) и значения без «#» не обрабатываются. Значение может содержать несколько указателей, разделённых пробелами: wit="#T1 #T2".

Ввод. В значении такого атрибута введите #: список идентификаторов откроется сам, с текстом каждой записи и её файлом, например «personnes.xml#bernard — Bernardus». Следующие буквы фильтруют список; Enter или Tab вставляет значение; Esc закрывает список. Для @wit и @edRef список предлагает свидетелей, описанных в TEI (<witness> в <listWit>). Ctrl+Space открывает те же значения в окне («Идентификаторы проекта»), где фильтр учитывает и описания: «Bern» находит personnes.xml#bernard. Предлагаемые идентификаторы зависят от элемента: persName/@ref предлагает person, personGrp и persona, placeName/@ref — place, orgName/@ref — org, @who — лица. В остальных случаях предлагаются все идентификаторы. В custom-elements.xml элемент <values source="ids" elements="person personGrp" prefix="#"/> задаёт этот список для атрибута. Идентификатор другого документа вставляется в виде файл.xml#id, идентификатор самого документа — в виде #id.

Переход. На ссылке нажмите F12, щёлкните с нажатой клавишей Ctrl или выберите Перейти к цели в контекстном меню: откроется документ, содержащий цель, и элемент будет выделен. Если идентификатор определён несколько раз, Varians спросит, какую цель показать. Alt+← (или Вернуться в контекстном меню) возвращает к исходному месту, даже из другого документа. Ненайденная цель отображается в строке состояния. Для краткой формы, цель которой находится только в другом документе, Varians тоже переходит к ней и указывает, какую форму написать.

Проверка. Команда Правка → Ссылки проверяет ссылки во всех документах проекта. Панель, открывающаяся под исходным текстом, указывает их число и перечисляет проблемные: цель не найдена, краткая форма с целью в другом документе (с формой, которую нужно написать), неоднозначная цель (идентификатор определён несколько раз в целевом документе) или файл не найден, со столбцами «Документ», «Строка», «Атрибут», «Значение» и Проблема. Двойной щелчок ведёт к ссылке. После исправления Проверить снова повторяет проверку. Эта проверка — подсказка: она никогда не мешает сохранению и не изменяет файлы.

Поиск и замена

Меню Поиск объединяет поиск в XML и во фрагменте; поиску XPath посвящён отдельный раздел.

  • Простой поиск (Ctrl+F): поле панели инструментов для XML, панель поиска фрагмента, когда фокус во фрагменте; F3 и Shift+F3 переходят к следующему или предыдущему совпадению.
  • Показать все (Поиск → Показать все совпадения, Ctrl+Shift+L), кнопка рядом с полем поиска: панель под редактором перечисляет все совпадения поиска в XML с теми же параметрами (регистр, регулярные выражения). В каждой строке — номер строки и совпадение в контексте, выделенное и расположенное по центру между предшествующим и последующим текстом (представление KWIC). Щелчок ведёт к совпадению. Если отмечен флажок Весь проект, список охватывает все документы проекта, со столбцом «Документ»; щелчок по совпадению в другом документе показывает этот документ. Открытая панель следует за новыми поисками, параметрами, изменениями текста и отображаемым документом; свыше 2 000 совпадений выводятся только первые. × закрывает её.
  • Учитывать регистр и Регулярные выражения: два флажка меню Поиск, которые повторяют кнопки Aa и .* рядом с полями поиска. Они действуют для XML и фрагмента (поиск в Представление XSLT / CSS остаётся буквальным) и сохраняются от сеанса к сеансу. Регулярные выражения — это выражения Python (модуль re): ^ и $ относятся к каждой строке, \b обозначает границу слова; неверное выражение сообщается в строке состояния.
  • Найти и заменить (Ctrl+H) открывает панель под редактором XML или, если фокус во фрагменте, строку Заменить на под его поиском. Заменить заменяет выделенное совпадение и переходит к следующему; Заменить все заменяет во всём документе (или во всём фрагменте) и отменяется одним Ctrl+Z. Искомый текст берётся как введён, включая пробелы. Заменяется найденное, и ничего больше: замена открывающего тега не переименовывает и не удаляет его закрывающий тег. Esc закрывает панель.
  • С регулярным выражением текст замены может использовать группы в скобках: \1, \2… или \g<имя> для именованной группы (?P<имя>…); \n начинает новую строку. Примеры: wit="#(\w+)", заменённое на wit="#\1 #T3", добавляет T3 к каждому чтению одного свидетеля; <(rdg|lem)\b находит оба элемента; <lb n="\d+"/> находит пронумерованные разрывы строк.
  • Поиск XPath (Ctrl+Shift+F): см. Поиск XPath. Его открывает также кнопка XPath на панели инструментов.
  • Поиск в справке: в этом окне справки поле вверху (Ctrl+F) ищет по всей справке без учёта диакритики и регистра; несколько слов — разделы, которые содержат их все, в любом порядке; в кавычках — точное выражение ("заменить все"). Слева — список найденных разделов с отрывком; щелчок ведёт к разделу. Совпадения выделены; Enter, F3 и Shift+F3 или ◀ ▶ переходят по ним.

Поиск XPath

Поиск → Поиск XPath (кнопка XPath, Ctrl+Shift+F) открывает панель под редактором: выражение XPath 1.0 выполняет в ней поиск по отображаемому документу, например //note для элементов <note>. В TEI, использующем стандартное пространство имён, простой запрос без префикса повторяется с префиксом tei:.

В результатах указаны строка, элемент, его путь и отрывок. Щелчок по результату выделяет весь элемент, от открывающего до закрывающего тега, даже если он занимает несколько строк; выделение сохраняется при переходе в представление XSLT / CSS и восстанавливается при возврате к исходному тексту. Выражение, возвращающее значение, например count(//tei:note), показывает это значение.

Для проверки критического аппарата команда Справка → Отладка аппарата… предлагает готовые запросы: см. Отладка аппарата.

6. Проверка

Varians проверяет отображаемый документ по его схеме RELAX NG и правилам Schematron. Таблица стилей XSLT или файл правил Schematron, когда они отображаются, тоже проверяются: см. Редактирование таблицы стилей XSLT и Правила Schematron.

Проверка RELAX NG

Схема документа — та, которую объявляет его <?xml-model?>, или та, которую задаёт Файл → Параметры проекта… (там же проверку можно отключить). Varians проверяет документ при открытии, при сохранении и по запросу: Проверить RNG (F8). Ошибки перечисляются в панели Проверка RELAX NG и Schematron под редактором, с уровнем, строкой и столбцом; двойной щелчок ведёт к ошибке. После того как эта панель была использована, проверка повторяется сама после короткой паузы в наборе, а исправленная ошибка исчезает из списка. Строка состояния подводит итог; имя вкладки неправильно сформированного документа окрашивается красным, недействительного — оранжевым.

Удалённая схема (адрес http) загружается при первом использовании, затем хранится в кэше схем; кнопка панели Обновить удалённую схему и проверить снова загружает её заново.

Без зависания окна. Проверка выполняется в отдельном процессе, который Varians запускает при первой необходимости. Первая компиляция большой схемы, например TEI_ALL, занимает около десяти секунд; всё это время окном можно пользоваться, а рядом с состоянием RNG: идёт проверка… в строке состояния вращается маленький огонёк. Скомпилированная схема затем сохраняется на весь сеанс, даже если открыть другой проект. Автоматическая проверка никогда не прерывает работу; Проверить RNG (F8) и сохранение, напротив, ждут результата: окно продолжает отображаться, но щелчки и нажатия клавиш до ответа игнорируются. Если процесс проверки не удаётся запустить, Varians проверяет сам и сообщает об этом в строке состояния; тогда окно может зависнуть во время компиляции.

Правила Schematron

Схема RELAX NG определяет, какие элементы и атрибуты допустимы и где. Правила Schematron проверяют то, что схема выразить не может: например, в TEI — что <lg> содержит хотя бы один стих или что @target и @cRef не используются вместе. Varians применяет их вместе с RNG: при открытии, во время набора, по команде Проверить RNG (F8) и при сохранении, в том же отдельном процессе (см. Проверка RELAX NG).

Какие правила. Сначала правила, встроенные в используемую схему RELAX NG, — объявлена ли она документом или выбрана в параметрах проекта: tei_all.rng содержит 91 группу правил, настройка ODD — свои. Затем правила каждого объявления Schematron в документе, указывающего на файл .sch или на RNG:

<?xml-model href="regles.sch" type="application/xml"
    schematypens="http://purl.oclc.org/dsdl/schematron"?>

Относительный адрес отсчитывается от документа; адрес http загружается один раз и затем хранится в кэше схем. Одни и те же правила никогда не проверяются дважды: объявление Schematron в документах TEI указывает на тот же tei_all.rng, что и их RNG. Новые проекты получают оба объявления. Для издания из частей правила, как и RNG, применяются к собранному изданию.

Схема XSD. Схема XSD, объявленная как Schematron (тот же schematypens), даёт правила, встроенные в её xs:appinfo, включая правила файлов, которые она включает или импортирует (xs:include, xs:import). Varians не проверяет документ по самой XSD.

Фазы. Файл Schematron может объединять свои группы правил (sch:pattern) в фазы (sch:phase). Без других указаний Varians проверяет фазу файла по умолчанию (defaultPhase), а если её нет — все его правила. Чтобы выбрать фазу, добавьте к объявлению стандартный атрибут phase, как в Oxygen:

<?xml-model href="regles.sch" type="application/xml"
    schematypens="http://purl.oclc.org/dsdl/schematron" phase="lecons"?>

#ALL проверяет все правила, #DEFAULT — фазу по умолчанию. Фаза, которой нет в файле, — ошибка в правилах (см. ниже); к сообщению прилагается список фаз файла. Объявление не обязательно писать вручную: щелчок по индикатору Schematron в строке состояния или кнопка Правила… панели проверки открывает окно Правила Schematron документа. Для каждого объявленного файла правил оно предлагает фазу в списке (фаза по умолчанию, все правила, фазы файла); оно также добавляет или удаляет объявление. Изменения записываются в объявления <?xml-model?> документа, и Ctrl+Z их отменяет.

Сообщения. Они добавляются к сообщениям RNG на панели Проверка RELAX NG и Schematron: в столбце Источник указано Schematron, а двойной щелчок ведёт к строке соответствующего элемента (для правила об атрибуте — к строке его элемента) в его документе. Уровень задаётся @severity, иначе @role: warning, warn или nonfatal дают Предупреждение, info — Информация, всё остальное — ошибку. Ошибка делает документ недействительным, как ошибка RELAX NG: имя вкладки становится оранжевым, а перед сохранением появляется вопрос Документ недействителен (Всё равно сохранить). Предупреждение или информация остаются в списке, не делая документ недействительным.

Строка состояния. Рядом с состоянием RNG индикатор Schematron подводит итог: Schematron: ✓, число ошибок или сообщений либо Schematron: не проверяется, когда проверка для проекта отключена. Его подсказка называет файлы применённых правил и их фазу: «apparat.sch (фаза lecons)». Щелчок по индикатору открывает окно Правила Schematron документа.

Ошибки в правилах. Неверное выражение XPath, неизвестная фаза или файл правил, который не найден или неправильно сформирован, дают Schematron: ошибки в правилах. Каждое ошибочное правило занимает строку в панели, после сообщений документа: источник Schematron (правила), а в столбце Документ — файл правил. Двойной щелчок показывает этот файл на строке правила; файл из папки проекта, который ещё не является документом проекта, можно добавить в проект (Varians это предлагает); файл вне проекта, например копия удалённого файла в кэше, не открывается, о чём сообщает строка состояния. Ошибка — в схеме: документ не становится недействительным, а остальные правила применяются. Когда файл правил изменён и сохранён, документ проверяется заново, как только вы к нему возвращаетесь.

Написание правил в Varians. Файл → XML-/XSLT-документы проекта… → Добавить XML-, XSLT- или Schematron-документ… принимает файлы .sch; файл вне проекта копируется в его папку xml/. Новый файл Schematron… создаёт минимальный файл (предлагается xml/regles.sch), который объявляет префикс tei и содержит правило-пример; затем добавьте его объявление в документ. Отображаемый файл Schematron проверяется вместо проверки RELAX NG: Проверить правила Schematron (F8), при показе, во время набора после первого использования F8 и при сохранении. Проверяется отображаемый текст, даже несохранённый: правильность формирования, структура по схеме ISO Schematron (поставляется с Varians), включённые файлы, затем компиляция всех фаз в Saxon; каждая ошибка указывается на своей строке, и двойной щелчок ведёт к ней. Ctrl+Space и автоматический список атрибутов предлагают элементы и атрибуты Schematron с префиксом файла, а также обычные значения для severity, role и queryBinding. Документ проверяется по отображаемому тексту открытого файла правил, даже несохранённому: при возврате к документу после изменения его правил он проверяется заново, и подсказка индикатора Schematron сообщает об этом («regles.sch, не сохранён»). То же относится к файлу, который он включает (sch:include, sch:extends), если тот открыт и изменён: подсказка называет его («regles.sch (не сохранено: motifs.sch)»), а проверка файла правил учитывает его — снова при возврате к этому файлу. Новшества редакций стандарта 2020 и 2025 годов, которые применяет SchXslt2, принимаются и предлагаются автодополнением: sch:group, sch:rules, sch:library, sch:param на уровне схемы, @visit-each, @from и @when фаз.

Механизм. Varians использует SchXslt2 (David Maus, лицензия MIT), поставляемый вместе с ним, и Saxon (пакет saxonche, устанавливается файлом installer_dependances.bat, как и для сценариев преобразования). Без Saxon индикатор показывает Schematron: нет Saxon, и выполняется только проверка RELAX NG. Правила подготавливаются при первой проверке менее чем за секунду, затем хранятся до конца сеанса и подготавливаются заново, если их файл изменился.

Ограничения. Правила вычисляются в XPath 3.1, каким бы ни был их queryBinding: правило, написанное для XPath 1.0, почти всегда ведёт себя так же. Для редакций 2020 и 2025 годов, схема которых не находится в свободном доступе, проверка файла .sch следует тому, что принимает SchXslt2. Старый Schematron 1.5 не поддерживается, как и проверка по XSD.

7. Представление XSLT / CSS и редактор фрагмента

Предпросмотр

Вкладка Представление XSLT / CSS показывает издание, оформленное таблицей стилей XSLT и CSS: таблицами Varians или проекта (Файл → Параметры проекта…, Источник XSLT: XSLT редактора по умолчанию, который обновляется вместе с Varians, или Пользовательский XSLT — файл проекта); строка Оформление представления позволяет попробовать другую таблицу стилей XSLT или CSS. Предпросмотр обновляется, когда вы возвращаетесь к нему после изменения; Автоматический предпросмотр обновляет его при каждой паузе в наборе, Обновить — по запросу; Размер увеличивает или уменьшает текст. Оглавление даёт доступ к озаглавленным разделам; поле Поиск в предпросмотре ищет в нём слово или выражение.

Щелчок по тексту предпросмотра ставит курсор исходного текста в то же место, и свидетели следуют за ним. Строка, выделенная в предпросмотре, выделяется в исходном тексте при возврате на вкладку Исходный XML, на том же вхождении того же отрывка (даже слово, разделённое <lb break="no"/>); и наоборот, выделение в исходном тексте, например результат XPath, находится в предпросмотре. Возврат к исходному тексту без изменения выделения в предпросмотре восстанавливает прежнее выделение.

Преобразование может читать локальные файлы (например, файл авторитетных записей), но не может ни записывать файлы, ни обращаться к сети. Ошибка таблицы стилей сообщается как есть, с указанием её файла и строки.

Редактор фрагмента

Карандаш ✎ в начале блока предпросмотра открывает этот блок, в том виде, в каком он записан в XML, в редакторе фрагмента под предпросмотром. Его исправляют так же, как исходный текст (автодополнение, Ctrl+E, поиск и замена), затем Применить к XML записывает его в документ, на его место; Применить и продолжить записывает его, не закрывая редактор; Перезагрузить фрагмент снова берёт текст из документа. Фрагмент должен оставаться правильно сформированным. Перед выходом Varians предлагает применить изменённый фрагмент.

Общее выделение с редактором фрагмента. Карандаш ✎ в начале элемента предпросмотра (абзаца, строфы, заголовка…: см. Редактируемые элементы) открывает этот элемент в редакторе фрагмента, не сдвигая изображения свидетелей; щелчок по тексту предпросмотра по-прежнему их синхронизирует. Когда редактор открыт, строка, выделенная в этом элементе предпросмотра (перетаскиванием мыши или двойным щелчком), выделяется и в редакторе фрагмента, который получает фокус: место для исправления находится сразу. И наоборот, выделение, сделанное в редакторе фрагмента, выделяется в предпросмотре, который прокручивается к нему; фокус остаётся в редакторе. Находится то же вхождение повторяющегося слова, в том числе слова, разделённого <lb break="no"/>. Выделение в другом элементе не меняет редактор фрагмента: откройте этот элемент его карандашом. Текст, набранный во фрагменте, появляется в предпросмотре только после Применить к XML. Щелчок по карандашу сохраняет текущее выделение в предпросмотре: если оно в этом элементе, оно выделяется и в редакторе фрагмента. В предпросмотре F2 открывает в редакторе фрагмента элемент выделения (или курсора) вместе с выделением. Уже открытый элемент с неприменёнными исправлениями не перезагружается.

Редактируемые элементы. Карандаш ✎ открывает каждый блок, стоящий в разделе <body>: любой элемент классов TEI model.divPart (<p>, <ab>, <lg>, <l>, <sp>…) и model.inter (<list>, <table>, <quote>, <cit>, <stage>…), а также <head>, <figure> и <note>. Элемент, находящийся внутри другого элемента этого набора, не имеет своего карандаша: он открывается вместе с ним. Так, у <lg> есть карандаш, у его <l> нет; у <p> он есть, у содержащихся в нём <quote> или <note> нет; у реплики (<sp>) он есть и стоит у имени говорящего; у <note> между двумя абзацами он есть. Классы читаются из схемы RELAX NG проекта, найденной при проверке: элемент, добавленный в эти классы настройкой ODD, редактируем. Без схемы, или если схема не определяет эти классы, Varians берёт список TEI P5 4.10.2. Карандаши ставит сам Varians, какой бы ни была таблица стилей XSLT представления: ей ничего не нужно для них предусматривать, а у элемента, который она не показывает, карандаша нет. Подпись редактора называет открытый элемент, например «Фрагмент TEI · <lg> 3/40».

Таблица стилей Varians

Таблица стилей, поставляемая с Varians (tei-to-html.xsl, она же используется в сценарии HTML-издание (таблица стилей Varians)), выводит:

  • структуру: раздел озаглавлен своим первым <head>, а при его отсутствии — своим @n (но никогда не своим @xml:id), и оглавление перечисляет озаглавленные разделы по уровням; каждая строфа (<lg>) — блок с отступом, каждый стих (<l>) — на своей строке; список нумеруется, если у него есть @rend="numbered" или @type="ordered" (или numbered), и его заголовок стоит перед ним; <table> — таблица с подписью, ячейками-заголовками (@role="label") и объединёнными ячейками (@cols, @rows); рисунок — блок с подписью;
  • театр: каждая реплика (<sp>) — блок, в начале которого стоит говорящий (<speaker>), набранный капителью; ремарка (<stage>) — в скобках, курсивом: блок с отступом между двумя репликами или двумя абзацами, строка внутри строфы и часть фразы, когда она стоит в абзаце;
  • редакционные явления, как в «Критическое издание (HTML)»: <choice> показывает одну форму (<corr>, <reg>, <expan>, иначе <sic>, <orig>, <abbr>), остальные — во всплывающей подсказке; <sic> отмечается; <del> и <surplus> зачёркнуты, <add> подчёркнут; <supplied> — в квадратных скобках; <gap> даёт «[lacune]»; <hi> передаёт полужирный шрифт, подчёркивание, верхний и нижний индексы и капитель; <emph>, <title> и <foreign> — курсивом;
  • цитаты: <ref> цитаты <cit> следует за цитатой, в угловых скобках и серым цветом.

CSS проекта (rendering/tei.css) задаёт внешний вид; Varians сам задаёт отступ строф и вид реплик, которые CSS проекта может переопределить. Предпросмотр (Qt) понимает лишь подмножество CSS: правило, стоящее после @media, в нём игнорируется.

8. Свидетели и факсимиле

У каждого свидетеля проекта своя панель рядом с редактором. Его ресурсы объявляются в Файл → Параметры проекта…, в разделе Свидетели и ресурсы (Добавить…, Изменить…): изображения, строки (ALTO или PAGE XML), файл выравнивания. Все они необязательны и добавляются в любом порядке.

Изображения

Источник изображений свидетеля — один из трёх:

  • Пока без изображений;
  • Локальные изображения (JPEG, PNG, TIFF, BMP, WebP): Добавить изображения…; Копировать изображения в проект делает проект переносимым. Каждое изображение получает обозначение листа или страницы (Фолио / страница) и идентификатор своей поверхности TEI (Поверхность TEI). Добавленные файлы сортируются в естественном порядке (img_1r, img_1v, img_2r…); Естественная сортировка сортирует существующий список, а ↑ / ↓ перемещают изображение;
  • Манифест IIIF (IIIF Presentation 2 или 3): вставьте адрес манифеста, затем нажмите Загрузить / обновить.

Varians дополняет <facsimile> издания, добавляя по одной <surface> на каждое выбранное изображение, но никогда не перестраивает существующий <facsimile>: поверхности, зоны и всё, что вы в них добавили, сохраняются, а ставшая ненужной поверхность никогда не удаляется без вашего участия.

<facsimile>
  <surface xml:id="A1-p0002" n="1v">
    <graphic url="../images/A1/002.jpg"/>
  </surface>
</facsimile>

Изображения IIIF, выбранные для издания

Манифест часто содержит гораздо больше страниц, чем использует издание. Выберите Только выбранные для издания изображения, затем Выбрать изображения и связать файлы OCR…: отфильтруйте листы, отметьте нужные страницы; предпросмотр открывает страницу в браузере. Только отмеченные страницы образуют корпус изображений свидетеля и получают поверхность TEI, идентификатор которой сохраняет позицию страницы в манифесте.

То же окно связывает каждую страницу с её строками и с её синхронизированной страницей:

  • OCR (ALTO или PAGE XML). Varians сам связывает страницу IIIF и файл с тем же именем изображения (без расширения), в том числе с именем изображения, указанным в самом файле; неоднозначное соответствие не применяется. Сопоставить автоматически (точные имена) заполняет пустые поля; последний столбец позволяет выбрать файл для каждой страницы, даже если имена совершенно не совпадают. Один файл соответствует только одной странице.
  • Синхронизированная страница. Для свидетеля, синхронизируемого по строкам, Varians находит страницу файла выравнивания, соответствующую каждой странице IIIF, по идентификатору Canvas, сервису изображений, адресу изображения, надёжной связи с OCR или однозначному обозначению листа. В противном случае её можно выбрать в столбце Синхронизированная страница; этот выбор сохраняется в project.xml.
  • Столбцы Локальная копия и Состояние связи показывают, есть ли копия страницы, на чём основана связь и какой источник будет показан.

Место страницы в списке никогда не служит для её идентификации: без доказательства Varians ничего не связывает.

Локальные копии изображений IIIF

Использовать локальную рабочую копию изображений IIIF в Varians загружает страницы — на выбор (Загружать страницы:) Все изображения выбранного корпуса или Только страницы с соответствующими файлами ALTO или PAGE. Загрузка начинается после сохранения параметров, в отдельном окне, не блокируя редактирование; Файл → Менеджер загрузок IIIF… снова открывает это окно в любой момент. Оно показывает число страниц манифеста, выбранных, имеющихся, недостающих и исключённых; Загрузить недостающие продолжает загрузку, не загружая повторно уже полученные страницы, Обновить выбранные загружает всё заново; Пауза, Продолжить и Остановить действуют между двумя изображениями. Закрытие окна скрывает его, не останавливая работу. Копии хранятся в iiif/local/<свидетель>/; страница без копии по-прежнему читается с сервера.

Использовать локальную копию при создании веб-просмотрщика — отдельный выбор: если флажок установлен, веб-просмотрщик включает в себя имеющиеся копии и для этих страниц работает без сети; если он снят, просмотрщик читает изображения с исходных серверов. Перед распространением изображений проверьте права учреждений-хранителей на воспроизведение.

Когда сервер предоставляет сервис изображений IIIF, Varians показывает изображение в полном разрешении, а при неудаче использует изображение предпросмотра из манифеста. Процент увеличения отсчитывается от автоматического вписывания, а не от разрешения файла.

Строки: ALTO и PAGE XML

Строки свидетеля (их положение на изображении и их текст) берутся из файлов ALTO или PAGE XML, по одному на страницу, созданных программой распознавания. В окне свидетеля раздел Геометрическая разметка текста (ALTO / PAGE) предлагает в поле Источник ALTO / PAGE варианты Автоматически / данные из файла синхронизации или Отдельные файлы ALTO или PAGE: Добавить файлы ALTO / PAGE… (в порядке листов) и Копировать файлы ALTO / PAGE в проект. Каждый файл распознаётся отдельно: у одного свидетеля могут быть оба формата. Строка ALTO обычно прямоугольник; строка PAGE сохраняет свой многоугольник (Coords/@points) и базовую линию (Baseline/@points); её текст берётся из её TextEquiv/Unicode или из её слов.

Добавление строк к свидетелю IIIF не меняет его изображений. Страница OCR связывается с изображением, только если связь доказана; остальные подсчитываются во всплывающей подсказке свидетеля.

Строки — это ещё не синхронизация. Пока никакое выравнивание не связывает строки рукописи со строками опорного свидетеля, свидетель отслеживается по страницам, и панель показывает всю страницу; рамки строк можно показать, но ни одна строка не выделяется.

Построчная синхронизация

Файл выравнивания свидетеля (Синхронизация JSON (необязательно) и Копировать синхронизацию в проект) создаётся программой Varians-Synchro. Файл опорного свидетеля описывает его физические строки, страница за страницей; файл каждого другого свидетеля связывает его строки со строками опорного (base_keys). Формат описан в ALIGNMENT_FORMAT.md.

В TEI первый <lb edRef="#A"/> опорного свидетеля A соответствует первой строке его файла выравнивания, следующий — следующей, и так далее; <pb> отмечают страницы, не перенумеровывая строки. Строка состояния считает строки опорного свидетеля (например, «A: 3599 строк ✓») и сообщает, если их число отличается от числа строк в выравнивании; при сохранении об этом напоминается. Изменение внутри тега, например дополнение edRef="#T" до edRef="#T1", учитывается сразу.

Свидетель отслеживается по строкам, только если его выравнивание пригодно: настоящие строки для опорного свидетеля, настоящие связи с опорным для остальных. Пустой или предварительный файл, файл без связей с опорным свидетелем или со связями, не указывающими ни на одну строку опорного, оставляет свидетеля в режиме отслеживания по страницам, и Varians сообщает об этом.

После повторного экспорта выравниваний Вид → Обновить синхронизацию… (Ctrl+Shift+R) перечитывает их без повторного открытия проекта: файлы проверяются, список изменений предлагается для подтверждения, а неверный файл никогда не заменяет загруженные данные. Транскрипция и её история отмены не меняются; панели по возможности сохраняют свою страницу, масштаб и рамки.

Панель свидетеля

В заголовке панели указаны свидетель и показанная позиция (страница и строка). Её элементы управления:

  • ← → переходят к предыдущей или следующей строке (или странице) рукописи; ⤺ возвращает к месту, соответствующему отрывку издания; кнопка с открытой книгой определяет, ведут ли эти стрелки издание (см. Следовать рукописи в её собственном порядке);
  • − и + меняют масштаб, кнопка между ними возвращает 100 %; колесо мыши тоже меняет масштаб, а двойной щелчок по изображению возвращает 100 %;
  • Рамки показывает контуры строк этого свидетеля: оранжевым — синхронизированные строки, синим — просматриваемую строку; многоугольники PAGE рисуются как есть; при отсутствии геометрии об этом выводится сообщение;
  • Страница ↗ открывает изображение всей страницы в приложении или браузере по умолчанию;
  • Отметить страницу и Разворот…, а также список Листы: — для свидетеля, отслеживаемого по страницам;
  • ↗ открепляет панель в отдельное окно (см. Расположение панелей).

В узкой панели Рамки, Страница ↗, Отметить страницу и Разворот… сокращаются до ▣, □, pb и ↔; их всплывающие подсказки называют их.

Кадрирование строки показывает соседние строки, но не строки другой колонки или другой страницы. Если строке опорного свидетеля соответствуют несколько строк свидетеля, панель центрируется на действительно связанной строке.

Отметить страницу вставляет в позицию курсора начало показанной страницы:

<pb n="1v" edRef="#A1" facs="#A1-p0002"/>

@n повторяет обозначение листа, @edRef указывает свидетеля, @facs — поверхность (или зону) TEI. Курсор должен находиться в тексте или между двумя тегами, а не внутри тега. Свидетель, отслеживаемый по страницам, показывает страницу своего последнего <pb> перед курсором: страницу указывает его @facs, а при его отсутствии — @n, если он указывает лишь на одну страницу свидетеля. У двух свидетелей может быть одинаковый номер листа: их различает @edRef.

Разворот… описывает изображение, на котором два листа или две страницы: окно показывает миниатюру изображения с красной линией, которую нужно поставить на границу, и запрашивает обозначения для полей Левая часть: и Правая часть:. Varians записывает две <zone> в поверхность изображения, не трогая само изображение. Затем Отметить страницу указывает на часть, содержащую показанную строку, или спрашивает, какую выбрать; список Листы: и стрелки переходят от одной части к другой; Изображение целиком показывает всё изображение. Отмена в этом окне ничего не добавляет.

Следовать рукописи в её собственном порядке

Стрелки ← и → каждой панели свидетеля ведут издание: свидетель продвигается вперёд или назад в своём собственном порядке, а курсор издания переходит к соответствующему месту, при необходимости показывая часть или текст, где оно находится. Остальные свидетели следуют за опорным, как при движении курсора. Когда показан вспомогательный документ, стрелки только листают свидетеля.

Свидетель, синхронизируемый по строкам. Панель переходит к следующей строке свидетеля; издание переходит к строке опорного свидетеля, на которую указывает эта строка. Строка, не связанная с опорным свидетелем, оставляет издание на предшествующей ей связанной строке, и строка состояния сообщает об этом. Кнопка ⤺ возвращает панель к строке, связанной со строкой опорного свидетеля.

Свидетель, отслеживаемый по страницам. Стрелки и список листов ведут издание к выбранной странице: к первой строке свидетеля на этой странице в одном из его JSON, иначе к концу его <pb edRef="#M" n="45v"/>, иначе к началу текста, для которого <locus from> свидетеля — эта страница. Без этих ориентиров издание не сдвигается, и строка состояния сообщает об этом.

От текста к тексту. В конце текста стрелки переходят к следующему тексту в рукописи — со сквозной нумерацией или синхронизируемому отдельно. Панель опорного свидетеля делает то же самое: опорный свидетель, общий для нескольких текстов, проходится целиком. Страница, на которой кончается один текст и начинается другой, остаётся на экране. Панель свидетеля, которого нет в показанном тексте («Для этого текста нет выравнивания этого свидетеля.»), своими стрелками ведёт к следующему или предыдущему тексту, где этот свидетель есть, в порядке издания.

Порядок текстов в рукописи. Varians выводит его из страниц свидетеля:

  • место страниц в объявленном списке изображений свидетеля (манифест IIIF или файлы, в Файл → Параметры проекта…);
  • иначе — общие страницы его JSON: каждый JSON уже идёт в порядке рукописи, а страница, на которой кончается один текст и начинается другой, связывает их;
  • иначе — <locus from> свидетеля для текста или фолиация первой страницы текста (число с r или v), сравнённая с фолиацией других страниц;
  • иначе текст сохраняет своё место в порядке издания, и Varians сообщает об этом.

Вид → Диагностика рукописей… показывает порядок текстов в каждой рукописи, присутствующей в нескольких текстах, и сообщает о неустановленном месте. Чтобы установить его надёжно, объявите изображения свидетеля или добавьте в его <witness> элемент <locus from="80r" target="#s04">.

Вести издание или листать. Кнопка с открытой книгой, сразу после ← → ⤺, определяет, ведут ли стрелки рукописи издание. Когда она нажата (серо-голубой фон), стрелки и выбор листа этой рукописи перемещают и курсор в издании, как описано выше; когда отпущена, они только листают рукопись, не затрагивая издание. По умолчанию нажата только кнопка опорного свидетеля. Панель по-прежнему следует за изданием, когда в нём движется курсор. Состояние каждой рукописи запоминается для проекта, без изменения project.xml.

Лакуны свидетелей

Отрывок, которого нет у свидетеля (утраченный лист, оборванный текст), в TEI заключается между <lacunaStart/> и <lacunaEnd/>. TEI помещает эти элементы в чтение: свидетель — это свидетель содержащего их <rdg> (или <lem>), а в чтении нескольких свидетелей — свидетель их собственного @wit:

<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaStart/></rdg></app>
…
<app><lem wit="#T1 #P"/><rdg wit="#T2"><lacunaEnd/></rdg></app>

<rdg wit="#T2 #P">… <lacunaStart wit="#P"/></rdg>

Varians распознаёт эти элементы и вне чтения, с @wit, но проверка TEI отмечает их там как ошибки.

В панелях. Когда курсор находится в лакуне свидетеля, его панель остаётся на строке (для свидетеля, отслеживаемого по страницам, — на странице), на которой его текст обрывается, с плашкой «Лакуна этого свидетеля: его текст здесь обрывается.». Когда курсор находится в лакуне опорного свидетеля, свидетели, синхронизируемые по строкам, остаются на последней строке опорного свидетеля с плашкой «Лакуна опорного свидетеля: в этом отрывке строки не синхронизируются.»; об этом сообщает и строка состояния. Свидетели, отслеживаемые по страницам, продолжают следовать своим <pb>, которые от опорного свидетеля не зависят.

Отладка аппарата. Проверка «Неполные <app> (у свидетеля нет чтения)» не ожидает чтения от свидетеля внутри его лакуны.

Лакуна без <lacunaEnd/> длится до конца текста. В издании из частей лакуна может начаться в одной части и закончиться в другой; в тексте, синхронизируемом отдельно, учитываются только лакуны этого текста. Веб-просмотрщик показывает те же плашки.

Расположение панелей

Вид → Выбрать отображаемых свидетелей…: отметьте свидетелей, которых нужно показать, затем упорядочьте их кнопками Выше и Ниже. Если ни один свидетель не показан, область изображений исчезает. Панели делят между собой высоту, которую можно регулировать; двойной щелчок по заголовку свидетеля разворачивает его панель, повторный восстанавливает распределение. Веб-просмотрщик публикует показанных свидетелей в этом порядке.

Вид → Расположение рукописей: Вертикально, Горизонтально или Сетка (2 столбца), без потери масштаба, рамок и синхронизации. Открепить рукопись (или ↗ в её заголовке) открывает её в отдельном окне, которое можно перенести на другой экран, с флажком Поверх всех окон; закрытие этого окна или ↙ (Вернуть в главное окно) возвращает её на место; Вернуть все рукописи в главное окно возвращает все. Разделитель между редактором и изображениями можно перемещать: редактор может занимать лишь пятую часть ширины. Перезагрузить изображения (F5) перечитывает изображения.

Эти настройки хранятся на вашем компьютере, для каждого проекта; они не изменяют ни TEI, ни project.xml, ни выравнивания.

Диагностика свидетелей

Вид → Диагностика рукописей… показывает для каждого свидетеля его страницы, изображения, строки и действительные связи с опорным свидетелем. Её предупреждения отличают обычное отсутствие выравнивания от неисправностей: файл выравнивания не найден, другой опорный свидетель, связи с неизвестными строками, строки ALTO или PAGE, не связанные с изображением IIIF. Для издания из частей она показывает также охват (издание или показанный текст), тексты, синхронизируемые отдельно, и порядок текстов в каждой рукописи.

9. Критический аппарат

Кодирование аппарата

Varians ожидает аппарат, закодированный методом parallel segmentation (см. Основные понятия): по одному <app> на каждое место разночтения в тексте, с принятым чтением (<lem>) и разночтениями (<rdg>), в которых @wit указывает свидетелей. Чтения <rdgGrp> учитываются наравне с другими; пустое чтение <rdg wit="#B"/> — это пропуск у свидетеля B. <app> может содержать другие <app>.

<app>
  <lem wit="#A #C">uidelicet</lem>
  <rdg wit="#B">scilicet</rdg>
  <rdg wit="#D"/>
</app>
  • Ввод. В @wit ввод # открывает список свидетелей из <listWit> с их описанием; несколько свидетелей разделяются пробелами, а уже указанные повторно не предлагаются.
  • Указанные свидетели. О свидетеле, который указан, но не объявлен в <listWit>, сообщает команда Правка → Ссылки (см. Ссылки между документами).
  • Лакуны. Отрывок, которого нет у свидетеля, заключается между <lacunaStart/> и <lacunaEnd/> в одном из его чтений: см. Лакуны свидетелей.
  • Установленный текст. Везде, где Varians публикует установленный текст, приоритет имеет <lem>; <app> без <lem> берёт чтение выбранного свидетеля, по умолчанию опорного.

Отладка аппарата

Справка → Отладка аппарата… предлагает готовые запросы XPath для поиска ошибок в критическом аппарате отображаемого документа, закодированного методом parallel segmentation: каждый <app> объединяет свои чтения (<lem>, <rdg>, в том числе внутри <rdgGrp>), а @wit указывает свидетелей в виде #A. Свидетели — это свидетели из <listWit> документа.

  • Свидетель указан несколько раз: один и тот же свидетель встречается в двух чтениях одного <app> или дважды в одном @wit; его чтение неоднозначно.
  • Неполные <app>: у свидетеля нет чтения. Для <app> верхнего уровня ожидаются все свидетели из <listWit>, для вложенного <app> — свидетели содержащего его чтения. <lem> без @wit считается чтением свидетелей, отсутствующих в <rdg>: такой <app> не отмечается.
  • <app> без <lem>: <app>, у которых нет <lem>; <lem> внутри <rdgGrp> этого <app> учитывается. Этот поиск не зависит от свидетелей: он доступен и без <listWit>.
  • Заданный свидетель: <app>, в которых выбранный из списка свидетель встречается или не встречается в <lem> или <rdg> либо только в <rdg>.
  • Мои запросы: собственные именованные запросы XPath для проверок, свойственных вашей разметке. Добавить… предлагает текущий запрос панели XPath; Изменить… и Удалить управляют ими. Они сохраняются в project.xml (элемент <xpathQueries>) и переносятся вместе с проектом.

Найти выполняет запрос в панели XPath: щелчок по результату выделяет <app>. Запрос остаётся в поле XPath: это обычный XPath 1.0 с префиксом tei:, который можно скопировать в другие XML-инструменты. Он может быть длинным, так как содержит по одному условию на каждого свидетеля.

Ограничения: группы свидетелей (<listWit xml:id="…">, указанный в @wit) не раскрываются; о свидетеле, указанном, но отсутствующем в <listWit>, сообщает команда Правка → Ссылки; если часть свидетелей из <listWit> не сличена в аппарате, все <app> выглядят неполными.

Публикация аппарата

  • Критическое издание (HTML): установленный текст и аппарат после каждого раздела, с отсылками в виде цифр; см. Критическое издание.
  • TEI: DOCX (Word) и TEI: ODT (LibreOffice): аппарат в постраничных сносках, по тем же правилам; см. TEI Stylesheets.
  • Веб-просмотрщик: фиолетовый кружок у каждого места разночтения показывает чтения и их свидетелей; показываемый текст — на выбор установленный текст или транскрипция одного свидетеля; см. Веб-просмотрщик.

10. Издания из частей (XInclude)

Большое издание, собрание или корпус можно разделить на файлы, по файлу на текст, которые издание собирает через XInclude. Varians обрабатывает их совокупность как единый документ, но каждый файл редактируется отдельно. В этой главе сначала описано, как это работает, а затем — пошаговая подготовка такого проекта.

Принцип

Как пошагово подготовить такой проект, описано в руководстве.

Издание может включать свои части, например по файлу на проповедь, по стандарту XInclude. Издание, объявленное в project.xml, остаётся главным документом; его части определяются по его элементам xi:include, без других объявлений:

<TEI xmlns="http://www.tei-c.org/ns/1.0"
     xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
    <xi:include href="sermons/s03.xml" xpointer="element(/1/2/1/1)"/>
  </body>

Часть — это либо фрагмент (весь файл, корнем которого служит, например, <div> проповеди), либо элемент полного документа TEI, указанный через xpointer: его идентификатором (s02 или element(s02)) или путём (element(/1/2/1/1): TEI, затем его 2-й дочерний элемент text, затем body, затем первый div). Часть сама может включать другие части. Относительные пути, записанные в части, отсчитываются от папки этой части.

Части и вкладки

У каждой части своя вкладка, названная по имени её файла, после вкладки издания и в порядке включения. Часть редактируется и сохраняется отдельно (Ctrl+S), со своей историей отмены; перед выходом Varians предлагает сохранить изменённые части. Список частей перечитывается при каждом сохранении издания или части. «Переименовать вкладку…» и «Исключить документ из проекта» относятся только к вспомогательным документам. Представление XSLT / CSS остаётся открытым при показе части: оно показывает всё издание (см. Представление XSLT / CSS собранного издания); свидетели тоже остаются на экране (см. ниже). Сохранение издания в другую папку нарушило бы пути его элементов xi:include: Varians заранее предупреждает об этом.

Проверка

Издание и каждая его часть запускают проверку собранного издания — по схеме издания и с учётом несохранённых изменений частей. Панель RELAX NG тогда добавляет столбец Документ; двойной щелчок по ошибке открывает нужную часть на нужной строке. Вкладка каждой части окрашивается по её собственным ошибкам. Отсутствующая или неправильно сформированная часть, циклическое включение или неподдерживаемая форма (parse="text", xi:fallback, другая схема xpointer) отмечаются на строке соответствующего xi:include.

Ссылки и свидетели

Издание и его части образуют единый документ: #id сначала ищется в файле, где он записан (включая заголовок), затем в других частях. F12, команда Ссылки и автодополнение учитывают это. К собранному изданию относятся только идентификаторы включённого элемента части: свидетель, объявленный лишь в <teiHeader> проповеди, включённой через xpointer, находится Varians в этой проповеди, но инструмент, читающий только собранное издание, его не увидит. В части команда Справка → Отладка аппарата… использует собственных свидетелей части: её <listWit>, иначе свидетелей издания, чей <locus target="#s01"> указывает на часть, иначе свидетелей, указанных в её @wit.

Синхронизация свидетелей

Если издание разделено на файлы лишь для удобства (собрание, тексты которого идут в том же порядке, что и в опорном свидетеле), свидетели синхронизируются так же, как для издания в одном файле: строки опорного свидетеля (<lb edRef="#A"/>) считаются в порядке собранного издания, от одной части к другой, а файлы выравнивания остаются такими же, как для издания в одном файле, — по одному на свидетеля для всего издания. Курсор издания или части ведёт за собой свидетелей; щелчок или прокрутка в опорном свидетеле переносят курсор в часть, содержащую строку, и открывают её вкладку, даже после «Скрыть вкладку». Состояние структуры (строка состояния) считает строки опорного свидетеля во всём собранном издании, а при сохранении издания или части Varians предупреждает, если это число отличается от числа строк в выравнивании опорного свидетеля. <lb/> в комментарии или вне включённого элемента части не учитывается, как и в других XML-инструментах.

Условие: опорный свидетель должен содержать эти тексты в порядке издания. Varians проверяет число строк, а не их порядок. Другие свидетели могут иметь иной порядок или не содержать какого-то текста: их выравнивание и так указывает на строки опорного свидетеля. Свидетель, синхронизируемый по страницам, следует последнему относящемуся к нему <pb> в порядке издания, даже в предыдущей части: если у этого свидетеля тексты идут в другом порядке, отметьте его страницу в начале каждого текста.

В части «Отметить страницу» вставляет <pb> в часть, в позицию курсора, и дополняет <facsimile> издания; «Разворот…» записывает свои зоны в <facsimile> издания. Издание при этом изменяется, не будучи показанным: на его вкладке появляется «*». Отмена в части удаляет <pb>, но не добавленное в <facsimile>.

Тексты, синхронизируемые отдельно

В корпусе, тексты которого передаются разными свидетелями и в разном порядке, текст может иметь собственные выравнивания: по одному JSON на свидетеля, в обычном формате, в папке, названной по имени файла текста без расширения (alignments/s02/B.json для xml/sermons/s02.xml). Ничего объявлять не нужно: текст, у которого есть своя папка, синхронизируется отдельно; остальные следуют сквозной нумерации. Опорный свидетель текста — опорный свидетель проекта, кроме исключения, объявленного в project.xml: <part name="s02" base="B"/>.

Когда такой текст показан, панели свидетелей переходят на его выравнивания и его опорного свидетеля; расположение, масштаб и откреплённые окна не меняются. Свидетель без JSON для этого текста сохраняет свою панель, где написано «Для этого текста нет выравнивания этого свидетеля.». Строки считаются только в этом тексте (например, «B: 8 строк ✓»); щелчок в опорном свидетеле остаётся в тексте. Диагностика свидетелей и обновление синхронизации относятся к показанному тексту.

Свидетели, отслеживаемые по страницам. Свидетель, у которого нет JSON для этого текста, но который этот текст содержит — <pb edRef="#C"/> в тексте или <locus target="#s04"> в его <witness> из <listWit>, — следует там своим страницам. До своего первого <pb> в тексте он показывает начальную страницу: @from этого locus (<locus from="13r" to="14r" target="#s04">), иначе страницу, предшествующую странице этого первого <pb>, в порядке страниц свидетеля. Там работает и «Отметить страницу». Диагностика свидетелей называет для каждого текста его свидетелей, отслеживаемых по страницам. Остальные свидетели без JSON сохраняют сообщение об отсутствии выравнивания.

Представление XSLT / CSS собранного издания

Представление XSLT / CSS показывает всё издание вместе с частями, какой бы документ ни был показан, и используется так же, как для издания в одном файле. Переход от издания к части не закрывает его; закрывает его только показ вспомогательного документа.

  • Редактирование фрагментов. Карандаш ✎ элемента открывает его в редакторе фрагмента в том виде, в каком он записан в содержащем его файле; подпись называет этот файл, например «Фрагмент TEI · <p> 10/16 · s03.xml». Применённый фрагмент записывается в этот файл, даже если он не показан или ни разу не открывался: его вкладка тогда помечена «*», а одна отмена в части убирает изменение. Файл должен оставаться правильно сформированным. Ctrl+S в редакторе фрагмента сохраняет этот файл, затем показанный документ, если он изменён; перед выходом Varians предлагает сохранить неприменённый фрагмент вместе с его файлом.
  • Щелчок, оглавление, поиск. Щелчок по строке ставит курсор на эту строку в содержащем её файле, вкладка которого открывается, не покидая предпросмотра; свидетели следуют за ним, с собственной нумерацией текста, синхронизируемого отдельно. Оглавление и поиск в предпросмотре работают так же.
  • Выделение. Строка, выделенная в предпросмотре, при возврате на вкладку Исходный XML выделяется в файле, который содержит текст (в части или в издании), на том же вхождении в том же абзаце; без выделения курсор переходит к показанной строке. И наоборот, выделение или позиция в части находится в предпросмотре. Между предпросмотром и редактором фрагмента выделения соответствуют друг другу, как для издания в одном файле.
  • Ограничения. Абзац, который сам содержит xi:include, редактируется в файле своего тега; включённый текст редактируется в своей части. Как и для издания в одном файле, абзац или строка, которые XSLT не выводит, сдвигают следующие за ними карандаши или метки строк.

Веб-экспорт собранного издания

Создать веб-просмотрщик экспортирует всё издание вместе с частями, сохраняя те же переходы между частями, что и в окне.

  • Текст и строки. Текст частей входит в просмотрщик, а строки опорного свидетеля считаются в нём от одной части к другой, как в окне. Текст, синхронизируемый отдельно, сохраняет своего опорного свидетеля и свои JSON (alignments/s02/): когда выбранная строка переходит в него, каждая панель показывает своего свидетеля в этом тексте — по его строкам, по его страницам начиная с начальной страницы или с сообщением «Для этого текста нет выравнивания этого свидетеля.». Масштаб и рамки каждой панели сохраняются от текста к тексту. Кнопки заголовка проходят по всем строкам в порядке чтения, от одного текста к другому.
  • Стрелки панелей. Как в окне, стрелки ← → любой панели ведут текст в собственном порядке рукописи, от одной части или текста к другому, как и список листов свидетеля, отслеживаемого по страницам; ⤺ возвращает панель к связанной строке. Сообщения строки состояния окна (начало или конец рукописи, несвязанная строка, неопределённая страница, неустановленное место) показываются под заголовком просмотрщика.
  • Лакуны. Плашки те же, что и в окне (см. Лакуны свидетелей): лакуна продолжается от одной части к другой, а текст, синхронизируемый отдельно, начинается без лакуны.
  • Сохранение. Экспорт читает сохранённые файлы: сначала Varians сохраняет издание, каждую изменённую часть и неприменённый фрагмент части; если что-либо из этого сохранить не удаётся, экспорт отменяется. Ненайденная часть или неподдерживаемое включение (parse="text", xi:fallback) указываются в отчёте об экспорте: соответствующий текст в просмотрщике отсутствует.
  • Ограничения. Учитывается положение фрагмента текста, по которому щёлкнули. <pb> или <lb>, помещённый в непринятое чтение или в примечание, просмотрщик не видит. «Диагностика рукописей…», «Обновить синхронизацию…», «Отметить страницу» и «Разворот…» остаются принадлежностью окна. После изменения издания создайте просмотрщик заново.

Ограничения

Порядок текстов в рукописи выводится из её страниц; текст, который не удаётся к ним привязать, сохраняет своё место в порядке издания (см. Следовать рукописи в её собственном порядке). У веб-экспорта свои ограничения: см. Веб-экспорт собранного издания. Проекта без xi:include это не касается.

Руководство

Это руководство пошагово описывает, как организовать проект, издание которого разделено на несколько файлов, например по файлу на каждую проповедь. Подробности о каждой функции — выше, в разделе Принцип.

1. Упорядочить файлы

Оставьте один файл издания — тот, который объявлен в project.xml (например, xml/edition.xml): это главный документ с заголовком, списком свидетелей и порядком текстов. Поместите тексты в соседнюю папку, по файлу на текст. Дайте каждому файлу имя, уникальное во всём проекте: это имя без расширения служит и именем папки выравниваний текста, синхронизируемого отдельно (шаг 4). Пути относительны к содержащему их файлу: sermons/s01.xml из издания, ../personnes.xml#augustinus из проповеди.

project.xml
alignments/T1.json, T2.json …
alignments/s02/B.json, D.json
xml/edition.xml
xml/sermons/s01.xml, s02.xml, s03.xml …

2. Написать xi:include

Объявите пространство имён XInclude на корневом элементе издания и поставьте xi:include на место каждого текста:

<TEI xmlns="http://www.tei-c.org/ns/1.0" xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
  </body>
</TEI>

Текст — это либо фрагмент: весь файл, корень которого — включаемый элемент с пространством имён TEI (<div xmlns="http://www.tei-c.org/ns/1.0" xml:id="s01">); либо полный документ TEI, из которого включается один элемент — по идентификатору (xpointer="s02") или по пути (xpointer="element(/1/2/1/1)"). Полный документ можно проверять и отдельно; его заголовок в издание не входит. Текст может сам включать другой текст. Не используйте parse="text" и xi:fallback: Varians сообщает о них, но не поддерживает. Сохраните издание: каждый текст получит свою вкладку.

3. Объявить свидетелей

Объявите каждую рукопись один раз, в Файл → Параметры проекта…, с общей для всего собрания сиглой. В TEI объявляйте свидетелей в <listWit> издания, в <listWit> каждого текста (полного документа TEI) или в обоих. Свидетеля, объявленного только в заголовке текста, включённого через xpointer, Varians находит, но инструмент, читающий только собранное издание, его не видит.

4. Выбрать синхронизацию каждого текста

  • Тексты идут так же, как в опорном свидетеле, с теми же свидетелями (собрание, разделённое для удобства): сквозная нумерация. По одному JSON на свидетеля для всего издания, как для издания в одном файле, объявленному в параметрах проекта. Строки опорного свидетеля считаются от текста к тексту в порядке издания; опорный свидетель должен содержать тексты в этом порядке.
  • Свидетели меняются от текста к тексту (корпус): текст, синхронизируемый отдельно. Создайте папку alignments/<имя файла текста>/ и поместите в неё по одному JSON на свидетеля для этого текста, в обычном формате: alignments/s02/B.json, alignments/s02/D.json. Создайте эти JSON программой Varians-Synchro по файлу текста. Ничего объявлять не нужно: достаточно папки. Свидетель без JSON для этого текста, но со своими <pb edRef> в нём или с <locus target> в своём <witness>, следует там своим страницам: см. Тексты, синхронизируемые отдельно.
  • Оба способа можно сочетать: тексты со своей папкой синхронизируются отдельно; остальные следуют сквозной нумерации, и общий JSON каждого свидетеля содержит только их строки.

5. Объявить собственного опорного свидетеля текста

Опорный свидетель текста, синхронизируемого отдельно, — опорный свидетель проекта. Если в опорном свидетеле проекта нет этого текста или точкой отсчёта должен служить другой свидетель, впишите исключение вручную в project.xml, перед </teiManuscriptProject>, затем снова откройте проект:

<parts>
  <part name="s02" base="B"/>
</parts>

name — имя файла текста без расширения; base — сигла опорного свидетеля. Строками этого текста становятся его <lb edRef="#B"/>, а в его папке должен быть B.json. Varians сохраняет этот элемент при сохранении параметров проекта.

6. Проверить

  • Покажите каждый текст: состояние структуры в строке состояния должно быть верным, например «B: 8 строк ✓»; всплывающая подсказка говорит, относится ли счёт к собранному изданию или к тексту, синхронизируемому отдельно.
  • Вид → Диагностика рукописей… показывает охват (издание или показанный текст), тексты, синхронизируемые отдельно, с их опорным свидетелем и свидетелями, и проблемы: JSON необъявленного свидетеля, неизвестный опорный свидетель, отсутствующий JSON опорного свидетеля…
  • Проверка RELAX NG относится к собранному изданию; столбец «Документ» указывает файл каждой ошибки.
  • Команда Ссылки проверяет ссылки между текстами.
  • Другой XML-инструмент собирает проект без Varians: xmllint --xinclude --noout xml/edition.xml или oXygen с включённым XInclude в настройках валидатора.
  • Вид → Диагностика рукописей… показывает также порядок текстов в каждой рукописи и сообщает о неустановленном месте: см. Следовать рукописи в её собственном порядке.

7. В повседневной работе

  • Каждый текст редактируется в своей вкладке и сохраняется отдельно (Ctrl+S); перед выходом Varians предлагает сохранить изменённые тексты.
  • Чтобы добавить текст: создайте его файл, добавьте его xi:include в издание, сохраните издание; появится его вкладка. Для текста, синхронизируемого отдельно, добавьте и его папку выравниваний, затем выполните Вид → Обновить синхронизацию….
  • Если вкладок много: щелчок правой кнопкой по вкладке → Скрыть вкладку; щелчок в опорном свидетеле снова покажет вкладку нужного текста.
  • Сохранение издания в другую папку нарушило бы его xi:include: Varians заранее предупреждает об этом.
  • Представление XSLT / CSS показывает всё издание: карандаш ✎ открывает в нём элемент любого текста, а щелчок ведёт к тексту, который содержит строку; см. Представление XSLT / CSS собранного издания. Веб-экспорт содержит всё издание; см. Веб-экспорт собранного издания.
  • Чтобы читать рукопись от текста к тексту, пользуйтесь стрелками её панели: издание покажет нужный текст.

11. Веб-просмотрщик

Веб-просмотрщик публикует издание вместе с факсимиле: текст слева, рукописи справа, синхронизированные, как в Varians. Это автономная HTML-страница, которая открывается в любом браузере без сервера и без Varians и может быть выложена в интернет как есть.

Создание просмотрщика

Создать веб-просмотрщик (на панели инструментов или Файл → Создать веб-просмотрщик) сначала спрашивает, какой текст показывать (см. Выбор текста), затем записывает просмотрщик в web_output/ (viewer.html) вместе с используемыми в нём локальными изображениями (web_output/images/). Папка и имя файла задаются в Файл → Параметры проекта….

Перед экспортом Varians сохраняет издание, его изменённые части и неприменённый фрагмент части; если что-либо из этого сохранить не удаётся, экспорт отменяется. Просмотрщик публикует показанных свидетелей в их порядке (Вид → Выбрать отображаемых свидетелей…); скрытый опорный свидетель служит в нём только для синхронизации. Отчёт об экспорте сообщает о ненайденных изображениях и местах без чтения выбранного свидетеля. Просмотрщик — это копия: после изменения издания создайте его заново.

Не открывая Varians, перетащите project.xml проекта на generer_viewer_web.bat или выполните python -m web_viewer.generator project.xml: просмотрщик будет тем же, с выбором текста, сохранённым в проекте.

Текст

Текст для чтения. Просмотрщик читает все тексты издания: <front>, <body> и <back>, а также каждый текст <group>. Раздел озаглавлен своим первым <head>, а при его отсутствии — своим @n; его @xml:id заголовком не является. Вступительная часть и приложения без заголовка называются «Вступительная часть» и «Приложения». Оглавление перечисляет озаглавленные разделы с отступом под озаглавленным разделом, который их содержит. Каждый <lg> — строфа, каждый <l> — на своей строке, его @n — на полях; список сохраняет свои подсписки; <table> — таблица с подписью, ячейками-заголовками (@role="label") и объединёнными ячейками (@cols, @rows); <note> между двумя абзацами — метка, скрываемая вместе с примечаниями. Каждая реплика (<sp>) — блок, в начале которого стоит говорящий (<speaker>), набранный капителью; ремарка (<stage>) — в скобках, курсивом: отдельный блок между двумя репликами или внутри реплики и часть фразы, когда она стоит в абзаце. Как в «Критическое издание (HTML)», <choice> показывает одну форму (исправление, нормализацию, раскрытие сокращения), другую — во всплывающей подсказке; <del> зачёркнут, <add> подчёркнут пунктиром, <supplied> — в квадратных скобках, а <gap> даёт «[…]», с причиной и объёмом во всплывающей подсказке. Чтения <rdgGrp> учитываются наравне с другими. Текст получает язык своего @xml:lang, который управляет переносами. Как в «Критическое издание (HTML)», <ref> цитаты <cit> с type="bible" следует за цитатой в угловых скобках; <ref> другой <cit> становится примечанием.

Выбор текста. «Создать веб-просмотрщик» сначала спрашивает, какой текст показывать: установленный текст (<lem>, иначе чтение выбранного свидетеля, как в «Критическое издание (HTML)») или текст выбранного свидетеля, даже если это не <lem>, что восстанавливает его транскрипцию. По умолчанию выбранный свидетель — опорный свидетель каждого текста. Там, где у него нет чтения (ни одно чтение <app> его не называет: отсутствующее место, лакуна, неполный аппарат), просмотрщик показывает <lem>, иначе чтение опорного свидетеля, на сером фоне в пунктирной рамке, с подсказкой «Здесь нет чтения свидетеля …»; «∅» отмечает такое пустое место. Пропуск (<rdg wit="#T2"/>) — это чтение, и он не отмечается. Заголовок просмотрщика и отчёт об экспорте указывают число таких мест. Синхронизация по-прежнему следует строкам опорного свидетеля: строки его непоказанного чтения распределяются по показанному тексту; когда свидетель пропускает место, их положение сохраняет невидимая метка. При установленном тексте флажок Выделить жёлтым чтения, взятые не из <lem> в том же окне изначально выделяет чтения, принятые за отсутствием <lem>, — те, по которым решение ещё не принято; в просмотрщике читатель показывает или скрывает их флажком Чтения вне <lem> в заголовке. Выбор хранится в project.xml, <webViewer text="established|witness" textWitness="T2" highlightNonLem="true"/>; generer_viewer_web.bat следует ему.

В тексте фиолетовый кружок v отмечает каждое разночтение: щелчок показывает чтения и их свидетелей. Кружок n отмечает примечание. Флажки Разночтения и Примечания в заголовке скрывают эти метки; флажок Чтения вне <lem> в установленном тексте выделяет жёлтым чтения, взятые не из <lem>; A− и A+ меняют размер текста; Язык меняет язык просмотрщика.

Текст и рукописи

У каждого свидетеля своя карточка справа, с элементами управления его панели в Varians: стрелки, масштаб (также колесом мыши и двойным щелчком для возврата к 100 %), Рамки, Страница ↗ и ⤺. Проект без изображений публикуется без столбца факсимиле.

  • По строкам. Щелчок по тексту выбирает строку опорного свидетеля; каждый синхронизированный свидетель показывает свою строку, кадрированную, с синим контуром, даже когда остальные его рамки скрыты. ← строка и строка → в заголовке проходят по строкам в порядке чтения.
  • По страницам. Щелчок в тексте показывает для каждого свидетеля, отслеживаемого по страницам, страницу его последнего <pb>; когда выравнивания нет совсем, кнопки заголовка становятся ← страница и страница →.
  • В порядке рукописи. Как в Varians, стрелки ← → любой карточки ведут текст: свидетель продвигается в собственном порядке, а текст переходит к строке опорного свидетеля, на которую указывает его строка, или к его <pb> для свидетеля, отслеживаемого по страницам, чей список листов тоже ведёт текст; ⤺ возвращает карточку к связанной строке. Сообщения (начало или конец рукописи, несвязанная строка…) показываются под заголовком.
  • Лакуны. Лакуны свидетелей отмечаются плашками, как в Varians (см. Лакуны свидетелей).

Текст без метки строки или строка, отсутствующая в экспорте, отмечаются: просмотрщик никогда не выводит неуверенное соответствие. Об издании из частей см. Веб-экспорт собранного издания.

Поиск

Поле Поиск… в заголовке ищет слово или выражение во всём показанном тексте, включая заголовки, стихи, пункты списков, ячейки, имена говорящих и ремарки. Если ничего не выбрано, поиск точный, без учёта регистра; в группе Средневековые варианты написания флажки u/v, i/j и c/t делают эти буквы равнозначными. Результаты перечисляются и выделяются; результат ведёт к своему месту и к строкам рукописей.

Изображения

Локальные изображения копируются вместе с просмотрщиком. Изображения IIIF читаются с их серверов: просмотрщик каждый раз запрашивает нужный размер (сервисы IIIF Image 1, 2 и 3), а если сервер отказывает, использует изображение меньшего размера, затем изображение целиком, затем изображение предпросмотра из манифеста. Поэтому для них нужны доступ к интернету и необходимые права, кроме страниц, локальная копия которых опубликована (см. Локальные копии изображений IIIF). Рамки следуют контурам PAGE и зонам разворота, в координатах исходного изображения.

12. Публикация с помощью XSLT

Помимо веб-просмотрщика, Varians публикует издание с помощью таблиц стилей XSLT: своих (Критическое издание, HTML-издание), таблиц консорциума TEI (DOCX, ODT, EPUB, HTML, LaTeX…) и ваших. Каждая публикация — это сценарий, который повторяется одним щелчком.

Сценарии преобразования XSLT

Сценарий преобразования применяет таблицу стилей XSLT к изданию или к другому документу проекта и записывает результат в файл: HTML-издание, указатель, список цитат, преобразованный XML… У сценария есть название, он сохраняется в проекте и повторяется в точности. Веб-просмотрщик остаётся отдельной публикацией, которую сценарий не меняет.

Файл → Сценарии преобразования… показывает две группы:

  • Сценарии проекта, сохраняемые в project.xml (элемент <transformations>): ими управляют Добавить…, Изменить…, Дублировать… и Удалить.
  • Готовые сценарии, поставляемые с Varians: HTML-издание (таблица стилей Varians), который публикует издание с таблицей стилей и CSS предпросмотра Varians в publications/edition.html; Критическое издание (HTML) — критическое издание с аппаратом по опорному свидетелю (см. Критическое издание); и в подгруппе TEI Stylesheets, изначально свёрнутой (щелчок по её стрелке разворачивает её), — сценарии таблиц стилей TEI-C (см. TEI Stylesheets). В меню кнопки Преобразовать последние образуют подменю. Готовый сценарий можно выполнить как есть или продублировать в проект, чтобы изменить.

В каждой строке указаны источник, процессор и красным — то, что мешает выполнить сценарий (таблица стилей не найдена, Saxon не установлен…). Выполнить выполняет выбранный сценарий; Предпросмотр выполняет его во временной папке и открывает результат, не трогая файл сценария.

Сценарий

  • Источник: Издание (издание проекта, собранное, если у него есть части: каждая часть сохраняет своё место, и относительный document() находит там свои файлы), Открытый документ (документ текущей вкладки, например вспомогательный документ, см. Вспомогательные XML-документы; собранное издание, если это оно) или Файл (файл, читаемый как есть).
  • Процессор: XSLT 1.0 (lxml) или XSLT 3.0 (Saxon) для таблиц стилей на XSLT 2.0 или 3.0. Saxon-HE (пакет saxonche) устанавливается вместе с Varians: installer_dependances.bat или pip install -r requirements.txt.
  • Таблица XSLT и необязательный CSS: пути относительно проекта; ${varians}/ обозначает таблицы стилей, поставляемые с Varians. CSS копируется рядом с результатом, а его имя передаётся таблице стилей в параметре css (таблица Varians вставляет его в свой <link>). Новый сценарий предлагает таблицу стилей и CSS предпросмотра.
  • Результат: записываемый файл, заменяемый при каждом выполнении (предлагается publications/<название>.html). Им не может быть исходный файл проекта (project.xml, издание и его части, документ, таблица стилей, схема, JSON выравнивания). С Saxon таблица стилей может записывать другие файлы через xsl:result-document (например, по странице на каждую проповедь), но только в папке результата и её подпапках; в ином месте выполнение отклоняется.
  • Формат результата (с Saxon): чаще всего Один файл; Страницы HTML (по одной на раздел), когда таблица стилей пишет index.html и свои страницы через xsl:result-document; DOCX (Word), ODT (LibreOffice) или EPUB, когда она пишет файлы архива в папку, адрес которой получает, как таблицы стилей TEI-C: тогда Varians собирает архив, который и является результатом (см. TEI Stylesheets).
  • Предварительный проход TEI → TEI (необязательно), с Saxon: таблица стилей, применяемая к источнику до таблицы сценария, с теми же параметрами. Так сценарии DOCX и ODT переносят аппарат в постраничные сноски.
  • Параметры: пары название / значение, передаваемые таблице стилей (<xsl:param name="titre"/>). С Saxon они передаются без типа, как из его командной строки: «false» подходит для параметра xs:boolean, «3» — для xs:integer, а в остальных случаях значение остаётся строкой; с lxml это строки. В значении ${pivot} заменяется идентификатором опорного свидетеля проекта, а ${tei}/ — адресом папки установленных TEI Stylesheets.

Выполнение

Кнопка Преобразовать рядом с Создать веб-просмотрщик снова выполняет последний сценарий, выполненный в проекте (также Ctrl+Shift+T); её стрелка показывает список сценариев. Перед выполнением Varians сохраняет то, что читает сценарий: издание, его изменённые части и неприменённый фрагмент, как при веб-экспорте, а также исходный документ, таблицу стилей и CSS, если они открыты и изменены. Преобразование идёт в отдельном процессе: Varians остаётся доступным, а Отменить останавливает его.

Отчёт указывает записанные файлы и длительность; Открыть открывает результат в приложении по умолчанию (в браузере для HTML), Открыть папку — папку, в которой он лежит. В подробностях — журнал: процессор и версия, параметры, xsl:message, чтение из сети (с lxml), отклонённые записи. При ошибке сообщение указывает соответствующий файл и строку, а прежний результат остаётся нетронутым.

Безопасность: таблица стилей может читать любой локальный файл, а также адреса http или https (тогда результат может зависеть от сервера); записывает она только свой результат (а с Saxon — файлы в его папке). Внешние сущности источников не читаются.

Критическое издание

Готовый сценарий Критическое издание (HTML) публикует издание (собранное, если оно состоит из частей) в виде автономной HTML-страницы для чтения с экрана или печати: publications/edition-critique.html. Его таблица стилей, edition-critique.xsl (${varians}/, на XSLT 3.0: процессор Saxon), взята из таблицы стилей для критических изданий TEI и доработана для Varians.

  • Установленный текст. <lem> аппарата всегда имеет приоритет (пустой <lem/> — установленный пропуск); иначе берётся чтение свидетеля, выбранного параметром temoin-de-base, значение которого — ${pivot}: опорный свидетель проекта. В окне продублированного сценария он выбирается из списка: сначала опорный свидетель («T1 (опорный)»), затем остальные свидетели проекта и <listWit>, затем «aucun (только леммы)»; значение, записанное иначе (#B), сохраняется; без значения это первый <witness> из <listWit>. С aucun текст следует только элементам <lem>, и в каждом <app> он должен быть. Неизвестный свидетель или aucun при аппарате без леммы прерывают выполнение с понятным сообщением. Аппарат без чтения выбранного свидетеля даёт «[lecture du témoin non disponible]» («чтение свидетеля недоступно»). Когда в установленном тексте есть чтения, взятые не из <lem>, на странице есть флажок Surligner les leçons hors <lem> («Выделить чтения вне <lem>»): если он отмечен, такие чтения выделены жёлтым, чтобы было видно, по каким местам решение ещё не принято.
  • Аппарат. После каждого раздела, в двух сериях: Apparat critique (критический аппарат), отсылки к которому в тексте обозначены цифрами, и менее многочисленные Notes (примечания) издателя, обозначенные буквами (a, b… z, aa…). Статья даёт принятое чтение, «]», затем каждое другое чтение с его сиглами курсивом; чтения <rdgGrp> учитываются наравне с другими. Пустое чтение даёт om.; когда установленный текст опускает место, остальные чтения — добавления (add.). Чтение, содержащее только <lacunaStart/> или <lacunaEnd/>, даёт «lacuna incipit T1» или «lacuna desinit T1» (см. Лакуны свидетелей). Весь текст аппарата, который не происходит из свидетеля, набран курсивом: сиглы, om., add., lacuna incipit и desinit, комментарии; чтения остаются прямым шрифтом, даже <sic> (за ним следует «sic» курсивом), цитата или выделение. Знаки отсылки и статьи связаны в обе стороны.
  • Текст. Раздел без <head> получает заголовком свой @n, иначе остаётся без заголовка. Показываются только <pb> выбранного свидетеля или без @edRef (⟨12r⟩), а с aucun — все (⟨T1 : 12r⟩). Соседние <lb> нескольких свидетелей дают один разрыв, который соединяет слово, если у одного из них есть break="no". Стихи и строфы (<l>, <lg>) сохраняют свою структуру и номера. Каждая реплика (<sp>) — блок, говорящий (<speaker>) набран капителью; ремарка (<stage>) — в скобках, курсивом: отдельный блок между двумя репликами или двумя стихами и часть фразы, когда она стоит в абзаце.
  • Параметры (окно сценария, после Дублировать…; флажки, кроме temoin-de-base): montrer-folios и montrer-numeros-de-vers; sauts-lb (если отмечен, разрыв строки выбранного свидетеля становится разрывом строки на странице); surligner-hors-lemme (если отмечен, флажок на странице изначально отмечен; по умолчанию не отмечен).

Те же правила переносят аппарат в постраничные сноски в сценариях DOCX и ODT (см. TEI Stylesheets). Тексты страницы («Apparat critique», «Notes»…) написаны по-французски: чтобы изменить их, продублируйте сценарий, затем нажмите Открыть таблицу стилей; таблица стилей копируется в xslt/ вместе с apparat-commun.xsl, где собраны её правила (см. Сценарии преобразования XSLT).

TEI Stylesheets

TEI Stylesheets — это таблицы стилей XSLT консорциума TEI (github.com/TEIC/Stylesheets), которые используют также Oxygen и другие инструменты. Varians поставляет их и устанавливает при первом использовании, один раз для всех проектов, в папку данных пользователя: они работают без сети. Они написаны на XSLT 3.0: их сценарии используют Saxon.

Готовые сценарии. В Файл → Сценарии преобразования… подгруппа TEI Stylesheets готовых сценариев объединяет восемь сценариев, публикующих издание (собранное, если оно состоит из частей): TEI: HTML, TEI: HTML в нескольких файлах, TEI: DOCX (Word), TEI: ODT (LibreOffice), TEI: EPUB, TEI: текст, TEI: Markdown и TEI: LaTeX. Изначально она свёрнута и образует подменю кнопки Преобразовать. Их результаты записываются в publications/tei/ (edition.html, pages/index.html, edition.docx, edition.odt, edition.epub, edition.txt, edition.md, edition.tex). Рядом с HTML кладётся CSS из TEI Stylesheets (tei.css), без ссылок на сайт TEI-C; тексты, которые добавляют таблицы стилей («Содержание»…), следуют языку интерфейса через параметры lang и documentationLanguage. В сценарии ${tei}/ обозначает файл установленных TEI Stylesheets, например ${tei}/profiles/default/html/to.xsl; см. Сценарии преобразования XSLT. Журнал выполнения называет использованную версию («Библиотека: TEI Stylesheets 7.61.0»).

Форматы из нескольких файлов. У четырёх из этих сценариев свой Формат результата (см. Сценарии преобразования XSLT):

  • TEI: HTML в нескольких файлах пишет publications/tei/pages/index.html, оглавление, и по странице на каждый раздел и подраздел (s02.html…, по их @xml:id), с tei.css. Параметр splitLevel задаёт деление: 1, значение сценария, делит разделы и их подразделы, что даёт страницу на каждое произведение, когда текст — единый раздел, который их объединяет; 0 — только разделы верхнего уровня. По правилу TEI Stylesheets первый раздел остаётся на странице оглавления, если ему ничего не предшествует (нет <front>).
  • TEI: DOCX (Word) и TEI: ODT (LibreOffice) пишут edition.docx и edition.odt на основе шаблона TEI Stylesheets. Сами TEI Stylesheets передали бы аппарат плохо (все чтения подряд, каждое в своём абзаце) и превратили бы каждый <pb> в разрыв страницы, а каждый <lb> — в разрыв строки: поэтому предварительный проход Varians, apparat-en-notes.xsl, сначала готовит текст по опорному свидетелю (параметр temoin-de-base со значением ${pivot}). Каждый <app> становится принятым чтением, за которым следует постраничная сноска (<note place="foot" type="apparatus">): «чтение ] разночтение сиглы; …», с om., add., lacuna incipit и lacuna desinit, по правилам критического издания. Примечание издателя без @place становится концевой сноской (place="end"): аппарат и примечания образуют две серии. Остаются только листы опорного свидетеля, в виде меток ⟨12r⟩ в тексте, а разрывы строк свидетелей сливаются с текстом.
  • TEI: EPUB пишет edition.epub с CSS установленных TEI Stylesheets (${tei}/tei.css), прочитанными без сети.
  • Локальные изображения (<graphic url="…"/>) помещаются в архив DOCX, ODT или EPUB вместе с их размерами; удалённое изображение не загружается, и журнал об этом сообщает.

Настройка таблицы стилей. TEI Stylesheets не изменяют: их переопределяют в таблице стилей проекта. Продублируйте сценарий TEI (Дублировать…), затем выберите копию и нажмите Открыть таблицу стилей: Varians предложит создать в xslt/ таблицу настройки, например xslt/tei-html.xsl (Создать таблицу настройки), которую затем будет использовать сценарий. Она импортирует (xsl:import) таблицу TEI-C по её официальному адресу, http://www.tei-c.org/release/xml/tei/stylesheet/…, который Varians читает из установленных TEI Stylesheets без сети; Oxygen поступает так же, и таблица остаётся в нём действительной. Параметры (xsl:param) и шаблоны (xsl:template), которые вы в ней пишете, имеют приоритет над импортированными; всё остальное берётся из TEI Stylesheets. Например:

<xsl:stylesheet version="3.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
    xmlns:tei="http://www.tei-c.org/ns/1.0" xmlns="http://www.w3.org/1999/xhtml"
    exclude-result-prefixes="#all">
  <xsl:import href="http://www.tei-c.org/release/xml/tei/stylesheet/profiles/default/html/to.xsl"/>
  <!-- Без нумерации заголовков. -->
  <xsl:param name="numberHeadings">false</xsl:param>
  <!-- Имена людей полужирным. -->
  <xsl:template match="tei:persName"><b><xsl:apply-templates/></b></xsl:template>
</xsl:stylesheet>

Для вывода в HTML xmlns="http://www.w3.org/1999/xhtml" делает добавленные элементы (здесь <b>) элементами XHTML, как и элементы TEI Stylesheets. Таблица настройки редактируется, проверяется (F8) и дополняется, как любая таблица стилей: см. Редактирование таблицы стилей XSLT. Обновление TEI Stylesheets её не затрагивает: она продолжает применяться.

Обновления. TEI-C выпускает около двух версий в год. При запуске Varians не чаще раза в месяц, не блокируя окно, проверяет, вышла ли новая версия; если её нет или нет сети, ничего не сообщается. Иначе он предлагает её установить: Установить или Позже (вопрос вернётся при следующей проверке). Установка показывает ход выполнения, её можно отменить; неверный архив или отмена оставляют установленную версию. Новая версия используется со следующего преобразования во всех проектах; старая удаляется при следующем запуске. Файл → TEI Stylesheets… или кнопка TEI Stylesheets… в списке сценариев показывает установленную версию, её источник, папку, лицензию и дату последней проверки; Проверить обновление проверяет сразу. Установлена только одна версия: публикация, сделанная заново после обновления, может отличаться от предыдущей; журнал называет версию.

Лицензия. Консорциум TEI распространяет TEI Stylesheets на выбор по лицензии BSD с двумя пунктами или по лицензии CC BY-SA 3.0; файл LICENCE устанавливается вместе с ними (Показать лицензию).

Ограничения. LaTeX компилируется в PDF установленным TeX (xelatex) вне Varians. В тексте и в Markdown TEI Stylesheets пишут лемму и разночтение подряд: таблица настройки может изменить этот выбор TEI-C. В DOCX и ODT аппарат нумеруется 1, 2, 3 внизу страницы, а примечания издателя — i, ii… в конце документа; в Word TEI Stylesheets добавляют пробел после знака концевой сноски. Страницы HTML не забирают с собой изображения: их адрес остаётся таким же, как в источнике.

Редактирование таблицы стилей XSLT

Таблица стилей XSLT — это XML-документ: Varians открывает её как документ проекта, на отдельной вкладке (см. Вспомогательные XML-документы), проверяет её и помогает её писать, без внешних инструментов.

  • Добавление таблицы стилей: Файл → XML-/XSLT-документы проекта… → Добавить XML-, XSLT- или Schematron-документ… принимает файлы .xsl и .xslt. Таблица стилей вне папки проекта копируется в неё, в папку xslt/ (рядом с xml/), никогда не заменяя существующий файл; таблица стилей, уже находящаяся в проекте, остаётся на своём месте.
  • Новая таблица стилей XSLT… (то же меню) создаёт минимальную таблицу стилей, в XSLT 1.0 (lxml) или в XSLT 3.0 (Saxon), предлагаемую в xslt/: объявленное пространство имён TEI, вывод HTML, шаблон для корня документа.
  • Из сценариев (см. Сценарии преобразования XSLT): Открыть таблицу стилей, в списке сценариев или в окне сценария (который при этом сохраняется), показывает таблицу стилей сценария проекта. Таблица стилей, поставляемая с Varians (${varians}/…), сначала копируется в xslt/; таблицу стилей вне проекта тоже можно скопировать или открыть без копирования. После копирования сценарий использует копию. Для готового сценария сначала используйте Дублировать…. Таблица стилей Varians, которая включает или импортирует другие (xsl:include, xsl:import), копируется вместе с ними, не заменяя уже имеющийся файл: edition-critique.xsl с apparat-commun.xsl.

Проверка. Для таблицы стилей Проверить таблицу стилей XSLT (F8, вместо «Проверить RNG») компилирует её, не выполняя, процессором сценариев проекта, которые её используют (обоими, если они разные); таблица стилей, которую не использует ни один сценарий, проверяется по своей версии: version="1.0" — с помощью lxml, другая — с помощью Saxon. Как и при проверке RELAX NG, таблица стилей проверяется при первом показе, после каждого изменения, если F8 уже использовалась, и при сохранении, которое при ошибках просит подтверждения. Панель проверки показывает каждую ошибку с её строкой; двойной щелчок ведёт к ней. Ошибка в импортированной (xsl:import) или включённой (xsl:include) таблице стилей указывает её файл в столбце «Документ», и двойной щелчок ведёт к этой таблице, если она входит в проект. Строка состояния показывает результат, а вкладка таблицы стилей окрашивается как вкладка недействительного документа.

Автодополнение. Ctrl+Space предлагает элементы и атрибуты XSLT, допустимые в этом месте, с префиксом таблицы стилей (xsl:), а список атрибутов открывается при наборе. Внутри элемента результата (<div>, <tei:p>…) это инструкции XSLT и атрибуты xsl:*. Таблица стилей с version="1.0" получает только элементы и атрибуты XSLT 1.0. Предложения берутся из схемы RELAX NG для XSLT 3.0 консорциума W3C, поставляемой с Varians (лицензия BSD); пользовательские элементы проекта (custom-elements.xml) в таблице стилей не предлагаются.

Сопутствующие файлы. Varians копирует только саму таблицу стилей. Файлы, нужные ей для полного результата (таблицы стилей, импортируемые через xsl:import или включаемые через xsl:include, изображения, CSS, JavaScript…), нужно самостоятельно поместить в папку xslt/ проекта, сохраняя относительные пути, которые использует таблица стилей. Проверка сообщает о ненайденной импортированной или включённой таблице стилей. CSS сценария, напротив, копируется рядом с результатом автоматически.

Ограничения: таблица стилей, предназначенная для импорта или включения, проверяется отдельно, и её ссылки на объявления основной таблицы стилей могут быть отмечены как ошибки; таблица стилей XSLT 2.0 получает предложения XSLT 3.0; имена, объявленные в таблице стилей (шаблоны, режимы, ключи), и выражения XPath не дополняются.
