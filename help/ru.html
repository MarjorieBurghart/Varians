Varians — редактор TEI XML для текстологии

Руководство пользователя — версия 0.8.5.24

Varians — рабочая среда для критического издания текстов в TEI. Она объединяет редактирование XML, проверку RELAX NG, предпросмотр XSLT/CSS, управление свидетелями и изображениями, необязательный ALTO, синхронизацию свидетелей и создание веб-просмотрщика.

1. Проекты и запуск

При первом запуске проект не открывается. В дальнейшем Varians может снова открыть проект, который был активен при закрытии программы. Файл → Закрыть проект (Ctrl+W) возвращает на начальный экран и запрещает автоматическое открытие этого проекта при следующем запуске.

Файл → Новый проект… позволяет начать с существующего TEI либо создать новую транскрипцию. Во втором случае создаётся минимальный xml/edition.xml и TEI-<listWit> на основе свидетелей проекта. Свидетель может сначала не иметь изображений, ALTO и синхронизации; эти ресурсы можно добавить позже.

project.xml
xml/edition.xml
images/
alto/
alignments/
rendering/
i18n/
web_output/

Старые проекты, где edition.xml лежит в корне, по-прежнему поддерживаются.

2. Редактирование XML и предпросмотр XSLT/CSS

Исходный XML содержит документ TEI. Визуальный перенос длинных строк не меняет XML и логическую нумерацию строк. Представление XSLT / CSS даёт редакционный предпросмотр. Выделение в исходном тексте и предпросмотре по возможности синхронизируется, в том числе при повторении одного и того же слова в одном фрагменте.

Редактор фрагмента позволяет редактировать ограниченный отрывок и затем применить его обратно к основному документу.

3. Помощь при разметке, RNG и custom-elements.xml

Ctrl+E оборачивает выделение в элемент или вставляет новый элемент в позицию курсора. Ctrl+Space дополняет имена элементов, атрибуты и некоторые значения атрибутов на основе схемы RELAX NG и custom-elements.xml. У предложений указывается источник.

Списки указателей вроде @wit дополняются по одному токену. Динамический источник witnesses может предлагать реальные идентификаторы проекта, например #A1 и #B1.

Важно: проектные подсказки ввода никогда не меняют действительность документа по RELAX NG. Полная проверка (F8) остаётся авторитетной.

Результаты проверки выводятся в нижней панели. При смене проекта они очищаются, поэтому сообщения от предыдущего документа не остаются на экране.

4. Поиск XPath

XPath (Ctrl+Shift+F) выполняет XPath 1.0 по TEI. Простое выражение вроде //note при необходимости автоматически повторяется в пространстве имён TEI; в сложных выражениях можно явно использовать префикс tei:.

В результатах показываются строка исходного XML, элемент, путь и предпросмотр. Щелчок по результату выделяет весь соответствующий XML-элемент от открывающего до закрывающего тега, даже если он занимает несколько строк. Самозакрывающийся элемент выделяется целиком.

Скалярные выражения, например count(//tei:note), показывают своё значение вместо списка элементов.

Для проверки критического аппарата команда Справка → Отладка аппарата… предлагает готовые запросы: см. Отладка аппарата.

5. Парные теги и безопасное форматирование

Varians распознаёт пары XML-тегов. Когда курсор находится внутри открывающего тега, соответствующий закрывающий тег подсвечивается. Если соответствие однозначно, изменение QName и полное удаление открывающего тега могут быть зеркально применены к закрывающему.

Отступы форматируют структурные области консервативно и защищают смешанное текстовое содержимое. Новые пробелы вокруг <lb/> не добавляются, xml:space="preserve" соблюдается, а неоднозначное или смешанное содержимое остаётся без изменений. В custom-elements.xml можно задавать formatting="inline", block или preserve.

6. Свидетели, изображения, факсимиле и страницы

Свидетель может быть без изображений, использовать локальные JPEG/PNG/TIFF/BMP/WebP или Manifest IIIF Presentation 2/3. Локальные файлы можно копировать в проект или оставлять ссылками на исходное расположение.

Страницы изображений можно описывать в TEI с устойчивыми идентификаторами <surface>:

<facsimile>
  <surface xml:id="A1-p0002" n="1v">
    <graphic url="../images/A1/002.jpg"/>
  </surface>
</facsimile>
Безопасность: Varians обновляет данные факсимиле постепенно. Он не перестраивает существующий <facsimile> целиком и сохраняет зоны и метаданные, добавленные вручную.

Отметить страницу вставляет указание смены страницы для текущей отображаемой страницы свидетеля:

<pb n="1v" edRef="#A1" facs="#A1-p0002"/>

Если курсор находится внутри любого XML-тега, операция отменяется. Поместите курсор в текст или между тегами.

7. ALTO и синхронизация строк

ALTO необязателен и не зависит от источника изображений. Он даёт OCR-текст и геометрию страницы, но сам по себе ALTO не является синхронизацией строк. Без реального соответствия TEI ↔ физическая строка Varians остаётся в режиме страниц и показывает текущую страницу целиком.

Режим строк включается только при действительно пригодной синхронизации: у опорного свидетеля должны быть опорные строки, у вторичных — реальные base_keys. Пустой или предварительный JSON выравнивания не включает режим строк.

8. Отображение свидетелей

Меню Вид содержит Перезагрузить изображения, Выбрать отображаемых свидетелей… и меню языка. Можно показывать от нуля до любого числа свидетелей. Выбор хранится локально для проекта и не изменяет project.xml.

Панели свидетелей разделены вертикальным сплиттером, поэтому их высоту можно менять. Двойной щелчок по заголовку временно разворачивает одного свидетеля на максимум; повторный двойной щелчок восстанавливает прежние пропорции.

V0.8.5.16 — Видимость и порядок. Откройте Вид → Выбрать отображаемые рукописи…, отметьте нужные рукописи, выделите строку и кнопками Выше или Ниже задайте порядок панелей изображений сверху вниз. Скрытые рукописи сохраняют своё место в списке. Настройки хранятся локально для каждого проекта и восстанавливаются после перезапуска; новые рукописи добавляются в конец. Опорный свидетель, данные синхронизации, project.xml и порядок в создаваемом веб-просмотрщике не изменяются.

9. Веб-просмотрщик

Создать веб-просмотрщик формирует автономный результат, обычно в web_output/. Нужные локальные изображения копируются в пакет вывода.

Без синхронизации строк просмотрщик работает в режиме страниц с кнопками ← страница и страница →. Щелчок по тексту издания независимо для каждого свидетеля определяет последний подходящий <pb>. При пригодной синхронизации включается навигация по строкам. Проекты без изображений экспортируются без пустого столбца факсимиле.

10. Сохранение и безопасность

Ctrl+S сохраняет издание. Корректность формирования XML проверяется автоматически, скомпилированные схемы RNG кэшируются, а важные записи при необходимости используют атомарную замену и/или резервные копии .bak. Неоднозначные автоматические изменения следует отвергать, а не применять молча к редакционному TEI.

ALTO, PAGE XML и локальные копии изображений IIIF (0.8.5)

Геометрическая разметка рукописей

В разделе Настройки проекта → Свидетели → Изменить → Геометрическая разметка текста (ALTO / PAGE) добавьте файлы XML в порядке страниц. Varians автоматически определяет формат каждого файла. В одном проекте могут быть свидетели с ALTO и PAGE; оба формата допустимы даже у одного свидетеля. Для переноса проекта между компьютерами скопируйте файлы в его каталог.

Строки ALTO обычно описаны прямоугольниками, а контуры строк PAGE сохраняются как многоугольники (Coords/@points); при наличии сохраняется и базовая линия (Baseline/@points). Включите отображение Рамок, чтобы увидеть контуры. Текст строки PAGE берётся из TextEquiv/Unicode, а при его отсутствии — из отдельных слов. Импорт геометрии сам по себе не создаёт синхронизацию со строками TEI <lb>; это отдельные данные.

Менеджер загрузок IIIF

В разделе Параметры проекта → Свидетели → Изменить включите локальную рабочую копию и выберите Все страницы манифеста либо Только страницы с соответствующими файлами ALTO или PAGE. Для каждого свидетеля действует собственная настройка. При выборочной загрузке сначала укажите его файлы ALTO/PAGE. Varians сопоставляет имена изображений, подписи страниц и фолиацию с холстами IIIF. Один лишь порядок файлов не считается доказательством соответствия; неоднозначные или нераспознанные страницы пропускаются с предупреждением.

После сохранения параметров загрузка запускается в отдельном окне и не блокирует редактирование. Менеджер можно вновь открыть через Файл → Менеджер загрузок IIIF…. Он показывает общее число страниц, выбранные, уже сохранённые, недостающие и исключённые. Загрузить недостающие продолжает работу без повторной загрузки имеющихся файлов; Обновить выбранные запрашивает изображения заново. Пауза, продолжение и остановка действуют между изображениями. Закрытие окна скрывает его, не останавливая загрузку.

Файлы сохраняются в iiif/local/<рукопись>/ и после завершения операции доступны без повторного открытия проекта. Страницы без локальной копии по-прежнему требуют соединения с сервером. Настройка экспорта веб-просмотрщика независима: включить можно лишь изображения, уже сохранённые локально.

Независимая настройка веб-просмотрщика

Включите Использовать локальную копию при создании веб-просмотрщика, чтобы включить доступные изображения в web_output/images/. Если флажок снят, веб-просмотрщик использует исходные URL IIIF, даже когда сама программа Varians работает с локальными файлами. Страницы без локальной копии могут требовать сети. Перед распространением изображений проверьте права и условия лицензирования учреждения-хранителя.

Явный выбор IIIF-изображений и привязка файлов OCR (0.8.5.4)

В настройках проекта откройте редактирование свидетеля, выберите «Только выбранные для издания изображения», затем «Выбрать изображения и связать файлы OCR…». Манифест остаётся полным каталогом; в издание включаются лишь отмеченные канвасы. Можно фильтровать листы, выделять или снимать выделение с видимых строк и открывать изображение IIIF в браузере для просмотра.

Varians автоматически предлагает связь между Canvas IIIF и ALTO/PAGE, если базовые имена файлов изображений полностью совпадают (без учёта расширения). Также проверяется исходное имя изображения, указанное в OCR XML, даже если XML-файл переименован. Неоднозначные совпадения не применяются, а существующие ручные привязки имеют приоритет. Кнопка «Сопоставить автоматически (точные имена)» заполняет пустые поля; любое предложение можно изменить или удалить. Порядок файлов и приблизительное сходство обозначений листов не используются.

После добавления локальных файлов ALTO/PAGE назначьте каждому выбранному канвасу соответствующий OCR-файл в последнем столбце. Совпадение имён не требуется. В текущей версии ручная привязка предполагает один OCR-файл на изображение.

При явном выборе режим «Все страницы» в диспетчере загрузок означает только выбранные для издания изображения, а «Страницы с ALTO/PAGE» дополнительно ограничивает загрузку изображениями с привязанными OCR. Для невыбранных канвасов не выполняется загрузка и не создаются новые TEI <surface>. Идентификаторы поверхностей основаны на исходных позициях канвасов в манифесте.

Существующие TEI-поверхности и уже загруженные изображения автоматически не удаляются: на них могут ссылаться редакторские данные. Проверьте неиспользуемые поверхности до удаления вручную. Новые локальные изображения и файлы ALTO/PAGE сортируются в естественном порядке (1r, 1v, 2r). К существующему списку можно применить «Естественная сортировка», сохраняя возможность менять порядок вручную.

Синхронизированные страницы и Canvas IIIF (0.8.5.6)

Для свидетеля с изображениями IIIF импортируйте JSON из Varians-Synchro и откройте Выбрать изображения и связать OCR…. Идентификаторы страниц и строк в JSON остаются неизменными; выбор IIIF определяет только нужные для издания изображения, даже если манифест содержит сотни Canvas.

Varians сопоставляет страницы по точному идентификатору Canvas, адресу сервиса IIIF Image, осторожно нормализованному URL изображения, достоверной связи с ALTO/PAGE либо однозначной метке листа. При полном совпадении имён файлов связь устанавливается автоматически. Если однозначной связи нет, выберите страницу JSON в столбце Синхронизированная страница вручную. Положение в списке никогда не считается доказательством идентичности. Ручные связи имеют приоритет и сохраняются в project.xml.

Столбцы Локальная копия и Состояние связи показывают наличие скачанного файла, основание сопоставления и предпочтительный источник изображения. Для работы без сети нужна локальная копия; иначе используется сервис IIIF. Неоднозначные совпадения не выбираются произвольно. Новые элементы surface в TEI создаются только для выбранных Canvas; существующие элементы автоматически не удаляются.

Подготовка пустой TEI-транскрипции по опорному списку

В окне создания проекта или в его настройках можно сформировать <pb/> для опорного свидетеля и, по желанию, <lb/>. <pb/> добавляются только для страниц, выбранных для издания: @facs ссылается на соответствующую <surface>, а @edRef обозначает список. Создаваемые <lb/> имеют @edRef, но не имеют @n и автоматических ссылок на области изображения. Число строк прежде всего берётся из однозначно сопоставленных ALTO/PAGE; при их отсутствии учитываются физические строки, действительно перечисленные в JSON синхронизации, даже если нумерация начинается с 41. Пропущенные строки отмечаются, но не выдумываются. Выбранная страница без перечисленных строк всё равно получает <pb/>. Предварительный просмотр, подтверждение и датированная резервная копия защищают текст; OCR-текст не вставляется.

Подготовка TEI по опорному списку (0.8.5.7)

В меню Файл → Новый проект выберите Начать новую транскрипцию. Раздел подготовки транскрипции по опорному списку находится непосредственно под выбором способа начала работы, перед списком свидетелей. Включите создание <pb/> — после этого станет доступен предварительно отмеченный параметр <lb/>. В настройках существующего проекта этот раздел расположен перед списком свидетелей. На небольших экранах окно можно прокручивать. В заголовке указан номер «Varians 0.8.5.7».

Varians 0.8.5.8 — Неполные страницы

Исправление 0.8.5.8: для фрагмента листа со строками 41–68 создаются 28 <lb/>, а не 0 или 68; атрибут @n не добавляется. Страница JSON с пустым списком строк всё равно получает <pb/>, если её изображение выбрано для издания. В противном случае выводится предупреждение об отсутствии связанного изображения или <surface>.

Кадрирование на границах колонок и страниц (0.8.5.9)

Если синхронизация выбирает строку на границе колонок или страниц, Varians больше не включает в область кадрирования соседние строки из другой колонки или страницы. Кадрирование охватывает только физически смежные строки. Номера строк, соответствия JSON и ключи синхронизации не изменяются. Полное изображение по-прежнему можно открыть кнопкой «Страница ↗».

Контуры синхронизированных строк (0.8.5.10)

Кнопка «Рамки» включается отдельно для каждого свидетеля; активное состояние теперь заметнее. Оранжевые контуры обозначают синхронизированные строки, синий — строку, выбранную вручную, без создания нового текстологического соответствия. Если строке опорного свидетеля соответствуют несколько строк другого свидетеля, Varians центрирует изображение на действительно связанной строке, в том числе при переходе между колонками. Полигоны PAGE отображаются как многоугольники, обычные строки ALTO — преимущественно как прямоугольники. При отсутствии координат выводится предупреждение. В создаваемом веб-просмотрщике пока используются прямоугольные выделения.

Смешанная навигация: страницы и строки для каждого свидетеля (0.8.5.11)

В одном издании могут одновременно использоваться свидетели, синхронизированные по строкам, и рукопись, для которой доступны только локальные изображения. Каждая панель рукописи использует собственный уровень синхронизации. Свидетели с пригодным JSON-файлом синхронизации по-прежнему следуют элементам <lb/> опорного свидетеля и связям base_keys. Для несинхронизированного свидетеля переход между страницами определяется его элементами <pb/>: атрибут @edRef указывает свидетеля, а @facs — соответствующий элемент <surface>. Если @facs отсутствует, @n принимается только при точном и однозначном совпадении с обозначением страницы. Порядок изображений не используется для догадок. Метки страниц одного свидетеля не переключают изображения других. Такой же принцип действует в форматированном представлении, при переходах по строкам и в экспортированном веб-просмотрщике.

V0.8.5.12 — Несколько рукописей. Область изображений теперь имеет вертикальную прокрутку: четвёртая рукопись не сжимается до узкой полосы. «Опорный свидетель» — только техническая точка отсчёта синхронизации, а не выбранный для критического издания основной список. Если в <pb/> нет @facs, страницу определяет пара @edRef + @n; одинаковые номера листов в разных рукописях допустимы.

Автодополнение закрывающих тегов

В редакторе исходного XML и редакторе фрагментов при вводе </ Varians предлагает ближайший ещё не закрытый элемент. Например, после <div><p>…</p></ появится подсказка div>; нажмите Enter или Tab, чтобы вставить </div>. Можно предварительно набрать часть имени, например </di. Клавиша Esc закрывает подсказку без изменения текста; Ctrl+Пробел вызывает её снова. Имена с префиксом пространства имён, например tei:div, сохраняются. Пустые элементы (<lb/>), комментарии, разделы CDATA и незавершённые атрибуты не считаются открытыми элементами. При неоднозначной вложенности закрывающий тег не подбирается наугад.

Добавление ALTO/PAGE к изображениям IIIF (0.8.5.14)

При добавлении файлов ALTO/PAGE к несинхронизированному свидетелю IIIF его изображения больше не исчезают, в том числе при наличии локальных рабочих копий. Определяющим остаётся выбранный набор холстов. Геометрия OCR связывается с изображением только при наличии точного идентификатора холста, ручной связи, однозначного обозначения листа или проверенной локальной копии изображения. Не связанные с изображениями страницы OCR сохраняются в производном кэше; их число показано в подсказке к панели свидетеля. Сопоставление по порядку не выполняется. Для установления связей откройте настройки свидетеля и выбор изображений с привязкой OCR. JSON синхронизации и TEI не изменяются.

Построчная синхронизация и качество изображений IIIF (0.8.5.15)

Если JSON свидетеля не содержит связей base_keys с опорным свидетелем, Varians сообщает об этом и сохраняет навигацию по страницам. Программа также предупреждает, если связи не соответствуют ни одной строке опорного свидетеля. При наличии сервиса IIIF Image API редактор запрашивает изображение полного разрешения вместо миниатюры из манифеста и использует миниатюру как резервный вариант. Контуры масштабируются по фактическим размерам показанного изображения, даже если локальная копия меньше холста Canvas. Вспомогательные XML-документы

Помимо издания, проект может включать другие XML-документы: файл авторитетных записей (лица, места), примечания и т. д. Используйте Файл → XML-документы проекта. Добавить XML-документ… включает в проект существующий файл; файл, находящийся вне папки проекта, копируется в xml/, никогда не заменяя существующий файл. Новый XML-документ… создаёт пустой документ с выбранным вами корневым элементом. Исключить документ из проекта исключает отображаемый документ, не удаляя его файл.

Как только появляется вспомогательный документ, над исходным XML отображается ряд вкладок: Издание, затем по одной вкладке на каждый документ. Каждый документ сохраняет собственную историю отмены, позицию и состояние; звёздочка обозначает несохранённые изменения, а цвет названия — неправильно сформированный или недопустимый XML. Проверка RELAX NG и автодополнение следуют <?xml-model?> отображаемого документа. Рукописи, представление XSLT / CSS и команды свидетелей относятся только к изданию: они скрываются, пока отображается другой документ, а затем восстанавливаются без изменений. Ctrl+S сохраняет отображаемый документ; перед выходом или сменой проекта Varians предлагает сохранить все изменённые документы. Веб-экспорт использует только издание.

Отображаемые вкладки. Команда Вид → Выбрать отображаемые документы… позволяет выбрать, у каких документов есть вкладка, и порядок вкладок. Щелчок правой кнопкой по вкладке предлагает Скрыть вкладку, Переименовать вкладку…, Выбрать отображаемые документы… и Исключить документ из проекта для документа этой вкладки, даже если он не отображается. Скрытый документ остаётся в проекте: его изменения сохраняются, и перед выходом Varians предлагает их записать. Его вкладка снова появляется, когда к нему ведёт ссылка (F12, Ctrl+щелчок, двойной щелчок в панели Ссылки). Последнюю видимую вкладку скрыть нельзя; при открытии проекта отображается издание вместе со своей вкладкой. Этот выбор сохраняется локально для проекта и не изменяет project.xml. Имя, заданное командой Переименовать вкладку…, напротив, записывается в атрибут label элемента <document> в project.xml; пустое имя восстанавливает имя файла.

Документы объявляются в project.xml элементом <documents>; проект без вспомогательных документов не меняется. Более ранняя версия Varians открывает такой проект как обычно, но стирает этот список, если в ней сохранить параметры проекта.

Ссылки между документами

Атрибут-указатель (@ref, @corresp, @target, @who, @wit, @edRef, @sameAs, @ana, @resp, @source, @hand, @facs, @prev, @next, @synch, @copyOf) обозначает элемент по его @xml:id. Как и в стандартном TEI, а значит, для всех XML-инструментов, краткая форма #bernard обозначает элемент самого документа. Чтобы указать на другой документ проекта (см. Вспомогательные XML-документы), пишут personnes.xml#bernard, с путём относительно документа, содержащего ссылку. Веб-адреса (https://…) и значения без «#» не обрабатываются. Значение может содержать несколько указателей, разделённых пробелами: wit="#T1 #T2".

Ввод. В значении такого атрибута введите #: список идентификаторов откроется сам, с текстом каждой записи и её файлом, например «personnes.xml#bernard — Bernardus». Следующие буквы фильтруют список; Enter или Tab вставляет значение; Esc закрывает список. Для @wit и @edRef список предлагает свидетелей, описанных в TEI (<witness> в <listWit>). Ctrl+Space открывает те же значения в окне («Идентификаторы проекта»), где фильтр учитывает и описания: «Bern» находит personnes.xml#bernard. Предлагаемые идентификаторы зависят от элемента: persName/@ref предлагает person, personGrp и persona, placeName/@ref — place, orgName/@ref — org, @who — лица. В остальных случаях предлагаются все идентификаторы. В custom-elements.xml элемент <values source="ids" elements="person personGrp" prefix="#"/> задаёт этот список для атрибута. Идентификатор другого документа вставляется в виде файл.xml#id, идентификатор самого документа — в виде #id.

Переход. На ссылке нажмите F12, щёлкните с нажатой клавишей Ctrl или выберите Перейти к цели в контекстном меню: откроется документ, содержащий цель, и элемент будет выделен. Если идентификатор определён несколько раз, Varians спросит, какую цель показать. Alt+← (или Вернуться в контекстном меню) возвращает к исходному месту, даже из другого документа. Ненайденная цель отображается в строке состояния. Для краткой формы, цель которой находится только в другом документе, Varians тоже переходит к ней и указывает, какую форму написать.

Проверка. Кнопка Ссылки на панели инструментов проверяет ссылки во всех документах проекта. Панель, открывающаяся под исходным текстом, указывает их число и перечисляет проблемные: цель не найдена, краткая форма с целью в другом документе (с формой, которую нужно написать), неоднозначная цель (идентификатор определён несколько раз в целевом документе) или файл не найден, со столбцами «Документ», «Строка», «Атрибут», «Значение» и Проблема. Двойной щелчок ведёт к ссылке. После исправления Проверить снова повторяет проверку. Эта проверка — подсказка: она никогда не мешает сохранению и не изменяет файлы.

Отладка аппарата

Справка → Отладка аппарата… предлагает готовые запросы XPath для поиска ошибок в критическом аппарате отображаемого документа, закодированного методом parallel segmentation: каждый <app> объединяет свои чтения (<lem>, <rdg>, в том числе внутри <rdgGrp>), а @wit указывает свидетелей в виде #A. Свидетели — это свидетели из <listWit> документа.

  • Свидетель указан несколько раз: один и тот же свидетель встречается в двух чтениях одного <app> или дважды в одном @wit; его чтение неоднозначно.
  • Неполные <app>: у свидетеля нет чтения. Для <app> верхнего уровня ожидаются все свидетели из <listWit>, для вложенного <app> — свидетели содержащего его чтения. <lem> без @wit считается чтением свидетелей, отсутствующих в <rdg>: такой <app> не сообщается.
  • Заданный свидетель: <app>, в которых выбранный из списка свидетель встречается или не встречается в <lem> или <rdg> либо только в <rdg>.
  • Мои запросы: собственные именованные запросы XPath для проверок, свойственных вашей разметке. Добавить… предлагает текущий запрос панели XPath; Изменить… и Удалить управляют ими. Они сохраняются в project.xml (элемент <xpathQueries>) и переносятся вместе с проектом.

Найти выполняет запрос в панели XPath: щелчок по результату выделяет <app>. Запрос остаётся в поле XPath: это обычный XPath 1.0 с префиксом tei:, который можно скопировать в другие XML-инструменты. Он может быть длинным, так как содержит по одному условию на каждого свидетеля.

Ограничения: группы свидетелей (<listWit xml:id="…">, указанный в @wit) не раскрываются; свидетеля, указанного, но отсутствующего в <listWit>, сообщает кнопка Ссылки; если часть свидетелей из <listWit> не сличена в аппарате, все <app> выглядят неполными.

Проверка RELAX NG без ожидания

Начиная с версии 0.8.9.2 проверка RELAX NG выполняется в отдельном процессе, который Varians запускает при первой необходимости. При первой проверке после запуска компиляция большой схемы, например TEI_ALL, занимает около десяти секунд; всё это время окном можно пользоваться, а рядом с состоянием RNG: идёт проверка… в строке состояния вращается маленький огонёк. Скомпилированная схема затем сохраняется на весь сеанс, даже если открыть другой проект.

Автоматическая проверка (открытие, переключение документа, правка) никогда не прерывает работу. Проверить RNG (F8) и сохранение, напротив, ждут результата: окно продолжает отрисовываться, но щелчки и нажатия клавиш до ответа игнорируются. Поэтому сохранение во время первой компиляции дожидается её окончания, а затем, как обычно, предупреждает, если документ недействителен.

Если процесс проверки не удаётся запустить, Varians проверяет сам, как раньше, и один раз сообщает об этом в строке состояния; тогда окно может зависнуть во время компиляции. Загрузка удалённой схемы при самом первом её использовании по-прежнему выполняется в Varians.

Собранные издания (XInclude)

Издание может включать свои части, например по файлу на проповедь, по стандарту XInclude. Издание, объявленное в project.xml, остаётся главным документом; его части определяются по его элементам xi:include, без других объявлений:

<TEI xmlns="http://www.tei-c.org/ns/1.0"
     xmlns:xi="http://www.w3.org/2001/XInclude">
  …
  <body>
    <xi:include href="sermons/s01.xml"/>
    <xi:include href="sermons/s02.xml" xpointer="s02"/>
    <xi:include href="sermons/s03.xml" xpointer="element(/1/2/1/1)"/>
  </body>

Часть — это либо фрагмент (весь файл, корнем которого служит, например, <div> проповеди), либо элемент полного документа TEI, указанный через xpointer: его идентификатором (s02 или element(s02)) или путём (element(/1/2/1/1): TEI, затем его 2-й дочерний элемент text, затем body, затем первый div). Часть сама может включать другие части. Относительные пути, записанные в части, отсчитываются от папки этой части.

Части и вкладки

У каждой части своя вкладка, названная по имени её файла, после вкладки издания и в порядке включения. Часть редактируется и сохраняется отдельно (Ctrl+S), со своей историей отмены; перед выходом Varians предлагает сохранить изменённые части. Список частей перечитывается при каждом сохранении издания или части. «Переименовать вкладку…» и «Исключить документ из проекта» относятся только к вспомогательным документам. Как и для вспомогательного документа, при показе части скрыты Представление XSLT / CSS и свидетели. Сохранение издания в другую папку нарушило бы пути его элементов xi:include: Varians заранее предупреждает об этом.

Проверка

Издание и каждая его часть запускают проверку собранного издания — по схеме издания и с учётом несохранённых изменений частей. Панель RELAX NG тогда добавляет столбец Документ; двойной щелчок по ошибке открывает нужную часть на нужной строке. Вкладка каждой части окрашивается по её собственным ошибкам. Отсутствующая или неправильно сформированная часть, циклическое включение или неподдерживаемая форма (parse="text", xi:fallback, другая схема xpointer) отмечаются на строке соответствующего xi:include.

Ссылки и свидетели

Издание и его части образуют единый документ: #id сначала ищется в файле, где он записан (включая заголовок), затем в других частях. F12, команда Ссылки и автодополнение учитывают это. К собранному изданию относятся только идентификаторы включённого элемента части: свидетель, объявленный лишь в <teiHeader> проповеди, включённой через xpointer, находится Varians в этой проповеди, но инструмент, читающий только собранное издание, его не увидит. В части команда Справка → Отладка аппарата… использует собственных свидетелей части: её <listWit>, иначе свидетелей издания, чей <locus target="#s01"> указывает на часть, иначе свидетелей, указанных в её @wit.

Ограничения этой версии

Синхронизация свидетелей для издания из частей приостановлена: свидетелей можно свободно просматривать, и строка состояния сообщает об этом. Она появится в следующих версиях. Представление XSLT / CSS показывает собранное издание вместе с частями, но только для чтения: редактирование фрагментов в нём пока недоступно. Веб-экспорт пока не содержит частей; перед экспортом Varians предлагает «Всё равно экспортировать». Проекта без xi:include это не касается.
